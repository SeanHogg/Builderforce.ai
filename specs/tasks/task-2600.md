## Problem & Goal

The developer container for #2554 can `write_file` onto `seanhogg/builderforce.ai` on `builderforce/task-2554`, but `list_files`, `read_file`, `git_*`, and `run_command` fail with “no repository bound” / “no repository checked out”.

B0–B5 cannot be implemented without reading live sources (`CONNECTED_CANVAS_ACTIONS`, the form surface registry, formObject publish, `summarizeForm`, `CanvasFormSurface`, `peopleObjects`, `growthApi.createCampaign`, `CAMPAIGN_BLOCKERS`, `marketing_audience_members`, and the five next-intl catalogs). Blind overwrites already destroyed production code (`0267ffd` probed `canvasChange.ts`).

**Goal:** Bind a full checkout of SeanHogg/Builderforce.ai as branch `builderforce/task-2554` so the next developer run can search, edit in place, run `pnpm run check` in `frontend`, and open a real PR. This PRD unblocks that checkout only.

## Target users / ICP roles

- Downstream developer agents executing #2554 / PRD 27 B0–B5
- Human reviewers who must inspect a real branch and CI, not blind writes

No end-customer surface is in scope.

## Scope

In scope:

- Bind SeanHogg/Builderforce.ai to the developer container as a complete, readable working tree
- Check out (or create from current default/base) branch `builderforce/task-2554`
- Enable `list_files`, `read_file`, search, in-place edit, `git_*`, and `run_command` against that working tree
- Preserve existing production files; no speculative overwrites
- Leave enough workspace for a later run to execute `pnpm run check` in `frontend` and open a PR from `builderforce/task-2554`

Out of this ticket’s product surface, but required as environment preconditions:

- Auth/credentials sufficient to clone/fetch the private repo and push the task branch
- Working tree includes the files B0–B5 must read (listed in Acceptance criteria)

## Functional requirements

1. **Repository bind.** The container has a single bound git repository: SeanHogg/Builderforce.ai (same remote as `seanhogg/builderforce.ai`).
2. **Branch checkout.** HEAD is `builderforce/task-2554`. If the branch exists remotely, check it out and fast-forward or reset only as needed to match remote without discarding unpublished task work. If it does not exist, create it from the current integration base and track origin.
3. **Full working tree.** The checkout is a complete clone (or equivalent sparse-disabled checkout), not write-only stubs. `list_files` at repo root returns the real tree.
4. **Read path.** `read_file` succeeds for any path present on the branch, including TypeScript/TSX sources, registries, and the five next-intl catalogs.
5. **Write path.** `write_file` / in-place edit updates the bound working tree (not an unbound shadow). Writes are git-visible (`git status`, `git diff`).
6. **Git operations.** `git status`, `git log`, `git diff`, `git add`, `git commit`, and `git push` of `builderforce/task-2554` succeed against the bound repo.
7. **Command execution.** `run_command` runs in the checkout. From `frontend`, `pnpm run check` is invokable (install/tooling failures are environment bugs to report, not “no repository checked out”).
8. **No blind mutation.** Binding and checkout must not rewrite application sources. In particular, do not touch `PHASE_SURFACES` and do not re-probe or overwrite `canvasChange.ts` or other production files as a side effect of binding.
9. **Handoff.** After bind, a subsequent developer run can search the tree, edit the B0–B5 files in place, run frontend check, and open a PR — without another bind step.

# PRD: Planned Vitest bump in `/webdit/converter`

## Problem & Goal

`/webdit/converter` is a Node CLI. Vitest is a direct `devDependency` (`^2.1.0`, lockfile `2.1.9`) with `vitest.config.ts` (`environment: node`). Vite is **not** a direct dependency and there is no `vite.config`. Build is `tsc -p tsconfig.json`. Vitest 2.x still pulls **transitive Vite 5.4.21** and **vite-node 2.1.9**, which carry residual Vite 5.4.21 advisories.

Dependabot PRs **820** (ticket 2180) and **821** (ticket 2181: esbuild, tsx, vitest) were closed 2026-09-10 (“these dependencies are no longer a dependency”); PR 820’s head branch is deleted. Ticket **2180 is disposed**. Those PRs must not be merged, reopened, or used as the merge vehicle. Security residual on Vite 5.4.21 is in-scope **here**, not on 2180.

**Goal:** First-class, planned upgrade of Vitest in `/webdit/converter` **off 2.1.x**, accepting the Vite-family transitives that the new Vitest major requires, with a compatibility pass on config, Node 22, and package scripts—without treating converter as a Vite app or inventing a standalone Vite pin.

## Target users / ICP roles

- Maintainers of `/webdit/converter` (Node CLI, TypeScript, Vitest).
- Downstream agents implementing this bump (deps, config, scripts, CI).
- Security / dependency reviewers clearing Vite 5.4.21 residual via the Vitest upgrade path.

Not an end-user product change.

## Scope

**In scope**

- Package: `/webdit/converter` only.
- Direct bump: `vitest` off `2.1.x` to a current major/minor that is compatible with Node 22 (`.nvmrc`) and existing test/typecheck/build scripts.
- Transitive Vite-family packages (`vite`, `vite-node`, related) **as required by the new Vitest**—lockfile resolution only, not a first-class Vite app upgrade.
- Review `tsx` / `esbuild` **only if** the new Vitest major requires a compatible bump.
- Compatibility: `vitest.config.ts`, Node 22, converter `test` / `typecheck` / `build` scripts.
- Security: eliminate or otherwise resolve residual Vite **5.4.21** advisories as a consequence of the Vitest bump.
- New first-class PR / branch for this ticket (not 820/821).

**Constraints**

- Converter is a Node CLI, not a Vite app. Do **not** add a standalone `vite` pin (including any invented `8.2.2` pin) or introduce `vite.config`.
- Do not merge, reopen, or retarget GitHub PRs **820** or **821**. Do not retarget disposed ticket **2180** into this work.

## Functional requirements

1. **Vitest upgrade**  
   Update `/webdit/converter` `package.json` so `vitest` is no longer on the 2.1.x line. Refresh the lockfile so Vite-family transitives match what the new Vitest requires.

2. **No standalone Vite**  
   Do not add `vite` as a direct dependency. Do not add `vite.config`. Do not pin Vite independently of Vitest.

3. **Conditional tsx / esbuild**  
   Inspect whether the chosen Vitest major documents or otherwise requires newer `tsx` / `esbuild`. Bump those only when required for Vitest or for converter scripts to keep working. Do not bundle an unrelated esbuild/tsx Dependabot sweep (that was PR 821).

4. **Config compatibility**  
   Review `vitest.config.ts` (`environment: node` and any Vitest 2.x APIs). Adjust only what the new major needs so tests still run as a Node CLI suite.

5. **Runtime and scripts**  
   Remain compatible with Node 22 per `.nvmrc`. `test`, `typecheck`, and `build` (`tsc -p tsconfig.json`) must succeed without changing converter’s product build model.

6. **Security**  
   After the bump, Vite 5.4.21 must not remain as the resolved Vite used by converter’s Vitest stack, unless a documented exception is impossible—in which case the work is incomplete. Advisories tied to that residual are owned by this ticket, not 2180.

7. **Delivery**  
   Land via a new branch/PR for this planned bump. Leave 820/821 closed.

## Acceptance criteria

- `vitest` in `/webdit/converter` is off `2.1.x`; lockfile no longer resolves Vitest 2.1.9 as the installed Vitest.
- `vite` is not a direct dependency; no `vite.config` added; no invented standalone Vite version pin.
- Transitive `vite` / `vite-node` (if still present) are whatever the new Vitest requires—not leftover 5.4.21 / 2.1.9 from Vitest 2.x.
- `tsx` / `esbuild` unchanged unless the new Vitest major requires a bump; any such bump is justified in the PR.
- `vitest.config.ts` is valid for the new Vitest; `environment: node` behavior preserved for the CLI test suite.
- On Node 22 (`.nvmrc`): converter `test`, `typecheck`, and `build` succeed.
- Residual Vite 5.4.21 advisories for this package’s Vitest tree are addressed by the upgrade.
- GitHub PRs 820 and 821 remain closed; ticket 2180 is not reopened or retargeted.

## Out of scope

- Merging, reopening, rebasing, or retargeting Dependabot PRs **820** / **821** or ticket **2180**.
- Treating `/webdit/converter` as a Vite application (Vite as a bundler/dev server, `vite.config`, direct `vite` dependency, standalone Vite 8.x pin).
- Unrelated esbuild/tsx upgrades that the new Vitest does not require (closed PR 821 scope).
- Vitest/Vite upgrades outside `/webdit/converter`.
- Product/CLI feature work, public API changes, or changing `build` away from `tsc -p tsconfig.json` except as strictly required for the Vitest bump.
- Re-litigating Dependabot’s “no longer a dependency” closures except to keep those PRs closed.

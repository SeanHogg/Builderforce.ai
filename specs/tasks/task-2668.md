# PRD: Operator Cleanup — Open/Resolve PR for `builderforce/task-2642`

## Problem & Goal

**Problem:** Branch `builderforce/task-2642` is 2 commits ahead of `main` with no pull request ever opened. This orphaned branch blocks repository cleanup and leaves an ambiguous artifact in the repo's branch list. It's unclear from branch state alone whether the net change is a legitimate, mergeable fix (removal of a stray spec file) or a reversion to a prior bad state (re-adding spec dumps).

**Goal:** Resolve the branch definitively — either by opening and merging a PR that cleanly deletes the stray `specs/tasks/task-2642.md` file, or by closing the branch without merging if the net diff is polluted with re-added spec dumps. This is pure git bookkeeping with no functional code impact.

## Target Users / ICP

- **Repo operator/agent** performing automated or semi-automated branch cleanup.
- No end-user-facing impact; this is internal repository hygiene tied to task/issue #2642's operator workflow.

## Scope

**In scope:**
- Inspecting the diff between `origin/main` and `builderforce/task-2642`.
- Conditionally opening a PR and merging it, OR closing the branch unmerged.
- Documenting the resolution outcome for traceability back to #2642.

**Out of scope (see below):** Any change to the actual #2642 deliverable (the revert of commit `0267ffd` on `builderforce/task-2554`), which is tracked separately under issue #2642 itself.

## Functional Requirements

1. **Verify net diff** using:
   ```
   git diff --stat origin/main...builderforce/task-2642
   ```
2. **Decision logic:**
   - **Case A — Clean deletion only:** If the net diff shows *only* the deletion of `specs/tasks/task-2642.md` (no other files added, modified, or re-added):
     - Open a pull request from `builderforce/task-2642` into `main`.
     - Title/description should reference that this is operator bookkeeping for a stray spec-dump cleanup, not the #2642 feature deliverable.
     - Merge the PR once opened (no additional review gate implied beyond standard merge process).
   - **Case B — Spec dumps re-added:** If the diff includes re-added spec-dump content (i.e., net effect is not solely the deletion):
     - Do **not** open a PR / do **not** merge.
     - Close or delete the branch without merging.
     - Note in the closure that #2642 is an operator-only git remainder with no repo artifact to ship.
3. **Traceability:** Any PR, comment, or closure action must reference issue #2642 and clarify the distinction between this branch cleanup and the actual #2642 deliverable (revert of `0267ffd` on `builderforce/task-2554`).

## Acceptance Criteria

- [ ] `git diff --stat origin/main...builderforce/task-2642` has been run and its output recorded/reviewed.
- [ ] If net diff = deletion of `specs/tasks/task-2642.md` only:
  - [ ] PR opened from `builderforce/task-2642` → `main`.
  - [ ] PR merged into `main`.
  - [ ] Post-merge, `specs/tasks/task-2642.md` no longer exists on `main`.
- [ ] If net diff includes re-added spec dumps:
  - [ ] No PR opened (or PR closed without merge if already opened).
  - [ ] Branch closed/deleted without merging into `main`.
- [ ] Resolution explicitly distinguishes this bookkeeping action from the #2642 feature deliverable (revert of `0267ffd` on `builderforce/task-2554`), avoiding any conflation in commit messages, PR descriptions, or issue comments.
- [ ] No unrelated files are merged into `main` as a side effect of this cleanup.

## Out of Scope

- The revert of commit `0267ffd` on branch `builderforce/task-2554` — this is the actual #2642 deliverable and is tracked/handled independently under issue #2642.
- Any code, feature, or spec content changes beyond resolving this single orphaned branch.
- Broader cleanup of other stale/orphaned branches not named `builderforce/task-2642`.
- CI/CD pipeline changes or merge policy changes — standard existing merge process applies.

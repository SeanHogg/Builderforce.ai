# PRD 26 — Advisor Platform (epic composition)

## Problem & Goal

PRD 26 and its implementation notes describe two different products. Ticket **#2522** Spec points at `specs/builderforce/26-prd-advisor-platform.md`, which still specifies epic **#2545** (marketplace Book bind, A0–A5 workshops/academy/packs, restricted Brain thread, no advisory meeting kind). PR **#829** added `specs/builderforce/26-implementation-notes-advisor-platform.md` for **this** epic: Advisors talent filter, `advisory` meeting kind, Meeting Notes agent, and minutes→board via a generalised `pullStandupMinutesAct`.

Children that follow both files will fork pipelines. That is the failure the epic composition contract exists to prevent.

**Goal:** Make PRD 26 the single product source for #2522. Rewrite `26-prd-advisor-platform.md` so it matches this epic. Explicitly split or defer A2–A5 (and the rest of the #2545 surface) to epic **#2545**. Keep implementation notes composing on that PRD, not replacing it.

## Target users / ICP roles

- **Founders / operators** who hire or meet Advisors and need a durable record of advisory conversations on the board.
- **Advisors** (talent `category=advisors`) who run advisory meetings and expect notes to land without a separate standup ritual.
- **Internal agents** (Meeting Notes and board-sync) that must share one meeting kind and one pull path.
- **Downstream implementers** on #2522 who must not also build marketplace, academy, or restricted Brain from this PRD.

## Scope

In scope for this epic (#2522) and for the updated PRD 26:

- Talent filter and listing behaviour for `category=advisors`.
- First-class meeting kind `advisory` (not standup, not a marketplace Book bind).
- Meeting Notes agent scoped to advisory meetings.
- Generalise `pullStandupMinutesAct` so advisory minutes flow to the board the same way standup minutes do, without a standup-only code path.
- Composition contract: PRD 26 describes only this epic; implementation notes may add build detail but must not introduce a second product.

Out of this rewrite’s file set: only `specs/builderforce/26-prd-advisor-platform.md` must change as the product contract. `26-implementation-notes-advisor-platform.md` is aligned after the PRD matches; do not invert ownership (notes must not become the PRD).

## Functional requirements

1. **Single product on PRD 26.** `26-prd-advisor-platform.md` specifies Advisors + advisory meetings + Meeting Notes + generalised minutes pull. It must not specify `/marketplace?family=talent` Book bind, A0–A5 workshops/academy/packs, or a restricted Brain thread as this epic’s delivery.
2. **Explicit split.** PRD 26 names epic **#2545** as the owner of A2–A5 and the marketplace/academy/packs/Brain surface, and states those items are deferred (not “later in 26”).
3. **Advisors talent filter.** Users can filter talent to Advisors (`category=advisors`) and act on that list without treating Advisors as a marketplace family Book.
4. **Meeting kind `advisory`.** Creating, listing, and completing advisory meetings uses kind `advisory`. Standup kind remains distinct. There is no requirement that advisory meetings exist only as a side effect of a Book bind.
5. **Meeting Notes agent.** An agent produces minutes for `advisory` meetings. Input is the advisory meeting; output is structured minutes suitable for board pull.
6. **Minutes → board.** Board sync uses a generalised pull (today: `pullStandupMinutesAct` renamed or extended) that accepts standup and advisory minutes. Advisory minutes appear on the board without a standup meeting or a second scrape pipeline.
7. **Notes compose on the PRD.** After the PRD update, implementation notes may only refine how (agent wiring, act generalisation, filters). If notes and PRD diverge, the PRD wins and notes are edited to follow.
8. **Ticket alignment.** #2522 Spec continues to point at `26-prd-advisor-platform.md`. That file must be sufficient for children to implement this epic without reading #2545’s product as in-scope.

## Acceptance criteria

- `26-prd-advisor-platform.md` describes Advisors filter, `advisory` meeting kind, Meeting Notes agent, and generalised minutes→board pull, and does **not** present marketplace Book bind, A0–A5, or restricted Brain as #2522 scope.
- The same PRD contains an explicit deferral: A2–A5 (workshops, academy, packs) and `/marketplace?family=talent` Book bind + restricted Brain thread belong to **#2545**, not this epic.
- `26-implementation-notes-advisor-platform.md` does not introduce product behaviour absent from the updated PRD; any leftover #2545 language is removed or marked as non-goals.
- A child implementing only PRD 26 cannot be required to ship A2–A5, Book bind, or restricted Brain to close #2522.
- Advisory minutes reach the board through the generalised pull path; standup minutes still work; no parallel advisory-only board pipeline.
- #2522 Spec path remains `26-prd-advisor-platform.md` and is consistent with the notes.

## Out of scope

- Building or restating epic **#2545**: marketplace `family=talent` Book bind, A0–A5 workshops/academy/packs, restricted Brain thread.
- Changing #2545’s own PRD/specs beyond a pointer that 26 no longer owns that product.
- New meeting kinds other than `advisory` (standup unchanged except for shared pull).
- Replacing board pull with a new minutes store or a second act beside the generalised `pullStandupMinutesAct`.
- Rewriting implementation notes to re-specify the old 26-prd product so that #2522 would ship marketplace/A0–A5.
- Pipeline, billing, or talent-category work unrelated to Advisors.

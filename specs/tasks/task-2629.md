# PRD: C1 — Guided campaign journey contract

**Status:** WIP  
**Owner:** Creation Canvas / Growth contract  
**Depends on:** C0 (`canvasAiSystemPrompt.ts` CAMPAIGN block on main)  
**Retry of:** #2547 (Contents API 403, 2026-09-16)

## Problem & Goal

Operators ask the canvas to *run* a campaign. Today the product can list campaigns and can draft copy, but it has no shared contract that:

1. Distinguishes **run** intent from **list** intent.
2. Separates a human journey **checklist** (brand, consent audience, sender, offer, copy) from Growth **sendReadiness** (suppression, unsubscribe, transport).
3. Keeps anonymous sessions and cloud agents **draft-only**.
4. Refuses to invent ROI from opens, clicks, or `/api/roi/rollup`.

Without that contract, downstream agents duplicate HubSpot-shaped flows, gate on empty ICP, treat connect-success as send, or promote engagement metrics into a dollar number.

**Goal:** Ship a compose-only TypeScript contract plus tests, barrel export, and a thin frontend adapter so every downstream agent shares one journey: intake → checklist → copy → confirm. List remains a secondary path. Send and spend remain human-gated and server-persisted.

## Target users / ICP roles

- **Operator (signed-in, server persistence):** runs a campaign for a chosen channel after confirming checklist + sendReadiness.
- **Guest / anonymous canvas user:** may draft objects via guest-safe `canvas_add_object` only; never `maySend`.
- **Cloud / agent session (`agentDraftOnly`):** may assemble draft campaign objects; never `maySend`.
- **Downstream agents** consuming `creation-canvas-contract`: must import this module rather than inventing campaign gates.

Empty ICP is **not** a user, role, or gate. Absence of ICP never blocks checklist, copy, or draft.

## Scope

**In**

- `packages/creation-canvas-contract/src/guidedCampaign.ts`
- Unit tests colocated with the contract
- Barrel export from the package index
- Thin adapter `frontend/src/lib/canvasMarketing.ts` that maps canvas/marketing state onto the contract (no new product surface, no HubSpot clone)
- Composition of existing primitives only (intent, checklist, sendReadiness, persistence, ROI, connect)

**Explicit non-goals in this slice:** UI chrome, send pipeline, spend, attribution jobs, prompt rewrite (C0 already defines intake→checklist→copy→confirm and guest-safe tools).

## Functional requirements

### 1. Intent

- Primary: **campaign-RUN**. Phrases such as “I want to run a marketing campaign” and “connect my email and run a marketing campaign” resolve to run.
- Secondary: **campaign-LIST**. Listing must not overwrite or replace `marketing.campaigns.list`.
- Connect-then-run is still RUN intent. Connect success is not send.

### 2. Journey checklist (not sendReadiness)

Checklist items, all required for `checklist.ready`:

| Item | Meaning |
| --- | --- |
| brand | voice **and** doNotSay |
| consentAudience | consented audience for this run |
| senderAccount | sender/account for the **chosen channel** |
| offer | the offer this run promotes |
| copy | campaign copy |

Growth `sendReadiness` stays orthogonal: suppression, unsubscribe, transport. Do not fold those into the checklist. Do not treat checklist.ready as sendReadiness.ready or the reverse.

Empty ICP must never appear as a checklist item or a readiness gate.

### 3. `maySend`

`maySend === true` **only if all** of:

- `persistence === "server"`
- `humanConfirmed === true`
- `checklist.ready === true`
- `sendReadiness.ready === true`
- `agentDraftOnly === false`

Otherwise `maySend === false`.

Anonymous persistence and cloud agents are draft-only even when checklist and copy are complete.

### 4. Campaign ROI for this run

- Default: `roi.status === "unknown"` (not `0`, not inferred).
- ROI may become a number **only** when **this run** has spend and/or attributed pipeline/revenue.
- Opens, clicks, and `/api/roi/rollup` are ignored. They must never be promoted to a numeric ROI.

### 5. Connect

Connect success never sends and never spends. It may satisfy `senderAccount` on the checklist; it does not set `humanConfirmed`, `maySend`, or ROI.

### 6. Composition and packaging

- Compose existing primitives; do not reimplement HubSpot objects, sequences, or lists.
- Do not re-author C0 `CAMPAIGN` system prompt.
- Adapter is mapping-only: canvas/marketing state in, contract view out. No send, no spend, no list overwrite.

Do not rename to a HubSpot-shaped `Campaign` / `Workflow` / `Sequence` type. An alias `guidedCampaign = guidedCampaignRun` is allowed; `guidedCampaignRun` is the name C3 imports.
2. **Checklist ≠ Growth `sendReadiness`.** Journey checklist is brand (voice **and** doNotSay), consentAudience, senderAccount for the **chosen channel**, offer, copy. `sendReadiness` stays suppression, unsubscribe, transport — an **input** to `maySend`, never folded into checklist items. `checklist.ready` MUST NOT be treated as `sendReadiness.ready` or the reverse.
3. **Empty ICP is never a gate.** `intake.icp` is optional. Absence of ICP MUST NOT appear as a checklist item, a `maySend` conjunct, or a `sendReadiness` blocker. C2 binds the picker to this optional field; C1 must not invent a required ICP.

5. **Campaign ROI defaults to `unknown`.** Numeric ROI is allowed **only** from **this run’s** spend and/or attributed pipeline/revenue. Opens, clicks, sent counts, and `/api/roi/rollup` are ignored and MUST NEVER be promoted to a number (including `0`).
6. **Connect success never sends or spends.** It MAY satisfy checklist `senderAccount` for the chosen channel. It MUST NOT set `humanConfirmed`, MUST NOT set `maySend` by itself, and MUST NOT set ROI.

Do not re-author C0 `CAMPAIGN` system prompt. Do not name `canvas_add_inbox` (or any send/spend tool) on an anonymous board — guest remains `canvas_add_object` only (C0).
8. **Adapter is mapping-only.** `frontend/src/lib/canvasMarketing.ts` maps canvas/marketing state onto `GuidedCampaignInput` and calls `guidedCampaignRun`. It MUST NOT duplicate checklist / `maySend` / ROI arithmetic, MUST NOT send, MUST NOT spend, MUST NOT clobber list.

### R-1 — Intent: campaign-RUN is primary; LIST is secondary

- Classify operator utterance into `intent: "run" | "list" | "none"`.
- **RUN (primary).** The following MUST classify as `"run"`:
  - “I want to run a marketing campaign”
  - “connect my email and run a marketing campaign”
  - Close variants that include a run/launch/start verb on a campaign (e.g. “run a campaign”, “launch a marketing campaign”, “start a marketing campaign”).
- **Connect-then-run is still RUN.** “Connect my email and run a marketing campaign” is `"run"`, not a send, not a list.
- **LIST (secondary).** Utterances that only ask to list/show/see existing campaigns (e.g. “list my campaigns”, “show campaigns”, “what campaigns do I have”) classify as `"list"`.
- If an utterance matches **both** RUN and LIST, **RUN wins**.
- `"none"` is anything that is neither. C1 MUST NOT invent a third product path or auto-route `"none"` to list.
- Classifying `"run"` starts (or resumes) the guided journey view. It MUST NOT send, spend, confirm, or fulfill the ask by listing campaigns.

### R-2 — List must not clobber `marketing.campaigns.list`

- Existing `marketing.campaigns.list` remains the list API. C1 MUST NOT overwrite, replace, wrap-as-replacement, rename, or delete it.
- `"list"` intent MAY be fulfilled by callers invoking that existing API. `"run"` intent MUST NOT auto-invoke list as the primary response.
- Tests MUST assert the list symbol/path is unchanged by this module (no re-export that shadows the Growth/tool list).

### R-3 — Journey checklist items (five; all required for `checklist.ready`)

Evaluate these items only. Do **not** add ICP, persona completeness, guest identity, suppression, unsubscribe, or transport as checklist items.

| Item | Ready when | Not ready when |
| --- | --- | --- |
| `brand` | `brand.voice` is a non-empty string **and** `brand.doNotSay` is a **defined** list (array present). An authored empty `doNotSay` array (`[]`) is valid (“nothing forbidden”). | `voice` null/undefined/whitespace-only; `doNotSay` null/undefined (field missing). Voice without doNotSay (or the reverse) is not ready. |
| `consentAudience` | A consented audience is bound to **this run** (audience id/handle present **and** consented for this send). | Missing audience, unbound audience, or audience present but not consented. Not satisfied by ICP. Not satisfied by a suppression list. |
| `senderAccount` | A sender/account exists for the **chosen channel** (email → mailbox or SendGrid sender; SMS → Twilio; social → connected social account; ads → connected ads account). If multiple channels are chosen, **each** chosen channel has its sender. | No channel chosen; sender missing; sender bound to a **different** channel than the one chosen. Connect success MAY flip this item to ready when the connected account matches the chosen channel (R-10). |
| `offer` | Non-empty offer/CTA string for this run. | Null/undefined/whitespace-only. |
| `copy` | Non-empty campaign copy draft for this run (channel-appropriate: email subject/body, SMS body, social/ad primary text). | Null/undefined/whitespace-only. |

`checklist.ready === true` **iff all five** items are ready. Partial progress is allowed for draft; it does not yield `checklist.ready`.

### R-4 — Checklist is orthogonal to Growth `sendReadiness`

- C1 **accepts** `sendReadiness` as an input (`{ ready: boolean }` plus optional opaque diagnostics). C1 MUST NOT recompute suppression, unsubscribe, or transport health.
- C1 MUST NOT copy suppression / unsubscribe / transport into checklist items or require them for `checklist.ready`.
- `checklist.ready === true` with `sendReadiness.ready === false` is a valid state (draftable, not sendable).
- `sendReadiness.ready === true` with `checklist.ready === false` is a valid state (`maySend` still false).
- If `sendReadiness` is omitted, treat `sendReadiness.ready === false` for `maySend` only; do not fail the checklist.

### R-5 — Empty ICP is never a gate

- `intake.icp` is optional (`string | null | undefined`). Omit or null when unset. NEVER send a dummy/placeholder ICP id.
- A fixture with empty/missing ICP MUST still be able to reach checklist evaluation, copy draft, and `maySend` arithmetic. ICP MUST NOT appear in the checklist item set, in `checklist.ready`, in `maySend`, or in `sendReadiness`.
- C2 (#2636) owns list/create/select UI for `ri_icps` and binds to this optional field. C1 MUST NOT require C2 to have shipped in order for the contract to evaluate.

### R-6 — `maySend` five-way conjunction

`maySend === true` **only if all** of the following hold. Otherwise `maySend === false`.

| Conjunct | Required value |
| --- | --- |
| `persistence` | exactly `"server"` |
| `humanConfirmed` | `true` |
| `checklist.ready` | `true` (R-3) |
| `sendReadiness.ready` | `true` (R-4) |
| `agentDraftOnly` | `false` |

No other combination yields `maySend`. In particular:

- `checklist.ready` alone is not send.
- `sendReadiness.ready` alone is not send.
- Connect success is not send (R-10).
- Chat assent is not `humanConfirmed` (C3 owns the confirm control; C1 only reads the boolean).
- There is no sixth conjunct for ICP, persona, or guest identity.

### R-7 — Persistence, anonymous, and cloud agents are draft-only

- `persistence === "server"` means a signed-in operator session whose campaign objects persist on the server.
- Any other persistence value (including `"anonymous"`, guest, local, missing) is **not** `"server"` → `maySend === false`.
- `agentDraftOnly === true` for cloud / autonomous agent sessions. Adapter MUST pass `true` for those sessions. If `true`, `maySend === false` even when the other four conjuncts are true.
- Anonymous canvas may draft via guest-safe `canvas_add_object` only (C0). C1 MUST NOT introduce `canvas_add_inbox`, send, schedule, publish, or spend tools for anonymous or agent sessions.
- Fixtures that MUST yield `maySend === false`: anonymous + complete checklist + copy; `agentDraftOnly: true` + complete checklist + copy + server persistence + sendReadiness + humanConfirmed.

### R-8 — `humanConfirmed` is an explicit flag, not connect and not chat

- C1 reads `humanConfirmed: boolean`. It does not render the confirm UI (C3).
- `humanConfirmed` MUST be `true` only when the operator has completed the explicit confirm control for this run (C3). Default / omitted / false → not confirmed.
- The following MUST NOT set `humanConfirmed` to `true`: connect OAuth/success, mailbox/social/ads connect, chat messages (“yes”, “send it”, “looks good”), checklist.ready, sendReadiness.ready, copy complete, agent tool success.

### R-9 — Campaign ROI for **this run** (`unknown` until spend and/or attributed pipeline/revenue)

- Default: `roi.status === "unknown"`. Not `0`. Not inferred. Not omitted-as-zero.
- `roi` MAY become `{ status: "numeric", value: number }` **only when this run** has at least one of:
  - recorded **spend** for this run (e.g. ads/ledger amount attributed to this campaign run id), and/or
  - **attributed pipeline** and/or **attributed revenue** for this run (events tagged with this run/campaign id).
- The numeric `value`, when present, MUST be derived **only** from those this-run spend and/or attributed pipeline/revenue figures. Architect may pick the ratio/difference formula; C1 does not invent a multi-touch model.
- The following MUST leave `roi.status === "unknown"` even when they are numeric and present:
  - opens
  - clicks
  - sent / delivered counts
  - workspace `/api/roi/rollup` (or any rollup payload)
  - `canvasRunComparison.ts` workspace-level comparison without this-run attribution
- Engagement metrics MAY be displayed elsewhere as counters; they MUST NOT be copied into `roi.value`.
- ROI is per **this run**, not workspace-level, not another campaign’s spend.

### R-10 — Connect success

- Connect success (mailbox, SendGrid, Twilio, social, ads, OAuth) NEVER sends and NEVER spends.
- Connect success MAY satisfy checklist `senderAccount` when the connected account matches the **chosen channel**.
- Connect success MUST NOT set `humanConfirmed`, MUST NOT flip `maySend` except insofar as `senderAccount` now contributes to `checklist.ready` **and** the other four `maySend` conjuncts are independently true (they will not be, unless the operator already confirmed — and confirm is C3, not connect).
- Connect-success fixture: `senderAccount` may become ready; `humanConfirmed` stays false; `maySend` stays false; `roi.status` stays `"unknown"`; no send; no spend.

### R-12 — Input / view shape (semantics locked; field names may be refined by architect)

`guidedCampaignRun(input: GuidedCampaignInput): GuidedCampaignView`

**Input (minimum semantics):**

- `utterance?: string` — used to classify intent when `intent` is not pre-set.
- `brand?: { voice?: string \| null; doNotSay?: string[] \| null }`
- `consentAudience?: { id: string; consented: boolean } \| null`
- `channel` / chosen channels — required for `senderAccount` evaluation.
- `senderAccount?: { channel: string; id: string } \| null` (or equivalent per chosen channel).
- `offer?: string \| null`
- `copy?: string \| null`
- `intake?: { icp?: string \| null }` — ICP optional; extra intake fields (business, vertical, goal) MAY pass through but MUST NOT become gates.
- `sendReadiness?: { ready: boolean }` — Growth passthrough.
- `persistence: "server" \| "anonymous" \| string`
- `humanConfirmed: boolean`
- `agentDraftOnly: boolean`
- `connectSuccess?: boolean` — MAY flip `senderAccount` when account matches channel; never confirm/send/spend/ROI.
- `thisRun?: { spendCents?: number \| null; attributedRevenueCents?: number \| null; attributedPipelineCents?: number \| null; opens?: number; clicks?: number; rollup?: unknown }` — only spend / attributed pipeline / attributed revenue may feed ROI; opens, clicks, rollup ignored.

**View (minimum semantics):**

- `intent: "run" \| "list" \| "none"`
- `checklist: { items: { brand: boolean; consentAudience: boolean; senderAccount: boolean; offer: boolean; copy: boolean }; ready: boolean }`
- `sendReadiness: { ready: boolean }` — echo of input, not recomputed.
- `maySend: boolean`
- `roi: { status: "unknown" } \| { status: "numeric"; value: number }`
- Echoes of `persistence`, `humanConfirmed`, `agentDraftOnly` as needed by C3.

Architect may refine TypeScript names but MUST preserve these semantics. MUST NOT add HubSpot Contact / Company / Deal / Workflow / Sequence / List types.

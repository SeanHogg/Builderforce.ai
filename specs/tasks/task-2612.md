# PRD 29 Change B — `chatTicketParent.test.ts`

WIP Product Requirements Document. Shared by every downstream agent on this task.

## Problem & Goal

**Problem.** Parent PRD 29 Change B requires `TicketParent` on `TicketHealth` and names `api/src/application/brain/chatTicketParent.test.ts` as the proof file. On `main`, `ChatTicketService` already exports `TicketParent` and `TicketHealth.parent` (task/epic/gap via `tasks.parent_task_id`; absent for top-level tickets, deleted parents, and non-task-tier kinds). The dedicated test file is not on `main`: a `chatT*` glob under `api/src/application/brain` returns only `ChatTicketService.ts`, and `chatTicketParent.test.ts` is not found.

Issue **#2558** is verify-only. It runs whatever Vitest discovers under `src/application/brain`, then `pnpm type-check`. It must not invent a skip, a stub, or a stand-in for Change B. Without this file, Change B has no proof in the brain suite, and #2558 cannot certify it.

**Goal.** Add the missing proof file so Vitest under `src/application/brain` exercises `TicketHealth.parent` as specified. Do not change product behavior, do not weaken #2558’s existing suite, and do not paper over the gap with a skip or a substitute assertion.

## Target users / ICP roles

- Downstream implementation and test agents sharing this PRD
- API brain maintainers of `ChatTicketService` / `TicketHealth`
- #2558 verify-only reviewers (Vitest discovery + typecheck)

End-user product behavior is unchanged; this change is proof-only.

## Scope

In scope:

- Create `api/src/application/brain/chatTicketParent.test.ts`
- Cover `TicketHealth.parent` as already implemented on `ChatTicketService`
- Keep the file discoverable by the existing brain Vitest run used by #2558
- Assert parent presence, absence, and label using current `TicketParent` / `TicketHealth` types

Out of product-code scope unless a real type or export mismatch blocks the proof (see Out of scope).

## Functional requirements

1. **Proof file location.** Add `api/src/application/brain/chatTicketParent.test.ts`. Do not relocate proof to another package, folder, or filename.

2. **In-tenant task-tier parent.** When the ticket is a task-tier kind (`task` / `epic` / `gap`) with an in-tenant `tasks.parent_task_id` that resolves to a live parent, `TicketHealth.parent` is set. `parent` is a `TicketParent` whose identity matches that parent row.

3. **Parent label.** When `parent` is set, `parent` label is the parent ticket’s title (not the child title, not an id, not a kind name).

4. **Absent — top-level.** When the ticket has no `parent_task_id`, `TicketHealth.parent` is absent (`null` / `undefined` consistent with the existing type).

5. **Absent — deleted parent.** When `parent_task_id` points at a deleted parent, `TicketHealth.parent` is absent.

6. **Absent — non-task-tier kinds.** For `portfolio`, `objective`, `initiative`, `roadmap`, `spec`, `retro`, and `poker`, `TicketHealth.parent` is absent even if a `parent_task_id` column value exists.

7. **Tenant isolation.** Parent is only set when the parent row is in the same tenant as the child. Cross-tenant `parent_task_id` must not populate `TicketHealth.parent`.

8. **No #2558 weakening.** Do not add skips, `.todo`, filtered-out describes, or stand-in tests in other brain files to satisfy Change B. Do not change #2558’s verify-only contract (discover Vitest under `src/application/brain`, then `pnpm type-check`).

9. **No behavior invention.** Tests assert existing `ChatTicketService` / `TicketHealth.parent` behavior. Do not expand parent resolution (e.g. new kinds, soft-delete rules, or label fallbacks) unless production code already does so.

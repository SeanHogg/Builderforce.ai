# PRD: Restore `canvasChange.ts` after probe overwrite (revert 0267ffd)

## Problem & Goal

Commit `0267ffd360e524dbd6ae8a93d1e71df8202d4dee` on `builderforce/task-2554` did **not** overwrite the real canvas domain module. It **added** a nested probe file at the wrong prefix:

`Builderforce.ai/frontend/src/domains/canvas/domain/canvasChange.ts`

Content at the tip of `builderforce/task-2554` (verified 2026-09-16):

```ts
// probe — will be overwritten; write_file capability check
export {};
```

The developer container had no usable git checkout, so the write landed as a **created** path relative to a sparse/wrong bind of main (repo root treated as if it were already under `Builderforce.ai/`). Diff of `0267ffd` is `+2 / −0`.

The **real** module is intact on both `origin/main` and `builderforce/task-2554`:

`frontend/src/domains/canvas/domain/canvasChange.ts` (138 lines)

Public surface: `ProposedCanvasChange`, `canvasChangesCanAutoApply`, `CONNECTED_CANVAS_ACTIONS`, `canInvokeCreationObjectAction`. It does **not** export `CanvasChangeKind`, `applyObjectChange`, or `CANVAS_CHANGE_PROBE`.

**Risk if `builderforce/task-2554` is merged as-is:** a junk `Builderforce.ai/` prefix tree ships on main. The live canvas-change API would keep working (the real file is untouched), but the probe must not merge.

**Goal:** Revert `0267ffd` (or delete the nested probe path) so `builderforce/task-2554` matches `origin/main` at that path — meaning the nested file is **absent**. Do not merge `builderforce/task-2554` until that is true. Do not rewrite the real 138-line module.

**Reference:** `SeanHogg/Builderforce.ai@0267ffd`

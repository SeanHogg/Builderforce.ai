# PRD: Restore `canvasChange.ts` after probe overwrite (revert 0267ffd)

## Problem & Goal

Commit `0267ffd` on `builderforce/task-2554` replaced `Builderforce.ai/frontend/src/domains/canvas/domain/canvasChange.ts` with a 9-line developer probe:

```ts
export const CANVAS_CHANGE_PROBE = "task-2554-repo-probe" as const
```

The original ~128-line domain module (exports `CanvasChangeKind`, `applyObjectChange`, and related canvas-change types/logic) was destroyed. The developer container had no git checkout, so `git_undo` could not restore it. Platform recorded the path as created relative to a sparse/wrong bound of main. If this branch is merged, the stub would ship and canvas change application would break.

**Goal:** Revert `0267ffd` (or equivalently restore the file from `origin/main`) so `canvasChange.ts` matches main. Do not merge `builderforce/task-2554` until that is true.

**Reference:** `SeanHogg/Builderforce.ai@0267ffd`

## Target users / ICP roles

- Downstream agents executing this restore (primary consumers of this PRD)
- Frontend canvas domain maintainers
- Reviewers / operators gating merge of `builderforce/task-2554`

## Scope

In scope:

- Revert commit `0267ffd` on `builderforce/task-2554`, **or** restore `Builderforce.ai/frontend/src/domains/canvas/domain/canvasChange.ts` byte-for-byte from `origin/main`
- Confirm the restored file again exports `CanvasChangeKind` and `applyObjectChange` and is ~128 lines (not the 9-line probe)
- Leave the branch unmerged until the file matches main
- No product/behavior change beyond undoing the probe overwrite

## Functional requirements

1. **FR-1 Restore source of truth.** `Builderforce.ai/frontend/src/domains/canvas/domain/canvasChange.ts` on `builderforce/task-2554` must match `origin/main` at that path (same content as before `0267ffd`).
2. **FR-2 Preferred restore path.** Prefer `git revert 0267ffd` (or equivalent restore of the pre-probe blob). Do not rewrite history unless revert is impossible.
3. **FR-3 Domain API.** Restored module must export `CanvasChangeKind` and `applyObjectChange` (and the rest of the original public surface). It must **not** export `CANVAS_CHANGE_PROBE`.
4. **FR-4 No stub ship.** The 9-line probe file must not be present on the branch tip that would be merged.
5. **FR-5 Merge gate.** `builderforce/task-2554` must not be merged until FR-1–FR-4 hold.
6. **FR-6 Minimal blast radius.** Do not change unrelated files, task-2554 product work, or other domains as part of this restore.

## Acceptance criteria

- [ ] Tip of `builderforce/task-2554` does not contain `CANVAS_CHANGE_PROBE` / `"task-2554-repo-probe"`.
- [ ] `Builderforce.ai/frontend/src/domains/canvas/domain/canvasChange.ts` matches `origin/main` (diff empty for that path vs main).
- [ ] File is the original ~128-line domain module, not a 9-line stub.
- [ ] `CanvasChangeKind` and `applyObjectChange` are exported and usable by existing canvas consumers.
- [ ] Restore is attributable to revert of `0267ffd` (or an equivalent restore commit with that intent).
- [ ] Branch is not merged until the above are true.

## Out of scope

- Completing, debugging, or shipping other work on `#2554` / `builderforce/task-2554`
- Rewriting canvas change semantics, types, or `applyObjectChange` behavior
- Fixing platform sparse-tree / “created vs main” recording
- Changing CI, merge queue, or branch protection beyond holding this merge
- Force-push / history rewrite unless revert cannot restore the file
- Any new probe, placeholder, or partial reimplementation of `canvasChange.ts`

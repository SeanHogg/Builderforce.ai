# PRD: Render `%` in `sessionsTree.ts` chat item descriptions

## Problem & Goal

Chat item descriptions in the sessions tree (`sessionsTree.ts`) do not display a literal `%`. The character is treated as a format/interpolation token (or otherwise stripped/escaped) so values such as `50%`, query strings, and encoded paths appear wrong or truncated.

**Goal:** Show `%` exactly as authored in each chat item’s `description` in the sessions tree, with no extra escaping visible to the user and no change to other tree fields.

## Target users / ICP roles

- End users viewing chat/session history in the sessions tree (percent-complete, URLs, encoded paths, titles containing `%`).
- Downstream agents implementing and verifying the `sessionsTree.ts` change.

## Scope

In scope: the chat item `description` path in `sessionsTree.ts` (assignment, any format/l10n/`printf`-style handling, and the string that the tree view renders).

Out of scope items are listed below.

## Functional requirements

1. A chat item `description` that contains `%` must render those characters literally in the sessions tree.
2. A single `%` (not part of a known format pair) must not drop the rest of the string or throw.
3. Existing format tokens used elsewhere in the tree (if any) must keep working; only chat item `description` is changed to treat `%` as literal text.
4. Doubled or encoded forms (`%%`, `%25`) must not be required of callers and must not show up as extra characters in the UI unless they were in the source description.
5. Empty, missing, and `%`-free descriptions must behave as they do today.
6. No change to chat item `label`, `tooltip`, icons, commands, or session identity.

## Acceptance criteria

- A description of `Progress 50%` shows as `Progress 50%`.
- A description of `100% done` and of a lone `%` shows those characters unchanged.
- A description with several `%` signs (e.g. `a%b%c`) shows every `%`.
- Descriptions without `%` match current rendering.
- No runtime error when `description` includes `%`.
- Change is confined to `sessionsTree.ts` chat item `description` handling (or a helper used only for that string).

## Out of scope

- Labels, tooltips, markdown bodies, and other views.
- Localization/message catalogs outside this description string.
- URL encoding/decoding of session data.
- New description fields, copy, or tree UX.
- Performance, accessibility, or theming work beyond correct `%` display.

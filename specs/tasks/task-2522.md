# PRD 26 — Advisor Platform

**Spec:** `specs/builderforce/26-prd-advisor-platform.md`  
**Class:** SCORE-class advising, marketplace-dogfooded  
**Principle:** Compose existing primitives. Do not clone SCORE.

---

## Problem & Goal

New and solo entrepreneurs need trusted, bookable advice (start, grow, exit) without hiring a firm. Volunteer networks like SCORE provide that help, but they are offline-first, affiliation-heavy, and not a product founders already live in.

BuilderForce already has the pieces: marketplace talent profiles, ATS public book-by-token, WebRTC meetings with `runAgentTurn` + `summarizeMeeting`, `parseMeetingMinutes`, `pullStandupMinutesAct`, and marketplace listings for agents, skills, courses, playbooks, and templates.

**Goal:** Make BuilderForce the default place advisors list themselves and founders find, book, and leave a session with work already on the board — by composing those primitives, not by building a mentoring org, a new video stack, or a new CMS.

**Kill condition:** A logged-out visitor discovers an advisor, books a slot, joins the meeting, and after it ends sees at least one board task and one proposed follow-up — no staff click.

---

## Target users / ICP roles

| Role | Who | Job to be done |
| --- | --- | --- |
| Advisor | Operators, ex-founders, functional specialists listing on talent | Publish expertise, take bookings, run advisory sessions, leave structured notes |
| Founder / solo entrepreneur | New or early-stage operators seeking advice, not a retained consultant | Discover a fit, book, join from a link, walk away with tasks and a next meeting |
| Logged-out visitor | Same founder before account conversion | Full discover → book → join path; artifacts appear without staff |
| Marketplace operator (BuilderForce) | Internal, not a user of this epic | No new staff workflow; dogfood existing listings, ATS, and meeting agents |

Advisors are talent, not a new user type. Founders are marketplace visitors / workspace members using existing booking and meeting identity.

---

## Scope

Ship in priority bands. P0 + P1 satisfy the kill condition. P2–P3 deepen discovery and advisor identity.

**Compose only:**

- Marketplace talent profiles
- ATS public `/book/{token}`
- Meetings: WebRTC + `runAgentTurn` + `summarizeMeeting`
- `parseMeetingMinutes`
- `pullStandupMinutesAct` (generalise, do not fork a second pipeline)
- Marketplace listings: agent / skill / course / playbook / template

**P0 — List, book, meet, notes**

- Advisor toggle + advisor fields on talent
- `/marketplace?category=advisors`
- Public Book on the advisor profile (existing book-by-token)
- Meeting `kind=advisory`
- Visitor join-by-token
- Meeting Notes as a marketplace agent
- Minutes generated on meeting end

**P1 — Work leaves the call**

- Auto-place action items by generalising the standup minutes act
- Propose a follow-up meeting from advisor availability

**P2 — Fit and conversation**

- Filters: expertise, language, method, stage
- Visitor chat on the advisor profile
- Advisor Resources tab (existing listing types only)

**P3 — Trust and journey filters**

- Volunteer / pro-bono badge
- Location
- Start / Grow / Exit as listing filters

## Functional requirements

### Shared / composition rules

1. Advisors are talent profiles with an advisor flag, not a new entity, CMS, or LMS.
2. Booking reuses ATS public book-by-token; the profile Book CTA issues or reuses that token.
3. Sessions are meetings with `kind=advisory`. Same WebRTC stack, `runAgentTurn`, and `summarizeMeeting`.
4. Join for a booked visitor is token-based. No staff provisioning of rooms or accounts.
5. Notes, action items, and follow-ups run from existing minutes parse + generalised standup-minutes act. No new notes schema.
6. Marketplace category `advisors` is a listing filter over talent, consistent with agent/skill/course/playbook/template categories.
7. Logged-out discovery and booking must work. Post-meeting board task and proposed follow-up must appear for the visitor/workspace produced by that booking, with zero staff clicks.

### P0

**Advisor talent**

- Talent profile gains an advisor toggle (opt-in). Off by default.
- When on, advisor fields are required for listing: headline, expertise tags, method (e.g. 1:1, office hours), stage fit (start / grow / exit — stored now, filterable in P3), languages, short bio, availability source already used by ATS.
- Non-advisor talent does not appear in `category=advisors`.

**Discovery**

- `/marketplace?category=advisors` lists opted-in advisors using the same marketplace listing chrome as other categories.
- Each card links to the public talent/advisor profile.

**Public Book**

- Public advisor profile shows Book, wired to ATS `/book/{token}` for that advisor’s calendar.
- Logged-out visitor can pick a slot and complete a booking. Booking creates the advisory meeting and join token.

**Advisory meeting**

- Created meetings set `kind=advisory`.
- Visitor joins via token (no login wall that blocks join). Host (advisor) joins as the talent user.
- Same WebRTC meeting surface as today.

**Meeting Notes agent**

- “Meeting Notes” is a marketplace agent listing that runs on advisory meetings via `runAgentTurn` + `summarizeMeeting` + `parseMeetingMinutes`.
- On meeting end, minutes are produced automatically (no staff, no extra advisor click beyond ending the call).

### P1

**Action items → board**

- Generalise `pullStandupMinutesAct` so advisory minutes yield board tasks the same way standup minutes do.
- On end, at least parsed action items are placed as board tasks on the visitor’s resulting workspace/board (create the minimum workspace/board the booking already implies; do not invent a parallel task system).

**Follow-up proposal**

- From minutes + advisor availability, propose one follow-up meeting.
- Proposal is visible to the visitor after the call ends, bookable without staff.

### P2

- Marketplace advisors view filters: expertise, language, method, stage.
- Visitor chat on the public advisor profile (existing chat primitive if present; no new messenger product).
- Advisor profile Resources tab surfaces that advisor’s existing marketplace listings only (agents, skills, courses, playbooks, templates). No new content types.

### P3

- Volunteer / pro-bono badge on talent and marketplace cards when the advisor marks sessions as unpaid.
- Location on profile and as an optional filter.
- Start / Grow / Exit as first-class listing filters on `category=advisors`.

## Acceptance criteria

### Kill condition (P0 + P1, release gate)

A tester with a logged-out browser, no staff session:

1. Opens `/marketplace?category=advisors` and sees at least one advisor.
2. Opens the profile and books a slot via public Book (book-by-token).
3. Joins the advisory meeting by token; advisor joins; call runs on existing WebRTC.
4. Meeting is ended.
5. Without any staff click, the visitor can see: (a) at least one board task from the minutes, and (b) at least one proposed follow-up meeting from availability.

If any step requires a staff user, a new video product, a new notes format, or a manual minutes paste, the epic fails.

### P0

- Talent advisor toggle + fields persist; only opted-in profiles appear in `category=advisors`.
- `/marketplace?category=advisors` is a working category, not a marketing page.
- Public profile Book completes a booking while logged out.
- Resulting meeting has `kind=advisory`.
- Visitor join-by-token works for that meeting.
- Meeting Notes agent exists as a marketplace agent and is what produces notes.
- Ending the meeting writes minutes via `summarizeMeeting` + `parseMeetingMinutes` with no extra staff action.

### P1

- Advisory minutes produce board tasks through a generalised standup-minutes act (one pipeline, parameterized by meeting kind / source).
- At least one action item from a fixture advisory transcript lands on the board automatically.
- At least one follow-up slot is proposed from the advisor’s real availability after end.
- Kill condition passes on a fresh logged-out run.

### P2

- Expertise, language, method, and stage filters narrow the advisors category without breaking other marketplace categories.
- Visitor can start chat from the public advisor profile.
- Resources tab shows only that advisor’s existing listings; empty state is allowed.

### P3

- Pro-bono / volunteer badge is visible when set, hidden when not.
- Location displays and filters when present.
- Start / Grow / Exit filters match advisor stage fields set in P0.

### Cross-cutting

- No SCORE name, logo, or SBA affiliation in UI or copy.
- No new payout rail; paid vs pro-bono is badge/availability only until an existing rail is reused in a later epic.
- No new video, notes, CMS, or LMS surfaces.

---

## Out of scope

- SCORE trademark, branding, playbooks, or any SBA affiliation
- New video stack (WebRTC meetings as they exist only)
- New notes format or notes editor (minutes parse + existing summarization only)
- New CMS or LMS (Resources tab is existing listing types)
- New payout rail, invoicing, or tax forms
- New user type or advisor-only identity provider
- Mentorship programs, chapter/volunteer ops, hours tracking for a third-party org
- Matching algorithms beyond explicit filters
- Mobile-native apps
- Multi-party advisory boards or cohort programs
- Guaranteed outcomes, certifications, or background-check products
- Cloning SCORE’s org model (chapters, workshops-as-the-product, counselor certification)

P2 and P3 must not block P0/P1 or the kill condition.

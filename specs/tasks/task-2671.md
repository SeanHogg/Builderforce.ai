# PRD: Remove Dead Spec File from `builderforce/task-2585`

## Problem & Goal

**Problem:** Branch `builderforce/task-2585` contains `specs/tasks/task-2585.md`, a product-repo spec-dump file that is explicitly forbidden from shipping per three independent statements in the ticket PRD (BA Requirements, PM lock P8, PM freeze preamble). The file was created by execution #31734 and subsequently modified by #31862, #31863, and #32032, but no PR has been opened yet — this is our last clean opportunity to remove it before review begins.

A prior attempt (execution #32142) failed to remove the file: `delete_file` was unavailable as a tool, and all git/read tooling returned "no repository bound," meaning the branch could not be inspected or modified from that execution container (tracked in #2670).

**Goal:** Delete `specs/tasks/task-2585.md` from branch `builderforce/task-2585` so that when the PR for #2585 is eventually opened, it contains only files the ticket genuinely requires — with the contract living solely on the ticket PRD, not duplicated in-repo.

## Target Users / ICP Roles

- **BA/PM lanes** authoring and locking the #2585 ticket contract — require the product repo to stay free of duplicate spec artifacts.
- **Reviewers** of the eventual #2585 PR — require a clean diff containing only genuinely needed files.
- **Platform/tooling maintainers** (owners of #2670) — need visibility that branch-bound tooling failures block routine cleanup work.

## Scope

- Remove exactly one file — `specs/tasks/task-2585.md` — from branch `builderforce/task-2585`.
- Use a tool/execution path that has confirmed, working access to the actual branch (real checkout or a `delete_file` call bound to `builderforce/task-2585`, not main).
- Verify post-removal branch state via a read/list operation that is confirmed to resolve against the branch itself, not main.

## Functional Requirements

1. **FR1 — Branch-bound access.** The removal execution must operate against a tool/environment where git operations are confirmed bound to `builderforce/task-2585` (not "no repository bound," and not silently defaulting to main).
2. **FR2 — File deletion.** Delete `specs/tasks/task-2585.md` as a commit (or amendment) on `builderforce/task-2585`, preserving the branch's other 3 commits' intent — no unrelated file changes.
3. **FR3 — Verification against the correct ref.** After deletion, confirm the file's absence using a read/list call explicitly targeting `builderforce/task-2585` (e.g., real checkout + `ls`/`git show`), not the default `read_file`/`list_files` tools, which are known to resolve against main and therefore cannot prove branch cleanliness.
4. **FR4 — No collateral changes.** No other files on the branch are added, modified, or removed as part of this task.
5. **FR5 — Escalation path.** If no available tool can bind to the branch (repeat of #32142/#2670), the execution must fail loudly and flag the tooling gap rather than reporting false success based on main-resolved reads.

## Acceptance Criteria

- [ ] `specs/tasks/task-2585.md` does not exist on branch `builderforce/task-2585`, confirmed via a branch-bound checkout or equivalent verified-branch read (not `read_file`/`list_files` against main).
- [ ] The branch's commit history reflects the removal (new commit or amended commit), with no unrelated diffs introduced.
- [ ] No PR is required to be opened as part of this task, but the branch is left in a state where opening a PR would produce a diff free of `specs/tasks/task-2585.md`.
- [ ] If the removal cannot be performed due to tooling limitations (no bound `delete_file`, no repository binding), the execution reports explicit failure/blocker status referencing #2670 rather than a false "not found" success.
- [ ] Verification evidence (command output, checkout log, or equivalent) demonstrating the check was run against `builderforce/task-2585`, not main, is captured in the execution record.

## Out of Scope

- Opening or updating a pull request for #2585.
- Any changes to the ticket PRD, BA Requirements, or PM lock content.
- Fixing the root cause of execution #32142's tooling failure or resolving #2670 generally (only working around it for this specific deletion, or escalating if unworkable).
- Modifying, reviewing, or validating any other files on `builderforce/task-2585` beyond the single target file.
- Retroactive changes to executions #31734, #31862, #31863, or #32032.

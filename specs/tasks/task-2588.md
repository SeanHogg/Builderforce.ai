# PRD: Bind a readable checkout for the developer container (unblock #2527)

## Problem & Goal

**Problem.** Ticket #2527 (P0 Advisor profiles) is blocked by an environment gap, not by product design. The developer container can `write_file` into `seanhogg/builderforce.ai` on branch `builderforce/task-2527`, but `list_files`, `read_file`, and all `git_*` operations fail with `no repository bound` / `credential delegation absent`. Implementing Advisor mode requires reading existing talent listing, marketplace category, `PEOPLE_OBJECT_KINDS`, `TalentDetailClient`, Canvas destinations, and i18n. Blind overwrites would destroy production code.

**Goal.** Bind a readable checkout (or restore git credential delegation) for branch `builderforce/task-2527` so the next developer run can search the tree, edit in place, and open a real PR. Success is unblocking #2527 without changing Advisor product behavior in this ticket.

## Target users / ICP roles

- Downstream developer agents assigned to #2527 (primary)
- Platform / container operators who bind repos and credential delegation
- Reviewers who must receive a real PR against `builderforce/task-2527`

## Scope

In scope: bind (or re-bind) a readable working copy of `seanhogg/builderforce.ai` at `builderforce/task-2527` inside the developer container; restore credential delegation so `list_files`, `read_file`, and `git_*` succeed on that checkout; confirm write path still works so in-place edits and a PR are possible.

Out of this ticket’s product work: Advisor profile UX, talent listing changes, marketplace category, `PEOPLE_OBJECT_KINDS`, `TalentDetailClient`, Canvas destinations, and i18n. Those remain #2527 after this unblock.

## Functional requirements

1. The developer container has a bound working tree for `seanhogg/builderforce.ai` on branch `builderforce/task-2527`.
2. `list_files` enumerates the bound tree (at least paths needed for Advisor: talent listing, marketplace category, `PEOPLE_OBJECT_KINDS`, `TalentDetailClient`, Canvas destinations, i18n).
3. `read_file` returns file contents from that tree without “no repository bound”.
4. `git_*` operations (status, diff, log, branch, commit, push as already authorized for this task) succeed; they must not fail with “credential delegation absent”.
5. `write_file` continues to work on the same bound branch so edits are in-place, not disconnected blobs.
6. Binding is durable for the next developer run on this task (same repo, same branch) without a second manual bind.
7. No production files are truncated or replaced as a side effect of binding.

## Acceptance criteria

- A developer-container run on this task can `list_files` and `read_file` existing Advisor-related sources listed above.
- The same run can `git_*` against `builderforce/task-2527` without “no repository bound” or “credential delegation absent”.
- An in-place edit via `write_file` is visible in `git status` / `git diff` on that branch.
- The next agent can open a real PR from `builderforce/task-2527` using the bound checkout.
- Binding does not rewrite, empty, or force-push production code.

## Out of scope

- Implementing Advisor mode, profile UI, or any #2527 product behavior
- Changing talent listing, marketplace category, `PEOPLE_OBJECT_KINDS`, `TalentDetailClient`, Canvas destinations, or i18n
- Broad git / credential platform redesign beyond this container and branch
- Access to repos or branches other than `seanhogg/builderforce.ai` @ `builderforce/task-2527`
- Blind file creation as a substitute for a readable checkout

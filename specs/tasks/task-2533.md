# PRD: Public Availability Read

## Problem & Goal

**Problem.** Callers who hold a public booking token or slug currently cannot discover when a host is bookable without either authenticating as the host or receiving calendar internals (raw busy windows, event titles, attendee lists). That leaks private schedule data and blocks anonymous booking flows.

**Goal.** Expose a tokenised / slug-scoped public read that returns **only future free slots** for the scoped host (or resource). Responses must never include raw busy windows, event metadata, or other attendees. Downstream booking agents consume this contract as the single source of truth for public availability.

## Target users / ICP roles

- **Anonymous booker** — visitor with a public link (`/book/{slug}` or tokenised URL); needs free slots to pick a time.
- **Host / calendar owner** — publishes a slug or token; expects no calendar internals to leak.
- **Integrating agent / client** — booking UI, embed, or partner service calling the public read.

## Scope

In scope for this WIP:

- Unauthenticated (or token-only) HTTP read of availability.
- Scope resolution strictly from path/query **slug** or **token**; no session, no host user id from the client.
- Computation of **future free slots** from the host’s busy data, working hours, buffers, and existing bookings.
- Response limited to free slot intervals (start/end in UTC, plus display timezone if the host has one).
- Token/slug invalid, revoked, expired, or unknown → not-found / unauthorized without leaking whether the host exists.
- Only slots whose start is strictly in the future at request time.
- Pagination or bounded window (e.g. next N days, max M slots) so the payload stays finite.

## Functional requirements

1. **Identity of the read**
   - Resolve the calendar/resource exclusively from a public **slug** or **token**.
   - Reject requests that supply host ids, emails, or attendee lists as selectors.
   - Treat slug and token as opaque; do not echo internal ids in errors.

2. **Slot computation**
   - Derive free intervals from working hours minus busy time, existing bookings, and configured buffers.
   - Emit **free slots only** — never busy windows, never “raw” availability windows, never merged busy blocks.
   - Drop any slot that starts at or before `now` (server time).
   - Honour host timezone for display; serialise instants in UTC.

3. **Privacy constraints (hard)**
   - Do not return other attendees, participant emails, names, or counts.
   - Do not return event titles, locations, descriptions, conference links, or recurrence ids.
   - Do not return raw calendar windows or busy/free bitmaps that would allow reconstruction of the private schedule.
   - Do not return other hosts’ or other resources’ availability on the same token/slug.

4. **Response shape**
   - Ordered list of free slots: `{ start, end }` (ISO-8601 UTC). Optional: `timezone` (IANA) for the host’s display zone.
   - Empty list is a valid success when the host has no future free time in the requested bound.
   - Stable sort: ascending by `start`.

5. **Access & abuse**
   - No cookie/session required.
   - Rate-limit by token/slug + client IP.
   - Revoked/expired token or disabled slug → same generic failure as unknown (no existence oracle).

6. **Bounds**
   - Client may request a horizon (e.g. `from`/`to` or `days`); clamp to a server max (default: next 14 days, hard cap 60 days).
   - `from` earlier than now is clamped to now.
   - `to` before `from` → 400.

## Acceptance criteria

- Given a valid slug or token, the endpoint returns **200** and only future free slots for that scope.
- Given an invalid, revoked, or expired slug/token, the endpoint returns **404** (or equivalent generic denial) with no host/calendar identifiers.
- Response JSON contains no fields for attendees, events, busy windows, titles, or emails; contract tests fail if any such key appears.
- No slot in the payload has `start <= now`.
- Two consecutive free gaps separated by a busy period appear as **two free slots**, not as a busy window and not as one raw availability span that includes the busy period.
- A booker cannot obtain another attendee’s identity or another host’s slots via this read.
- Empty availability in-range returns **200** with `slots: []`.
- Horizon clamp and rate limits are enforced; oversized `to` is truncated, not rejected as 500.

## Out of scope

- Creating, updating, or cancelling bookings.
- Authenticated “my calendar” or admin availability reads.
- Returning busy/tentative/OOO reasons or working-hour configuration to the public client.
- Multi-host pooled availability, round-robin, or collective “find a time for N people”.
- ICS/feed export, webhooks, or push of availability.
- Slot-hold / reservation before booking.
- Custom slot duration negotiation beyond the host’s configured granularity (fixed duration is assumed from host settings).
- UI/embed implementation (this PRD is the read contract only).

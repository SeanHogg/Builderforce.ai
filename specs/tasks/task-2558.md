# PRD: API Brain tests and typecheck

## Problem & Goal

The `api` package must prove that `src/application/brain` is green under Vitest and that the package still typechecks. Downstream agents share this gate so work in brain (and any related types) is not considered done until both commands succeed from the correct working directories.

**Goal:** From the `api` package, `pnpm vitest run src/application/brain` exits 0, then a typecheck run from `api/` also exits 0.

## Target users / ICP roles

- Downstream coding agents implementing or verifying brain application logic
- Reviewers confirming the API package is test- and type-safe before merge

## Scope

- `api` package only
- Vitest run scoped to `src/application/brain` (that path and its test files as resolved by the existing Vitest config)
- Typecheck executed from `api/` using the package’s existing TypeScript / `pnpm` typecheck script (do not invent a new toolchain)
- Fixes required to make those two commands pass (brain application code, colocated tests, and types they depend on)

## Functional requirements

1. Working directory for the test command is `api/`.
2. Command 1: `pnpm vitest run src/application/brain` — run once, non-watch, that path only.
3. Command 2: typecheck from `api/` after tests pass (use the repo’s existing typecheck script, typically `pnpm` + `tsc --noEmit` or the package `typecheck` script if defined).
4. If either command fails, fix the underlying brain / API types or tests; do not skip, weaken, or delete coverage to force green.
5. Do not change Vitest, tsconfig, or CI wiring unless that is the actual cause of a false failure.
6. Keep changes limited to what is necessary for these two gates.

## Acceptance criteria

- From `api/`: `pnpm vitest run src/application/brain` exits 0 with no failing or skipped-as-broken tests.
- From `api/`: typecheck exits 0 with no new or remaining type errors attributable to this work.
- Commands are run in that order: Vitest first, typecheck second.
- No unrelated package, app, or config churn.

## Out of scope

- Other packages, apps, or monorepo roots
- Full `api` test suite beyond `src/application/brain`
- E2E, integration outside this path, lint-only, or format-only work
- New product features not required to pass the two commands
- Changing test runners, adding coverage thresholds, or rewriting CI
- Runtime/deploy verification beyond local Vitest + typecheck

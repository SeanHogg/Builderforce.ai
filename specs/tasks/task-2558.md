# PRD: API Brain Application Tests and Typecheck

## Problem & Goal

The `api` package’s application-layer brain module must be proven green before further work lands on top of it. Downstream agents currently lack a single shared definition of “done” for this gate: unit tests under `src/application/brain` must pass, and the `api` package must typecheck.

**Goal:** From the `api/` package root, `pnpm vitest run src/application/brain` exits 0 with no failing tests, and the package typecheck exits 0. Fix only what is required to make those two commands succeed.

## Target users / ICP roles

- API maintainers and downstream coding agents implementing or reviewing the brain application layer
- CI / local verification of the `api` package

## Scope

- `api/` package only
- Vitest run scoped to `src/application/brain` (that path and its test files)
- Typecheck of the `api` package from `api/`
- Minimal production or test code changes inside `api/` needed to clear failures (types, imports, test fixtures, obvious brain-layer bugs surfaced by those commands)

## Functional requirements

1. Tests are executed from `api/` with `pnpm vitest run src/application/brain` (no watch mode, no unrelated suites).
2. All tests in that run pass; no skipped-as-failure, no ignored assertion errors.
3. After tests pass, typecheck is run from `api/` using the package’s existing typecheck script (for example `pnpm typecheck` or the equivalent `tsc --noEmit` script already defined in `api/package.json`).
4. Typecheck reports zero errors for the `api` project.
5. Changes stay limited to making those two commands succeed; public API behavior of brain is preserved unless a test or type error requires a correction.
6. New or updated tests remain valid Vitest tests and do not depend on network, live services, or non-deterministic time unless already present and required.

## Acceptance criteria

- Working directory for both commands is `api/`.
- `pnpm vitest run src/application/brain` completes with exit code 0.
- Vitest reports no failed tests.
- Typecheck from `api/` completes with exit code 0.
- No new TypeScript errors introduced elsewhere in `api/` as a result of the fix.
- No unrelated package, app, or repo-wide test/typecheck runs are required for this task to be considered done.

## Out of scope

- Running the full `api` or monorepo test suite
- Coverage thresholds, mutation testing, or adding new brain features not required to pass existing tests/types
- Frontend, workers, or other packages outside `api/`
- Refactors, dependency upgrades, lint/format-only churn, or CI config changes unless a command cannot run without them
- Performance, observability, or product UX work
- Changing Vitest or TypeScript toolchain versions unless the current toolchain cannot execute the two commands

## Requirements

This ticket is the **api verify slice** of PRD 29 (#2555). It does not add product behaviour. It proves that `api/src/application/brain` is green under Vitest and that the `api` package typechecks, so downstream packaging (#2556–#2561, #2563) can treat brain application logic as gated.

### R1 — Working directory

All commands run with **cwd = `api/`** (the directory that contains `api/package.json`). Do not run them from the monorepo root, from `api/src`, or from another package. Vitest and TypeScript both resolve config from this cwd.

### R2 — Command 1 (Vitest)

From `api/`, run exactly once, non-watch:

```
pnpm vitest run src/application/brain
```

- The path argument is `src/application/brain`. Vitest must discover **every** `*.test.ts` under that directory via the package’s **existing** Vitest config.
- Do not add `--passWithNoTests` to green an empty run.
- Do not filter to a subset of files for the gate (filtering is allowed only while reproducing a single failure).
- Do not invoke `pnpm test` as a substitute: that script is `npm run check && vitest run` (full package checks + full suite) and is out of scope.

**Inventory observed on `main` at requirements time** (the gate is the directory, not this list; new files on the ticket branch are in scope automatically):

`chatTicketParent.test.ts` (named by parent PRD 29 Change B) is **not** on `main`. See R8 and the gap ticket.

### R3 — Command 2 (typecheck)

After Command 1 exits 0, from `api/` run the package’s existing typecheck script:

```
pnpm type-check
```

This is `"type-check": "node ../scripts/run-checks.mjs scripts/typecheck.manifest.mjs"` in `api/package.json`. The manifest runs **`tsgo --noEmit` and `tsc --noEmit` concurrently**. Both checkers must succeed (the runner reports both; a tsgo-only pass is not enough).

Do **not**:

- substitute `pnpm typecheck:native` (`tsgo` only);
- hand-roll `tsc --noEmit` / `tsgo --noEmit` outside the manifest;
- invent a new toolchain, tsconfig, or CI job.

If typecheck OOMs on the machine, `NODE_OPTIONS=--max-old-space-size=8192` may prefix the same script. That is an environment prefix, not a different command.

### R4 — Order

1. Command 1 (Vitest)  
2. Command 2 (`pnpm type-check`)

A green typecheck does not waive a failing or skipped test run.

### R5 — Pass criteria

- Command 1 exits **0**. Zero failing tests. Zero tests skipped-as-broken to force green (`it.skip` / `describe.skip` / `it.todo` / `xit` / `xdescribe` introduced or left in place as a workaround). If a skip already existed before this ticket, name it in Implementation Notes; do not treat it as coverage.
- Command 2 exits **0**. The script typechecks the **whole `api` package**, not a brain subset. Remaining errors anywhere in `api` fail this gate.
- Neither command is “passed” by deleting tests, narrowing the Vitest path, or silencing types (`@ts-expect-error` / `any` / `as never` added only to green the gate).

### R6 — Failure policy

If either command fails, **fix the underlying brain application code, colocated tests, and types they depend on**.

- Do not skip, weaken, or delete coverage.
- Do not change Vitest config, `tsconfig`, `scripts/typecheck.manifest.mjs`, or CI wiring unless that wiring is the **proven** cause of a false failure — and then change only that cause.
- Keep the diff limited to what the two commands require.

**Out of scope**

- Full `api` Vitest suite beyond `src/application/brain`
- E2E, lint-only, format-only, new product features
- VSIX install / packaging (siblings #2560, #2561, #2565)

### R8 — Contracts that must stay proven

This gate must not regress PRD 29 Changes A and B, or the other brain tests Vitest will load.

**Change A — run-visibility** (`chatRunMilestones.test.ts` exercising `ChatTicketService.postRunMilestone`)

- Phases `started` / `completed` / `failed` / `paused` / `resumed` / `cancelled` narrate into every **live** linked chat.
- Archived and merged chats receive nothing (no ghost notifications).
- Idempotent on `eventKey`: a duplicate insert is a no-op and broadcasts nothing.
- Paused lines include the `ask_human` question; paused/resumed keys include the approval nonce.
- Failed lines include the error reason (orphan/stale reaper wording flows through).
- Unlinked ticket or invalid kind → no insert, no broadcast.
- A chat-write failure must **not** throw into the run caller.

**Change B — ticket parent** (`TicketHealth.parent` on `ChatTicketService`)

- `TicketParent` is `{ kind: 'epic' | 'task' | 'gap'; ref: string; label: string }`.
- `parent` is set for task-tier kinds (`task` / `epic` / `gap`) whose `tasks.parent_task_id` resolves in-tenant.
- `parent` is **absent** for top-level items, deleted parents, and non-task-tier kinds (`portfolio` / `objective` / `initiative` / `roadmap` / `spec` / `retro` / `poker`).
- Parent PRD 29 names `chatTicketParent.test.ts` as the proof file. That file is **not on `main`**. The developer must not invent a skip or a passing stand-in. If the file exists on the ticket branch, it is in the R2 path. If it is still absent after R2, record that in Implementation Notes. Coverage for Change B is tracked as a gap under #2555; this verify ticket still ships on the tests that exist.

**Ceremony health** (`ceremonyTicketHealth.test.ts`)

- `TICKET_KINDS` includes `retro` and `poker`.
- Retro is a **leaf**: 0% empty-open, 50% once it has items, 100% completed or cancelled; deleted → `exists: false`.
- Poker is a **container** over stories with a final estimate; empty open = 0%, empty closed = 100%.
- Health is batched (grouped child query per kind, not one query per link).

**Prompt ↔ tool-list** (`agentReplyPrompt.test.ts`)

- Accountability framing names tools as the model is **advertised** them (`builtin_manager_digest`, …), not catalog ids (`manager.digest`). Every framed tool must be on the agent allowlist.

**Other files in the R2 inventory** must remain green: account preferences defaults/upsert; addressed-agent run picking (never another agent’s run; live > paused > newest terminal); Evermind learn-on-persist; diagnostics size/retention; chat mode vocabulary (`chat`/`work`, unknown normalize → `null`, team/manager pin to `work`); read-state high-water mark only moves forward.

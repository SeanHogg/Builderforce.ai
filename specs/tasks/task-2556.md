# PRD: brain-embedded — test then dist

## Problem & Goal

`brain-embedded` must be verifiably green before any distributable is produced. Downstream agents currently risk shipping untested or stale `dist` output. The goal is a single, ordered pipeline: run the package test suite with pnpm, and only on success emit a production `dist` that matches the tested source.

Success means: `pnpm test` exits 0, then a complete `dist` artifact is written from that same tree with no extra source changes in between.

## Target users / ICP roles

- Downstream implementation agents executing this WIP
- Package maintainers of `brain-embedded`
- CI / release agents that consume `dist`

## Scope

In scope:

- The `brain-embedded` package only
- Running the existing pnpm test script as the gate
- Producing `dist` immediately after a passing test run, from the same checkout
- Leaving the repo in a state where tests passed and `dist` is current

## Functional requirements

1. Work exclusively in the `brain-embedded` package context (correct workspace / cwd for pnpm).
2. Install dependencies with pnpm if the workspace is not already install-ready; do not switch package managers.
3. Run `pnpm test` with no skipped failing suites and no test-command rewrites that hide failures.
4. Treat any non-zero test exit as a hard stop: do not build or refresh `dist`.
5. After tests pass, produce `dist` using the package’s existing dist/build script (the project’s configured pnpm dist or build-to-dist path). Do not invent a parallel bundler.
6. `dist` must be generated from the exact tree that just passed tests (no intervening feature edits, refactors, or dependency churn).
7. Do not commit, publish, or tag unless a later explicit task requires it.

## Acceptance criteria

- `pnpm test` in `brain-embedded` exits 0.
- `dist` exists and is newly generated after that passing run (timestamps/output reflect the post-test build).
- No `dist` step is executed when tests fail.
- Package manager remains pnpm throughout.
- Source used for `dist` is the same revision/tree that passed tests.

## Out of scope

- Changing product behavior, public APIs, or test assertions except where required to make the existing suite run
- Adding new features, docs sites, or example apps
- `pnpm publish`, npm registry release, or git tagging
- Work in sibling packages or the rest of the monorepo except as required to install/test `brain-embedded`
- Replacing pnpm, the test runner, or the existing dist toolchain
- Coverage gates, performance benches, or extra CI matrix work not already in `pnpm test`

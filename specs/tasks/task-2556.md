# PRD: brain-embedded — `pnpm test`, then `dist`

## Problem & Goal

The `brain-embedded` package must be verified and then published as a production build. Downstream agents currently lack a single shared definition of what “done” means for this step.

**Goal:** Run the package test suite with `pnpm test`. If and only if tests pass, produce the `dist` artifact(s) with the project’s standard build command so consumers can install and import a complete, tested build.

## Target users / ICP roles

- **Maintainer / release engineer** — needs a green test run and a complete `dist` before tagging or publishing.
- **Downstream agents** — need a shared, unambiguous sequence (test → dist) and pass/fail rules.
- **Package consumers** — need a built `dist` that matches the public API after a passing test run.

## Scope

In scope for this WIP:

- Work only in the `brain-embedded` package (or the repo path that owns it).
- Use the existing `pnpm` toolchain and existing `package.json` scripts.
- Execute tests via `pnpm test`.
- On success, produce `dist` via the existing dist/build script (typically `pnpm run dist` or `pnpm run build` if that is what emits `dist`).
- Confirm `dist` exists, is non-empty, and matches what the package `exports` / `main` / `module` / `types` fields expect.
- Leave a short record of commands run, exit codes, and artifact location.

## Functional requirements

1. Resolve the `brain-embedded` package root (the directory that contains its `package.json`).
2. Install dependencies with `pnpm` if `node_modules` is missing or incomplete; do not change lockfile intent unless install is otherwise impossible.
3. Run `pnpm test` from that package root (or the workspace filter that targets `brain-embedded`).
4. Treat any non-zero test exit code as a hard stop. Do not build `dist` after failed, skipped-as-failed, or incomplete tests.
5. After a zero-exit test run, produce `dist` using the package’s designated script. Prefer `pnpm run dist` if defined; otherwise use the script that is documented or configured to emit `dist`.
6. Do not hand-author or patch files under `dist`; `dist` must come from the build.
7. Do not change product behavior, public API, test assertions, or CI config unless required to make an existing test or build command actually run.
8. Preserve existing `pnpm-workspace.yaml`, lockfile, and package `files`/`exports` unless a blocking defect prevents test or dist.

## Acceptance criteria

- `pnpm test` is executed against `brain-embedded` and exits `0`.
- No `dist` build is started if tests do not exit `0`.
- After tests pass, the dist script exits `0`.
- A `dist` directory (or the configured output path) exists and contains the compiled artifacts the package declares for publish/consumption (JS and, if the package ships them, type declarations and sourcemaps).
- `package.json` entrypoints (`main`, `module`, `types`, `exports`, `files`) resolve to files that exist in the produced `dist`.
- The working tree has no unexplained extra changes beyond install side-effects and generated `dist` output.
- Command sequence, working directory, and exit codes are identifiable from the agent trail.

## Out of scope

- Publishing to npm or any registry.
- Version bumps, changelog, git tags, or GitHub releases.
- New features, refactors, or test rewrites not required to run the existing suite.
- Changing test runners, bundlers, or pnpm version for preference.
- Running the full monorepo test matrix beyond `brain-embedded`.
- Docker, cloud deploy, or runtime embedding of a model/“brain” beyond what this package already implements.
- Fixing unrelated packages, lint-only failures, or docs-only drift.

## Design

This ticket is a **verify-and-package gate**, not a new runtime design. Change A (composing-phase visibility, idle-stream watchdog, triage budget) is already written and re-exported from `brain-embedded/src/index.ts`. Architect lock: run the existing test suite, then regenerate the committed `dist/` that consumers resolve. Do not redesign the package, add scripts, or change the public API.

### 1. Package identity and install topology

| Fact | Value |
|---|---|
| npm name | `@seanhogg/builderforce-brain-embedded` |
| Path / cwd | `brain-embedded/` (directory that contains its `package.json`) |
| Version on tree | `2026.9.31` — **do not bump** (owned by **#2564**) |
| Workspace | **None.** There is no `pnpm-workspace.yaml`. The repo is a set of separately installed packages, each with its own `package.json` + `pnpm-lock.yaml`, joined by `link:` specifiers. |
| Canonical command form | `cd brain-embedded && pnpm <script>`. Do **not** use `pnpm --filter @seanhogg/builderforce-brain-embedded` — that flag requires a workspace file that does not exist. |

`brain-embedded` `devDependencies` link three source-only packages:

- `@builderforce/agent-loop` → `link:../packages/agent-loop`
- `@builderforce/agent-stall` → `link:../packages/agent-stall`
- `@builderforce/agent-tools` → `link:../packages/agent-tools`

`postinstall` runs `node ../scripts/ensure-linked-deps.mjs`. That script exists because pnpm’s `link:` only symlinks the target directory and does **not** install the linked package’s own deps. Those three links must resolve before tests run. If `node_modules` is missing or incomplete, `pnpm install` from `brain-embedded/` (or the repo root of that package’s lockfile) **without rewriting lockfile intent**. Failures in `ensure-linked-deps.mjs` are warnings by design; they must not be “fixed” by converting the repo into a workspace.

`prepare` / `prepublishOnly` both run `npm run build`. They are install/publish hooks, **not** the dist command for this ticket (R-5).

### 2. Dual-entry library (why `dist` has two roots)

`tsup.config.ts` uses `libraryConfig` from `scripts/tsup.base.mjs` with **two entries**:

```
entry: { index: 'src/index.ts', chatError: 'src/chatError.ts' }
```

| Entry | Role | Who consumes it |
|---|---|---|
| `index` | Full React + hook layer (`BrainProvider`, run store, composing activity, triage, …) | `packages/brain-ui` (`link:../../brain-embedded`), web app |
| `chatError` | Pure TypeScript error classifier. **No React.** | VS Code extension **process** (native surfaces that classify chat errors without bundling the hook layer) |

This split is load-bearing. Collapsing `chatError` into the root bundle would pull React into the extension host. Do not add, merge, or remove entries.

Shared tsup options (`scripts/tsup.base.mjs` `libraryConfig`):

- `format: ['esm', 'cjs']` → `.mjs` / `.cjs`
- `dts` on, `sourcemap: true`, `clean: true`, `outDir: 'dist'`
- `external: REACT_EXTERNALS` = `react`, `react-dom`, `react/jsx-runtime`

Package-specific dts override (do not revert):

- `dts: { resolve: [/^@builderforce\//], compilerOptions: { rootDir: '.' } }`
- JS already inlines `@builderforce/agent-stall` (it is a devDependency, so tsup does not treat it as external). Bare `dts: true` left declarations re-exporting that specifier; the package ships no `dist`, is `link:`-only, and consumers could not resolve it. `resolve` rolls those types into `dist/index.d.ts`. `rootDir: '.'` is for the declaration program only (the stall source lives outside `src/`); app `tsc --noEmit` keeps `rootDir: "src"`.

`dist/` **is committed** (root `.gitignore` explicitly keeps `brain-embedded/dist`, same pattern as `studio-embedded` / `builderforce-embedded`, so a frozen CI install can resolve `link:` targets that have no build step). A successful `pnpm run build` replaces the directory (`clean: true`). The developer’s only allowed tree change is that regenerated `dist/` (plus install side-effects). Do **not** hand-author files under `dist/`.

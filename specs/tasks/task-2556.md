# PRD: brain-embedded — `pnpm test`, then `dist`

## Problem & Goal

The `brain-embedded` package must be verified and then published as a production build. Downstream agents currently lack a single shared definition of what “done” means for this step.

**Goal:** Run the package test suite with `pnpm test`. If and only if tests pass, produce the `dist` artifact(s) with the project’s standard build command so consumers can install and import a complete, tested build.

## Target users / ICP roles

- **Maintainer / release engineer** — needs a green test run and a complete `dist` before tagging or publishing.
- **Downstream agents** — need a shared, unambiguous sequence (test → dist) and pass/fail rules.
- **Package consumers** — need a built `dist` that matches the public API after a passing test run.

## Scope

In scope for this WIP:

- Work only in the `brain-embedded` package (or the repo path that owns it).
- Use the existing `pnpm` toolchain and existing `package.json` scripts.
- Execute tests via `pnpm test`.
- On success, produce `dist` via the existing dist/build script (typically `pnpm run dist` or `pnpm run build` if that is what emits `dist`).
- Confirm `dist` exists, is non-empty, and matches what the package `exports` / `main` / `module` / `types` fields expect.
- Leave a short record of commands run, exit codes, and artifact location.

## Functional requirements

1. Resolve the `brain-embedded` package root (the directory that contains its `package.json`).
2. Install dependencies with `pnpm` if `node_modules` is missing or incomplete; do not change lockfile intent unless install is otherwise impossible.
3. Run `pnpm test` from that package root (or the workspace filter that targets `brain-embedded`).
4. Treat any non-zero test exit code as a hard stop. Do not build `dist` after failed, skipped-as-failed, or incomplete tests.
5. After a zero-exit test run, produce `dist` using the package’s designated script. Prefer `pnpm run dist` if defined; otherwise use the script that is documented or configured to emit `dist`.
6. Do not hand-author or patch files under `dist`; `dist` must come from the build.
7. Do not change product behavior, public API, test assertions, or CI config unless required to make an existing test or build command actually run.
8. Preserve existing `pnpm-workspace.yaml`, lockfile, and package `files`/`exports` unless a blocking defect prevents test or dist.

## Acceptance criteria

- `pnpm test` is executed against `brain-embedded` and exits `0`.
- No `dist` build is started if tests do not exit `0`.
- After tests pass, the dist script exits `0`.
- A `dist` directory (or the configured output path) exists and contains the compiled artifacts the package declares for publish/consumption (JS and, if the package ships them, type declarations and sourcemaps).
- `package.json` entrypoints (`main`, `module`, `types`, `exports`, `files`) resolve to files that exist in the produced `dist`.
- The working tree has no unexplained extra changes beyond install side-effects and generated `dist` output.
- Command sequence, working directory, and exit codes are identifiable from the agent trail.

## Out of scope

- Publishing to npm or any registry.
- Version bumps, changelog, git tags, or GitHub releases.
- New features, refactors, or test rewrites not required to run the existing suite.
- Changing test runners, bundlers, or pnpm version for preference.
- Running the full monorepo test matrix beyond `brain-embedded`.
- Docker, cloud deploy, or runtime embedding of a model/“brain” beyond what this package already implements.
- Fixing unrelated packages, lint-only failures, or docs-only drift.

### Functional requirements

**R-1 — Package context.** All install / test / build commands for this ticket SHALL run in the `brain-embedded` package context. Sibling packages (`packages/brain-ui`, `clients/vscode`, `frontend`, `api`, …) SHALL NOT be tested, rebuilt, or edited except as required to satisfy this package's existing `link:` / `postinstall` (`node ../scripts/ensure-linked-deps.mjs`) so that `pnpm test` can run.

**R-2 — Toolchain.** The package manager SHALL remain pnpm for every step (install, test, build). Do not rewrite `package.json` `scripts.test` or `scripts.build`. Do not add `--bail` hiding, extra `-t` filters, `vitest related`, or skip flags. The existing `vitest run --passWithNoTests` is the gate as written; do not strip it and do not add more skip behavior.

**R-3 — Install.** If the workspace is not already install-ready, install with pnpm against the existing lockfile. Do not upgrade, add, or remove dependencies as part of this ticket.

**R-4 — Test gate.** Run **`pnpm test`** in `brain-embedded`. Every existing suite SHALL execute. A non-zero exit is a **hard stop** (R-5). Passing means process exit code 0 from the package's `test` script.

**R-5 — Hard stop on failure.** If `pnpm test` exits non-zero, the implementer SHALL NOT run `pnpm run build`, SHALL NOT refresh or overwrite `dist/`, and SHALL NOT proceed to sibling tickets (#2557+). Report the named failing files / assertions. Only **mechanical** breakage (broken imports, stale string literals that prevent the suite from loading) may be patched so the **existing** assertions can run; product-behavior changes, public API changes, and assertion rewrites to hide failures are **out of scope**. If the failure is a real logic defect, record it and stop.

**R-6 — Dist after green tests.** Only after R-4 exits 0, produce `dist/` by running the package's existing build script: **`pnpm run build`** (`tsup --config tsup.config.ts`). Do not introduce webpack/rollup/esbuild CLI, a new `dist` script, or a parallel bundler.

**R-7 — Same tree.** The `dist/` emitted in R-6 SHALL be generated from the **exact tree that passed R-4**. No intervening feature edits, refactors, format-only churn, dependency changes, or version bumps between test and build.

**R-8 — Dist completeness.** After R-6, `brain-embedded/dist/` SHALL exist and SHALL contain at least the files named by `package.json` exports:

- `dist/index.cjs`, `dist/index.mjs`, `dist/index.d.ts`
- `dist/chatError.cjs`, `dist/chatError.mjs`, `dist/chatError.d.ts`

An empty `dist/`, a build that writes elsewhere, or a missing `chatError` entry is a failed ticket. Source maps / `*.d.cts` / chunk files that tsup already emits MAY remain; do not hand-edit `dist/`.

**R-9 — Freshness.** `dist/` MUST be newly generated after the passing test run (file mtimes / tsup output SHALL reflect the post-test build, not a stale pre-test artifact left on the branch).

**R-10 — No release actions.** Do not `pnpm publish`, npm-registry publish, git tag, or commit unless a **later explicit task** requires it. Do not bump `package.json` `version` (currently `2026.9.31`) on this ticket. Parent epic #2555's VSIX `2026.9.72` target is **not** this ticket's job.

**R-11 — Concurrent dirt.** Unrelated uncommitted work in other packages SHALL be left untouched. This ticket's working tree changes, if any, are limited to (a) mechanical fixes required for R-4, and (b) `dist/` regenerated by R-6.

**R-12 — Evidence.** The implementer SHALL record, for QA / validator:

1. cwd / filter used,
2. exact commands (`pnpm test`, then `pnpm run build`),
3. exit codes,
4. that `dist/` timestamps are after the test run,
5. that the six R-8 files exist.

**R-13 — Sequencing.** This ticket MUST complete (tests 0, dist current) before #2557 (`brain-ui` test then dist). Do not start later packaging steps on a failed or skipped `brain-embedded` gate.

### Business rules

- **BR-1.** Test is the gate; dist is the consequence. Dist SHALL never run on a red suite.
- **BR-2.** Existing toolchain only. `pnpm test` and `pnpm run build` are the two allowed production commands after install.
- **BR-3.** Mechanical-only exception to "no source changes": import / literal / config breakage that prevents vitest from loading. Not: weakening assertions, deleting tests, or changing Brain behavior.
- **BR-4.** Docs-only files such as `specs/tasks/task-2556.md` are **not** the apply and are **not** a substitute for R-4/R-6. The BA deliverable is this Requirements section on the ticket PRD.

### Non-functional

- **NFR-1.** Commands must be reproducible from a clean `brain-embedded` cwd with pnpm.
- **NFR-2.** Build must honor existing tsup externals (`REACT_EXTERNALS`) and the `chatError` second entry (non-React host / VS Code extension process).
- **NFR-3.** Do not change `prepare` / `prepublishOnly` (they currently call `npm run build`); those hooks are out of scope.

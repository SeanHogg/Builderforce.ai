# PRD: brain-embedded — `pnpm test`, then `dist`

## Problem & Goal

The `brain-embedded` package must be verified and then published as a production build. Downstream agents currently lack a single shared definition of what “done” means for this step.

**Goal:** Run the package test suite with `pnpm test`. If and only if tests pass, produce the `dist` artifact(s) with the project’s standard build command so consumers can install and import a complete, tested build.

## Target users / ICP roles

- **Maintainer / release engineer** — needs a green test run and a complete `dist` before tagging or publishing.
- **Downstream agents** — need a shared, unambiguous sequence (test → dist) and pass/fail rules.
- **Package consumers** — need a built `dist` that matches the public API after a passing test run.

## Scope

In scope for this WIP:

- Work only in the `brain-embedded` package (or the repo path that owns it).
- Use the existing `pnpm` toolchain and existing `package.json` scripts.
- Execute tests via `pnpm test`.
- On success, produce `dist` via the existing dist/build script (typically `pnpm run dist` or `pnpm run build` if that is what emits `dist`).
- Confirm `dist` exists, is non-empty, and matches what the package `exports` / `main` / `module` / `types` fields expect.
- Leave a short record of commands run, exit codes, and artifact location.

## Functional requirements

1. Resolve the `brain-embedded` package root (the directory that contains its `package.json`).
2. Install dependencies with `pnpm` if `node_modules` is missing or incomplete; do not change lockfile intent unless install is otherwise impossible.
3. Run `pnpm test` from that package root (or the workspace filter that targets `brain-embedded`).
4. Treat any non-zero test exit code as a hard stop. Do not build `dist` after failed, skipped-as-failed, or incomplete tests.
5. After a zero-exit test run, produce `dist` using the package’s designated script. Prefer `pnpm run dist` if defined; otherwise use the script that is documented or configured to emit `dist`.
6. Do not hand-author or patch files under `dist`; `dist` must come from the build.
7. Do not change product behavior, public API, test assertions, or CI config unless required to make an existing test or build command actually run.
8. Preserve existing `pnpm-workspace.yaml`, lockfile, and package `files`/`exports` unless a blocking defect prevents test or dist.

## Acceptance criteria

- `pnpm test` is executed against `brain-embedded` and exits `0`.
- No `dist` build is started if tests do not exit `0`.
- After tests pass, the dist script exits `0`.
- A `dist` directory (or the configured output path) exists and contains the compiled artifacts the package declares for publish/consumption (JS and, if the package ships them, type declarations and sourcemaps).
- `package.json` entrypoints (`main`, `module`, `types`, `exports`, `files`) resolve to files that exist in the produced `dist`.
- The working tree has no unexplained extra changes beyond install side-effects and generated `dist` output.
- Command sequence, working directory, and exit codes are identifiable from the agent trail.

## Out of scope

- Publishing to npm or any registry.
- Version bumps, changelog, git tags, or GitHub releases.
- New features, refactors, or test rewrites not required to run the existing suite.
- Changing test runners, bundlers, or pnpm version for preference.
- Running the full monorepo test matrix beyond `brain-embedded`.
- Docker, cloud deploy, or runtime embedding of a model/“brain” beyond what this package already implements.
- Fixing unrelated packages, lint-only failures, or docs-only drift.

### R-1 — Package identity and working directory

The package is `@seanhogg/builderforce-brain-embedded` at repo path `brain-embedded/` (the directory that contains its `package.json`). All test and build commands run with that directory as cwd, or equivalently `pnpm --filter @seanhogg/builderforce-brain-embedded <script>`. Do not run the monorepo-wide test matrix.

### R-2 — Toolchain and install

Use the existing pnpm toolchain and existing `package.json` scripts. Do not change pnpm version, vitest, tsup, `pnpm-workspace.yaml`, or lockfile intent.

If `node_modules` is missing or incomplete, install with pnpm from the package root or the workspace root **without** rewriting lockfile intent. The package `postinstall` runs `../scripts/ensure-linked-deps.mjs` and the package links `@builderforce/agent-loop`, `@builderforce/agent-stall`, and `@builderforce/agent-tools` (`link:`). Those links must resolve before tests run.

### R-3 — Test command

From the package root, run **`pnpm test`**. That script is `vitest run --passWithNoTests` (`vitest.config.ts`: environment `jsdom`, setup `src/test/setup.ts`).

`--passWithNoTests` is **not** success. A zero-exit run that executed **zero** test files is a hard fail. The run must execute the existing suite, including at minimum the Change A files already in tree:

- `src/composingActivity.test.ts`
- `src/streamIdleWatchdog.test.ts`
- `src/runActivity.test.ts`
- `src/brainTriage.test.ts`
- `src/modelScorecard.test.ts`
- `src/persistedSteps.test.ts`
- `src/runProgress.test.ts`
- `src/streamChatCompletion.test.ts`

### R-4 — Hard stop on test failure

Any non-zero test exit code, skipped-as-failed, incomplete, or zero-files-executed run is a **hard stop**. Do **not** start a dist/build after failed tests. Record cwd, command, exit code, and failing `file` / test names.

### R-5 — Dist command (there is no `dist` script)

`package.json` has **no** `pnpm run dist` script. After tests exit 0 with a non-zero test count, produce `dist` with **`pnpm run build`** (`tsup --config tsup.config.ts`).

Do **not** use `prepare` / `prepublishOnly` as the dist command (they also run build, but they fire on install). Do **not** hand-author or patch files under `dist/`. tsup is configured with `clean`; a successful build replaces the directory.

### R-6 — Dist artifacts that must exist

After a successful build, `brain-embedded/dist/` must be non-empty and contain at least:

| Role | Files |
|---|---|
| Root export | `index.mjs`, `index.cjs`, `index.d.ts` (plus sourcemaps / `index.d.cts` tsup emits) |
| Subpath `./chatError` | `chatError.mjs`, `chatError.cjs`, `chatError.d.ts` (plus matching maps / `chatError.d.cts`) |

These must satisfy `package.json` entrypoints:

- `main` → `dist/index.cjs`
- `module` → `dist/index.mjs`
- `types` → `dist/index.d.ts`
- `exports["."]` `types` / `import` / `require`
- `exports["./chatError"]` `types` / `import` / `require`
- `files`: `["dist"]`

Every path named above must exist on disk after the build.

### R-7 — Public API in the produced types

`dist/index.d.ts` must declare the Change A exports already re-exported from `src/index.ts`, including:

- `createComposingActivity`, `toolCallArgBytes`, `utf8ByteLength` and types `ComposingActivity`, `ComposingSink`, `ComposingOptions`
- `formatBytes` and `BrainRunPhase` (including `'composing'`)
- `readWithIdleWatchdog`, `StreamIdleError`, `STREAM_IDLE_MS` and types `IdleWatchdogOptions`, `IdleWatchdogReader`
- `HISTORY_TOKEN_BUDGET`

Do not add, rename, or remove public exports to make the build pass.

### R-8 — Product freeze

Do not change product behavior, public API, test assertions, CI config, `pnpm-workspace.yaml`, lockfile, or package `files` / `exports` unless a blocking defect prevents the existing test or build command from actually running.

Fix policy (PRD 29): **mechanical breakage only** (wrong import path, type error from the new `composing` phase). Anything that looks like a real logic defect is **reported, not patched**. Concurrent unrelated edits in `api`, `frontend`, and `ROADMAP.md` are left alone.

### R-9 — Version, publish, and sibling freeze

- Do **not** bump `brain-embedded` version (tree already shows `2026.9.31`; a further bump is **#2564** / PRD 27 R3). PRD 29’s `2026.9.30` is stale — consume the version already on the package.
- Do **not** publish to npm, tag, changelog, or GitHub-release.
- Do **not** package or install the VSIX (**#2560** / **#2561**).
- Do **not** start `packages/brain-ui` test/dist (**#2557**). This ticket’s `dist` is the prerequisite because brain-ui typecheck resolves `@seanhogg/builderforce-brain-embedded` through `dist/index.d.ts`.

### R-10 — Working tree

No unexplained extra changes beyond install side-effects and generated `dist` output. Do **not** add `specs/tasks/task-2556.md` or other docs-only stand-ins (a stub on this branch was dropped). PRD 29: do not commit unless the person asks — report results first. If the executor must open a PR, it may contain only generated `dist` (and install side-effects), not source edits.

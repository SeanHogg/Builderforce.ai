# Product Requirements Document (PRD)

## Problem & Goal

### Problem
The current test suite lacks an integration-level test that verifies the full dispatch and INSERT path for the `submitted_by` field in the `executions` and `outbox` tables. While unit tests confirm the correctness of the label composer, they do not ensure that coordinator-dispatched runs persist correctly in the database.

### Goal
Develop an integration test that simulates dispatching a run with a `submitted_by` label composed as `"system:coordinator:producer:<role>"` for a long role key and asserts that the `executions` and `outbox` rows persist without any PostgreSQL 22001 ("value too long for type character varying") errors.

## Target Users / ICP Roles
- **Software Engineers**: Developers responsible for maintaining and enhancing the coordinator-dispatcher system.
- **QA Engineers**: Quality assurance personnel who will use the integration test to validate system behavior.

## Scope

### In Scope
- **Test Environment Setup**: Configure a test environment that mimics the production environment for dispatching runs.
- **Dispatch Simulation**: Simulate the dispatch of a run with a `submitted_by` label that includes a long role key.
- **Database Assertions**: Verify that the `executions` and `outbox` rows are inserted correctly without truncation or errors.
- **Error Handling**: Ensure that any potential PostgreSQL 22001 errors are caught and handled appropriately.

### Out of Scope
- **Performance Testing**: This test is not intended to measure the performance of the dispatch and INSERT operations.
- **Security Testing**: The test does not cover security aspects such as authentication or authorization.
- **Edge Cases**: While the test covers a long role key, it does not include other edge cases such as special characters or extremely long strings beyond the specified limit.

## Functional Requirements

1. **Test Environment Configuration**
   - The test must set up a test database with the latest schema and migrations.
   - The test must initialize the necessary tables and triggers for the `executions` and `outbox` tables.

2. **Dispatch Simulation**
   - The test must simulate the dispatch of a run with a `submitted_by` label composed as `"system:coordinator:producer:<role>"`.
   - The role key must be a long string, e.g., "business-analyst" or "engineering-manager".

3. **Database Insertion Verification**
   - The test must verify that the `executions` row is inserted with the correct `submitted_by` value.
   - The test must verify that the `outbox` row is inserted with the correct `submitted_by` value.
   - The test must ensure that no PostgreSQL 22001 errors occur during the insertion.

4. **Error Handling**
   - The test must handle any unexpected errors gracefully and provide meaningful feedback.

## Acceptance Criteria

- The test successfully simulates the dispatch of a run with a long `submitted_by` label.
- The `executions` and `outbox` rows are inserted without any truncation or errors.
- The test passes without any PostgreSQL 22001 errors.
- The test provides clear and actionable feedback in case of failures.

## Out of Scope

- **Performance Metrics**: The test does not measure the time taken for dispatch and insertion operations.
- **Security Validation**: The test does not verify the security of the dispatch and insertion processes.
- **Comprehensive Edge Case Testing**: The test does not cover all possible edge cases, such as extremely long strings or special characters beyond the specified limit.
- **Integration with Other Systems**: The test does not verify integration with other systems or services.

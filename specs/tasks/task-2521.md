# Advisor Platform — WIP PRD

## Problem & Goal

Builderforce users currently piece together project, estimate, schedule, and customer context by hand, then go outside the product for advice. That context-switching produces inconsistent recommendations, lost history, and advice that ignores live job data.

**Goal:** Ship an in-product Advisor Platform that answers questions, proposes next actions, and explains tradeoffs using the user’s Builderforce workspace (jobs, estimates, schedule, CRM, and docs). Advice must be attributable, reversible, and safe to act on—never a black-box mutation of production data.

Success looks like: a user can start an advisor thread from any job or estimate, receive grounded guidance with citations to workspace records, accept or reject suggested actions, and resume the same thread later with full history.

## Target users / ICP roles

| Role | Why they use Advisor |
| --- | --- |
| Owner / GM (home-services & light commercial contractors, ~5–75 field staff) | Margin, mix, capacity, and “what should we do this week” decisions |
| Estimator / sales lead | Bid strategy, scope gaps, comparable jobs, pricing risk |
| Project / operations manager | Schedule conflicts, crew loading, change-order impact |
| Office admin / CSR | Customer comms drafts, follow-up cadences, missing paperwork |
| Builderforce internal (CS, onboarding, solutions) | Reproducing a customer’s workspace question and coaching them in-product |

Primary ICP: US residential and light-commercial contractors already live on Builderforce jobs + estimates. Secondary: multi-location operators and franchise GMs who need portfolio-level advice.

## Scope

In scope for this WIP:

- Advisor surface (global + contextual entry from job, estimate, schedule, and customer records)
- Threaded conversations with persistence, resume, and share-within-org
- Retrieval over the signed-in user’s permitted Builderforce records
- Grounded answers with citations (record type, id, and field/snippet)
- Suggested actions the user can preview, edit, accept, or dismiss
- Advisor personas (Operations, Estimating, Customer, Financial pulse) as selectable lenses—not separate products
- Usage, quality, and safety telemetry sufficient to operate the feature
- Spec file `specs/builderforce/26-prd-advisor-platform.md` as the shared source of truth for downstream implementation

## Functional requirements

1. **Entry points**
   - Global “Ask Advisor” from the app shell.
   - Contextual “Ask about this” on job, estimate, schedule, and customer detail views, preloading that record as the primary context.
   - Deep link to an existing thread.

2. **Conversation model**
   - Threads belong to the org; visible to the author and roles the author shares with.
   - Messages are user, advisor, system (context/citation), or action-proposal.
   - User can rename, archive, and search their threads.
   - Switching persona mid-thread is allowed; the switch is recorded in-thread.

3. **Grounding & permissions**
   - Retrieval may only include records the current user can already read in the UI.
   - Answers that use workspace data must attach citations. If retrieval is empty or low-confidence, the advisor must say so and ask a clarifying question instead of inventing numbers.
   - No cross-org retrieval. No use of other customers’ data for few-shot examples in production.

4. **Personas (lenses)**
   - **Operations:** crew, schedule, job status, blockers.
   - **Estimating:** price, scope completeness, comps, risk flags.
   - **Customer:** comms tone, follow-ups, outstanding items.
   - **Financial pulse:** backlog, margin, aging, cash-relevant job health (read-only; no GL posting).
   - Default persona is inferred from the entry point; user can override.

5. **Suggested actions**
   - Advisor may propose discrete, previewable actions (e.g., draft a change order note, create a follow-up task, suggest a schedule move, draft a customer SMS/email).
   - Every proposal shows the target record, fields to change, and before/after.
   - Accept writes through existing product APIs with the user’s auth; dismiss discards; edit opens the native form with values prefilled.
   - Advisor never writes production data without an explicit accept.

6. **Safety & non-goals baked into behavior**
   - No legal, tax, or licensed-professional advice presented as definitive; those answers must include a limitation line and a recommend-human-review cue.
   - No instructions that bypass permissions, export another user’s private data, or fabricate bid numbers as if they were calculated.
   - Rate-limit and cost-cap per org; degrade to “Advisor busy / try again” rather than ungrounded completion.

7. **Observability**
   - Log thread id, persona, retrieval hit/miss, citation count, action proposed/accepted/dismissed, latency, and token/cost.
   - PII in logs follows existing Builderforce redaction rules.

## Acceptance criteria

- From a job detail page, a user can open Advisor and see that job already attached as context within one click.
- An answer that references a job, estimate, or customer includes at least one citation that navigates to the live record.
- When the user lacks access to a record, Advisor neither mentions it nor leaks its existence beyond what the UI already allows.
- A proposed action shows a diff/preview; accepting it persists via the same path as the equivalent UI action; dismissing it leaves data unchanged.
- Refreshing the browser restores the thread, persona, citations, and pending proposals.
- Empty-retrieval questions produce a clarification prompt, not a numeric guess.
- Org admin can disable Advisor; when disabled, all entry points hide and API calls return a stable disabled error.
- Telemetry events fire for thread start, message, citation, and action accept/dismiss, and are queryable in the existing ops store.
- Spec at `specs/builderforce/26-prd-advisor-platform.md` matches this document (problem, users, scope, requirements, acceptance, out of scope) so implementation agents do not diverge.

## Out of scope

- Autonomous agents that mutate jobs, invoices, payroll, or accounting without an explicit user accept
- Voice / phone advisor, SMS inbound advisor, or field-tech mobile-offline advisor
- Training or fine-tuning on customer workspace data
- Human marketplace of live advisors; video consults
- Custom org-authored personas or bring-your-own model in this WIP
- Public unauthenticated advisor, SEO chat widget, or embeddable third-party script
- Tax, legal, insurance, or licensed engineering sign-off
- Multi-org / franchise rollup advisor (portfolio across legal entities)
- Replacing existing reports, dashboards, or estimate math engines
- End-to-end UI pixel spec, model vendor selection, or pricing packaging (tracked separately)

# PRD: Install VSIX via Absolute Path and Confirm 2026.9.72

## Problem & Goal

The workspace tree now ships extension version **2026.9.72**. An earlier PRD targeted **2026.9.71**; a later bump (PRD 27) advanced the packaged version, so install and verification must follow the live tree, not the stale pin.

**Problem:** Relative-path VSIX installs are fragile across agent working directories, shells, and CI checkouts. Version checks that still expect 2026.9.71 will fail against the current package.

**Goal:** Install the VSIX using an **absolute path** and confirm the installed extension identity and version are **2026.9.72**, so every downstream agent shares one unambiguous install contract.

## Target users / ICP roles

- Downstream coding agents executing this task in a shared workspace
- Local developers and maintainers validating the packaged extension
- CI / release operators installing the VSIX into VS Code / Cursor / compatible hosts

## Scope

- Locate the 2026.9.72 VSIX in the current tree
- Install it with a fully resolved absolute filesystem path (no relative path, no unspecified CWD)
- Confirm the host reports version **2026.9.72** after install
- Treat 2026.9.72 as the source of truth over any prior 2026.9.71 wording

## Functional requirements

1. **Resolve absolute path.** Compute the VSIX file’s absolute path (canonical, OS-native) before invoking the installer. Do not pass a relative path.
2. **Install from that path.** Use the host CLI/API install-from-VSIX flow (e.g. `code --install-extension <absolute-path>` or equivalent Cursor/VS Code command) against that absolute path only.
3. **Target version.** The VSIX on disk and the installed extension must be **2026.9.72**. Do not install or accept 2026.9.71.
4. **Idempotency.** If 2026.9.72 is already installed from the same package, re-install or no-op is acceptable; the post-condition remains 2026.9.72 installed.
5. **Verification.** After install, query the host’s extension list (or equivalent) and assert name/id plus version **2026.9.72**.
6. **Failure visibility.** If the file is missing, the path is not absolute, install fails, or the reported version is not 2026.9.72, fail the task with a clear error (path used, expected vs actual version).

## Acceptance criteria

- The installer is invoked with a path that is absolute (starts with `/` on Unix or a drive/UNC prefix on Windows), not a relative segment.
- The VSIX at that path is the **2026.9.72** artifact from the current tree.
- After install, the editor host lists the extension at version **2026.9.72**.
- Checks that still mention 2026.9.71 are treated as outdated; passing means **2026.9.72**, not 2026.9.71.
- A missing VSIX, non-absolute path, install error, or version mismatch fails the run.

## Out of scope

- Changing extension source, bumping the version again, or re-packaging the VSIX
- Marketplace / gallery publish or download
- Relative-path install as a supported fallback
- Host upgrades, new editor profiles, or multi-host matrix beyond the environment already in use
- Feature work inside the extension; this PRD is install + version confirm only
- Reconciling historical PRD 2026.9.71 docs except to ignore that pin in favor of 2026.9.72

# PRD: Talent Profile Structured Fields & Toggles

**Status:** WIP  
**Owner:** Product  
**Surface:** Freelancer / talent profile (edit + public)

## Problem & Goal

Talent profiles today lack structured signals for *how* someone works (channel, stage, session length, price, confidentiality, location, languages) and *what* they cover (expertise, industries). Matching, search, and booking therefore rely on unstructured bio text, which is inconsistent and hard to filter.

**Goal:** Let talent declare a complete, structured working profile via toggles and fields, persist it as first-class profile data, and expose it on the public profile so clients can evaluate fit before booking. Price `0` means volunteer / complimentary.

## Target users / ICP roles

- **Talent (freelancer, advisor, expert):** Creates and maintains the profile; needs fast, unambiguous controls.
- **Client / buyer:** Reads the public profile to decide channel, budget, stage fit, and confidentiality.
- **Internal ops / matching:** Uses structured fields for search, filters, and recommendations (read path only in this slice).

## Scope

In scope for this WIP:

- Profile **edit** experience: toggles + fields listed below, with validation and save.
- Profile **public** experience: display of saved values (including volunteer pricing and confidentiality default).
- Persistence on the talent record; empty/off fields do not appear as required for publish unless noted.
- Price semantics: `0` = volunteer (complimentary). Positive amounts are paid session rates in the platform currency already used for bookings.

Out of scope items are listed at the end.

## Functional requirements

### Profile fields (edit)

Talent can set the following on their profile. Each group is independently editable and savable with the rest of the profile.

1. **Expertise**  
   Multi-select (or tag) list of expertise areas. At least one recommended for a complete profile; not a hard block to save.

2. **Industries**  
   Multi-select list of industries served.

3. **Languages**  
   Multi-select of languages the talent can work in.

4. **Methods**  
   Multi-select of delivery methods: `video`, `phone`, `email`, `in-person`.  
   Unselected methods are not offered. At least one method required to be bookable.

5. **Stages**  
   Multi-select of company/engagement stages: `start`, `grow`, `exit`.  
   Unselected stages mean the talent does not position for that stage.

6. **Session length**  
   Talent sets offered session duration(s) (e.g. minutes). Must be a positive duration. If multiple lengths are supported by the existing booking model, allow multiple; otherwise a single default length.

7. **Price**  
   Numeric rate for a session. `0` is valid and means **volunteer** (no charge). Negative values are rejected. Display unit matches existing marketplace currency.

8. **Location**  
   Location used for in-person work and/or timezone context (city/region or equivalent existing location control). Required if `in-person` is selected; optional otherwise.

9. **Confidentiality default**  
   Toggle/default for whether sessions are treated as confidential by default (on/off). Public profile shows the default so clients know the baseline; it does not replace a booking-time agreement.

### Toggles and empty state

- Methods, stages, and confidentiality default are explicit on/off (or multi-select equivalent) controls, not free text.
- Off / empty optional fields are omitted from the public profile rather than shown as “None.”
- Talent can clear optional fields and save.

### Public profile

- Show expertise, industries, languages, methods, stages, session length, price (with volunteer treatment when `0`), location (when present), and confidentiality default.
- Volunteer price is labeled as volunteer / complimentary, not as `$0` alone.
- In-person is only presented as available when method `in-person` is on and location is set.

### Validation

- Price ≥ 0; non-numeric rejected.
- Session length > 0.
- If method includes `in-person`, location must be set.
- At least one method required before the profile can be marked bookable / complete (draft save without methods is allowed).
- Unknown enum values for methods/stages are rejected.

## Acceptance criteria

- Talent can open profile edit and set all nine field groups, then save and reload without data loss.
- Methods are limited to video, phone, email, in-person; stages to start, grow, exit.
- Saving price `0` stores volunteer; public profile shows volunteer / complimentary, not a paid `$0` rate.
- Saving price `> 0` shows the paid rate in the existing currency format.
- Negative price and non-positive session length are blocked with inline errors; profile is not saved in an invalid state.
- Selecting in-person without location is blocked; clearing in-person allows location to be optional.
- Confidentiality default persists and is visible on the public profile as the stated default.
- Public profile hides unset optional fields (expertise, industries, languages, stages, location) instead of empty placeholders.
- A profile with no methods can be saved as draft but cannot be bookable until ≥ 1 method is set.
- Existing profile fields (name, bio, photo, etc.) are unchanged by this work.

## Out of scope

- Search / filter / matching UI that consumes these fields (data is stored for later use).
- Booking-flow changes, checkout, tax, or payouts (including charging `0`).
- Per-session override of price, length, method, or confidentiality at booking time (defaults only).
- New expertise/industry/language taxonomies beyond wiring to existing or a simple selectable list.
- Multi-currency pricing, sliding-scale, or package pricing.
- NDA document generation, legal e-sign, or compliance workflows.
- Admin bulk-edit, CSV import, or migration of unstructured bio text into these fields.
- Mobile-specific redesign beyond using existing profile edit patterns.
- Notifications, completeness scoring, or mandatory profile-completion gating beyond bookable vs draft as specified.

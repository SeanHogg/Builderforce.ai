# PRD: Reconcile VSIX Version Pin Conflict Across #2555's Children (#2560/#2561/#2564/#2565 vs #2655)

## Problem & Goal

**Problem:** Two conflicting version pins exist for the `builderforce.builderforce-ai` VSIX across sibling tickets under parent #2555:

- **Pin A (2026.9.79):** Authoritative per #2560's description, which cites "#2614 decision (a), 2026-09-16: emit builderforce.builderforce-ai@2026.9.79" and explicitly RETIRES 2026.9.72 / 2026.9.71 as prior pins. #2560 also states that emitting 2026.9.72 against this decision is an "intentional fail, not a pass." The live `clients/vscode/package.json` version is 2026.9.79, corroborating this pin.
- **Pin B (2026.9.72):** Asserted by #2655, which proposes realigning #2561's wording to 2026.9.72, citing a conflict with "PRD 29." #2564's title ("VSIX already 2026.9.72") is independently flagged in #2560 as a **stale title**, not an active pin, and is the likely root cause of both #2564's staleness and #2655's mistaken premise.

If left unreconciled, #2560 (packager) will emit `builderforce-ai-2026.9.79.vsix` while #2561 (installer/verifier) checks for `2026.9.72` — a guaranteed dual-verify failure. #2560 already treats this exact mismatch as an intentional failure condition, not an incidental bug, so the blast radius of not fixing this is a hard CI break, not a flaky test.

**Goal:** Adjudicate a single authoritative version pin (2026.9.79) across all of #2555's children, correct the losing/stale tickets' wording to match, and leave a clear paper trail (decision citation) so this doesn't regress via future PRD or title staleness.

## Target Users / ICP Roles

- **Downstream agents/engineers** executing #2560, #2561, #2564, #2565 who need one unambiguous pin to implement against.
- **Reviewers** of #2560 and siblings, who need the conflict resolved before approving/merging in-review work.
- **CI/build tooling** consuming the VSIX filename/version — indirectly affected, must not require a package.json bump to pass.

## Scope

In scope:
- Reading and confirming the authoritative decision source (#2614 decision (a), as cited in #2560).
- Updating ticket **wording/descriptions/titles** (not code, not package.json) in #2561, #2564, #2655, and any other #2555 child that references 2026.9.72 or a stale VSIX version claim.
- Adjudicating and closing/repurposing #2655 in light of the corrected pin.
- Verifying #2560's own description/title is internally consistent (no action expected if already correct).
- Leaving an explicit audit trail (comment or description edit) on each touched ticket citing "#2614 decision (a), 2026-09-16 → 2026.9.79" as the source of truth.

Out of scope: see below.

## Functional Requirements

1. **FR-1 — Confirm authoritative pin.** Verify #2614 decision (a) and #2560's description agree the pin is `2026.9.79`, and that `clients/vscode/package.json` currently reads `2026.9.79`. Treat this as ground truth; do not re-litigate the decision itself.
2. **FR-2 — Correct #2561.** Ensure #2561's installer/verification logic and wording reference `builderforce-ai-2026.9.79.vsix` (or equivalent exact-identity check), not 2026.9.72. This directly resolves the dual-verify failure risk described in the ASK.
3. **FR-3 — Correct #2564.** Update #2564's title away from the stale "VSIX already 2026.9.72" claim to reflect 2026.9.79 (or a version-agnostic phrasing if the ticket's substance doesn't require a hardcoded version). Flag it clearly as a title-only correction.
4. **FR-4 — Correct #2565.** Audit #2565 for any 2026.9.72 references or assumptions inherited from #2564's stale title; update to 2026.9.79 where applicable.
5. **FR-5 — Resolve #2655.** Close #2655 as invalid/superseded, or repurpose it to instead correct any remaining stale "PRD 29" / 2026.9.72 references *toward* 2026.9.79 (i.e., flip its direction). Document why the original proposal (moving #2561 to 2026.9.72) is rejected, citing #2560's "intentional fail, not a pass" language and the live package.json value.
6. **FR-6 — Audit trail.** Every ticket touched must carry an explicit note citing the decision source (#2614 decision (a)) so future readers don't re-derive the conflict from a stale PRD reference again.
7. **FR-7 — No code/version changes.** No commits to `clients/vscode/package.json` or any build artifact. This task is wording/documentation reconciliation only, per #2560 R-1/R-13.

- [ ] No open ticket under #2555 contains an unqualified/unlabeled reference to 2026.9.72 or 2026.9.71 as a current (non-retired) pin.

## Out of Scope

- Any bump, downgrade, or modification of `clients/vscode/package.json` or the VSIX build/packaging logic in #2560.
- Fixing or updating "PRD 29" itself as a document (only downstream ticket wording that *cites* it is in scope).

- Resolving any unrelated open items within #2560, #2561, #2564, or #2565 that don't pertain to the version pin conflict.

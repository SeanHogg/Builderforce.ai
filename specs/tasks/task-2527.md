# PRD 26 P0 — Advisor profiles + marketplace category

## Problem & Goal

**Problem.** Operators need a way to find and book short, high-trust advisory sessions (video, phone, email, in-person) from people already on the talent marketplace. Treating advisors as a second user type would fork identity, profiles, search, and people objects. Advisory must be a mode on an existing talent listing.

**Goal.** Ship advisor mode on the freelancer/talent profile, a public `advisors` marketplace category that reuses the talent profile renderer, and an authenticated setup surface as a destination/Canvas object (PRD 21). Primary CTA on advisor listings is Book; Hire is secondary when the same talent is also available-for-hire. Five locales, both themes. Do not add advisory to `PEOPLE_OBJECT_KINDS`. Spec: `specs/builderforce/26-prd-advisor-platform.md` §4.2 J4, §8.1.

## Target users / ICP roles

- **Talent (freelancer listing).** Existing talent who opt into advisor mode and publish session terms.
- **Seeker (logged-out or authenticated).** Founders and operators browsing advisors and initiating Book (and Hire when applicable).
- **Not in ICP for this slice.** A distinct “advisor” account type, agency seats, or a standalone advisory app chrome.

## Scope

In scope for P0:

- Advisor-mode toggle and advisor fields on the talent/freelancer profile.
- Public marketplace category `advisors` (logged-out browse allowed).
- Advisor listing/detail rendering via the existing talent profile renderer.
- CTA rules: Book primary; Hire secondary iff the listing is also available-for-hire.
- Authenticated advisor setup as a destination/Canvas object per PRD 21 — no new chrome-ful app.
- i18n across all five product locales; light and dark themes.

Out of scope is listed below. This slice does not change people-object kinds and does not introduce a second user type.

## Functional requirements

### 1. Advisor is a mode, not a type

- Advisor mode is a flag/mode on an existing talent listing. There is no second user type and no parallel identity.
- Do **not** add advisory (or any advisor kind) to `PEOPLE_OBJECT_KINDS` (J4).
- Turning advisor mode off hides the listing from `advisors` and removes advisor-only CTAs; it does not delete the talent listing or hire availability.

### 2. Profile toggle and fields

On the talent/freelancer profile, when advisor mode is on, the following fields are captured and persisted:

| Field | Behavior |
|---|---|
| Expertise | Required. Advisor’s subject/practice areas. |
| Industries | Required. Sectors they advise. |
| Languages | Required. Session languages. |
| Methods | Required. One or more of: video, phone, email, in-person. |
| Stages | Required. One or more of: start, grow, exit. |
| Session length | Required. Default session duration. |
| Price | Required. Numeric; `0` means volunteer (unpaid). |
| Location | Required when methods include in-person; otherwise optional. |
| Confidentiality default | Required. Default confidentiality posture for sessions. |

- Fields are editable only by the listing owner (or equivalent talent-profile editor).
- Validation: advisor mode cannot be published until required fields are valid. Price `0` is valid and must display as volunteer, not as a free-hire rate.
- Existing hire/talent fields remain independent of advisor fields.

### 3. Marketplace category `advisors`

- Add marketplace category slug `advisors`.
- Logged-out users can browse the category and open advisor listings.
- Category index lists only talent with advisor mode on and a complete, publishable advisor profile.
- Filters/sort may use advisor fields (expertise, industries, languages, methods, stages, price including volunteer, location) without a new search stack.
- Category is localized in all five locales.

### 4. Listing renderer and CTAs

- Reuse the talent profile renderer for advisor listing and detail. No parallel advisor profile UI kit.
- Advisor-specific fields render in the existing profile layout (not a second profile template).
- **Primary CTA:** Book.
- **Secondary CTA:** Hire, shown only if the same listing is also available-for-hire.
- If the listing is advisor-only (not available-for-hire), Hire is omitted.
- Book and Hire are distinct actions; Book must not silently route to the hire flow.

### 5. Authenticated setup (destination / Canvas)

- Owner setup and edit of advisor mode lives as a destination/Canvas object per PRD 21.
- Not a new chrome-ful app: no extra shell, nav, or product surface outside Canvas destinations.
- Deep-linkable from the talent profile and from marketplace empty/owner states.
- Unauthenticated users hitting setup are sent through existing auth, then back to the same destination.

### 6. Locales and themes

- All new copy, field labels, validation, category name, CTAs, and volunteer/price treatment ship in all five product locales.
- Light and dark themes: advisor fields, category, renderer reuse, and both CTAs meet existing contrast and component token rules. No advisor-only color or type ramp.

## Acceptance criteria

1. A talent listing can enable advisor mode without creating a new user type or a new people-object kind. `PEOPLE_OBJECT_KINDS` is unchanged.
2. Advisor mode off → listing is absent from `advisors` and Book is not shown; hire behavior is unchanged.
3. Advisor mode on with invalid/missing required fields → listing is not published to `advisors`; owner sees field-level validation in the Canvas setup destination.
4. Advisor mode on with valid fields → listing appears in `/` marketplace category `advisors` for logged-out and logged-in users.
5. Price `0` publishes as volunteer and is distinguishable from a paid rate in list and detail.
6. Detail view uses the talent profile renderer. Primary CTA is Book. Hire appears only when available-for-hire is also true.
7. Advisor-only listing: Book only. Advisor + hire listing: Book primary, Hire secondary. Hire-only listing: unchanged; not in `advisors`.
8. Authenticated setup opens as a PRD 21 destination/Canvas object, not a new app chrome. Refresh and deep link restore the same object.
9. Category, profile fields, CTAs, and validation strings are complete in all five locales. No leftover source-locale keys on advisor surfaces.
10. Advisor category, profile, and CTAs render correctly in light and dark themes at existing breakpoints used by talent listings.
11. In-person method without location fails validation; other methods do not require location.
12. Disabling advisor mode does not clear hire fields or unpublish the talent listing from non-advisor talent surfaces.

## Out of scope

- Adding advisory/advisor to `PEOPLE_OBJECT_KINDS` or introducing a second user type.
- A new chrome-ful advisory app, nav item, or shell outside PRD 21 destinations/Canvas.
- Booking fulfillment: calendar, payments capture, contracts, NDAs beyond the confidentiality default field, session delivery, or post-session workflow.
- Advisor matching, ranking ML, or a separate search index.
- Reviews, badges, verification, or advisor-specific reputation.
- Changing hire pricing, hire CTAs, or talent categories unrelated to `advisors`.
- Agency, team, or multi-seat advisor listings.
- New locales or a third theme.

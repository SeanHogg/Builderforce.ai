# PRD 26 P0 — Advisor profiles + marketplace category

**Status:** WIP  
**Priority:** P0  
**Depends on:** PRD 21 (Canvas destinations)  
**Spec:** `specs/builderforce/26-prd-advisor-platform.md` §4.2 J4, §8.1

Advisor is a **mode on the talent listing**, not a second user type. Do **not** add advisory to `PEOPLE_OBJECT_KINDS`.

---

## Problem & Goal

Operators need short-form advice (strategy, fundraising, GTM, ops) from people already on the talent graph. Today that demand either leaks off-platform or is shoehorned into hire flows that imply a contract engagement.

**Goal:** Let existing freelancer/talent listings opt into advising without a new people kind or a chrome-ful app. Logged-out visitors can browse an `advisors` marketplace category. Authenticated setup lives as a Canvas destination (PRD 21). Primary action is **Book**; **Hire** remains secondary when the same listing is also available-for-hire.

Success for P0: a talent listing can be marked advisor-capable, appear in `/advisors` (and locale equivalents) for anonymous browse, and render with Book-first CTAs using the existing talent profile renderer—in five locales and both themes.

---

## Target users / ICP roles

| Role | Need |
| --- | --- |
| Talent / freelancer (advisor-capable) | Opt in on their existing listing; declare expertise, availability, price (including volunteer), confidentiality default |
| Seeker (founder, operator, hiring manager) | Discover advisors without an account; Book a session; Hire only if the person is also available-for-hire |
| Anonymous marketplace visitor | Browse `advisors` category; open a profile; hit a signed-in Book gate |
| Authenticated talent owner | Complete advisor fields in a Canvas destination, not a standalone app |

---

## Scope

**In**

- Advisor **mode** on the freelancer/talent listing (boolean toggle + fields).
- Marketplace category slug `advisors`, browsable logged-out.
- Reuse the talent profile renderer; no parallel advisor profile UI.
- Primary CTA **Book**; secondary **Hire** iff `available-for-hire`.
- Authenticated advisor setup as a PRD 21 Canvas destination/object.
- Five product locales; light and dark themes.

**Explicit non-goal for this P0 slice:** booking checkout, calendar sync, matching, reviews, and any new `PEOPLE_OBJECT_KINDS` value.

---

## Functional requirements

### 1. Advisor mode on talent listing

- Listing remains the existing talent/freelancer object. Advisor is a mode flag plus fields, not a new kind.
- Owner (or authorized editor) can toggle **Available as advisor**.
- When on, the following fields are required unless noted:

| Field | Notes |
| --- | --- |
| Expertise | Structured tags / free-text per existing talent taxonomy where possible |
| Industries | Multi-select |
| Languages | Multi-select, locale-aware labels |
| Methods | `video` \| `phone` \| `email` \| `in-person` (multi) |
| Stages | `start` \| `grow` \| `exit` (multi) |
| Session length | Duration the advisor offers as the default bookable unit |
| Price | Integer in listing currency; **0 = volunteer** |
| Location | Reuse talent location; required if `in-person` is selected |
| Confidentiality default | Default NDA/confidentiality posture shown on the public profile |

- Toggle off: listing is omitted from `advisors`; Book CTA is hidden; Hire behavior unchanged.
- Do not introduce an `advisory` (or similar) value in `PEOPLE_OBJECT_KINDS`.

### 2. Marketplace category `advisors`

- Public, logged-out browse at the advisors category (locale-prefixed routes as for other marketplace categories).
- Index only listings with advisor mode on and profile completeness sufficient to render the category card.
- Cards reuse talent card patterns; surface expertise, price (including volunteer), methods, stages as space allows.
- Category empty and loading states match other marketplace categories.

### 3. Profile render + CTAs

- Detail view **reuses the talent profile renderer**. Advisor fields appear as a first-class section when mode is on.
- **Primary CTA:** Book.
- **Secondary CTA:** Hire — only if the same listing is also available-for-hire.
- If advisor-only (not available-for-hire): Book only; do not show a disabled Hire.
- Logged-out Book: existing auth/sign-in gate, then return to Book. P0 does not require completing checkout.

### 4. Authenticated setup (Canvas)

- Setup/edit of the toggle + fields is a **destination/Canvas object** per PRD 21.
- Not a new chrome-ful app, nav root, or standalone settings product.
- Deep-linkable from the talent listing (“Offer advising”) and from empty/incomplete advisor state on the public profile (owner only).
- Save persists on the talent listing; validation errors stay in-canvas.

### 5. i18n and themes

- All owner, public category, and profile strings in the five product locales.
- Light and dark themes; no advisor-only color tokens unless existing marketplace tokens are insufficient.

---

## Acceptance criteria

1. Enabling advisor mode does not create a new people object kind and does not write `advisory` (or equivalent) into `PEOPLE_OBJECT_KINDS`.
2. With mode on and required fields valid, the listing appears in logged-out `advisors` browse; with mode off, it does not.
3. Public profile uses the talent profile renderer; advisor fields are visible when mode is on.
4. Book is the primary CTA whenever advisor mode is on.
5. Hire is shown only when the listing is also available-for-hire; advisor-only listings never show Hire.
6. Price `0` is labeled as volunteer in category, profile, and owner canvas (all five locales).
7. Owner setup/edit opens as a Canvas destination (PRD 21), not a new application chrome.
8. `in-person` cannot be saved without location; other methods do not require a new location field.
9. Category, profile, and canvas are usable in five locales and both themes (no clipped type, contrast failures, or untranslated keys on this surface).
10. Anonymous visitor can open an advisor profile from `advisors` without authenticating; Book then applies the existing auth gate.

---

## Out of scope

- New user type, people kind, or `PEOPLE_OBJECT_KINDS` membership for advisors
- Booking checkout, payments, payouts, calendar, Zoom/Meet provisioning
- Matching, ranking beyond default talent/category sort, or paid placement
- Reviews, endorsements, or advisor-specific reputation
- Messaging, contracts, or SOW attached to Book
- Admin moderation queues unique to advisors (reuse talent moderation)
- New mobile-native or chrome-ful advisor app
- Changing Hire semantics for non-advisor talent
- Locales or themes beyond the five product locales and two themes

# PRD: Chat Switcher Dropdown — Per-Chat Percentage

## Problem & Goal

**Problem:** The chat switcher dropdown renders the same percentage on every row. The value is not bound to the chat it sits next to, so users cannot tell conversations apart by usage and may act on a stale or duplicated number.

**Goal:** Each row in the chat switcher shows that chat’s own current percentage. The value stays correct when chats are opened, switched, updated, or removed, and when the dropdown is reopened.

## Target users / ICP roles

- End users who keep several chats open and use the switcher to jump between them
- Power users who use the percentage (context/token usage) to decide which chat to continue or start fresh
- QA and support validating multi-chat switching

## Scope

- Chat switcher trigger and dropdown list
- Per-row percentage for each listed chat
- Data binding, refresh, and empty/unavailable states for that metric
- Desktop and the product’s existing responsive/web layouts for this control

## Functional requirements

1. Every chat row in the dropdown displays the percentage that belongs to that chat, not the active chat, a shared default, or a previously selected chat.
2. The percentage is the same per-chat usage metric already used elsewhere in the product (context/token usage), formatted consistently (integer percent with a `%` suffix unless the design system already specifies otherwise).
3. Opening the dropdown always reads current per-chat values; it does not freeze a snapshot from first render or from the last selected chat.
4. After send/receive, model response, chat rename, chat delete, new chat, or switching the active chat, visible rows update to the latest per-chat percentages without a full page reload.
5. If a chat has no computable percentage yet, the row shows an explicit empty/unavailable treatment (em dash or hidden metric), never another chat’s number.
6. Percentage text does not overflow, truncate into another row’s label, or replace the chat title; title and metric remain distinct.
7. Keyboard, pointer, and screen-reader behavior of the switcher is unchanged except that each row’s accessible name/description includes that chat’s own percentage when a value is shown.
8. Performance: opening the dropdown and rendering a typical list (tens of chats) does not introduce a noticeable stall versus today’s switcher.

## Acceptance criteria

- Given two or more chats with different usage values, when the user opens the switcher, each row’s percentage matches that chat’s current usage and at least two rows differ when the underlying values differ.
- Given chats A and B, when the user is in A and opens the switcher, B’s row still shows B’s percentage (not A’s).
- Given a chat whose usage changes (message sent/received), when the user reopens or keeps the dropdown open per existing UI behavior, that row shows the updated percentage and other rows are unchanged.
- Given a newly created chat with no usage yet, its row does not inherit another chat’s percentage.
- Given a deleted chat, it disappears from the list and does not leave its percentage on another row.
- Given a single chat in the list, the one row shows that chat’s percentage correctly.
- Visual and a11y checks: no duplicated/stale percent string across rows; no overlap with titles; row accessible names reflect the correct per-chat value.
- Regression: selecting a chat from the dropdown still activates that chat; order, unread/active treatment, and existing switcher actions are unchanged.

## Out of scope

- Changing what the percentage means (billing, cost, quality score, or a new metric)
- Redesign of the switcher (new layout, search, pinning, folders, or sorting)
- History, export, or analytics of usage over time
- Recalculating usage on the server beyond using values the client already has or already fetches for the active chat
- Mobile-only nav patterns that are not this dropdown
- Localization/formatting overhaul beyond consistent percent display
- Performance work on chat list virtualization unless the current list size already requires it for this fix

# Chat switcher dropdown shows same percentage

## Problem & Goal

The chat switcher dropdown currently renders the same percentage for every conversation, so users cannot tell chats apart by usage, progress, or remaining context. The goal is for each row in the switcher to show the percentage that belongs to that chat only, computed from that chat’s own data, and to keep those values accurate as chats change.

## Target users / ICP roles

- Individual users who keep multiple chats open and switch between them from the dropdown
- Power users who use the percentage as a signal (context used, completion, or remaining capacity) when choosing which chat to resume
- Support and QA validating chat list accuracy after create, switch, archive, and delete

## Scope

- Chat switcher dropdown UI (trigger, list, and per-row percentage)
- Per-chat percentage calculation and binding to the correct conversation id
- Live updates when the active chat’s percentage changes and when the list is opened or refreshed
- Empty, single-chat, and many-chat list states
- Keyboard and pointer interaction with the existing switcher

## Functional requirements

1. Each dropdown row must display the percentage for that row’s conversation, not the active chat’s value and not a shared default.
2. Percentage must be derived from that conversation’s source data (e.g. context used vs. window, or equivalent product metric already used in the chat UI).
3. Opening the switcher must show current values; switching chats must not rewrite other rows to the newly selected chat’s percentage.
4. Creating, renaming, archiving, deleting, or updating a chat must add, change, or remove only that chat’s row and percentage.
5. If a chat has no computable percentage, show a defined empty or n/a treatment for that row only; other rows stay unchanged.
6. Rows remain distinguishable by title plus percentage; duplicate titles still show independent percentages.
7. Accessibility: percentage is included in the row’s accessible name; list remains operable by keyboard.

## Acceptance criteria

- Given two or more chats with different underlying percentages, the open dropdown shows a different value on each corresponding row.
- Given chats that share the same percentage, the dropdown may show matching numbers, but each value is still computed from that chat’s data.
- Selecting chat B does not cause chat A’s row to display B’s percentage on the next open.
- After the active chat’s metric changes, reopening the dropdown (or live-updating if the list is open) reflects the new value only on that chat’s row.
- A newly created chat appears with its own percentage; a deleted or archived chat disappears and does not leave a stale percentage on another row.
- Single-chat and empty-list states do not error; empty list shows the existing empty treatment with no leftover percentage.
- No visual regression to row layout, truncation, or scroll for long lists; percentages stay aligned consistently across rows.
- Automated or manual checks cover at least: mixed percentages, identical percentages, switch-then-reopen, create/delete, and missing-data row.

## Out of scope

- Changing how the percentage metric is defined or adding new metrics (cost, tokens, latency)
- Redesign of the switcher (search, pinning, folders, multi-select)
- Persistence or sync of percentages across devices beyond existing chat data
- Non-switcher surfaces (sidebar, command palette, mobile-only lists) unless they share the same row component
- Localization copy changes beyond displaying the numeric percentage already used in product
- Performance work unrelated to correct per-row binding

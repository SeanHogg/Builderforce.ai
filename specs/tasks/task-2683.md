# PRD: Guard Against Auto-Merge of Placeholder-Destructive Commits

## Problem & Goal

**Problem:** Project 11's autonomy policy (`allowAutoMerge: true`, `prMergePolicy: "on_green"`) will auto-merge any PR that goes green, with no check for whether the diff destructively guts a tracked source file. This has already happened twice — commit `0267ffd` (#2554) and commit `64f7b74` (#2601) both reduced substantial source files to a single-line `placeholder` string. Branch `builderforce/task-2601` currently carries this damage against `frontend/src/domains/canvas/domain/canvasChange.ts` (138 lines → 1 line, `-137/+1`).

Today this branch is inert only by circumstance: it has no open PR, and it's stalled `in_review` with two `changes_requested` reviews. None of that is an enforced guard. If a PR is opened and CI happens to pass (CI does not currently check for content destruction), autonomy is permitted to merge it and delete a live domain module from `main`.

**Goal:** Close the immediate hole on `builderforce/task-2601`, and ship a durable, generic CI guard that blocks auto-merge of any PR that collapses a tracked source file into a placeholder/stub, so this class of destructive agent overwrite cannot reach `main` a third time.

## Target Users / ICP Roles

- **Autonomous merge agents** — the direct consumers of the new guard; must respect its failure signal as a hard stop.
- **Code reviewers / team leads** — human or agent reviewers whose `changes_requested` state must continue to block merge regardless of CI/guard status.
- **Repo/platform maintainers** — own the CI guard configuration and manager policy (`allowAutoMerge`, `prMergePolicy`) for Project 11 and other projects with autonomy enabled.
- **Task/PR authors (agents)** — whose branches are the ones being checked; the guard should give them clear, actionable failure output.

## Scope

**In scope:**
1. Immediate interim guard: prevent any PR from being opened/merged on `builderforce/task-2601` until the placeholder regression is reverted.
2. A generic, reusable CI check ("placeholder-shrink guard") that fails a PR when a tracked source file's diff reduces it to a trivial placeholder body.
3. Wiring the guard's failure into the merge-gate so `prMergePolicy: "on_green"` cannot treat a placeholder-shrink PR as green.
4. Decision on whether to additionally withhold merge authority (disable `allowAutoMerge`) at the branch or project level as defense-in-depth.

**Out of scope:**
- The actual restore of `canvasChange.ts` content (tracked separately in #2643).
- Retroactive remediation of #2554/`0267ffd` beyond confirming the guard would have caught it.
- Broader rewrite of review/approval workflow beyond what's needed to enforce this guard.

## Functional Requirements

1. **Interim branch hold**
   - No PR shall be opened from `builderforce/task-2601` until:
     a. #2643's restore is committed to `main`, **and**
     b. `git diff origin/main -- frontend/src/domains/canvas/domain/canvasChange.ts` returns empty.
   - This hold must be enforced or clearly documented as a binding instruction to any agent capable of opening the PR, not just left as a note.

2. **Placeholder-shrink detection (CI check)**
   - Given a PR diff, for each modified tracked source file, compute:
     - Line count reduction ratio (e.g., new line count ≤ some small threshold, such as ≤5 lines, AND reduction ≥ some large percentage, e.g., ≥90% of original lines removed).
     - Resulting file body matches a placeholder pattern (e.g., single token such as `placeholder`, `TODO`, `stub`, or a file whose entire content is a comment/no-op with no functional code).
   - The check must apply per-file across the whole diff, not just aggregate PR stats — a PR that adds lines elsewhere must not mask a gutted file.
   - The check must run on every push to a PR and be a required status check for merge.
   - On trigger, the check must **fail** (not warn) and emit a message identifying the offending file(s), the before/after line counts, and the commit SHA that introduced the reduction.

3. **Merge-gate integration**
   - `prMergePolicy: "on_green"` evaluation must treat the placeholder-shrink check as part of "green" — i.e., a red placeholder-shrink check blocks auto-merge unconditionally, independent of other CI results.
   - Existing reviewer `changes_requested` state continues to block merge as today; the new check is additive, not a replacement for review gating.

4. **Merge authority withholding (evaluate & decide)**
   - Assess whether Project 11 (or the specific branch `builderforce/task-2601`) should have `allowAutoMerge` set to `false` until the CI guard is live and verified, as belt-and-suspenders protection.
   - Document the decision and, if adopted, the mechanism (project-level policy flag vs. branch protection rule vs. per-PR label).

5. **Auditability**
   - Both prior incidents (0267ffd/#2554, 64f7b74/#2601) should be referenced/linked in the guard's implementation (e.g., in commit message, test fixtures, or check description) so the rationale is traceable.
   - Test fixtures should include at least one regression test modeled on each real incident's diff shape.

## Acceptance Criteria

- [ ] No PR exists on `builderforce/task-2601` while `git diff origin/main -- frontend/src/domains/canvas/domain/canvasChange.ts` is non-empty.
- [ ] Once #2643 lands and the diff is empty, opening a PR on `builderforce/task-2601` is unblocked.
- [ ] A CI check exists that, given a synthetic PR replicating the `64f7b74` diff shape (137 lines removed, replaced with single-line `placeholder`), fails with a clear message naming the file and line delta.
- [ ] The same CI check, run against a synthetic PR replicating the `0267ffd` diff shape, also fails.
- [ ] The CI check passes (does not false-positive) on representative "normal" PRs, including:
  - Legitimate large deletions accompanied by equivalent functionality moved/refactored elsewhere.
  - Deletion of genuinely dead/empty files that are simultaneously removed from the tree (not shrunk to a stub).
  - Small files that are legitimately short by design (e.g., existing index/barrel files under the size threshold) — false-positive rate on a sample of recent merged PRs is documented and acceptably low.
- [ ] The placeholder-shrink check is configured as a required status check such that `prMergePolicy: "on_green"` cannot auto-merge a PR while it is failing.
- [ ] A written decision (merged into this doc or a linked follow-up) states whether `allowAutoMerge` is being withheld for Project 11 / this branch, with rationale.
- [ ] Guard implementation references both incident commits for traceability.

## Out of Scope

- Restoring the actual content of `frontend/src/domains/canvas/domain/canvasChange.ts` — this is #2643.
- Auditing or reverting any other files/branches for similar damage beyond the two cited incidents (may be a follow-up task).
- Redesigning the review/approval process beyond adding this one required check.
- Handling non-source tracked files (docs, config, fixtures) under the same guard, unless trivially covered by the same mechanism — a dedicated policy for those file classes is future work if needed.

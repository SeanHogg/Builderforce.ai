# PRD: Chat row context usage in the VSIX sidebar

## Problem & Goal

Developers using the VS Code extension cannot tell from the Sessions sidebar which conversations still have unfinished **linked tickets**. They only learn a chat’s board progress after opening the thread. That makes it hard to pick a chat that still needs attention or skip one that is already complete.

**Goal:** Each **conversation** row in the VSIX Sessions sidebar (Activity Bar → BuilderForce → Sessions) shows a compact ticket-progress marker next to the existing title and relative time, in the form `· 85%` (middle dot, space, integer percent). The marker is glanceable, always means the same thing — share of linked tickets complete (`ticketProgressPct` from `GET /api/brain/chats`) — and must not steal title space.

This ticket is **not** a model context-window meter. Token-fill (`usedTokens / modelContextWindow`) is a different product problem and is out of scope here (tracked as a follow-up gap, not under epic #2436).

## Functional requirements

1. **Placement and format**
   - Each conversation row continues to show title (TreeItem label) and relative time (description).
   - When `ticketProgressPct` is displayable, append it after the time using a middle-dot separator: `{title}` (label) + `{relativeTime} · {n}%` (description).
   - Percent is an integer 0–100, no decimals, no `~`, no `used`/`left`/`tickets` wording in the row itself.
   - If progress cannot be shown, omit the separator and percent; do not show `· —` or a fake `· 0%`.
   - **Do not prefix the title.** Today `conversationTreeLabel` renders `{n}% · {title}` as the label; that steals truncating title space and is not “next to time”. The label must be title-only.

2. **Meaning**
   - `n` = `clamp(0, 100, round(ticketProgressPct))`.
   - `ticketProgressPct` is overall linked-ticket progress from `GET /api/brain/chats` (already on `BfBrainChat`). It is **ticket completion**, not context-window fill.
   - The figure is how complete the linked work is, not remaining.

3. **When it appears**
   - Show when `ticketCount > 0` AND `ticketProgressPct` is a finite number (including `0`).
   - Hide when there are no linked tickets, when `ticketProgressPct` is `null`/`undefined`/non-finite, or on canvas/board rows.
   - Recalculate whenever the Sessions tree refreshes (create/rename/delete/sign-in/project change already call `refresh()`). Live health-driven refresh is #2441.

4. **Overflow and layout**
   - Title remains the TreeItem label — the flexible, truncating element (ellipsis at the end).
   - Time and `· n%` live in `TreeItem.description`, which VS Code keeps fully visible on the right; they must not wrap or be clipped before the title is truncated.
   - Marker uses the same secondary/muted description style as the timestamp so it does not compete with the title.
   - No extra column, badge, or progress bar in this iteration.
   - Existing description fragments stay: unfiltered project label, participant initials, attention prefix. Percent attaches to the **time** cluster (`{project?} · {time} · {n}%`), then badges/attention wrap as they do today.
   - If time is empty and percent is shown, render `{n}%` with no leading dangling ` · `.

5. **Tooltip**
   - When percent is shown, the row tooltip includes a short explanation, e.g. `Ticket progress: 85%` and, when `ticketCount` is present, `· 12 linked tickets`.
   - Tooltip is the only place ticket counts appear. Do **not** put token counts here.

6. **Color (non-blocking)**
   - Description is theme-muted; native TreeItem description cannot tint a substring. Do not use color as a signal in this iteration. Do not add a second icon solely for high progress.

7. **Accessibility**
   - The row is one TreeItem (one tab stop). Screen readers already concatenate label + description, so title, time, and `n%` are spoken together (e.g. `Auth refactor, 2h, 85%`).
   - Marker is not a separate control or tab stop.

8. **Performance**
   - Use the `ticketProgressPct` already on the list payload. No extra request per row. The existing 5s row cache may show a stale percent until the next `refresh()`; that is accepted.

## Acceptance criteria

- A conversation at 85% ticket progress renders a single-line Sessions row: title as label, relative time then `· 85%` as description (e.g. `Auth refactor` + `2h · 85%`).
- `0%` with linked tickets shows `· 0%`; a chat with no linked tickets / no estimable progress shows no percent and no dangling `·`.
- Fractional values display as a clamped integer: `99.4` → `99%`, `99.5` → `100%`, `100` or over → `100%`, never `· 101%`.
- Narrow sidebar: title ellipsizes; time and `· n%` remain fully readable (they are in `description`, not the label).
- After a tree `refresh()` that moves progress from 40% to 62%, the open sidebar row updates to `· 62%` without reloading the window.
- Tooltip on the row includes ticket progress percent (and ticket count when known). It does not mention tokens.
- Removing the last linked tickets (count 0 or pct null) removes `· n%` from the row.
- Empty state, search/filter (project scope), pin, shared, running, delete, and rename of chats are unchanged aside from the new suffix.
- Keyboard focus and click targets on the row still open the chat; the marker is not a separate control.
- Canvas/board rows are unchanged (no ticket-progress suffix).
- No second percent in the title. `conversationTreeLabel` must not keep `{n}% · {title}` once description carries the marker.
- No regression in Sessions-tree scroll/expand with 50+ rows (no per-row network).
- In-panel chat switcher / dropdown is **not** required to change on this ticket (#2440 / #2443).

## Requirements

_Owned by the business-analyst — authored 2026-09-16._

### R1. What “85%” means

The marker is **linked-ticket progress**, not context-window fill.

| Field | Source | Rule |
|---|---|---|
| `ticketProgressPct` | `GET /api/brain/chats` via `listBrainChats` / `BfBrainChat.ticketProgressPct` | Overall 0–100 progress of tickets linked to that chat. `null` when none are linked. |
| `ticketCount` | same payload | Used only to decide visibility and to enrich the tooltip. Not shown in the row. |

Display value: `n = Math.max(0, Math.min(100, Math.round(ticketProgressPct)))`.

Show the marker iff `ticketCount > 0` AND `ticketProgressPct` is a finite number (including `0`). Otherwise omit it entirely (no `· —`, no fake `· 0%`).

Do not compute a client-side ratio from messages, tokens, or model windows. Do not add a new API field. Do not persist percent.

### R2. Surface

**Only** conversation rows in Activity Bar → BuilderForce → Sessions (`SessionsTreeProvider.getTreeItem` in `clients/vscode/src/sessionsTree.ts`).

- Canvas/board rows: unchanged (`item.description` stays `{relativeTime}[ · {n} people]`).
- In-panel Brain chat switcher / dropdown: out of scope (#2440, #2443). Those surfaces may keep `chatSwitcherLabel`’s `{n}% · {title}` prefix. “Same percentage” in epic #2436 means the **same number**, not the same placement.
- Native TreeView, not a webview. There is no activity-bar chat-list webview.

### R3. Layout contract (the gap vs main)

**Current (main):** `conversationTreeLabel` sets `TreeItem.label` to `{n}% · {title}` and `description` to `{project?} · {time}[ · badges]`. Percent sits in the truncating title slot, not next to time.

**Required:**

```
label:        {title}                          // title-only; ellipsis at end
description:  [{project} · ]{relativeTime} · {n}%[ · {badges}]
              └ attention prefix, if any, still wraps the whole description
```

Worked examples:

| Situation | Label | Description |
|---|---|---|
| 85%, filtered, 2h ago | `Auth refactor` | `2h · 85%` |
| 85%, unfiltered, project named | `Auth refactor` | `BuilderForce.AI · 2h · 85%` |
| 0% with 3 linked tickets | `Auth refactor` | `2h · 0%` |
| No linked tickets | `Auth refactor` | `2h` |
| Empty time, 40% | `Auth refactor` | `40%` (no leading ` · `) |
| 100.4% from a sloppy payload | `Auth refactor` | `2h · 100%` |
| Canvas row | session title | `{time}` (no ticket %) |

`conversationTreeLabel` must stop prefixing the title once description carries the marker, so the row does not show percent twice.

### R4. Tooltip and accessibility

When the marker is shown, extend `TreeItem.tooltip` (MarkdownString or string) with a line:

`Ticket progress: 85%` optionally ` · 12 linked tickets` when `ticketCount` is a positive number.

Do not mention tokens, context window, or model name.

The row remains one TreeItem / one tab stop / one click target (`builderforce.openSession`). Description text is the accessible suffix; no extra widget.

### R5. Composition with sibling tickets (heuristic split)

Epic #2436 decomposed both its scope list and its acceptance criteria into children, so several tickets name the same change:

| Ticket | Owns | Relation to #2442 |
|---|---|---|
| #2437, #2444 | API list payload / no N+1 | Prerequisite. Field already flows as `ticketProgressPct` on main — do not re-spec. |
| #2438 | `BfBrainChat` type | Already on main. |
| **#2439** | Render `%` in `sessionsTree.ts` `item.description` | **Same implementation as this ticket.** Land once. This PRD is the UX contract; #2439 is the file-level task. |
| #2440, #2443 | Chat switcher / dropdown | Different surface. Do not change `chatSwitcherLabel` here. |
| #2441 | Refresh on ticket health | Consumes this render; do not wire health listeners here. |

If #2439 ships first and already places `{n}%` in `description` with a title-only label, #2442 is satisfied and must not add a second marker.

### R6. Behaviours that must not change

Pin, shared, running facets; project-scoped vs unfiltered labelling; participant avatars/initials; attention icon + prefix; rename/delete/open; 5s row cache; offline “keep last good list” path; canvas rows.

### R7. Test requirements (for developer / QA)

Pure helper (or `getTreeItem` description) cases, no network:

1. `ticketCount = 0` or `ticketProgressPct = null` → no `·` and no `%` in description; label is title-only.
2. `ticketProgressPct = 0`, `ticketCount = 3` → description contains `· 0%` (or `0%` if time empty).
3. `85` → `85%`; `99.4` → `99%`; `99.5` → `100%`; `101` → `100%`.
4. Title is never `85% · …`.
5. Unfiltered project prefix still appears before time.
6. Canvas items never gain ticket percent.

### R8. Explicit non-requirement (product correction)

A first PRD draft treated `· 85%` as **context-window usage**. That contradicts parent epic #2436 (“Add % complete to VSIX chat lists”), siblings #2437–#2444 (`progressPct` / `ChatTicketService` / ticket health), and the code already on main (`ticketProgressPct`). Context-window usage is **out of scope** and filed as a separate gap so it is not lost.

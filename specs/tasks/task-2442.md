# PRD: Chat row context usage in the VSIX sidebar

## Problem & Goal

Developers using the VS Code extension cannot tell from the Sessions sidebar which conversations still have unfinished **linked tickets**. They only learn a chat’s board progress after opening the thread. That makes it hard to pick a chat that still needs attention or skip one that is already complete.

**Goal:** Each **conversation** row in the VSIX Sessions sidebar (Activity Bar → BuilderForce → Sessions) shows a compact ticket-progress marker next to the existing title and relative time, in the form `· 85%` (middle dot, space, integer percent). The marker is glanceable, always means the same thing — share of linked tickets complete (`ticketProgressPct` from `GET /api/brain/chats`) — and must not steal title space.

This ticket is **not** a model context-window meter. Token-fill (`usedTokens / modelContextWindow`) is a different product problem and is out of scope here (tracked as a follow-up gap, not under epic #2436).

## Target users / ICP roles

- Professional developers and power users who keep many concurrent chats in the sidebar
- Users on models with tight context windows who hit limits often
- Users who resume older threads and need to know whether the thread still has headroom

## Scope

In scope for this WIP:

- Chat list rows in the VSIX activity-bar / sidebar webview only
- A single usage figure: tokens used in that conversation ÷ the selected model’s context window, shown as an integer percent
- Placement, typography, overflow, live updates, empty/error states, tooltip, and accessibility for that marker
- Behavior when the model, window size, or token estimate changes

## Functional requirements

1. **Placement and format**
   - Each chat row continues to show title and relative time.
   - When a usage value is available, append it after the time using a middle-dot separator: `{title}    {relativeTime} · {n}%`.
   - Percent is an integer 0–100, no decimals, no `~`, no `used`/`left` wording in the row itself.
   - If usage cannot be computed, omit the separator and percent; do not show `· —` or `· 0%` as a fake value.

2. **Meaning**
   - `n` = `min(100, floor(usedTokens / modelContextWindow * 100))`.
   - `usedTokens` is the extension’s current estimate for that chat (messages + attached context the next send would include).
   - `modelContextWindow` is the context window of the model bound to that chat. If the chat has no bound model, use the workspace default model’s window.
   - The figure is usage (how full), not remaining.

3. **When it appears**
   - Show for every non-empty chat that has a computable estimate, including the active chat.
   - Hide for brand-new chats with no messages and no attachments.
   - Recalculate after send/receive, edit/delete/regenerate, attachment add/remove, model change, and when the chat list is refreshed or the sidebar becomes visible.

4. **Overflow and layout**
   - Title remains the flexible, truncating element (ellipsis at the end).
   - Time and `· n%` stay fully visible on one line; they must not wrap or be clipped before the title is truncated.
   - Marker uses the same secondary/muted style as the timestamp so it does not compete with the title.
   - No extra column, badge, or progress bar in this iteration.

5. **Tooltip**
   - Hovering the percent (or the `· n%` cluster) shows a short explanation, e.g. `Context used: 85% (92,160 / 108,000 tokens)`.
   - Tooltip is the only place token counts appear.

6. **Color (non-blocking)**
   - Default: same muted color as time.
   - Optional warning tint at ≥90% so saturated threads are visible without reading the number. Do not use color as the only signal.

7. **Accessibility**
   - Screen reader label for the row includes title, time, and context used, e.g. `Auth refactor, 2 hours ago, 85 percent context used`.
   - Marker is not a separate tab stop.

8. **Performance**
   - Computing percent for the visible list must not block sidebar render. Stale cached percents may show for at most one frame, then update.

## Acceptance criteria

- A chat at 85% usage renders a single-line row with title, relative time, then `· 85%`.
- 0% with real empty usage on a chat that has content shows `· 0%`; a chat with no estimable usage shows no percent and no dangling `·`.
- 99.9% displays as `· 99%`; 100% or over displays as `· 100%` and never `· 101%`.
- Narrow sidebar: title ellipsizes; time and `· n%` remain fully readable.
- After a send that moves usage from 40% to 62%, the open sidebar row updates to `· 62%` without reload.
- Changing the chat’s model to one with a different window recalculates the percent.
- Tooltip on the marker includes both the percent and used/limit token counts.
- Removing the last messages such that usage is no longer estimable removes `· n%` from the row.
- Empty state, search/filter, pin, delete, and rename of chats are unchanged aside from the new suffix.
- Keyboard focus and click targets on the row still open the chat; the marker is not a separate control.
- No regression in chat-list scroll performance with 50+ rows.

## Out of scope

- Progress bars, pie icons, or a dedicated usage column
- Showing remaining percent, cost, cache-hit rate, or message count in the row
- Per-folder or per-workspace rollups
- Inline warnings, send-blocking, or auto-summarize when usage is high
- Chat panel header/composer usage meter (separate surface)
- JetBrains, web, or CLI chat lists
- Persisting percent as its own field; it is derived at render time
- User setting to hide the marker (revisit after ship)
- Localization of the middle-dot pattern beyond the percent number itself

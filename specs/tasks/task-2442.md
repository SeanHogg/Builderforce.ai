# PRD: Chat row context usage in the VSIX sidebar

## Problem & Goal

Developers who keep many concurrent chats in the VSIX Sessions view cannot tell from the list whether a conversation is already linked to a board ticket, or how far that ticket has progressed. They only learn after opening the thread. Today some rows already prefix the **title** with `{n}% · `, which steals title space, collides with #2439’s description-side `· n%`, and is easy to misread as model context fill.

**Goal:** Each Sessions TreeView conversation row that has a computable linked-ticket progress value shows a compact marker **after the relative time** in `TreeItem.description`, in the form `{relativeTime} · {n}%`. The title stays the chat title. The marker always means ticket complete percent (`BfBrainChat.ticketProgressPct`), is glanceable, and stays out of the way of title and timestamp.

**Not this ticket:** a model context-window meter (`usedTokens / modelContextWindow`). That is a separate product problem, filed as gap **#2608**.

## Scope

**In scope**

- Conversation rows in the VSIX **Sessions TreeView** only (`clients/vscode/src/sessionsTree.ts` and the `BfBrainChat` payload it already consumes)
- A single figure: linked-ticket progress, `ticketProgressPct` on `BfBrainChat` (integer 0–100, or absent)
- Placement: `TreeItem.description` = `{relativeTime} · {n}%` when a percent is present; `{relativeTime}` alone when it is not

- Live update when the chat list is refreshed or `ticketProgressPct` changes on an existing row

## Functional requirements

1. **Placement and format**
   - Each conversation row continues to show **title** (`TreeItem.label`) and **relative time** (`TreeItem.description`).
   - When `ticketProgressPct` is an integer in 0–100 inclusive, append it after the time using a middle-dot separator: `{relativeTime} · {n}%`.
   - Percent is an integer 0–100, no decimals, no `~`, no `used`/`left`/`context` wording in the row itself.
   - If progress cannot be shown (null, undefined, non-finite, or no linked ticket), omit the separator and percent. Do **not** show `· —` or a fake `· 0%`.
   - Do **not** prefix the title. `conversationTreeLabel` (or equivalent) must return the chat title only.

2. **Meaning**
   - `n` is `BfBrainChat.ticketProgressPct`, clamped to `[0, 100]` (`min(100, max(0, floor(pct)))`).
   - The figure is **linked-ticket complete percent**, not remaining work and not model-context fill.
   - Source of truth is the chat DTO already returned by the brain/chats API. This ticket does not invent a new field or a client-side estimator.

3. **When it appears**
   - Show on every conversation row whose DTO has a computable `ticketProgressPct`, including the active chat.
   - Hide on chats with no linked ticket / no percent.
   - Recalculate whenever the Sessions tree is refreshed or the chat list payload is replaced (send/receive that updates the DTO, ticket progress change, unlink).
   - Unlinking a ticket, or a payload that drops `ticketProgressPct`, removes `· n%` from the description and leaves `{relativeTime}`.

4. **Overflow and layout (VS Code TreeView constraints)**
   - Title (`label`) remains the flexible, truncating element (VS Code ellipsizes the label).
   - Time and `· n%` live in `description`, which VS Code keeps visible on the same row; they must not be stuffed into the label.
   - Marker uses the default description/secondary style. No extra column, badge, progress bar, or custom webview row in this iteration.
   - Do not also write the percent into `label` — that would double-render against #2439 and this contract.

5. **Tooltip**
   - `TreeItem.tooltip` (or the description hover) on a row with a percent includes a short explanation, e.g. `Ticket progress: 85%`.
   - Tooltip is the only place extra wording (“ticket progress”) appears. Do not put token counts here; this is not a context meter.

6. **Color (non-blocking)**
   - Default: same muted/description color as time (VS Code theme).
   - Optional warning tint at ≥90% is **not** required; TreeView description has limited styling. Do not use color as the only signal.

7. **Accessibility**
   - The row’s accessible name includes title, time, and ticket progress, e.g. `Auth refactor, 2 hours ago, 85 percent ticket progress`.
   - Marker is not a separate tab stop or command. Click / keyboard activate still opens the chat.

8. **Performance**
   - Formatting percent for the visible list is string concatenation over already-fetched DTOs. It must not add network calls or block tree render.
   - Stale cached percents may show for at most one refresh cycle, then update from the next chats list payload.

9. **Sibling tickets (do not collide)**
   - **#2439** — same description-side `· n%` contract. Implement once; both tickets are satisfied by one render path.
   - **#2440 / #2443** — ticket picker / dropdown. Out of this ticket. Linking a ticket is what *produces* `ticketProgressPct`; this ticket only *displays* it.
   - **#2608** — context-window usage. Must not be implemented here or double-rendered next to ticket progress without a later layout decision.

## Acceptance criteria

- A chat whose DTO has `ticketProgressPct: 85` renders `TreeItem.label` = the chat title and `TreeItem.description` = `{relativeTime} · 85%` on one row.
- A chat with no `ticketProgressPct` (or a non-finite value) shows `{relativeTime}` only — no dangling `·` and no `· 0%` fake.
- A linked ticket at true 0% complete **does** show `· 0%` (real zero is allowed; absent is not).
- `99.9` displays as `· 99%`; `100` or any value &gt; 100 displays as `· 100%` and never `· 101%`. Negative values display as `· 0%`.
- Narrow sidebar: title ellipsizes; time and `· n%` remain in the description and stay readable.
- After a chats-list refresh that moves progress from 40% to 62%, the open Sessions row updates to `· 62%` without a window reload.
- Removing the ticket link (payload no longer has `ticketProgressPct`) removes `· n%` from the description.
- Existing `{n}% · {title}` label prefix is gone. Percent appears at most once per row.
- Empty state, search/filter, pin, delete, and rename of chats are unchanged aside from the description suffix.
- Keyboard focus and click on the row still open the chat; the marker is not a separate control.
- No regression in Sessions tree scroll/refresh with 50+ rows (no extra I/O per row).
- Tooltip/accessible name says **ticket progress**, never context used / tokens.

## Out of scope

- Progress bars, pie icons, or a dedicated usage column
- Showing remaining percent, cost, cache-hit rate, message count, or **model context fill** in the row (context fill = **#2608**)

- Inline warnings, send-blocking, or auto-summarize when progress is high
- Chat panel header / composer usage meter (separate surface)
- JetBrains, web, or CLI chat lists

- Localization of the middle-dot pattern beyond the percent number itself
- Ticket picker / link-ticket dropdown (**#2440 / #2443**)
- Changing what `ticketProgressPct` means on the API (owned by the chats/tickets backend; this ticket only renders it)

## Requirements

### R1 — User story (display)

**As a** developer scanning the VSIX Sessions list, **I want** each conversation that is already linked to a board ticket to show that ticket’s complete percent next to the relative time, **so that** I can pick a still-active work thread without opening it.

### R2 — User story (title intact)

**As a** developer with long chat titles, **I want** the percent **not** to prefix the title, **so that** the title remains the truncating element and I can still read what the chat is about.

### R3 — Data contract

| Field | Rule |
| --- | --- |
| Source | `BfBrainChat.ticketProgressPct` (already on the chats list DTO) |
| Type | number, integer-displayed |
| Present | show `· n%` |
| Absent / null / NaN / non-finite | hide marker |
| Clamp | `n = min(100, max(0, Math.floor(pct)))` |
| Meaning | linked-ticket **complete** percent. Never tokens, never remaining, never context window |
| Client compute | **none**. Do not estimate from messages. Do not call tasks.get per row |

### R4 — Render contract (Sessions TreeView)

| TreeItem property | Value |
| --- | --- |
| `label` | Chat title only. **Forbidden:** `{n}% · {title}` |
| `description` | `{relativeTime}` if no percent; `{relativeTime} · {n}%` if percent present |
| `tooltip` | Includes `Ticket progress: {n}%` when shown; otherwise unchanged |
| Commands / context menu | Unchanged. Marker is not a command |

Single render helper should serve **#2442 and #2439**. If `conversationTreeLabel` currently prefixes the title, that prefix is removed as part of this ticket.

### R5 — States

| Chat state | Description |
| --- | --- |
| No messages, no ticket | `{relativeTime}` only (or empty time if that is today’s behavior) |
| Messages, no ticket / no pct | `{relativeTime}` only |
| Linked ticket, pct = 0 | `{relativeTime} · 0%` |
| Linked ticket, pct = 85 | `{relativeTime} · 85%` |
| Linked ticket, pct ≥ 100 | `{relativeTime} · 100%` |
| Ticket unlinked on next payload | marker disappears |

### R6 — Accessibility

Accessible name: `{title}, {relativeTime}, {n} percent ticket progress` when the marker is shown; `{title}, {relativeTime}` when not. Not a separate tab stop.

### R7 — Non-functional

- No extra network per row.
- No new persisted field.
- No webview rewrite of the Sessions list.
- 50+ rows must not regress refresh cost vs today.

### R8 — Traceability to siblings

| Ticket | Relationship |
| --- | --- |
| Epic **#2436** | Parent. This is the row-level percent display. |
| **#2439** | Same description-side `· n%`. One implementation satisfies both. |
| **#2440 / #2443** | Dropdown / link-ticket. Out of scope; produces the DTO field this ticket displays. |
| **#2608** | Context-window usage meter. Explicitly **not** this ticket. Do not fold into #2436. |

### R9 — Open questions (resolved by BA)

1. **Is `· 85%` context fill or ticket progress?** Ticket progress. Original PM draft mixed the two. Context fill is #2608.
2. **Title prefix vs description suffix?** Description suffix. Title prefix is the current defect.
3. **May 0% show?** Yes, if and only if the DTO actually sent 0. Absent ≠ 0.
4. **May this ticket add a context estimator?** No.

### R10 — BA sign-off criteria for Ready

Architect may design; developer may implement, when:

- This Requirements section is the source of truth (not `specs/tasks/task-2442.md`, which must not ship as the feature).
- Implementation is confined to Sessions TreeView row render + DTO field already present.
- No context-window math lands on this branch.

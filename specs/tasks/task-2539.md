# PRD: Meeting Notes Marketplace Agent

## Problem & Goal

Advisory meetings currently rely on ad-hoc note-taking. Notes are inconsistent, often incomplete, and rarely available to the rest of the workspace without extra human effort. We already have `runAgentTurn` as the execution surface for agent turns, but Meeting Notes is not a first-class marketplace `agent` that advisors can discover, enable, or reason about like other agents.

**Goal:** Publish Meeting Notes as a marketplace `agent` listing that wraps `runAgentTurn` with a silent notetaker persona, scoped to `kind=advisory`. Enable it by default for dogfood advisors so internal advisory sessions produce structured notes without a setup step.

## Target users / ICP roles

- **Dogfood advisors** — internal advisors running `kind=advisory` sessions; primary launch cohort; default-on.
- **Advisor operators / workspace admins** — need the listing to be discoverable, toggleable, and clearly scoped so it does not leak into non-advisory kinds.
- **Downstream marketplace / agent-runtime agents** — consume this PRD to implement listing metadata, persona wrapping, default-on policy, and turn invocation.

End clients in advisory sessions are *not* the operator of this agent; they should experience notes as a silent byproduct, not as a participant.

## Scope

In scope for this WIP:

- A marketplace `agent` listing for Meeting Notes.
- A silent notetaker persona that wraps `runAgentTurn` (no spoken/visible participation in the live advisory turn stream unless notes are explicitly requested by product surfaces).
- Restriction to sessions with `kind=advisory`.
- Default-on enablement for dogfood advisors only.
- Listing metadata sufficient for marketplace discovery, enable/disable, and runtime binding to `runAgentTurn`.
- Persistence and attachment of notes to the originating advisory session so downstream surfaces can read them.

## Functional requirements

1. **Listing.** Meeting Notes is published as a marketplace `agent` with stable identity, display name “Meeting Notes”, short description that it silently captures advisory session notes, and capability tags that identify it as a notetaker (not a conversational advisor).
2. **Runtime wrap.** Each eligible turn is executed by wrapping `runAgentTurn` with the silent notetaker persona. The wrapper must pass through session, kind, and turn context required by `runAgentTurn`; it must not introduce a second execution path.
3. **Persona.** The persona is a silent notetaker: it does not address participants, does not ask questions, does not offer advice, and does not emit user-visible chat in the advisory transcript. It only produces notes artifacts.
4. **Kind gate.** The agent runs only when `kind=advisory`. For any other kind it must not be invoked, even if the listing is enabled on the workspace.
5. **Default-on (dogfood).** For dogfood advisors, the listing is enabled by default on advisory sessions. Advisors may disable it per session or per workspace. Non-dogfood advisors do not receive default-on; listing may exist but remains opt-in until a later rollout.
6. **Notes output.** On session completion (and on durable mid-session checkpoints if `runAgentTurn` already supports them), the agent writes structured meeting notes bound to the session: summary, decisions, action items (owner + due date when stated), and open questions. Notes are attributable to the Meeting Notes agent, not to a human participant.
7. **Idempotency.** Re-running a turn or retrying `runAgentTurn` must not duplicate notes; updates replace or version the existing notes artifact for that session.
8. **Disable path.** When disabled, `runAgentTurn` is not called for this agent, and no notes artifact is created or updated.
9. **Marketplace contract.** Listing fields, enablement flags, and persona binding are expressed in the same agent-listing schema used by other marketplace agents so catalog, policy, and runtime agents do not need a special case beyond `kind=advisory` and default-on dogfood.

## Acceptance criteria

- Marketplace catalog shows a Meeting Notes `agent` listing that binds to `runAgentTurn` with the silent notetaker persona.
- In a `kind=advisory` session for a dogfood advisor, the agent is enabled with no manual install or toggle; notes appear on the session after the session completes.
- The advisory live transcript contains no notetaker utterances, questions, or advice.
- In a non-`advisory` session, the agent does not run even if the listing is enabled.
- A dogfood advisor can disable Meeting Notes; subsequent advisory sessions produce no notes until re-enabled.
- A non-dogfood advisor does not get the agent on by default.
- Retrying the same turn does not create duplicate notes for the session.
- Notes include summary, decisions, action items, and open questions when those are present in the session; missing sections are omitted rather than hallucinated.
- Downstream agents can resolve the listing, its enablement state, and the session-bound notes artifact without a one-off API.

## Out of scope

- General availability default-on for non-dogfood advisors.
- Notetaking for kinds other than `advisory`.
- Visible / speaking meeting-participant personas, live captions, or in-call coaching.
- Client-facing notes editing UX, sharing, export, or email recap flows (consume the artifact later).
- Changing the `runAgentTurn` contract, billing, or quota model.
- Multi-language notes localization, custom note templates, CRM writeback, or compliance redaction beyond what `runAgentTurn` already applies.
- Auto-assigning action-item owners that were not stated in the session.

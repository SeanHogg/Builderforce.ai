# PRD: Bind SeanHogg/Builderforce.ai so ticket #2545 can ship A0

## Problem & Goal

Developer container runs for epic #2545 cannot check out code. `list_files`, `git_sync_latest`, `git_history`, and `run_command` all fail with "no repository bound to this task" / "no repository checked out". Project 11 `githubRepoUrl` is null.

This is the same class of blocker as historical gap #700 and tickets #2532 / #2538. Until a real checkout exists, A0 cannot be implemented in product code. Docs-only `specs/tasks/task-2545.md` is not the P0.

**Goal:** Connect GitHub repo `SeanHogg/Builderforce.ai` to project 11, bind ticket #2545 to branch `builderforce/task-2545`, re-dispatch the developer producer, and ship A0: Talent `person` listings bookable through existing booking infrastructure (host bind, marketplace Book CTA including Free / price 0, overlap-refusing reservations). Kill conditions remain in force.

## Target users / ICP roles

- Downstream developer / producer agents that must check out, implement, and verify A0 on ticket #2545.
- Marketplace bookers browsing `/marketplace?family=talent` who need a working Book CTA, including free listings.
- Talent hosts (`person` listings) whose availability is represented via `booking_hosts.host_ref` and `booking_services`.
- Platform operators who require project 11 to have a non-null `githubRepoUrl` so epic work is not stuck on a bind gap.

## Scope

**In scope**

1. Connect `SeanHogg/Builderforce.ai` to project 11 so `githubRepoUrl` is set and checkout APIs succeed.
2. Bind ticket #2545 to branch `builderforce/task-2545`.
3. Re-dispatch the developer producer against that bound checkout.
4. Implement A0 against existing booking tables and marketplace listing kinds:
   - Bind Talent `person` listing ↔ `booking_services` via existing `booking_hosts.host_ref`.
   - Book CTA on `/marketplace?family=talent`, including Free / price 0.
   - Create `booking_reservations` that refuse overlapping slots for the same host/service.
5. Preserve kill conditions: no `/advisors` route, no `advisor` in `MARKETPLACE_LISTING_KINDS`, no volunteer table.

**P0 vs non-P0**

- P0 is the bind + A0 product behavior in the bound repo.
- `specs/tasks/task-2545.md` (docs-only) is not P0 and must not be treated as the shipped artifact.

## Functional requirements

### Bind and dispatch

- Project 11 `githubRepoUrl` points at `SeanHogg/Builderforce.ai`.
- Ticket #2545 is bound to branch `builderforce/task-2545`.
- Developer container can `list_files`, `git_sync_latest`, `git_history`, and `run_command` against a checked-out working tree.
- Developer producer is re-dispatched after bind so A0 is implemented in that tree, not in task docs.

### A0 — Talent listing ↔ booking_services

- A Talent `person` listing is bookable only when it is bound to a `booking_services` row through existing `booking_hosts.host_ref` (no new host identity model).
- Unbound `person` listings do not expose a working Book path.
- Binding reuses current `booking_hosts` / `booking_services` schema; no parallel host table.

### A0 — Marketplace Book CTA

- `/marketplace?family=talent` shows a Book CTA for bound, bookable Talent listings.
- Book CTA works for paid prices and for Free / price 0 (zero is a valid bookable price, not a hidden or disabled state).
- CTA does not navigate to `/advisors` or any advisor-named surface.

### A0 — Overlap-refusing reservations

- Booking creates `booking_reservations` rows against the bound service/host.
- Overlapping time ranges for the same host/service are refused (no double-book).
- Non-overlapping ranges for the same host/service are allowed.
- Refusal is a first-class booking rule, not a UI-only disable.

### Kill conditions (must hold after A0)

- No `/advisors` route, page, or redirect.
- `MARKETPLACE_LISTING_KINDS` does not include `advisor`.
- No volunteer table (create, migrate, or read path).

## Acceptance criteria

1. Project 11 `githubRepoUrl` is `SeanHogg/Builderforce.ai` (non-null).
2. Ticket #2545 is bound to `builderforce/task-2545`.
3. A developer container for #2545 can check out the repo; `list_files`, `git_sync_latest`, `git_history`, and `run_command` succeed (no "no repository bound / checked out" errors).
4. Developer producer has been re-dispatched against that checkout.
5. A0 lives in product code on `builderforce/task-2545`, not solely in `specs/tasks/task-2545.md`.
6. Talent `person` listings that have `booking_hosts.host_ref` → `booking_services` are bookable; unbound listings are not.
7. `/marketplace?family=talent` Book CTA succeeds for bound listings at paid prices and at price 0 / Free.
8. Creating a `booking_reservations` row that overlaps an existing reservation for the same host/service is rejected; non-overlapping creates succeed.
9. After A0: no `/advisors`, no `advisor` in `MARKETPLACE_LISTING_KINDS`, no volunteer table.

## Out of scope

- New listing kind `advisor`, `/advisors` UX, or advisor copy in marketplace kinds.
- Volunteer table or volunteer booking flow.
- New host identity beyond existing `booking_hosts.host_ref`.
- Treating `specs/tasks/task-2545.md` as the shipped A0.
- Unrelated marketplace families, payment-provider changes, or booking schema redesign.
- Re-litigating historical bind gaps #700 / #2532 / #2538 except as the same blocker class to close the same way: bind repo, bind branch, re-dispatch.

### R5 — A0 Free / price 0

| ID | Requirement | Acceptance |
|----|-------------|------------|
| R5.1 | `booking_services.priceCents === 0` is a **valid bookable price** (Free). Zero MUST NOT hide, disable, or unbind Book. | Bound + price 0 → Book succeeds the same as a paid service. |
| R5.2 | Listing hourly rate (`hourlyRateCents`) is **not** the Book price. A Free session on a paid-rate profile (or the reverse) is allowed. Bookability is the host bind (R3), not `rate > 0`. | Grid may still show hourly rate; Book stays bound to services. |
| R5.3 | UI MAY label 0 as "Free". It MUST NOT treat 0 as "not for sale". | Founder browsing talent family can book a Free bound listing. |

### R6 — A0 overlap-refusing reservations

Server rule, not a UI-only disable. Existing `reserve()` in `api/src/application/commerce/bookings.ts`.

| ID | Requirement | Acceptance |
|----|-------------|------------|
| R6.1 | Creating a `booking_reservations` row that **overlaps** an existing non-cancelled reservation for the same service (and host when `hostRef` is set) MUST be rejected. | HTTP **409**, message `that slot is no longer available` (`BookingError`). |
| R6.2 | Overlap is **half-open** with service `bufferMin`: `startsAt < windowEnd AND endsAt > windowStart`. Back-to-back slots (end == next start, ignoring buffer) are allowed. | Non-overlapping creates succeed. |
| R6.3 | Clash count is against `service.capacity` (one_to_many workshops later). For default capacity 1, any overlapping confirmed row refuses. Cancelled rows are excluded. | Do not invent a second overlap table. |
| R6.4 | The Book panel MUST surface overlap as a booking failure (not a generic toast-only error). | `BookAdvisorPanel` maps `no longer available` → overlap copy; `expectedErrors: [409]`. |
| R6.5 | Successful Book inserts `booking_reservations` with `status=confirmed`, `serviceId`, `hostRef` = talent userId, `startsAt`/`endsAt` from service `durationMin`. | Row exists in the **host** tenant. |

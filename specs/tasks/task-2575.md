# PRD: R7 — DONE.md close-out, Gap Register cleanup, and gated release notes

## Problem & Goal

R6 work is complete only when the gap is closed in the shared records and a release note draft exists. Today the Gap Register still lists the open item at `ROADMAP.md` L142, `DONE.md` has no dated `RESOLVED` entry for this gap, and release notes have not been categorized. Publishing notes without an operator check risks shipping the wrong categories (especially the 403 chain, which must stay silent).

**Goal:** After R6 is done, write a dated `RESOLVED` into `DONE.md`, delete **only** Gap Register line `ROADMAP.md` L142, draft release notes with the mandated categories, and **stop** until the operator confirms publish.

## Target users / ICP roles

- **Operator** — sole authority to approve publishing release notes.
- **Downstream agents** — consume this PRD; they must not publish, invent extra Gap Register edits, or add a 403-chain note.
- **Release-notes consumer** (internal changelog / users of persona delegation and diagnostics) — sees only the two approved items.

## Scope

In scope, **strictly after R6**:

1. Append a dated `RESOLVED` record to `DONE.md` for this gap.
2. Delete Gap Register entry at `ROADMAP.md` L142 **and no other ROADMAP lines**.
3. Draft (do not publish) release notes:
   - `category=new` — persona delegation (`spawn_agent` `as_agent`)
   - `category=improvement` — persisted diagnostics
   - **omit** any note for the 403 chain
4. Ask the operator to confirm before any publish step.

## Functional requirements

1. **R6 gate.** Do not write `DONE.md`, delete L142, or draft/publish notes until R6 is complete. If R6 is not done, stop and report blocked.
2. **DONE.md.** Add one dated `RESOLVED` entry that names the closed gap (persona delegation + persisted diagnostics close-out). Date must be the resolution date, not a placeholder.
3. **Gap Register.** Delete exactly `ROADMAP.md` L142. Leave surrounding ROADMAP content unchanged. Do not delete L142 if R6 is incomplete.
4. **Release notes draft** (unpublished):
   - **New:** persona delegation via `spawn_agent` with `as_agent`.
   - **Improvement:** persisted diagnostics.
   - **None:** 403 chain — no title, no body, no “fixed 403” mention.
5. **Publish gate.** Present the `DONE.md` entry, the L142 deletion, and the draft notes to the operator. Publish only after explicit confirmation. If the operator declines or is silent, leave notes unpublished.
6. **Idempotency.** If L142 is already gone or `DONE.md` already has this `RESOLVED`, do not duplicate; still require operator confirm before any publish.

## Acceptance criteria

- R6 completed **before** any R7 mutation of `DONE.md` or `ROADMAP.md`.
- `DONE.md` contains a single new dated `RESOLVED` line for this gap.
- `ROADMAP.md` L142 (the matching Gap Register row) is deleted; no other ROADMAP edits.
- Draft notes include `new` for `spawn_agent` / `as_agent` persona delegation and `improvement` for persisted diagnostics.
- Draft notes contain **zero** 403-chain coverage.
- No release notes are published until the operator explicitly confirms.
- Operator is asked in-band before publish; a no/wait leaves artifacts local/draft-only.

## Out of scope

- Implementing or regressing persona delegation, diagnostics persistence, or the 403 chain.
- Editing any Gap Register line other than `ROADMAP.md` L142.
- Publishing release notes, tagging a release, or notifying customers without operator confirmation.
- Adding extra changelog entries, rewriting historical `DONE.md` resolutions, or backfilling notes for unrelated gaps.
- Treating this PRD as permission to skip the R6-before-L142-delete rule.

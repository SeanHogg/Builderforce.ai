# PRD 27 — Idea-validation survey loop (wiring only)

WIP product requirements for downstream agents. Implement PRD 27 idea-validation surveys as **wiring** of existing form, canvas, campaign, CRM, and collect surfaces. Do not invent a parallel survey product.

## Problem & Goal

Founders already author forms, publish them, send campaigns, keep CRM contacts, and collect responses. Idea validation still cannot close that loop: an Idea cannot host a form surface, draft test questions onto a linked form, send via the existing campaign path, pull owned CRM contacts into an audience, or fold response counts back onto the Idea card.

**Goal:** Wire B0–B5 so an Idea can run Idea → Make (form) → Run (campaign send) → Measure (collect on the card) without a new survey kind, second answer store, fifth contact store, `/surveys` destination, or second send path. Founders set `validated` / `dropped` themselves. Never auto-status.

## Target users / ICP roles

- **Founder / builder** on the Ideas canvas: drafts questions, publishes a form, sends to people, reads counts, marks the idea validated or dropped.
- **Respondent:** opens `/f/<slug>` on a phone (~360px) in either theme and submits.
- **Not in this slice:** sales reps as a second owner of contacts; marketers inventing a new campaign type.

## Scope

Wiring only against existing objects and APIs.

## Functional requirements

### B0 — Form surface on the canvas

1. Register form actions on `CONNECTED_CANVAS_ACTIONS`.
2. Object-scoped form surface: unique registry order, `AUTHORING_SURFACE`, mounted on the host object (Idea), not a global fifth surface.
3. Publish uses existing `formObject` publish body and existing `/f/<slug>` URL. Do not add `/surveys`.
4. Client can call `summarizeForm` for counts used later by B5.
5. `CanvasFormSurface` renders the linked form in-canvas.
6. `peopleObjects` add/close works for the people picker used by Ask people / send.
7. Copy lives in the five next-intl catalogs (same five locales as FR-10).

**Kill conditions:** `/f/<slug>` unopenable, **or** form surface not in the registry.

### B1 — Ask people on Ideas (FR-3 / FR-5)

1. Ideas expose **Ask people**. If send is blocked, the control is **disabled, not hidden**.
2. `IDEA_EVIDENCE_KINDS` includes `form`.
3. `idea.tested` catalog strings exist for the tested/evidence state.

### B2 — Draft test questions (FR-4)

1. Connect `idea.test`: draft questions onto the linked form from Idea `problem`, `segment`, and `riskiestAssumptions`.
2. Fix the `canvas_publish_form` hint so publish/send copy matches the wired form, not a missing survey dest.
3. `idea.explore`: **drop or connect** — do not leave a half-wired explore path that implies a second survey kind.

### B3 — Send (FR-6)

1. Send uses existing `growthApi.createCampaign` + existing send.
2. Evaluate `CAMPAIGN_BLOCKERS` first; blocked send stays on the disabled Ask people control (B1).
3. No second send path, no survey-specific campaign type.

### B4 — CRM into audience (FR-7)

1. Dedicated from-crm route. **Do not** reuse `POST` members (hardcoded `source: 'import'`).
2. Inserts `marketing_audience_members` with `source='crm'` only.
3. De-dupe on `(audience_id, email)`.
4. Read **own** `sales_contacts` only (`owner_user_id` = current user). `sales_contacts` is not the user-owned canonical store.

### B5 — Measure on the card (FR-8)

1. Collect folds `summarizeForm` counts onto the Idea card.
2. Founder sets `validated` / `dropped` **manually**. Never auto-advance from response counts.

### FR-10 — i18n, theme, public form

1. next-intl: five locale catalogs for all new strings (B0 catalogs included).
2. Theme tokens only; `/f/<slug>` works in both themes.
3. Public form usable at ~360px width.

### FR-11 — Launch content (conditional)

If the existing content pipeline is a small add: one `category=new` release note and one blog that narrates Idea → Make → Run → Measure. Skip if the pipeline is not a small add.

- Frontend: `pnpm run check`.

## Acceptance criteria

- Form surface is in the canvas registry (unique order, `AUTHORING_SURFACE`, host-mounted). `CONNECTED_CANVAS_ACTIONS` includes form actions.
- Publishing a linked form yields a working `/f/<slug>` (both themes, ~360px). Kill if unopenable or surface missing from registry.
- Ideas show Ask people; blocked send is disabled-not-hidden. `IDEA_EVIDENCE_KINDS` includes `form`. `idea.tested` catalog present in five locales.
- `idea.test` drafts questions from problem / segment / `riskiestAssumptions` onto the linked form. `canvas_publish_form` hint is correct. `idea.explore` is either dropped or fully connected.
- Send goes through `growthApi.createCampaign` + send after `CAMPAIGN_BLOCKERS`. No alternate send API or `/surveys` dest.
- From-crm route writes `marketing_audience_members` with `source='crm'`, de-dupes `(audience_id, email)`, and only copies contacts where `owner_user_id` is the current user. Members `POST` (`source: 'import'`) is unused.
- Idea card shows `summarizeForm` counts. Status `validated` / `dropped` changes only from an explicit founder action.
- `PHASE_SURFACES` unchanged. No new survey kind, answer store, contact store, or send path.
- `pnpm run check` passes in frontend on this change set.
- FR-11 ships only when it is a small add to the existing pipeline; otherwise omitted.

## Out of scope

- New survey kind, second answer store, fifth contact store, `/surveys` destination, second send path.
- Treating §11.4 / `sales_contacts` as user-owned canonical.
- Implementing §11.1–11.6 / §11.8 unless a listed wire cannot land without it.
- Changing `PHASE_SURFACES` or redoing §11.7 Ideas visibility.
- Auto-setting idea `validated` / `dropped` from form counts or any heuristic.
- Reusing members `POST` (`source: 'import'`) for CRM sync.
- Broad CRM / campaign / form refactors unrelated to B0–B5.
- Unrelated dirty-tree files; do not mix them into this change set.
- FR-11 if the content pipeline is not a small add.

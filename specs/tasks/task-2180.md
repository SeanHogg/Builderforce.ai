## 5. Security conclusion

- Direct vite on converter: none. Closing PR 820 does not leave an unpatched direct Vite 5.4.21 product dependency.
- Transitive vite 5.4.21 via vitest 2.1.9: still present on main. Vite 5.x has a history of server.fs.deny / dev-server advisories. Exploitability here is low: converter tests use Vitest environment node; the product is a CLI (tsx plus tsc), not a Vite preview/dev server exposed to browsers.
- vitest 2.1.9 remains the test runner. Addressing remaining advisories means a planned vitest bump, not resurrecting a Vite 8 Dependabot PR.
- PR 820 as a security-fix vehicle is invalid. The PR is closed and would have jumped three Vite majors the CLI does not own.
- This ticket ships no dependency change, so it introduces no new high/critical advisory.

Verdict: no unaccepted high/critical regression from disposing PR 820. Residual transitive Vite 5.4.21 is accepted for this ticket and handed to the vitest follow-up. AppSec does not need to sign off a Vite 8 merge that will not happen.

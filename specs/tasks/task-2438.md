# PRD: Add `progressPct` to `BfBrainChat`

## Problem & Goal

`BfBrainChat` in `clients/vscode/src/bfApi.ts` does not yet declare `progressPct`, so the VS Code client cannot type-safely consume the additive list field from `GET /api/brain/chats` (#2437).

`ticketProgressPct?: number | null` already exists on the same interface (overall linked-ticket progress, or `null` when none are linked). This ticket does **not** replace, rename, or collapse that field.

**Goal:** Add optional `progressPct?: number` to `BfBrainChat` so the client DTO matches the API list payload. The number is the ChatTicketService linked-ticket rollup (typically 0–100) — the overall % complete of tickets linked to that chat (epic #2436) — not streaming/generation progress and not context-window usage (#2608).

## Requirements

Add an optional numeric chat-progress field to the existing `BfBrainChat` type so callers can represent in-flight Brain chat progress without local type widening or untyped casts.

### Canonical type
- **File:** `clients/vscode/src/bfApi.ts`
- **Type:** `export interface BfBrainChat`
- **Field:** `progressPct?: number`
- This is the canonical definition. Any re-export or generated alias of `BfBrainChat` in the same file must carry the same field.

### Semantics
- `progressPct` is **chat-run progress** (streaming, generation, or other in-flight work on the conversation itself), typically a percent in the 0–100 range.
- It is **not** the same as the existing `ticketProgressPct?: number | null` (overall linked-ticket progress, or `null` when no tickets are linked). Both fields may be present; they must not be collapsed or renamed into each other.
- The field is **optional**. Objects without `progressPct` remain valid `BfBrainChat` values. Existing call sites must compile without required updates.
- Assigning a non-number is a TypeScript type error. This change does **not** add runtime clamping, rounding, NaN guards, or 0–100 enforcement.

### Compatibility & non-goals
- Keep every existing `BfBrainChat` field, optionality, and export unchanged.
- No new endpoints, UI, serialization, persistence, analytics, or backend contract/versioning as part of this ticket.
- Do not change other chat types unless they are the same `BfBrainChat` definition.

### Acceptance
1. `progressPct?: number` is present on `BfBrainChat` in `bfApi.ts`.
2. Typecheck accepts `BfBrainChat` without `progressPct` and with `progressPct` set to a number.
3. Assigning a non-number to `progressPct` is a type error.
4. No unrelated edits in `bfApi.ts`.

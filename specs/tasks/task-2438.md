# PRD: Add `progressPct` to `BfBrainChat`

## Problem & Goal

`BfBrainChat` in `clients/vscode/src/bfApi.ts` does not yet declare `progressPct`, so the VS Code client cannot type-safely consume the additive list field from `GET /api/brain/chats` (#2437).

`ticketProgressPct?: number | null` already exists on the same interface (overall linked-ticket progress, or `null` when none are linked). This ticket does **not** replace, rename, or collapse that field.

**Goal:** Add optional `progressPct?: number` to `BfBrainChat` so the client DTO matches the API list payload. The number is the ChatTicketService linked-ticket rollup (typically 0–100) — the overall % complete of tickets linked to that chat (epic #2436) — not streaming/generation progress and not context-window usage (#2608).

### D-1 — Semantics (product lock; BA “chat-run / streaming” rejected)

`progressPct` is the **ChatTicketService linked-ticket rollup** for that conversation — overall % complete of tickets linked to the chat (epic #2436; API child #2437). Typically integer **0–100**.

It is **not**:

### D-2 — Payload mapping (P8; epic AC overrules #2437 default-0)

JSON from `GET /api/brain/chats` maps **1:1** onto `BfBrainChat`. This ticket adds **no** client mapper, no `?? 0`, no clamp, no rounding, no NaN filter.

| List item (`#2437`) | `BfBrainChat` (this ticket) |
| --- | --- |
| `progressPct` omitted | field omitted — valid (older servers **and** chats with no ticket health) |
| `progressPct: <number>` including **0** | `progressPct: number` |
| `ticketProgressPct: number \| null` | unchanged; do not copy, coerce, or delete |

**Server populate rules (owned by #2437, recorded here so the client type is not documented against them):**

- No linked tickets / no summary → **omit** `progressPct`. Keep `ticketProgressPct: null` (or omit).
- Linked tickets with a known pct, **including 0** → set `progressPct` to that integer 0–100 **and** set `ticketProgressPct` to the same number.
- When both are present they **must match**.
- Fail-soft: if the ChatTicketService batch throws, omit `progressPct`.
- **Forbid** `progressPct: summary?.pct ?? 0` (and the #2437 PO-lock `s ? s.ticketProgressPct : 0`) when there is no summary. That is a misleading `0%` and violates epic AC. Child #2437 “never null / default 0” is **overruled** by epic #2436.

Client optionality is the correct TypeScript counterpart of “omit when unknown” **and** “older servers omit.” Downstream paint (#2439 / #2440) must not treat a missing field as `0`. Numeric **0 shows** (` · 0%`); `undefined` / omitted **omits**. That paint is **out of scope** here.

UI may fall back to a **finite** `ticketProgressPct` only if `progressPct` is absent (#2436). That fallback is **not** implemented on this ticket.

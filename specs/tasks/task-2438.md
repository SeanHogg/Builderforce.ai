# PRD: Add `progressPct` to `BfBrainChat`

## Problem & Goal

`BfBrainChat` in `clients/vscode/src/bfApi.ts` does not yet declare `progressPct`, so the VS Code client cannot type-safely consume the additive list field from `GET /api/brain/chats` (#2437).

`ticketProgressPct?: number | null` already exists on the same interface (overall linked-ticket progress, or `null` when none are linked). This ticket does **not** replace, rename, or collapse that field.

**Goal:** Add optional `progressPct?: number` to `BfBrainChat` so the client DTO matches the API list payload. The number is the ChatTicketService linked-ticket rollup (typically 0–100) — the overall % complete of tickets linked to that chat (epic #2436) — not streaming/generation progress and not context-window usage (#2608).

## Requirements

Add an optional numeric field to the existing `BfBrainChat` type so callers can consume `GET /api/brain/chats` `progressPct` without local type widening or untyped casts.

### Canonical type
- **File:** `clients/vscode/src/bfApi.ts`
- **Type:** `export interface BfBrainChat`
- **Field:** `progressPct?: number`
- This is the canonical client definition. Any re-export or generated alias of `BfBrainChat` in the same file must carry the same field.

### Semantics (product lock)
- `progressPct` is the **ChatTicketService linked-ticket rollup** for that conversation — overall % complete of tickets linked to the chat (epic #2436; API #2437 `progressPct: summary?.pct ?? 0`). Typically 0–100.
- It is **not** in-flight streaming/generation progress, not a context-window / token meter (#2608), and **not** a rename of `ticketProgressPct`.
- Keep existing `ticketProgressPct?: number | null` unchanged (null when no tickets are linked). Both fields may be present. Client difference: `ticketProgressPct` allows `null`; `progressPct` is a `number` when present (API never-null per #2437) and **optional** on the type so older servers that omit it still type-check.
- UI paint (#2439, #2440, #2442, #2443) and refresh (#2441) are **out of scope** for this ticket.

### Compatibility & non-goals
- Keep every existing `BfBrainChat` field, optionality, and export unchanged.
- No new endpoints, UI, serialization, persistence, analytics, runtime clamp/rounding/NaN/0–100 enforcement, or backend contract/versioning.
- Do not change other chat types unless they are the same `BfBrainChat` definition.

### Acceptance
1. `progressPct?: number` is present on `BfBrainChat` in `clients/vscode/src/bfApi.ts`.
2. Typecheck accepts `BfBrainChat` without `progressPct` and with `progressPct` set to a number.
3. Assigning a non-number to `progressPct` is a type error.
4. No unrelated edits in `bfApi.ts`.
5. Existing call sites compile without required updates.

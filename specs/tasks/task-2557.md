# PRD: packages/brain-ui — Test then Dist

## Problem & Goal

`packages/brain-ui` must be proven green and then emitted as a consumable build artifact. Downstream agents and packages cannot rely on this UI package until unit/integration tests pass and the `dist` output is produced from a clean, successful test run.

**Goal:** Run `pnpm test` in `packages/brain-ui`, require a passing result, then produce `dist` (package build / publishable output) from that same tree. Stop on test failure; do not ship or leave a stale `dist` as success.

## Target users / ICP roles

- Monorepo maintainers and CI operators who gate merges on package health
- Downstream package/app consumers that import `@brain-ui` (or equivalent) from `dist`
- Agent runners executing this WIP task without product-owner reinterpretation

## Scope

- Working directory: `packages/brain-ui`
- Package manager: `pnpm`
- Sequence: **test first, dist second**
- Success means tests pass and `dist` is generated (or refreshed) afterward
- Fail-fast: any test failure aborts; do not run or claim dist success

## Functional requirements

1. Resolve and use the package’s existing `pnpm` scripts and lockfile; do not invent a parallel toolchain.
2. Execute `pnpm test` inside `packages/brain-ui` (or the repo-equivalent filter that targets only this package).
3. Treat a non-zero test exit code as task failure. Do not continue to dist.
4. After a passing test run, execute the package dist/build path that writes `dist` (e.g. `pnpm dist` or the package’s documented build script that emits `dist`).
5. Dist must complete with exit code 0 and leave a present, up-to-date `dist` directory (or equivalent emit path defined by the package).
6. Do not skip tests, `--passWithNoTests` around real failures, ignore failing suites, or reuse an old `dist` to satisfy the dist step.
7. Do not change product behavior except as required to make tests pass and dist succeed (fix breakages in this package only if they block the sequence).

## Acceptance criteria

- `pnpm test` for `packages/brain-ui` exits 0.
- Dist/build is run only after that passing test run.
- Dist/build exits 0.
- `packages/brain-ui/dist` exists and reflects the post-test sources (not an untouched pre-test artifact).
- CI/agent logs show the ordered sequence: test → dist.
- No unpublished test failures, skipped blocking suites, or empty/missing dist presented as done.

## Out of scope

- Other packages’ tests, builds, or publishes
- App-level E2E, visual regression, or manual QA unless already wired into this package’s `pnpm test`
- Version bumps, changelog, npm publish, or registry release
- New product features, redesign, or dependency upgrades unrelated to unblocking test/dist
- Changing monorepo tooling, pnpm version policy, or CI graph beyond what this package needs to test then dist

## Requirements

This ticket is **verify-then-emit** for one package. It does not add product features. Requirements are grounded in `packages/brain-ui/package.json` as of 2026-09-16 (package `@seanhogg/builderforce-brain-ui` **2026.9.12**). Downstream roles (architect, developer, QA, validator) must treat these as the contract; do not invent a parallel toolchain.

### R-1 — Working directory and existing toolchain

- Work **only** in `packages/brain-ui` (or the repo-root equivalent `pnpm --filter @seanhogg/builderforce-brain-ui <script>`).
- Use the package’s existing **pnpm** scripts and lockfile. Do **not** add npm/yarn, a new test runner, or a new bundler.
- Existing scripts (do not rename or wrap unless a mechanical breakage in this package requires it):
  - `test` → `vitest run --passWithNoTests`
  - `build` → `tsup --config tsup.config.ts`  ← **this is the dist path**
  - `typecheck` → `tsc --noEmit` (optional extra; **not** a substitute for `test` or `build`)
- There is **no** `dist` script. Saying `pnpm dist` is a misread of this package. Dist is `pnpm build`.

### R-4 — Fail-fast: non-zero test exit aborts dist

- Treat a non-zero `pnpm test` exit as **task failure**.
- Do **not** run `pnpm build`, do **not** refresh `dist`, and do **not** claim success from a pre-existing `dist/` tree.
- Fix policy (inherited from parent #2555 / PRD 29): **mechanical breakage only** inside `packages/brain-ui` (wrong import path, exhaustive `Record` missing `'composing'`, stale test literal, missing catalog key). Report real logic defects; do not patch them here.
- Do not skip, `.skip`, or `--exclude` a blocking suite to go green.

### R-5 — Dist second: `pnpm build` emits the public artifact

- Only after R-3 exits 0, run **`pnpm build`** in `packages/brain-ui`.
- tsup entry is `src/index.ts`. Emit path is `packages/brain-ui/dist/`.
- `package.json` public contract that must exist after a successful build:
  - `main` → `dist/index.cjs`
  - `module` → `dist/index.mjs`
  - `types` → `dist/index.d.ts`
  - `exports["."]` maps types/import/require to those three files
- `styles.css` is shipped beside dist (not bundled). Do not omit it from `files`.
- Externals stay external (React, `react-markdown`, `remark-gfm`, `@seanhogg/builderforce-brain-embedded`). Do not bundle the host’s React or the brain core into this UI package.

### R-6 — Dist must be post-test and current

- `pnpm build` must exit 0.
- `packages/brain-ui/dist` must be **present and newer than the test run** (mtime of `dist/index.d.ts` / `index.mjs` / `index.cjs` ≥ test completion). Reusing an untouched pre-test artifact is failure.
- Do not copy a cached dist from another branch or CI job.

### R-7 — Scope, version, and commit policy

- In scope: this package’s test run + dist emit, plus mechanical fixes **in this package** that unblock that sequence.
- Out of scope (already owned elsewhere): other packages’ tests/builds, api/frontend/vscode steps (#2558–#2561), VSIX 2026.9.72 packaging, npm publish, version bump (package is already 2026.9.12; parent epic packages VSIX **2026.9.72**), product features, dependency upgrades, concurrent dirt (benchmarking, investor, identity, creation-canvas, ROADMAP).
- **Do not commit** unless the operator explicitly asks (parent PRD 29). Report results first.
- Do not dump a `specs/tasks/task-2557.md` conceptual stand-in. Requirements live on **this ticket PRD**.

Name every failing test with its file and assertion. A missing/empty dist, a skipped Change A/B file, or dist-before-test is not done.

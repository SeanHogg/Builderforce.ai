# PRD: packages/brain-ui — test then dist

## Problem & Goal

`packages/brain-ui` must be verified green and then produced as a consumable build artifact before any downstream package or app depends on it. Unrun tests or a missing/stale `dist` cause silent breakage, flaky CI, and incorrect UI behavior in consumers.

**Goal:** Run the package test suite to completion with a passing result, then emit a current `dist` output from that same package so consumers can use a known-good build.

## Target users / ICP roles

- Downstream agents executing this task in sequence
- Package maintainers of `brain-ui`
- CI / release operators consuming `packages/brain-ui` artifacts

## Scope

In `packages/brain-ui` only:

1. Execute the package test command via pnpm.
2. On success, produce the package `dist` (build output).
3. Confirm tests passed and `dist` exists and is current relative to that run.

No other packages, apps, or repo-wide scripts are in scope unless they are the documented way this package runs tests or writes `dist`.

## Functional requirements

1. Working directory for all commands is `packages/brain-ui` (or equivalent pnpm filter targeting that package only).
2. Run `pnpm test` using the package’s existing test script and config. Do not change test files, snapshots, or config unless a failure is caused by an environment issue that must be unblocked to complete the run.
3. Tests must finish. A failing suite is a failed task; do not proceed to dist.
4. After a passing test run, produce `dist` using the package’s existing build/dist script (typically `pnpm build` or the script that writes `dist/`).
5. Do not publish, version-bump, or change consumers.
6. Do not commit unless the surrounding workflow already requires committing generated `dist`; default is leave `dist` on disk as the deliverable.

## Acceptance criteria

- `pnpm test` in `packages/brain-ui` exits 0.
- Test output shows the suite completed (no hang, skip-all without running, or aborted run).
- Dist generation runs only after tests pass and exits 0.
- `packages/brain-ui/dist` exists after the build and contains the expected build outputs for this package (not an empty or leftover tree from a previous failed build).
- Source outside `packages/brain-ui` is unchanged.
- No new failing tests, skipped required suites, or suppressed errors to force a green run.

## Out of scope

- Fixing unrelated product bugs, visual regressions, or refactors in `brain-ui`
- Running monorepo-wide tests or builds
- Publishing to a registry
- Changing package version, exports, or public API
- Adding features, stories, or new test coverage beyond what is required to get the existing suite green
- Deploying or wiring the built `dist` into apps
- Performance, a11y, or visual snapshot campaigns unless they are already part of `pnpm test`

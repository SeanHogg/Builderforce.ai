# PRD: Land Advisor Platform Implementation Notes on Main

## Problem & Goal

**Problem.** PRD 26 for the Advisor Platform already lives on `main` at `specs/builderforce/26-prd-advisor-platform.md`. The companion epic composition contract — `specs/builderforce/26-implementation-notes-advisor-platform.md` — does not. P0/P1 child work currently reconstructs that contract from project memory: `category=advisors` is a talent filter, A0 bind is `booking_hosts.host_ref = talent userId`, and P0/P1 ship on #2527 / #2532 / #2538. That is fragile, unreviewable, and diverges as children land.

**Goal.** Put the implementation-notes spec on `main` as the single shared contract for Advisor Platform composition. Downstream agents must read the notes file, not chat memory, when implementing P0/P1.

## Target users / ICP roles

- Builderforce platform engineers implementing Advisor Platform P0/P1 children (#2527, #2532, #2538 and follow-ons).
- Downstream coding agents that share this PRD and must not re-derive bind rules from memory.
- PRD/spec authors reviewing epic #2522 composition without opening talent, booking, or minutes source.

## Scope

Land **only** `specs/builderforce/26-implementation-notes-advisor-platform.md` onto `main`.

The notes file is the epic composition contract. It must state, in durable spec form:

1. **Talent filter.** `category=advisors` is a talent-catalog filter, not a separate advisor entity or booking product type.
2. **A0 bind.** Booking host identity is `booking_hosts.host_ref = talent userId`. That equality is the Advisor Platform A0 bind; hosts are not bound by display name, email, or a parallel advisor id.
3. **P0/P1 ship vehicles.** P0/P1 behavior ships on #2527, #2532, and #2538. Those issues consume this contract; they do not redefine it.
4. **Epic boundary.** Epic #2522 owns composition and the notes spec. It does not absorb talent, booking, or minutes implementation source.

The file may include short composition tables (filter → bind → ship issues) and cross-links to `26-prd-advisor-platform.md`. It must not include application source, migrations, or environment-bind procedures.

## Functional requirements

1. Add `specs/builderforce/26-implementation-notes-advisor-platform.md` on `main` in the same `specs/builderforce/` tree as PRD 26.
2. Document `category=advisors` as a talent filter used to select advisor talent records.
3. Document A0 bind as `booking_hosts.host_ref = talent userId` with no alternate host-ref mapping.
4. Name #2527, #2532, and #2538 as the P0/P1 ship issues that implement against this contract.
5. Point readers to PRD 26 for product intent and to this notes file for composition/bind rules.
6. Keep the notes free of talent, booking, and minutes source dumps; no code, schemas-as-source, or large excerpts copied onto epic #2522.
7. Do not fold #2588 environment-bind work into this change. #2588 remains environment bind only and is out of scope here.
8. After merge, P0/P1 children must be able to cite the notes path on `main` instead of project memory.

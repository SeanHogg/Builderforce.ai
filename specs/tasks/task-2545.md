# PRD 26 — Advisor Platform as Marketplace Composition

## Problem & Goal

Founders need SCORE-like support — 1:1 mentoring, workshops, Academy courses, and stage-tagged templates — without a parallel advisor product, a fifth marketplace family, or SCORE.org cloned as a site.

The platform already has Talent `person` listings, `booking_services` / `booking_reservations`, `one_to_many` capacity, `course` + LMS enrolment, toolkit `pack`s, calendar, and Brain threads. The gap is composition: Talent is not bound to bookable services, reservations do not mint a confidential meeting surface, workshops are not sold as capacity-counted `one_to_many` slots on the existing family, courses are not stage-tagged for founder matching, packs are not one-per-`BUSINESS_STAGES`, and there is no first-class “continue with this advisor” engagement.

**Goal:** Ship founder support by composing existing Marketplace families and booking/LMS/Brain primitives. SCORE.org is a capability checklist only — not a brand, org model, or information architecture to copy.

**Hard constraint:** Kill the epic if any slice requires `/advisors`, a new listing family / `advisor` in `MARKETPLACE_LISTING_KINDS`, or a volunteer table.

**Sequencing:** A0 unblocks the rest. A0 must be measurable before A3–A5 start.

---

## Target users / ICP roles

| Role | Need |
| --- | --- |
| Founder (seeker) | Discovers ranked Talent on `/marketplace?family=talent`, books 1:1s (including Free / price 0), joins workshops, enrols in stage-tagged courses, installs the pack for their `business_stage`, and continues with the same advisor. Matching signals include `seeking:mentorship` and `business_stage` (e.g. `mvp`). |
| Advisor (Talent `person`) | Listed as Talent; offers `booking_services`; hosts 1:1s and `one_to_many` workshops; may author or be attached to `course` and `pack` listings. Not a separate kind or volunteer record. |
| Seat / roster agent | Remains on the existing agent roster; no advisor-specific agent type. |
| Operator | Configures services, capacity, stage tags, packs, and confidentiality defaults. No SBA/chapter/volunteer admin. |

---

## Scope

Compose SCORE-like capabilities onto current Marketplace families and booking/LMS/Brain surfaces.

| Slice | Composition |
| --- | --- |
| **A0** | Bind Talent `person` listing ↔ `booking_services`. Book CTA on `/marketplace?family=talent`. Do **not** add `advisor` to `MARKETPLACE_LISTING_KINDS`. |
| **A1** | Reservation → meeting + calendar event + restricted Brain thread. Confidentiality default **restricted**; thread is not in `aiContext` unless the founder invites it. |
| **A2** | Workshops as `one_to_many` with counted capacity. No `/webinars` page. |
| **A3** | Stage-tagged `course` listings + LMS enrolment. |
| **A4** | Exactly one toolkit `pack` per `BUSINESS_STAGES` value: `idea`, `mvp`, `early_revenue`, `growth`, `scale`. |
| **A5** | Continue-with-this-advisor engagement. Prefer a relation on existing records, not a new table. |

A0 is the gate: Book CTA + listing↔service bind must be demonstrable before Academy, packs, or continue-with-advisor work begins.

---

## Functional requirements

### A0 — Talent bind and Book CTA

- A Talent `person` listing may bind to one or more `booking_services` (duration, price including 0, availability). Binding uses existing listing and service records; no new listing kind.
- `/marketplace?family=talent` shows a Book CTA on bookable person listings. CTA starts reservation against the bound service. No `/advisors` route, nav item, or family switcher entry.
- Ranking for a founder with `seeking:mentorship` and a `business_stage` (e.g. `mvp`) includes advisors whose services are Free (`price` 0) alongside paid services.
- Seat agents stay on the existing roster; they are not modeled as advisors.

### A1 — Reservation to meeting surface

- Creating a 1:1 `booking_reservation` refuses overlap for the same advisor service window (and founder, where double-booking the founder would collide).
- On confirmed reservation: create a calendar event and a Brain thread for that engagement.
- Thread confidentiality defaults to **restricted**. Restricted threads are omitted from `aiContext` unless the founder explicitly invites the thread.
- Meeting artifacts attach to the reservation; do not invent a parallel session entity if reservation + calendar + thread suffice.

### A2 — Workshops as `one_to_many`

- Workshops are `one_to_many` listings/slots on the existing family, not a webinar product.
- Capacity is counted; join fails when the slot is full.
- Founders join a future slot from the same marketplace family used for Talent discovery (query/family composition, not a new family).
- No `/webinars` page or webinar-specific IA.

### A3 — Stage-tagged Academy

- `course` listings carry a business-stage tag aligned with `BUSINESS_STAGES`.
- Founders enrol through existing LMS enrolment. Do not start A3 until A0 is measurable.

### A4 — Stage toolkits

- Exactly one toolkit `pack` per `BUSINESS_STAGES` value (`idea`, `mvp`, `early_revenue`, `growth`, `scale`).
- Founder with `business_stage:mvp` can install the mvp pack. Do not start A4 until A0 is measurable.

### A5 — Continue with this advisor

- After a 1:1 (and optionally after workshop/course touchpoints), the founder can continue with the same advisor.
- Implement as a relation on existing records (e.g. founder ↔ Talent `person` / listing), not a new engagement/volunteer table. Do not start A5 until A0 is measurable.

### Cross-cutting

- Discovery, book, join, enrol, and install stay on existing marketplace URLs and families.
- Confidentiality: restricted by default for advisor 1:1 threads; founder-controlled invite into `aiContext`.
- Price 0 is a valid bookable service (Free), not a separate volunteer program.

---

## Acceptance criteria

Fail the epic (do not ship) if any accepted path requires `/advisors`, a new listing family, `advisor` in `MARKETPLACE_LISTING_KINDS`, or a volunteer table.

1. A founder with `seeking:mentorship` and `business_stage:mvp` sees ranked advisors on `/marketplace?family=talent`, including Free (`price` 0).
2. That founder books a 1:1 into `booking_reservations`; overlapping reservations for the same slot are refused.
3. After booking, the founder lands in a restricted Brain thread plus a calendar event; the thread is not in `aiContext` unless invited.
4. The founder joins a future `one_to_many` slot from the same family; capacity is enforced.
5. The founder enrols in a stage-tagged `course` and installs the `mvp` pack.
6. Seat agents remain on the roster (unchanged advisor-vs-agent split).

**A0 gate:** Criteria 1–2 (bind + Book CTA + ranked Free-inclusive Talent + overlap-refusing reservation) must be measurable before A3–A5 implementation starts.

---

## Out of scope

- Volunteer, SBA, or chapter tables; US-only eligibility; SCORE branding, copy, or IA clone
- Adding `advisor` to `MARKETPLACE_LISTING_KINDS` or introducing a fifth marketplace family
- A sixth launch mode
- `/advisors` or `/webinars` pages
- In-person venue logistics
- New engagement/volunteer table when a relation can express continue-with-this-advisor
- Starting A3–A5 before A0 is measurable
- Putting restricted advisor threads into `aiContext` by default

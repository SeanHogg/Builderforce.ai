# PRD 29 — Verify and package run-visibility + ticket-parent (with PRD 27)

Chat #120. Coordinated packaging of already-written Change A and Change B with PRD 27 so a single VSIX ships both.

## Problem & Goal

Run-visibility and ticket-parent behavior are already written (composing tool-call stream, idle watchdog, triage context-pressure, rail names parent epic) but are not verified end-to-end or packaged with PRD 27 (staffed work + chat diagnostics). Operators still cannot trust a production VSIX that shows live composing, names the parent epic on the rail, and opens triage without CONTEXT EXHAUSTION.

**Goal:** Verify the existing Change A and Change B implementations against their suites, apply only mechanical fixes, then produce one installable VSIX at **2026.9.72** that carries PRD 27 + PRD 29. Report results; do not commit unless asked.

The tree has already drifted from the original PRD 29 version **2026.9.71** because PRD 27 also bumped the package version. The packaged artifact must report **2026.9.72**.

## Target users / ICP roles

- **Staffed operators** using the VS Code extension who need live run visibility (composing label, idle watchdog) and a parent-epic line on the ticket rail.
- **Downstream agents** on this task who share this PRD as the single source of verify-and-package order, fix policy, and acceptance.
- **Triage users** who must open chat/triage without a CONTEXT EXHAUSTION banner when context pressure is handled.

## Scope

In scope:

- Verify already-written **Change A (run-visibility):** composing tool-call stream, idle watchdog, triage context-pressure.
- Verify already-written **Change B (ticket-parent):** rail names parent epic.
- Coordinate with **PRD 27** (staffed work + chat diagnostics) so **one VSIX** carries both.
- Mechanical-only breakage repair during verify (imports, composing-phase exhaustive `Record`s, i18n catalog keys, stale test literals).
- Strict build order through brain-embedded → brain-ui → api → frontend → clients/vscode → VSIX install.
- Report every §3 suite result (pass, or named failure). Report real logic defects without patching them.
- Confirm packaged version **2026.9.72** via both list commands and a live install from an absolute VSIX path.

## Functional requirements

### Change A — Run visibility

1. **Composing tool-call stream.** While a run is composing, the UI surfaces a live composing label driven by the tool-call stream (not a stale idle or generic busy state).
2. **Idle watchdog.** An idle watchdog distinguishes true idle from in-flight composing so operators are not left on a silent/hung run with no composing signal.
3. **Triage context-pressure.** Triage/chat must not open with CONTEXT EXHAUSTION when context-pressure handling is in place; pressure is absorbed rather than dumped as a blocking banner.

### Change B — Ticket parent

4. **Rail names parent epic.** The ticket rail displays the parent epic name for the active ticket (not an orphaned or untitled parent line).

### Packaging with PRD 27

5. **Single VSIX.** Staffed-work + chat-diagnostics (PRD 27) and run-visibility + ticket-parent (this PRD) ship in one extension package.
6. **Version.** Packaged extension version is **2026.9.72**.

### Verify-and-package build order

Execute in this order; do not skip dist/typecheck gates:

1. **brain-embedded** — `pnpm test`, then `dist`.
2. **packages/brain-ui** — `pnpm test`, then `dist`.
3. **api** — `pnpm vitest run src/application/brain`, then typecheck from `api/`.
4. **frontend** — typecheck + i18n catalog guard; vitest brain components if present.
5. **clients/vscode** — type-check, test, production esbuild + tsc + webview, package.
6. **Install** the VSIX with an **absolute path** and confirm **2026.9.72**.

### Fix policy

- Fix **mechanical breakage only:** imports, composing-phase exhaustive `Record`s, catalog keys, stale test literals.
- **Do not** patch real logic defects — name and report them.
- **Leave concurrent dirt alone:** benchmarking, investor, identity, creation-canvas, ROADMAP.
- **Do not commit** unless explicitly asked; report results first.

## Acceptance criteria

- Every §3 suite passes, **or** each failure is named in the report.
- A VSIX file exists after the vscode package step.
- Both list commands report the packaged version **2026.9.72**.
- Live install from the absolute VSIX path succeeds at **2026.9.72**.
- Live **composing label** is visible during composing.
- **Parent line** on the rail names the parent epic.
- **Triage no longer opens with CONTEXT EXHAUSTION**.
- Only mechanical fixes were applied; logic defects (if any) are reported, not patched.
- Concurrent dirt (benchmarking, investor, identity, creation-canvas, ROADMAP) is untouched.
- No commit unless asked; results reported first.

## Out of scope

- Implementing Change A or Change B from scratch (they are already written).
- Patching real logic defects in run-visibility, idle watchdog, context-pressure, or parent-epic naming.
- Reverting or re-bumping version back to 2026.9.71.
- Touching concurrent worktrees or files: benchmarking, investor, identity, creation-canvas, ROADMAP.
- New product features beyond verify, mechanical repair, and packaging.
- Committing, publishing the marketplace listing, or shipping outside the local VSIX install confirmation.
- Expanding PRD 27 scope (staffed work + chat diagnostics) beyond carrying it in the same VSIX.

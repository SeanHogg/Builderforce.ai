# Product Requirements Document (PRD)

## Problem & Goal

### Problem
The current implementation of the platform lacks essential chat and public advisor profile functionalities, which are critical for facilitating communication between employers and freelancers and for showcasing freelancer profiles. This absence blocks the progress of multiple development tasks and hinders the user experience.

### Goal
Implement the missing chat primitive and public advisor profile surface to enable seamless communication and profile visibility for freelancers. This will unblock dependent tasks and enhance the overall user experience.

## Target Users / ICP Roles
- **Employers**: Users who need to communicate with freelancers and view their profiles to make informed hiring decisions.
- **Freelancers**: Users who need to have a public profile to attract potential employers and communicate with them.

## Scope

### In-Scope
1. **Chat Primitive**
   - Implement a messaging API (`messagingApi.ts`) to handle chat functionalities.
   - Integrate chat functionality with the `startEmployerConversation({ freelancerUserId })` method.
   - Ensure chat threads and counterparty functionalities are available.

2. **Public Advisor Profile Surface**
   - Create a `PublicProfileClient` component to display freelancer profiles.
   - Implement the `/u/[username]` route to serve freelancer profiles.
   - Ensure the profile surface is accessible and displays relevant freelancer information.

3. **Integration with Existing Components**
   - Integrate the chat and profile functionalities with the existing `signInHref` in `frontend/src/lib/auth.ts`.
   - Ensure that the MarketplacePageClient component can utilize the new chat and profile features.

4. **Resources Tab**
   - Update the Resources tab to utilize the new public profile surface.
   - Implement a seller-scoped parameter on the public listings endpoint to support the Resources tab.

## Functional Requirements

1. **Messaging API**
   - Develop `messagingApi.ts` with the following functionalities:
     - Initiate conversations between employers and freelancers.
     - Retrieve and display chat threads.
     - Handle counterparty information.

2. **Public Profile Component**
   - Develop `PublicProfileClient` with the following functionalities:
     - Display freelancer profile information (e.g., bio, skills, portfolio).
     - Fetch and display relevant data from the backend.

3. **Routing**
   - Implement the `/u/[username]` route to serve freelancer profiles.
   - Ensure routing is handled correctly and profiles are accessible via the URL.

4. **Integration with Existing Features**
   - Update `frontend/src/lib/messagingApi.ts` to include the new chat functionalities.
   - Update the Resources tab to utilize the new profile surface and seller-scoped parameter.

## Acceptance Criteria

1. **Chat Functionality**
   - Employers can initiate conversations with freelancers via the `startEmployerConversation` method.
   - Chat threads are displayed correctly and updated in real-time.
   - Counterparty information is accurately reflected in the chat interface.

2. **Public Profile Display**
   - Freelancer profiles are accessible via the `/u/[username]` route.
   - Profiles display accurate and up-to-date information.
   - The `PublicProfileClient` component renders correctly and is responsive.

3. **Integration**
   - The `signInHref` in `frontend/src/lib/auth.ts` correctly utilizes the new chat and profile features.
   - The MarketplacePageClient component can interact with the chat and profile functionalities without issues.

4. **Resources Tab**
   - The Resources tab displays freelancer profiles using the new profile surface.
   - The seller-scoped parameter on the public listings endpoint is functional and correctly filters listings.

## Out of Scope

- **Chat Notifications**: Implementing real-time notifications for new messages is not part of this release.
- **Advanced Profile Customization**: Features like custom profile themes or advanced editing tools for freelancer profiles are not included.
- **Chat History Persistence**: While chat threads will be displayed, persistent storage and history management are not covered in this implementation.
- **Security Enhancements**: Additional security measures for the chat and profile surfaces, such as end-to-end encryption or advanced access controls, are not in scope.

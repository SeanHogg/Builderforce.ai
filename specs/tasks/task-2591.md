# PRD: Unblock ticket 2555 — bind a readable checkout for the developer container

**Status:** WIP  
**Ticket:** #2555  
**Related:** PRD 29 verify-and-package; PRD 27 (#2562) VSIX package `2026.9.72`; same class of blocker as #2588  
**Repo / branch:** `SeanHogg/Builderforce.ai` on `builderforce/task-2555` (reported 1 commit ahead of `main`, no PR)

## Problem & Goal

The developer container reports `seanhogg/builderforce.ai` as bound on `builderforce/task-2555`, but `list_files`, `read_file`, `git_*`, and `run_command` all fail with `no repository bound to this task`. Without a readable, executable checkout, PRD 29 cannot run the Change A/B suites, apply mechanical-only fixes, or confirm the VSIX.

**Goal:** Bind `SeanHogg/Builderforce.ai` as `builderforce/task-2555` (or restore git credential delegation) so the next developer run can search the tree, execute the §3 suites in order, package, and report. Do not dump conceptual run-visibility code.

## Target users / ICP roles

- Downstream developer-container agents executing PRD 29 verify-and-package
- Product / platform operators unblocking checkout binding (same class as #2588)
- Maintainers of `SeanHogg/Builderforce.ai` who need a working workspace on `builderforce/task-2555`

## Scope

In scope:

- Make the reported bind real: a readable, writable git checkout of `SeanHogg/Builderforce.ai` at `builderforce/task-2555` available to this task
- Restore git credential delegation if that is the missing piece
- Confirm `list_files`, `read_file`, `git_*`, and `run_command` succeed against the checkout
- Leave the workspace ready for the existing Change A/B suite order and the single VSIX package at `2026.9.72` (PRD 27 / #2562)

Out of scope items are listed below. Binding is the unblock; suite execution and packaging are the *next* run’s job once the checkout is readable.

## Functional requirements

1. **Effective bind.** The task workspace is bound to `SeanHogg/Builderforce.ai` on branch `builderforce/task-2555`. The bind is not merely reported; file and git tools operate on that tree.
2. **Credential / delegation path.** If the reported bind is a ghost (status says bound, tools say unbound), restore git credential delegation or re-bind so the same identity can fetch, status, and (if needed) commit on that branch.
3. **Tool surface.** After bind:
   - `list_files` enumerates the repo root and nested packages
   - `read_file` returns file contents
   - `git_*` (status, log, diff, branch) run against the bound repo
   - `run_command` executes in the checkout working directory
4. **Branch fidelity.** Working tree is `builderforce/task-2555`, not a detached or default-branch checkout that would hide the existing +1 commit vs `main`.
5. **Handoff readiness.** After bind, a subsequent developer run can:
   - search the tree
   - run Change A/B suites in order: `brain-embedded` → `brain-ui` → `api` → `frontend` → `clients/vscode`
   - package one VSIX at version `2026.9.72` per PRD 27 (#2562)
   - report results
6. **Mechanical-only posture.** This ticket does not introduce conceptual run-visibility code, new product features, or non-mechanical refactors. Fixes, if any, are limited to making the checkout readable/bound.
7. **Parity with #2588.** Treat this as the same class of blocker: reported bind vs actual unbound tools. Prefer the known restore/bind path over a new binding subsystem.

## Acceptance criteria

- Developer-container status and tools agree: the task has a bound repository, and that repository is `SeanHogg/Builderforce.ai` at `builderforce/task-2555`.
- `list_files` on the repo root succeeds and shows the expected package layout (`brain-embedded`, `brain-ui`, `api`, `frontend`, `clients/vscode`, and related paths).
- `read_file` on a known file in the checkout returns content (not a bind error).
- `git status` (or equivalent `git_*`) succeeds, shows branch `builderforce/task-2555`, and is consistent with “1 commit ahead of `main`, no PR.”
- `run_command` (e.g. `pwd` / `git rev-parse --show-toplevel`) runs in the checkout and does not return `no repository bound to this task`.
- No conceptual run-visibility code is added or dumped as part of this unblock.
- The next developer run can start the PRD 29 §3 suite sequence and the `2026.9.72` VSIX package without first re-fighting bind/credential errors.

## Out of scope

- Implementing or dumping conceptual run-visibility code
- Opening a PR for `builderforce/task-2555` (none exists; not required to unblock)
- Running the Change A/B suites or producing the VSIX on *this* ticket except as an optional smoke that the bind is real
- Changing VSIX version away from `2026.9.72` or altering PRD 27 (#2562) packaging rules
- Reordering or rewriting the suite sequence (`brain-embedded` → `brain-ui` → `api` → `frontend` → `clients/vscode`)
- Non-mechanical product changes, new binding architecture, or unrelated repo work
- Fixing unrelated failures inside the suites once the checkout is readable (those belong to the PRD 29 verify-and-package run)

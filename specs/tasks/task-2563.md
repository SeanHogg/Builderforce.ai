# PRD: R1/R2 Type-Check and Touched Vitest Gate

## Problem & Goal

Type errors and test regressions in core packages (`api`, `packages/agent-tools`, `packages/agent-loop`, `brain-embedded`, `clients/vscode`) and touched frontend files currently leak into later review rounds. Downstream agents share no single definition of which type-checks and vitest suites must pass, which file is excluded, or how memory is constrained.

**Goal:** Establish a single, executable quality gate for R1/R2: type-check the listed packages and any touched frontend files; run vitest only for touched tests (excluding `clients/vscode/harness/scenarios.test.ts` in full); run Node with `NODE_OPTIONS=--max-old-space-size=8192`; fix real failures so the gate is green.

## Target users / ICP roles

- Downstream coding agents executing this WIP on the shared branch
- Reviewers (R1/R2) verifying type-check and test evidence
- Maintainers of `api`, agent packages, `brain-embedded`, VS Code client, and frontend surfaces

## Scope

- Type-check: `api`, `packages/agent-tools`, `packages/agent-loop`, `brain-embedded`, `clients/vscode`, and frontend files actually changed in this work
- Vitest: only suites covering touched code; do **not** run `clients/vscode/harness/scenarios.test.ts` in full
- Process: `NODE_OPTIONS=--max-old-space-size=8192` for type-check and vitest invocations
- Fixes: real type errors and real test failures caused by this change or blocking the gate
- Evidence: commands run, packages/files covered, pass/fail outcome, and a short list of fixes applied

## Functional requirements

1. **Type-check packages**
   - Run the repo’s existing type-check entrypoints (tsc / package scripts) for:
     - `api`
     - `packages/agent-tools`
     - `packages/agent-loop`
     - `brain-embedded`
     - `clients/vscode`
   - Type-check only frontend files that are touched (changed/added) in this task; do not type-check the entire frontend tree unless those files pull in a required project reference.

2. **Vitest (touched only)**
   - Discover and run vitest files that correspond to touched source (co-located `*.test.ts` / `*.spec.ts` and clearly related suites).
   - Do not execute `clients/vscode/harness/scenarios.test.ts` as a full suite.
   - Prefer targeted vitest filters (`-t`, file path args) over workspace-wide `vitest` / `vitest run`.

3. **Memory**
   - Export or prefix all type-check and vitest Node processes with `NODE_OPTIONS=--max-old-space-size=8192`.

4. **Fix real failures**
   - Fix genuine type errors (incorrect types, missing exports, broken imports, `any`/`unknown` misuse that fails `strict` checks).
   - Fix genuine test failures (wrong assertions, broken mocks, API drift).
   - Do not “fix” by deleting tests, weakening assertions, `as any` / `@ts-ignore` / `@ts-expect-error` without a one-line justification, or skipping tests except the explicit scenarios exclusion above.
   - Do not change product behavior except as required to make types and tests correct.

5. **Reporting for downstream agents**
   - Record: commands, NODE_OPTIONS, packages/files type-checked, vitest files run, failures found, and patches applied.

## Acceptance criteria

- [ ] `api`, `packages/agent-tools`, `packages/agent-loop`, `brain-embedded`, and `clients/vscode` type-check with zero errors.
- [ ] Touched frontend files type-check with zero errors.
- [ ] Touched vitest suites pass.
- [ ] `clients/vscode/harness/scenarios.test.ts` was not run in full.
- [ ] Type-check and vitest ran with `NODE_OPTIONS=--max-old-space-size=8192`.
- [ ] Remaining failures are absent; any skipped item is only the scenarios file exclusion.
- [ ] Fixes address root causes (types/tests), not suppressions or deleted coverage.
- [ ] WIP notes list commands and outcomes so the next agent does not re-run the full scenarios harness or unbounded vitest.

## Out of scope

- Full `clients/vscode/harness/scenarios.test.ts` run (and expanding that harness)
- Untouched frontend trees, unrelated packages, and repo-wide `vitest` / CI
- New features, refactors, dependency upgrades, or format-only churn not required to clear the gate
- E2E, Playwright, integration, or VS Code extension host tests beyond touched vitest
- Performance tuning beyond the 8192 MB heap cap
- Changing tsconfig strictness, vitest config, or CI matrix unless a config bug is the real failure
- Flaky-test quarantines, snapshot re-goldens without a real contract change, and test skips other than the scenarios exclusion

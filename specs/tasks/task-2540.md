# PRD: Preserve three-section Markdown contract on meeting end

## Problem & Goal

`summarizeMeeting` already runs when a meeting ends. Downstream `parseMeetingMinutes` depends on a single, stable three-section Markdown shape. Any extra heading, reordered section, free-form body, or alternate template would force a second parse path.

**Goal:** Keep the existing end-of-meeting summary pipeline, and lock the output to the three-section Markdown contract so `parseMeetingMinutes` stays one implementation.

## Target users / ICP roles

- Meeting participants who receive minutes after the call
- Product and engineering agents that consume parsed minutes (decisions, owners, due dates)
- Support / ops staff who debug failed minute parses

## Scope

In scope:

- End-of-meeting invocation of the existing `summarizeMeeting` path only
- Output Markdown that always contains exactly three top-level sections, in fixed order
- Compatibility with the current `parseMeetingMinutes` contract (no parser fork, no dual-format detection)
- Empty-section handling that still emits the three headings so the parser can bind fields

Out of product surface: no new meeting UI, no new summary triggers, no new minute types.

## Functional requirements

1. **Trigger (unchanged):** On meeting end, call `summarizeMeeting`. Do not add a parallel summarizer or a minutes-only code path.
2. **Document shape:** `summarizeMeeting` must return GitHub-flavored Markdown whose body is exactly these H2 sections, in this order:
   1. `## Summary`
   2. `## Decisions`
   3. `## Action items`
3. **Section semantics:**
   - **Summary:** 2–6 sentences covering purpose, outcome, and unresolved threads. No nested headings.
   - **Decisions:** Bullet list of decided items. Each bullet is one decision. If none, a single bullet `- None`.
   - **Action items:** Bullet list. Each bullet MUST match `- [ ] <task> — <owner> — <due>` where `<due>` is `YYYY-MM-DD` or `TBD`. If none, a single bullet `- None`.
4. **Heading stability:** Use those exact H2 strings (spelling, capitalization, no trailing punctuation, no H1/H3 substitutes). No other H2/H1 headings in the document.
5. **Allowed Markdown inside sections:** Paragraphs and `-` / `*` unordered lists only. No tables, no code fences, no HTML, no nested lists, no extra `#` headings.
6. **Parser compatibility:** `parseMeetingMinutes` continues to split on the three H2 headings, map bullets under Decisions and Action items, and ignore nothing else because nothing else is present.
7. **Failure mode:** If summarization fails, do not emit a free-form fallback. Emit the three headings with `- None` under Decisions and Action items, and a one-line Summary stating that minutes could not be generated. Still valid for the single parser.

## Acceptance criteria

- Meeting end still invokes `summarizeMeeting` only; no second summarizer and no `parseMeetingMinutes` format switch.
- Every successful and failed summary document contains exactly three H2 headings: `## Summary`, `## Decisions`, `## Action items`, in that order, and no other headings.
- `parseMeetingMinutes` can extract summary text, decision bullets, and action-item bullets (task, owner, due) from that document without a format discriminator or legacy branch.
- Empty meetings still parse: Decisions and Action items each contain `- None`; Summary is non-empty.
- Action-item bullets that are not `- None` match `- [ ] <task> — <owner> — <due>`.
- Changing copy inside sections (wording, number of bullets) does not require parser changes, as long as headings and action-item bullet grammar hold.

## Out of scope

- Changing when `summarizeMeeting` runs (mid-meeting, manual rerun, scheduled backfill)
- New sections (Attendees, Transcript, Risks, Parking lot) or reordering the three sections
- Rich action-item metadata (priority, links, issue IDs) beyond task / owner / due
- Forking or versioning `parseMeetingMinutes` for alternate templates
- Transcript storage, recording, or speaker diarization
- Localization of heading labels
- Email / Slack / calendar delivery of minutes (consume the same Markdown; do not wrap it in another template)

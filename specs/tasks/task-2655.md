# Product Requirements Document (PRD)

## 1. Problem & Goal

### 1.1 Problem
The current wording in task #2561 asserts the use of version **2026.9.79** for the VSIX installation, which contradicts the authoritative pin specified in PRD 29 / #2624, which mandates the use of **2026.9.72**. This discrepancy creates a misalignment in the expected behavior and outcomes of the installation process.

### 1.2 Goal
Realign the wording in task #2561 to accurately reflect the use of version **2026.9.72** as the pinned version for the VSIX installation, ensuring consistency with PRD 29 / #2624 and maintaining the integrity of the installation process.

## 2. Target Users / ICP Roles

- **Developers:** Responsible for implementing and verifying the installation process.
- **QA Engineers:** Responsible for validating the installation process against the specified version.
- **Product Managers:** Responsible for ensuring alignment with product requirements and specifications.

## 3. Scope

### 3.1 In-Scope
- Update the title and description of task #2561 to assert version **2026.9.72**.
- Ensure the VSIX installation uses the basename `builderforce-ai-2026.9.72.vsix`.
- Update the dual-verify folder to `builderforce.builderforce-ai-2026.9.72`.
- Maintain the 72-vs-79 packaging gap attributed to #2560.
- Ensure lockstep with #2562 / PRD 27, which is also at version 2026.9.72.

### 3.2 Out-of-Scope
- Moving the pin to version **2026.9.79** without explicit operator confirmation on #2624 / PRD 29.
- Resolving the discrepancy by altering the pin in #2624 to version 79.
- Any changes to #2560, #2562, or PRD 27 unless explicitly required by this realignment.

## 4. Functional Requirements

### 4.1 Update Task #2561
- **Title:** Update to reflect the use of version **2026.9.72**.
- **Description:** Modify to assert the installation of `builderforce.builderforce-ai@2026.9.72` using the basename `builderforce-ai-2026.9.72.vsix` and the dual-verify folder `builderforce.builderforce-ai-2026.9.72`.

### 4.2 Maintain Packaging Gap
- Ensure that the 72-vs-79 packaging gap is maintained and attributed to #2560.
- No fallback installation of version 79 should be performed.

### 4.3 Lockstep with PRD 27 / #2562
- Ensure that the installation process remains in lockstep with PRD 27 / #2562, which is also pinned at version 2026.9.72.

## 5. Acceptance Criteria

- The title and description of task #2561 accurately reflect the use of version **2026.9.72**.
- The VSIX installation uses the basename `builderforce-ai-2026.9.72.vsix`.
- The dual-verify folder is set to `builderforce.builderforce-ai-2026.9.72`.
- The 72-vs-79 packaging gap is maintained and attributed to #2560.
- The installation process is in lockstep with PRD 27 / #2562, both pinned at version 2026.9.72.
- No changes are made to #2624's pin to version 79 without explicit operator confirmation on #2624 / PRD 29.

## 6. Out of Scope

- Altering the pin in #2624 to version 79 without proper confirmation.
- Making changes to #2560, #2562, or PRD 27 unless directly related to the realignment of #2561.
- Implementing any fallback installation of version 79.

# PRD: Guided Marketing Campaign Journey

**Status:** WIP  
**Epic:** Prompt-to-campaign founder journey  
**Principle:** Compose existing Growth, Canvas, and agent primitives. Do not clone HubSpot. Do not rebuild campaign engines.

---

## Problem & Goal

Builderforce already ships campaign *engines*: Growth email/SMS (draft → schedule → send, suppression, unsubscribe, sent/opened/clicked), Canvas objects (emailCampaign, emailTemplate, audience, brandKit, socialCampaign, ads connect/launch/insights), and agent tools (`campaign.*`, `social_campaign.*`, `ads.*`, `mailbox.*`, templates/assets). Intent `"connect my email and run a marketing campaign"` is a real canvas instruction.

What is missing is the **founder journey**. A user who types “I want to run a marketing campaign” is not walked from context to live campaign. Intake for business / vertical / ICP has no frontend (`ri_icps` is API-only and is not a send gate). Prerequisites stop at operational send blockers. Copy is not guided against brand voice / doNotSay. Prompt catalog lists campaigns (`marketing.campaigns.list`) instead of running one. ROI is not campaign-attributed: opens/clicks and `/api/roi/rollup` are insufficient; CMO review already flagged this in `canvasRunComparison.ts`.

**Goal:** A signed-in user can type “I want to run a marketing campaign” and be walked through **context → checklist → connect → draft copy → human-confirmed send → track including campaign ROI**. Anonymous canvas may author, never send. Cloud/autonomous agents remain draft-only (no send, publish, or spend).

---

## Target users / ICP roles

- **Primary:** Signed-in founders and operators who know they want a campaign, not a marketing suite. They have a product, an offer, and (often incomplete) brand, audience, and channel accounts.
- **Secondary:** Operators who already use Growth and Canvas objects and need a single guided path instead of assembling mailboxes, audiences, templates, and ads by hand.
- **Not v1:** Agency CMOs, multi-brand marketing orgs, or users expecting HubSpot-class nurture / A/B / heatmap consoles.

---

## Scope

In scope for v1: an orchestrated **guided campaign run** that sits on top of existing engines.

1. **Prompt entry** — Natural-language start (“I want to run a marketing campaign” and close variants) launches the journey instead of a campaigns table.
2. **Context intake** — Capture business, vertical, ICP, offer, goal, and channel preference. Surface `ri_icps` in the UI for selection/creation; ICP is **not** a campaign gate.
3. **Prerequisite checklist** — Brand kit (voice + doNotSay), consenting audience, sender/account for the chosen channel, offer, and copy. Distinct from Growth’s operational send blockers (suppression, unsubscribe, transport health).
4. **Guided connect** — Reuse mailbox, SendGrid, Twilio, social, and ads connect flows already in Growth/Canvas. Do not invent new transports.
5. **Draft copy** — Generate/edit campaign copy against brand voice and doNotSay; persist as existing emailTemplate / campaign / socialCampaign drafts.
6. **Human-confirmed send** — Signed-in user must explicitly confirm before send, schedule, publish, or ad spend. Reuse Growth draft → schedule → send and Canvas send-readiness (live audience consent).
7. **Track including ROI** — Per-campaign attribution of spend and/or pipeline/revenue. Opens/clicks remain secondary counters, not the ROI metric.
8. **Safety rails** — Anonymous canvas: author only. Cloud agents: draft-only (no send/publish/spend).

Compose: Growth `/growth` campaigns and transports, Canvas campaign/template/audience/brandKit/social/ads objects, existing agent tools, existing send-readiness and suppression.

---

## Functional requirements

### 1. Prompt-driven entry

- Recognize campaign-run intent from the canvas/prompt surface, including “I want to run a marketing campaign” and “connect my email and run a marketing campaign.”
- Start the guided journey; do **not** route to `marketing.campaigns.list` as the primary response.
- If an in-progress guided run exists for the workspace, resume it; otherwise create a new run bound to existing campaign primitives (do not fork a parallel campaign store).

### 2. Context intake

- Collect, in a short guided flow (chat + structured fields): business name/description, vertical, ICP, offer, campaign goal (e.g. demand, launch, reactivation), and channel (email, SMS, social, ads — one or more).
- ICP: list/create/select via `ri_icps`. Missing ICP must not block drafting or sending.
- Persist context on the campaign run so later copy, checklist, and ROI stay consistent.
- Prefill from brandKit, audiences, and any existing workspace profile when present.

### 3. Prerequisite checklist

Show a single checklist, always visible during the run, covering:

| Prerequisite | Ready when |
|---|---|
| Brand | brandKit present with voice and doNotSay |
| Audience | live audience with consent / send-readiness (Canvas existing rule) |
| Sender / account | mailbox or SendGrid (email), Twilio (SMS), connected social/ads account as required by chosen channel |
| Offer | explicit offer/CTA captured in intake |
| Copy | at least one draft that passed brand-voice / doNotSay check |

- Operational Growth blockers (suppression, unsubscribe, transport errors) remain enforced at send time; they are **not** a substitute for this checklist.
- Each item deep-links into the existing Growth/Canvas surface that fulfills it (brand, audience, mailbox connect, ads connect). Do not rebuild those UIs.
- Checklist is advisory for drafting; **send/schedule/publish/spend** requires all channel-relevant items plus human confirm.

### 4. Guided connect

- Channel-specific connect steps reuse existing mailbox, platform, SendGrid, Twilio, social, and ads connect/launch panels.
- After connect, re-evaluate send-readiness from live audience consent and account status.
- Do not auto-send or auto-spend on successful connect.

### 5. Draft copy against brand

- Generate draft copy (subject, body, SMS, social, ad primary text as applicable) using intake context + brandKit voice + doNotSay.
- Flag or rewrite phrases that violate doNotSay before the draft is marked checklist-ready.
- User can edit freely; regeneration stays in draft.
- Persist via existing `emailTemplate` / campaign / `socialCampaign` / ads creative objects and existing `campaign.create` / `social_campaign.*` / template tools.
- Cloud agents may draft and revise only.

### 6. Human-confirmed send

- Signed-in user sees a confirmation step: channel, audience size/consent summary, sender, schedule vs send-now, copy preview, and (for ads) budget/spend.
- Confirm is an explicit human action. No implicit send on “looks good” chat assent without a confirm control.
- On confirm: call existing `campaign.send` / `campaign.schedule` / social publish / ads launch — no new send pipeline.
- Anonymous users can complete intake, checklist (where possible), connect UX (read-only if auth required), and copy drafts. Send, schedule, publish, and spend controls are disabled with a sign-in prompt.
- Autonomous/cloud agents cannot invoke send, publish, or spend. Tools that do so remain user-gated.

### 7. Track including campaign ROI

- After send/launch, the run’s tracking view shows:
  - Existing counters: sent, opened, clicked (email/SMS); ads spend, clicks, conversions where the ads panel already provides them.
  - **Campaign ROI (required, new):** spend and/or pipeline/revenue **attributed to this campaign run**, not workspace-level `/api/roi/rollup`, and not opens/clicks presented as ROI.
- Attribution may use existing pipeline/revenue events plus campaign/ad identifiers already on send and ads launch; do not block v1 on BurnRateOS CMO tables.
- ROI is visible on the guided run and on the campaign object it composed. `canvasRunComparison.ts` failure mode (comparing runs without campaign-level ROI) is ineligible as the v1 answer.

### 8. Prompt catalog / continuation

- Catalog and agent entry points that previously only listed campaigns must offer **Run a campaign** (this journey) as the default action for campaign-run intent.
- Listing existing campaigns is a secondary action (resume, duplicate as draft, inspect ROI), not the fulfillment of “run a marketing campaign.”

---

## Acceptance criteria

1. A **signed-in** user types “I want to run a marketing campaign” and is taken through **context → checklist → connect → draft copy → human-confirmed send → track including ROI** without being dumped on a campaigns table.
2. Context intake records business, vertical, ICP (optional), offer, goal, and channel. `ri_icps` is usable in the frontend. Empty ICP does not block the run.
3. Checklist includes brand (voice + doNotSay), consent audience, sender/account, offer, and copy — not only Growth operational send blockers.
4. Connect steps reuse Growth/Canvas transports and ads connect; successful connect does not send or spend.
5. Draft copy is generated and editable against brand voice / doNotSay and stored on existing campaign/template/social/ads objects.
6. Send, schedule, publish, and ad spend occur only after an explicit confirm by a signed-in human, using existing send/launch tools.
7. **Anonymous** canvas can author drafts end-to-end and cannot send, schedule, publish, or spend.
8. **Cloud/autonomous agents** can create and edit drafts only; they cannot send, publish, or spend.
9. Post-send tracking shows campaign-attributed spend and/or pipeline/revenue for that run. Opens/clicks and `/api/roi/rollup` alone do not satisfy this criterion.
10. No new HubSpot-style campaign product, no duplicate campaign engine, no new email/SMS/ads transport.

---

## Out of scope

- Porting remaining BurnRateOS CMO tables (heatmaps, nurture, A/B) as a v1 dependency.
- Cloning HubSpot (workflows, attribution models beyond this campaign run, multi-touch reporting suites, marketing automation canvas).
- Rebuilding Growth `/growth` campaigns, mailboxes, audiences, senders, templates, transports, or Canvas email/social/ads objects.
- Making ICP (`ri_icps`) a send gate.
- Treating opens/clicks or `/api/roi/rollup` as campaign ROI.
- Agent- or anonymous-initiated send, publish, or spend.
- New ESP/SMS/ad network integrations.
- Multi-brand, agency, or approval-hierarchy features.

# PRD 28 — Creation Canvas one-composer and phone chrome (remainder)

**Status:** WIP remainder. One-composer and phone chrome already landed uncommitted on frontend `2026.9.34`. This PRD is the shared contract for verification, phone tests, VS Code host chrome, decision ratification, and an honest DONE.

**Primary spec path:** `Builderforce.ai/specs/builderforce/28-prd-canvas-one-composer-phone-chrome.md`

## Problem & Goal

Uncommitted canvas work shipped a single composer and phone app-bar chrome, but DONE.md cannot be honest until the frontend GATE is green, phone behavior is locked in CI, and a narrow VS Code editor webview does not impersonate a phone.

**Goal:** Close PRD 28 with (1) a green GATE and recorded CreationCanvas hooks-ratchet numbers, (2) shared jsdom `matchMedia` plus behavioural vitest and Playwright coverage of phone chrome, (3) host-aware phone detection so a ≤767px VS Code editor panel keeps desktop chrome, and (4) yes/reversal on the four implementer decisions. ROADMAP gap closed only after those four are done.

## Target users / ICP roles

- **Builders** on Creation Canvas: phone (thumb chrome, one sheet stack, one composer) and desktop.
- **VS Code extension users:** webview in a ~500px side editor; must keep desktop canvas chrome.
- **Downstream agents / CI:** GATE, vitest, Playwright, extension rebuild; no product invention beyond this remainder.

### §2 Shared matchMedia helper and phone tests

- One **shared** `matchMedia` helper for jsdom (not per-file mocks) so `usePhoneViewport` can be `true` in unit tests.
- Behavioural tests at phone width:
  - App bar: **back / title / stage / roster / •••**
  - Exactly **one** board-menu sheet
  - **+** sheet lists **every** registry action in **arc order**
  - Brain sheet **open** arms ask; **close** restores default composer
  - Unread count only while Brain sheet is **closed**
- Playwright: extend `qa-e2e/tests/creation-canvas.spec.ts` at **390×844** and **desktop**, **both** `bf-theme` values, plus a **360px** width floor.

### §3 VS Code host chrome

- A **500px editor panel must not** get the phone app bar.
- `usePhoneViewport` and CSS `@media 767` must consider **HOST** (`hostSurfaces`), not viewport width alone. Phone chrome is for a phone host, not a skinny desktop/webview.
- Rebuild the webview, type-check, bump the extension version.

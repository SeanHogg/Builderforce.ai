# PRD: Render `%` in brain-ui chat switcher/dropdown

**Status:** WIP  
**Type:** Bugfix / display correctness  
**Surface:** brain-ui chat switcher and chat dropdown

## Problem & Goal

**Problem.** The brain-ui chat switcher and chat dropdown do not surface linked-ticket completion. Epic #2436 (“Add % complete to VSIX chat lists”) requires every chat-list surface to show the same batched `progressPct` already computed by `ChatTicketService` (the same number the in-chat header widget uses). Without it, users scanning chats in brain-ui cannot tell which conversations are furthest along, and the switcher will diverge from the VS Code sessions tree (#2439).

A prior draft of this PRD misread the ticket title “Render `%`” as a display bug for the U+0025 character in chat *titles*. That is not the defect. Literal `%` in titles must still render as `%` (non-regression), but the work is to **render the progress percentage**, not to fix title encoding.

**Goal.** When a listed chat carries `progressPct` (0–100), the switcher trigger and every dropdown row show that value as ` · {n}%` next to the chat title, matching epic AC and the sessions-tree format. When `progressPct` is omitted or null (no linked tickets), no indicator is shown. Titles that themselves contain `%` remain character-for-character identical.

## Scope

In scope: visual rendering of **ticket-linked `progressPct`** on brain-ui **chat switcher** (collapsed trigger) and **chat dropdown** (open list) only.

Includes:

- Primary chat title plus optional ` · {n}%` suffix when `progressPct` is a number
- Selected, hover, focus, disabled, and overflow/ellipsis states of both trigger and rows
- Keyboard and pointer open/close of the switcher/dropdown
- Empty, short, and long titles, including titles that themselves contain one or more `%` characters
- Accessible name / `aria-label` / tooltip including the percent when present
- Consuming `progressPct` from the existing chat-list payload (`BfBrainChat`); no per-row ticket fetch
- Non-regression: U+0025 in titles, previews, and labels still paints as the character `%`

Sibling tickets (do **not** re-implement here):

- #2437 — API `GET /api/brain/chats` batches `progressPct` via `ChatTicketService`
- #2438 — `progressPct?: number` on `BfBrainChat` in `bfApi.ts`
- #2439 — same suffix on VS Code `sessionsTree.ts` `item.description`
- #2441 — live refresh when ticket health changes after the list was fetched

## Functional requirements

1. **Progress indicator.** If `chat.progressPct` is a finite number in `[0, 100]`, append ` · {n}%` (space, U+00B7 MIDDLE DOT, space, integer, percent sign) to the visible title on both the collapsed trigger and each dropdown row. `{n}` is `Math.round(progressPct)` clamped to 0–100.
2. **Absence vs zero.** If `progressPct` is `undefined`, `null`, or non-finite, omit the indicator entirely. Do **not** show ` · 0%`, ` · —`, or a placeholder. A numeric `0` **does** show ` · 0%` — that means linked tickets exist and none are done.
3. **Canonical format.** The suffix must match epic #2436 AC and sibling #2439: ` · 85%`, not `(85%)`, `85 percent`, a progress bar, or a colored chip.
4. **Literal `%` in titles (non-regression).** Chat titles, previews, and secondary labels that contain U+0025 must still render as `%`. Titles must not be passed through printf-style, i18n, or template formatters that consume `%`. A title `Q4 12% growth` with `progressPct: 40` shows `Q4 12% growth · 40%`.
5. **No interpolation.** The suffix is concatenated after the canonical title. Do not format the title with `%s` / `%d` / i18n `%{n}`.
6. **Overflow.** Long titles plus the suffix ellipsize with the same rules as titles without progress. Prefer clipping the title, not dropping the `%` glyph of the suffix or of a title that contains `%`.
7. **Selection & filter.** If the dropdown filters or highlights, matching is against the **title** (and existing search fields). `progressPct` is not a search wildcard. A query `%` matches titles containing `%`, not “any progress”.
8. **Accessibility.** Accessible name includes the title and, when progress is shown, a spoken form such as “, 85% complete”. Do not rely on the MIDDLE DOT alone for AT.
9. **Stability.** Presence or absence of `progressPct`, or of `%` in the title, must not crash the menu, blank the trigger, or skip the row.
10. **Parity.** Trigger and open list both show the same title + suffix for the current chat. The number shown is the list payload’s `progressPct`, not a second client-side computation.
11. **No extra I/O.** The switcher must not call ticket-health or `ChatTicketService` per row. It reads `progressPct` already on the chat DTO.
12. **Unchanged chats.** Chats without linked tickets (no `progressPct`) look unchanged versus today.

## Acceptance criteria

- A chat with title `Sprint board` and `progressPct: 85` shows `Sprint board · 85%` on the switcher trigger and in every dropdown row state (default, hover, selected, truncated).
- A chat with no `progressPct` (or `null`) shows only its title — no ` · 0%`, no dash, no extra separator.
- A chat with `progressPct: 0` shows ` · 0%`; a chat with `progressPct: 100` shows ` · 100%`.
- Titles `%`, `%%`, `%s`, `100%`, `foo%bar`, `%20`, `complete%`, and `Q4 12% growth` still render character-for-character; when `progressPct` is also set, the suffix is appended after the full title.
- Switching to a chat that has `progressPct` updates the trigger to that title + ` · {n}%` (modulo the same ellipsis rules as other titles).
- Filtering the dropdown by a substring of the title (including a substring that is `%`) still returns and labels the matching chats; the progress suffix is not required to be part of the query.
- Screen reader name for the row matches the visible title and includes the percent when present (e.g. “Sprint board, 85% complete”).
- No JS exception, blank row, extra network request per row, or layout jump unique to `progressPct` or to `%` in the title.
- Visual snapshot or equivalent covers at least: `progressPct: 85`, `progressPct: 0`, omitted `progressPct`, title `100%` with `progressPct: 50`, title `%s` with no progress, and a long title with `%` near the ellipsis boundary.
- Chats without `%` in the title and without `progressPct` are visually unchanged.

## Out of scope

- Renaming chats, persistence, or backend title validation
- Chat transcript / message body rendering
- Other brain-ui surfaces (sidebars, search results, share dialogs, tabs) unless they reuse this same switcher/dropdown component
- Changing search wildcard semantics product-wide
- Localization of the `%` character or percent-number formatting
- New visual design for the switcher/dropdown
- Encoding fixes for other special characters except insofar as a shared escaping path is required to make `%` correct without regressions

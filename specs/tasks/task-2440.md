# PRD: Render `%` in brain-ui chat switcher/dropdown

**Status:** WIP  
**Type:** Bugfix / display correctness  
**Surface:** brain-ui chat switcher and chat dropdown

## Problem & Goal

**Problem.** The brain-ui chat switcher and chat dropdown do not surface linked-ticket completion. Epic #2436 (“Add % complete to VSIX chat lists”) requires every chat-list surface to show the same batched `progressPct` already computed by `ChatTicketService` (the same number the in-chat header widget uses). Without it, users scanning chats in brain-ui cannot tell which conversations are furthest along, and the switcher will diverge from the VS Code sessions tree (#2439).

A prior draft of this PRD misread the ticket title “Render `%`” as a display bug for the U+0025 character in chat *titles*. That is not the defect. Literal `%` in titles must still render as `%` (non-regression), but the work is to **render the progress percentage**, not to fix title encoding.

**Goal.** When a listed chat carries `progressPct` (0–100), the switcher trigger and every dropdown row show that value as ` · {n}%` next to the chat title, matching epic AC and the sessions-tree format. When `progressPct` is omitted or null (no linked tickets), no indicator is shown. Titles that themselves contain `%` remain character-for-character identical.

- Power users scanning many chats to pick the one furthest along.

## Scope

In scope: visual rendering of chat identity strings in brain-ui **chat switcher** and **chat dropdown** only.

Includes:

- Primary chat title / name
- Secondary line if present (preview, timestamp, metadata) when it can contain `%`
- Selected, hover, focus, disabled, and overflow/ellipsis states
- Keyboard and pointer open/close of the switcher/dropdown
- Empty, very short, and long titles that include one or more `%` characters
- Leading, trailing, consecutive, and only-`%` titles (e.g. `%`, `100%`, `% complete`, `foo%bar`, `%%`, `%s`)

## Functional requirements

1. **Literal `%`.** The switcher and dropdown must render U+0025 PERCENT SIGN as the character `%`, not as a format specifier, URL encoding residue, or HTML/template escape.
2. **Round-trip fidelity.** The label shown for a chat must equal the chat’s canonical title string for all Unicode including `%`. No encode/decode pass may change visible text.
3. **No interpolation.** Titles must not be passed through printf-style, i18n, or template formatters that consume `%`.
4. **Overflow.** Long titles containing `%` ellipsize the same way as titles without `%`. `%` must not be the character that disappears incorrectly or breaks layout measurement.
5. **Selection & search-in-list.** If the dropdown filters or highlights matches, queries and highlights must work when the title contains `%` (`%` is not a wildcard unless product search already defines it that way; default is literal).
6. **Accessibility.** Accessible name / `aria-label` / tooltip for each row must include the same title string, including `%`.
7. **Stability.** Presence of `%` must not crash the menu, blank the trigger, or skip the row.
8. **Parity.** Trigger (collapsed switcher) and open list both show `%` correctly for the current and listed chats.

## Acceptance criteria

- A chat titled `Q4 12% growth` shows exactly `Q4 12% growth` on the switcher trigger and in every dropdown row state (default, hover, selected, truncated).
- Titles `%`, `%%`, `%s`, `100%`, `foo%bar`, `%20`, and `complete%` each render character-for-character with no extra escapes or missing glyphs.
- Switching to a `%`-titled chat updates the trigger label to that full title (modulo the same ellipsis rules used for other titles).
- Filtering the dropdown by a substring that includes `%` (if filter exists) returns and labels the matching chats correctly.
- Screen reader name for the row matches the visible title, including `%`.
- No JS exception, blank row, or layout jump unique to `%` in title.
- Visual snapshot or equivalent check covers at least: `100%`, `%s`, and a long title with `%` near the ellipsis boundary.
- Existing titles without `%` are unchanged.

## Out of scope

- Renaming chats, persistence, or backend title validation
- Chat transcript / message body rendering
- Other brain-ui surfaces (sidebars, search results, share dialogs, tabs) unless they reuse this same switcher/dropdown component
- Changing search wildcard semantics product-wide
- Localization of the `%` character or percent-number formatting
- New visual design for the switcher/dropdown
- Encoding fixes for other special characters except insofar as a shared escaping path is required to make `%` correct without regressions

# PRD: Campaign ROI remains `unknown` until this-run spend and/or attributed pipeline/revenue exist

## Problem & Goal

**Problem.** Campaign ROI is sometimes shown as a numeric value before a run has spend and/or attributed pipeline/revenue. Engagement signals (opens, clicks) and `/api/roi/rollup` have been treated as sufficient to “fill in” ROI. That produces false certainty, mixes runs, and misleads operators on whether a campaign actually paid back.

**Goal.** For a given campaign **run**, ROI is `unknown` until spend and/or attributed pipeline/revenue exist **for that run**. Opens, clicks, and `/api/roi/rollup` must never promote ROI from `unknown` to a number.

## Target users / ICP roles

- Growth / demand-gen operators reviewing campaign performance
- RevOps / marketing ops owners of attribution and spend
- Finance / FP&A consumers of campaign payback
- Downstream agents and UIs that render campaign ROI for a run

## Scope

In scope for **this campaign run only**:

- ROI state model: `unknown` vs numeric
- Inputs that may create a numeric ROI: this-run spend and this-run attributed pipeline/revenue
- Explicit exclusion of opens, clicks, and `/api/roi/rollup` as ROI inputs or promotion paths
- Display, API, and any shared rollup/aggregation that surfaces campaign ROI for a run
- Persistence so a later run cannot inherit a number from engagement or from another run’s rollup

## Functional requirements

1. **Default state.** Campaign ROI for a run is `unknown` until qualifying this-run financial data exists.
2. **Qualifying inputs (this run only).** A numeric ROI may be computed only when at least one of the following is present for **this run**:
   - spend
   - attributed pipeline
   - attributed revenue
3. **Promotion rule.** Absence of those inputs keeps ROI `unknown`. Partial engagement data does not change state.
4. **Forbidden inputs.** Opens, clicks, and any payload or derived metric from `/api/roi/rollup` must be ignored for ROI. They must never:
   - set ROI to a number
   - replace `unknown`
   - be used as a proxy, fallback, or imputed spend/pipeline/revenue
5. **Run isolation.** Spend, pipeline, and revenue from other runs, lifetime campaign totals, or rollup endpoints must not be used to compute this run’s ROI.
6. **Zero vs unknown.** A true this-run spend of `0` with this-run attributed pipeline/revenue may yield a defined numeric ROI (including `0` or infinite/undefined-by-policy only if explicitly derived from those financials). Missing spend **and** missing attributed pipeline/revenue remains `unknown`, not `0`.
7. **Surfaces.** All consumers (UI, exports, agent context, campaign detail, lists) must show `unknown` (not `0`, `N/A` as a number, or a fabricated percentage) until the promotion rule is met.
8. **No silent coercion.** Parsing, serialization, and charts must not coerce `unknown` to `0`, `null` displayed as `0%`, or a rollup-derived figure.

## Acceptance criteria

- Given a run with no this-run spend and no this-run attributed pipeline/revenue, ROI is `unknown` even if opens, clicks, or `/api/roi/rollup` return values.
- Given opens/clicks only, ROI stays `unknown` and is never a number.
- Calling or consuming `/api/roi/rollup` does not change this run’s ROI from `unknown` to a number.
- Given this-run spend and/or this-run attributed pipeline/revenue, ROI may become a number derived only from those fields.
- A run that later receives spend and/or attributed pipeline/revenue promotes from `unknown` to numeric using only this-run financials.
- Removing or never receiving those financials leaves or returns ROI to `unknown`; engagement and rollup still cannot fill the gap.
- UI, API, and downstream agent shared state agree: no surface shows a numeric ROI when the run is `unknown`.
- Automated tests cover: engagement-only, rollup-only, other-run financials, missing financials, and valid this-run financials.

## Out of scope

- Changing how opens, clicks, or `/api/roi/rollup` work for non-ROI metrics
- Multi-touch attribution model redesign
- Spend ingestion, CRM attribution, or pipeline/revenue calculation quality
- Cross-campaign or company-level ROI
- Historical backfill of ROI for runs that already have this-run financials
- Localization/formatting of the `unknown` label beyond not rendering a number

### Locked decisions

1. **Named accessor is `campaignRoi`.** Pure function. `guidedCampaignRun` (C1) MUST set `view.roi` from `campaignRoi(...)` only. Adapter `frontend/src/lib/canvasMarketing.ts` MUST NOT recompute ROI. C4 #2640 fills cents; it MUST NOT invent a second accessor or a second status enum.
2. **Discriminated union, fail-closed.** `roi` is `{ status: "unknown" } | { status: "numeric"; value: number }`. Default / uncomputable = `{ status: "unknown" }`. Not `0`. Not `null`. Not omitted-and-then-coerced. Not inferred.
3. **Qualifying inputs are this-run integer cents only:** `thisRun.spendCents`, `thisRun.attributedPipelineCents`, `thisRun.attributedRevenueCents` (names from parent #2629 R-12). A field is **present** when it is a finite number (including explicit `0`). A field is **missing** when it is `null`, `undefined`, omitted, `NaN`, or non-finite.
4. **Forbidden inputs never qualify:** `opened` / `clicked` / `sent` / delivered / `failed` / `suppressed` / `recipients`; any payload or derived metric from `GET /api/roi/rollup`; `feature_roi`; sprint burn; LLM usage cost; `canvasRunComparison.ts` scores; other runs’ cents; lifetime campaign totals; budget (`dailyBudgetCents` / `totalBudgetCents`); ESP/SMS cost.
5. **Formula is not this ticket.** Architect may pick the ratio/difference once at least one qualifying field is present. This ticket locks **when** a number is allowed and **which inputs** may feed it. No multi-touch model. No FX. C4 owns resolving cents from identifiers.
6. **Zero ≠ unknown.** Explicit this-run `0` is data. Missing is not data. Do not `?? 0`. Do not `Number(undefined)`. Do not chart-fill.
7. **Compose, do not reimplement.** No new source-of-truth table, no BurnRateOS CMO port, no overwrite of `marketing.campaigns.list`, no C0 prompt rewrite, no nested `Builderforce.ai/` prefix (#2601).

### R-1 — Default state: `unknown` until this-run financials exist

- For a given campaign **run**, `campaignRoi(...)` and `guidedCampaignRun(...).roi` MUST be `{ status: "unknown" }` until R-2 is satisfied for **that run**.
- `unknown` is the default for a new run, a draft run, a sent run with only engagement counters, and any run whose qualifying cents are all missing.
- `unknown` MUST NOT be represented as `0`, `"0"`, `0%`, `null` displayed as `0`, or a missing key that consumers treat as zero.
- ROI is a property of **this run**, not of the workspace, the marketing-campaign list, or the feature/portfolio rollup.

### R-2 — Qualifying inputs (this run only)

A numeric ROI MAY be computed **only** when **at least one** of the following is **present** (finite number, including explicit `0`) **for this run**:

| Field | Meaning | Not this field |
| --- | --- | --- |
| `thisRun.spendCents` | Recorded spend attributed to **this run** (C4 will resolve from ads identifiers + `ad_insights.spendCents` when that engine exists) | Sprint burn, LLM cost, `feature_roi`, `/api/roi/rollup`.spend, ads **budget**, ESP/SMS cost, another run’s spend |
| `thisRun.attributedPipelineCents` | Open pipeline attributed to **this run** | Workspace pipeline, person-lifetime, unlinked deals |
| `thisRun.attributedRevenueCents` | Closed revenue attributed to **this run** | Workspace revenue, unlinked closed-won, engagement-derived “value” |

- Presence is evaluated on **this run’s** `thisRun` object (parent #2629 R-12), not on list aggregates and not on rollup payloads.
- This ticket does **not** ingest spend or attribute CRM amounts (C4 #2640). It only reads whether those three fields are present on the run the contract is evaluating.
- Opens, clicks, sent, delivered, rollup, and comparison scores are **never** qualifying inputs (R-4).

### R-3 — Promotion rule

- If **none** of the three R-2 fields is present → `roi.status` MUST stay `"unknown"`. Partial engagement data does not change state.
- If **at least one** R-2 field is present → `roi.status` MAY be `"numeric"` and `roi.value` MUST be derived **only** from the present R-2 fields (architect formula). Forbidden inputs MUST NOT enter the formula.
- Promotion is **monotonic in data, not in time**: a run that later **receives** at least one R-2 field MAY promote `unknown` → numeric using only those fields. A run that **loses** all R-2 fields (never received, cleared, or engine reports all missing) MUST return to `"unknown"`. Engagement and rollup still cannot fill the gap.
- `guidedCampaignRun` MUST call `campaignRoi` on every evaluation; it MUST NOT cache a numeric ROI on the view after inputs have gone missing.

### R-4 — Forbidden inputs (opens, clicks, `/api/roi/rollup`)

The following MUST be ignored for ROI. They MUST NEVER set ROI to a number, replace `unknown`, or be used as a proxy, fallback, or imputed spend/pipeline/revenue:

- `CampaignView.opened` / `.clicked` / `.sent` / `.failed` / `.suppressed` / `.recipients`
- Per-send `openedAt` / `clickedAt` / `bouncedAt` / `failedAt` (`tracking.ts`)
- Any payload or derived metric from `GET /api/roi/rollup` (`roiRoutes.ts`: `time`, `spend.sprintRunwayBudget`, `spend.sprintActualBurn`, `spend.agentLlmCostUsd`, `spend.costModelTotal`, `roi[]` from `feature_roi`, `byProject`, `byTask`)
- `feature_roi` rows, sprint runway/burn, `llm_usage_log` cost, cost-model totals
- `canvasRunComparison.ts` training-run scores / ranks
- Sent / delivered counts, open rate, click rate, CTR, any engagement-derived “value”

Passing these through `thisRun.opens` / `thisRun.clicks` / `thisRun.rollup` (parent R-12 optional ignored fields) is allowed **only** so callers do not invent a second mapping — `campaignRoi` MUST ignore them. Tests MUST include fixtures where those fields are large numbers and ROI stays `"unknown"`.

### R-5 — Run isolation

- Spend, pipeline, and revenue from **other runs**, **lifetime** campaign totals, **list** aggregates (`listCampaigns` / `marketing.campaigns.list`), or **rollup** endpoints MUST NOT be used to compute this run’s ROI.
- A numeric ROI stored or displayed for run A MUST NOT be copied onto run B.
- Workspace `/api/roi/rollup` is segment/project portfolio finance — mixing unrelated sends, ads, and LLM cost. Using it for a campaign run is the failure this ticket exists to prevent (`canvasRunComparison.ts` already names rollup as the wrong comparison source for training runs; campaign ROI must not repeat that mistake).
- There is **no** FK from `marketing_campaigns` → `ad_campaigns` today (C4). This ticket MUST NOT invent a name-match or rollup join to “fill in” cents.

### R-6 — Zero vs `unknown`

| Situation | ROI |
| --- | --- |
| All three R-2 fields missing | `{ status: "unknown" }` — **not** `0` |
| At least one R-2 field present as explicit `0`, others missing | MAY be `{ status: "numeric"; value: … }` derived only from the present field(s). Explicit `0` is data. |
| This-run spend `0` **and** this-run attributed pipeline/revenue present (including `0`) | MAY be numeric (including `0`). Division-by-zero / infinite when spend is `0` and return is `> 0` is **architect policy**, and MUST still be derived only from those financials — never from engagement or rollup. |
| Ads/CRM source reports an honest `0` for this run (C4: identifiers present, source read, sum is 0) | That field is present `0`; it may participate in a numeric ROI. |
| Ads/CRM source **not** readable / identifiers missing (C4: field stays unset) | Field missing; does not qualify. If all three missing → `unknown`. |

Missing MUST NOT be coerced to `0` in parse, serialize, chart, SQL `COALESCE`, TypeScript `?? 0`, or `Number(x) || 0`.

### R-7 — Surfaces agree

Every consumer that surfaces campaign ROI for a run MUST show **`unknown`** (the status, not a number) until R-3 is met:

- Guided-campaign contract view (`guidedCampaignRun().roi`)
- Thin adapter `frontend/src/lib/canvasMarketing.ts` (mapping-only; MUST NOT duplicate arithmetic)
- Campaign detail, campaign list, exports, agent context, charts
- Any API JSON that exposes run ROI

No surface may show a numeric ROI (including `0`, `0%`, `N/A` as a number, or a fabricated percentage) when the run is `unknown`. Engagement counters MAY still render as counters on the same screen; they MUST NOT be labeled ROI and MUST NOT be used as the ROI figure. Localization/formatting of the `unknown` **label** is out of scope beyond **not rendering a number**.

List APIs (`GET /api/campaigns`, `listCampaigns`) today return engagement counts and **no** ROI — they MUST NOT start emitting a numeric ROI invented from those counts or from `/api/roi/rollup`.

### R-8 — No silent coercion; evidence later lanes must produce

Parsing, serialization, persistence, and charts MUST NOT coerce `unknown` to `0`, `null` displayed as `0%`, or a rollup-derived figure. A later run MUST NOT inherit a number from engagement or from another run’s rollup.

**Persistence rule:** do not write a numeric ROI onto a campaign/run record derived from opens, clicks, or `/api/roi/rollup`. If a display layer caches `roi`, the cache key is this run + the R-2 fields; engagement/rollup MUST NOT be in the key or the value.

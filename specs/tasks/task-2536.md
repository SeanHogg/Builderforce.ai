# PRD: Add `advisory` meeting kind

## Problem & Goal

Meeting routing currently recognizes a closed set of kinds in `meetingRoutes.ts`. Advisory sessions are a real meeting type in the product, but they are not a first-class kind, so they cannot be created, routed, or configured with kind-specific defaults.

Goal: register `advisory` as a valid meeting kind and keep team-ceremony chat **off** by default for that kind. Advisory meetings are not team ceremonies; they must not inherit ceremony chat defaults used by standups, retros, and similar rituals.

## Target users / ICP roles

- Engineering / product agents implementing meeting creation and routing
- Organizers who schedule advisory meetings (e.g. advisor–founder or advisor–team sessions)
- Participants in advisory meetings who should not be dropped into ceremony chat by default

## Scope

In scope:

- Add `advisory` to `KINDS` in `meetingRoutes.ts`
- Ensure advisory meetings can be created and routed as that kind
- Ensure team-ceremony chat is **not** default-on for `advisory`
- Keep existing kinds and their chat defaults unchanged

## Functional requirements

1. `KINDS` in `meetingRoutes.ts` includes the string `advisory`.
2. Requests and routes that validate against `KINDS` accept `advisory` as a legal meeting kind.
3. Creating or routing an `advisory` meeting does **not** enable team-ceremony chat by default.
4. Default chat / ceremony behavior for all other kinds is unchanged.
5. Any kind-specific default map (chat, ceremony flags, similar) treats `advisory` as non-ceremony: ceremony chat default is off / false / unset, not on.

## Acceptance criteria

- `KINDS` contains `advisory`.
- An `advisory` meeting can be created and routed without kind-validation errors.
- A newly created `advisory` meeting does not have team-ceremony chat turned on by default.
- Existing kinds still validate and keep their previous ceremony-chat defaults.
- No unrelated meeting-route behavior changes.

## Out of scope

- UI copy, templates, or calendar surfaces beyond kind registration and defaults
- Turning ceremony chat on for advisory via user preference, org setting, or explicit opt-in (allowed later; not default)
- New advisory-only features (agendas, advisor roles, billing, recording rules)
- Changing ceremony-chat defaults for non-advisory kinds
- Migrations of existing meetings into the `advisory` kind

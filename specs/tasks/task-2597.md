## Scope

In-scope work is exclusively the six operator checks below, executed in work-mode VS Code chat against project 11 subjects #2594 and #2595 (parent #2574), plus evidence recorded on this ticket.

## Functional requirements

1. Open work-mode VS Code chat and confirm the response is **not** manager-role required (or equivalent).
2. Invoke `/as Ada` against #2594 and `/as John Coder` against #2595.
3. Copy the chat/report. The copied payload **must** include the literal lines `Staffing:/as Ada` and `Staffing:/as John Coder`.
4. Confirm a `brain_chat_diagnostics` row exists with timestamp **after** the Copy action.
5. Confirm `builtin_chats_diagnostics` returns that same row (matching identifiers and timestamps).
6. If the session key still resolves as `developer`, inspect `auth:bfk:v2:` and record whether work-mode identity is present, stale, or missing. Do not paste key material. Do not treat a developer-resolved key as a pass.

## Acceptance criteria

Pass **only if all six hold**. Evidence on this ticket must include:

- Copy excerpt containing the literal lines `Staffing:/as Ada` and `Staffing:/as John Coder`.
- Diagnostics row id and timestamp (post-Copy), shown to match between `brain_chat_diagnostics` and `builtin_chats_diagnostics`.
- Auth prefix/role if the session key was checked (no key material).

Any of the following is a fail: manager-role required (or equivalent) in work-mode chat; Copy payload missing either Staffing line; diagnostics row missing, predating Copy, or mismatched across the two diagnostics surfaces; developer-resolved session key treated as success.

### R-5 — Copy payload contains both literal Staffing lines (check 3)

**Given** R-4 completed in that chat  
**When** the operator uses the chat **Copy** control (the product Copy that POSTs diagnostics — not OS clipboard of a selection that skips the report)  
**Then** the copied payload contains **both** of these **literal** lines, byte-for-byte as a line (leading/trailing whitespace ignored, spelling and slash required):

Staffing:/as Ada

The Copy report may also carry a trailing `ChatDiagnosticsReport` fenced JSON block with `schemaVersion: 1` (PRD 27 §6.5). That block is supporting evidence; it does **not** replace the two Staffing lines.

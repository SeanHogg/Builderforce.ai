# PRD: Marketplace Category `advisors` (Logged-out Browse)

## Problem & Goal

**Problem.** Prospective clients cannot discover advisors from a public marketplace surface. Advisory inventory is either gated behind login or mixed into general talent results, so booking intent is weak and advisor supply is under-exposed.

**Goal.** Ship a logged-out browse experience for marketplace category `advisors` that lets anyone discover advisor profiles, understand offering and availability, and start a booking flow. Reuse the existing talent profile renderer. Primary CTA is **Book**. **Hire** appears as a secondary CTA only when the same person is also available-for-hire.

Success looks like: public advisor inventory is crawlable and browsable without auth; profile content and layout match talent profiles; Book is the dominant action; Hire never outranks Book on advisor profiles.

## Target users / ICP roles

- **Logged-out buyers / operators** evaluating advisors before creating an account (founders, hiring managers, product/ops leads).
- **Advisors** listed in category `advisors` who sell booked sessions (and may also be available-for-hire as talent).
- **Growth / SEO** relying on public category and profile URLs for acquisition.
- **Not primary:** logged-in booking, advisor onboarding, or internal ops tooling.

## Scope

In scope for this WIP:

- Public category browse for `advisors` without authentication.
- Advisor profile detail pages rendered via the existing talent profile renderer.
- CTA hierarchy: Book primary; Hire secondary only if `available-for-hire`.
- Logged-out handling of Book / Hire (prompt auth or account creation; do not complete paid actions while logged out).
- Empty, sparse, and mixed-availability states for the category and profile.

Out of scope items are listed below and must not block this slice.

## Functional requirements

### Category browse (logged-out)

1. Category `advisors` is reachable on the public marketplace without login (direct URL, marketplace nav, and internal search/filter entry points that already expose categories).
2. Listing cards show advisor identity, headline/specialty, key proof (e.g. rating, reviews, rate or session price if already shown on talent cards), and a Book affordance.
3. Cards for advisors who are also available-for-hire may indicate hire eligibility but must not replace Book as the primary card action.
4. Filters/sort reuse existing marketplace listing patterns where they apply to advisors (no advisor-only filter IA in this slice unless already generic).
5. Pagination or infinite scroll matches the existing category listing behavior.
6. Empty category: clear empty state, no broken grid, no authenticated-only dead ends.

### Profile (reuse talent profile renderer)

7. Advisor profile pages use the **same talent profile renderer** (layout, modules, responsive breakpoints, SEO shell). Do not fork a parallel advisor profile UI.
8. Profile is fully viewable logged-out for public fields already visible on talent profiles (photo, name, headline, bio, skills/topics, reviews, rates/availability as currently modeled).
9. Advisor-specific fields map into existing renderer slots; do not add a second profile chrome.
10. If an advisor record is missing talent-profile-required fields, the renderer degrades gracefully (hide empty modules; do not error the page).

### CTAs

11. **Primary CTA is Book** on listing cards and profile (sticky header/footer CTAs included).
12. **Hire is secondary** and is shown only when the profile is also `available-for-hire`.
13. If not available-for-hire, Hire is omitted (not disabled).
14. Visual hierarchy: Book is the filled/primary button; Hire is outline/secondary or text+button one level down. Do not dual-primary.
15. Logged-out Book starts the existing auth/signup gate, then resumes booking intent (deep-link or return URL). Do not invent a new checkout in this slice.
16. Logged-out Hire (when shown) uses the same auth gate and existing hire intent resume as talent profiles.
17. CTAs are keyboard-accessible, labeled, and do not require hover-only discovery.

### Data & routing

18. Category and profile routes are public (no forced login wall before first paint of browse/profile content).
19. Only profiles in category `advisors` (and publicly listable) appear in this browse surface.
20. A person in both advisor and talent supply is one profile: Book primary, Hire secondary when `available-for-hire`.

## Acceptance criteria

- Logged-out user opens `/` marketplace category `advisors` and sees advisor listings with no auth modal blocking first content.
- Listing and profile use the talent profile renderer / shared card+profile components; no separate advisor profile template.
- Every advisor card and profile shows **Book** as the primary CTA.
- Hire is visible **only** when `available-for-hire` is true, and is visually and sequentially secondary to Book.
- Hire is absent when `available-for-hire` is false.
- Clicking Book or Hire while logged out opens the standard auth/signup flow and preserves return intent to that profile action.
- Profile modules with missing data are omitted rather than showing errors or placeholders that imply a broken profile.
- Empty category and zero-result filtered views render an empty state, HTTP 200 for a valid category, and no infinite spinner.
- Public category and profile URLs are indexable consistent with existing public talent surfaces (same robots/meta patterns).
- Responsive behavior matches talent profiles (mobile sticky CTA: Book primary; Hire secondary if present).
- Keyboard and screen-reader users can reach Book (and Hire if present) with visible focus and accessible names.

## Out of scope

- Logged-in booking/checkout, payments, calendar hold, or session fulfillment.
- Advisor application, vetting, onboarding, or availability management.
- New advisor-only profile sections, branding, or a forked renderer.
- Changing Hire behavior on pure talent (non-advisor) profiles.
- Messaging, proposals, or contracts.
- Personalized recommendations, logged-out saved lists, or account-based pricing.
- Admin/moderation tools and category taxonomy redesign beyond exposing `advisors`.
- Localization, new review types, or SEO content programs beyond matching current public talent patterns.

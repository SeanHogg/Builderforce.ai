# PRD: Marketplace Category `advisors` (Logged-out Browse)

## Problem & Goal

**Problem.** Prospective clients cannot discover advisors from a public marketplace surface. Advisory inventory is either gated behind login or mixed into general talent results, so booking intent is weak and advisor supply is under-exposed.

**Goal.** Ship a logged-out browse experience for marketplace category `advisors` that lets anyone discover advisor profiles, understand offering and availability, and start a booking flow. Reuse the existing talent profile renderer. Primary CTA is **Book**. **Hire** appears as a secondary CTA only when the same person is also available-for-hire.

Success looks like: public advisor inventory is crawlable and browsable without auth; profile content and layout match talent profiles; Book is the dominant action; Hire never outranks Book on advisor profiles.

## Target users / ICP roles

- **Logged-out buyers / operators** evaluating advisors before creating an account (founders, hiring managers, product/ops leads).
- **Advisors** listed in category `advisors` who sell booked sessions (and may also be available-for-hire as talent).
- **Growth / SEO** relying on public category and profile URLs for acquisition.
- **Not primary:** logged-in booking, advisor onboarding, or internal ops tooling.

## Scope

In scope for this WIP:

- Public category browse for `advisors` without authentication.
- Advisor profile detail pages rendered via the existing talent profile renderer.
- CTA hierarchy: Book primary; Hire secondary only if `available-for-hire`.
- Logged-out handling of Book / Hire (prompt auth or account creation; do not complete paid actions while logged out).
- Empty, sparse, and mixed-availability states for the category and profile.

Out of scope items are listed below and must not block this slice.

## Functional requirements

### Category browse (logged-out)

1. Category `advisors` is reachable on the public marketplace without login (direct URL, marketplace nav, and internal search/filter entry points that already expose categories).
2. Listing cards show advisor identity, headline/specialty, key proof (e.g. rating, reviews, rate or session price if already shown on talent cards), and a Book affordance.
3. Cards for advisors who are also available-for-hire may indicate hire eligibility but must not replace Book as the primary card action.
4. Filters/sort reuse existing marketplace listing patterns where they apply to advisors (no advisor-only filter IA in this slice unless already generic).
5. Pagination or infinite scroll matches the existing category listing behavior.
6. Empty category: clear empty state, no broken grid, no authenticated-only dead ends.

### Profile (reuse talent profile renderer)

7. Advisor profile pages use the **same talent profile renderer** (layout, modules, responsive breakpoints, SEO shell). Do not fork a parallel advisor profile UI.
8. Profile is fully viewable logged-out for public fields already visible on talent profiles (photo, name, headline, bio, skills/topics, reviews, rates/availability as currently modeled).
9. Advisor-specific fields map into existing renderer slots; do not add a second profile chrome.
10. If an advisor record is missing talent-profile-required fields, the renderer degrades gracefully (hide empty modules; do not error the page).

### CTAs

11. **Primary CTA is Book** on listing cards and profile (sticky header/footer CTAs included).
12. **Hire is secondary** and is shown only when the profile is also `available-for-hire`.
13. If not available-for-hire, Hire is omitted (not disabled).
14. Visual hierarchy: Book is the filled/primary button; Hire is outline/secondary or text+button one level down. Do not dual-primary.
15. Logged-out Book starts the existing auth/signup gate, then resumes booking intent (deep-link or return URL). Do not invent a new checkout in this slice.
16. Logged-out Hire (when shown) uses the same auth gate and existing hire intent resume as talent profiles.
17. CTAs are keyboard-accessible, labeled, and do not require hover-only discovery.

### Data & routing

18. Category and profile routes are public (no forced login wall before first paint of browse/profile content).
19. Only profiles in category `advisors` (and publicly listable) appear in this browse surface.
20. A person in both advisor and talent supply is one profile: Book primary, Hire secondary when `available-for-hire`.

## Acceptance criteria

- Logged-out user opens `/` marketplace category `advisors` and sees advisor listings with no auth modal blocking first content.
- Listing and profile use the talent profile renderer / shared card+profile components; no separate advisor profile template.
- Every advisor card and profile shows **Book** as the primary CTA.
- Hire is visible **only** when `available-for-hire` is true, and is visually and sequentially secondary to Book.
- Hire is absent when `available-for-hire` is false.
- Clicking Book or Hire while logged out opens the standard auth/signup flow and preserves return intent to that profile action.
- Profile modules with missing data are omitted rather than showing errors or placeholders that imply a broken profile.
- Empty category and zero-result filtered views render an empty state, HTTP 200 for a valid category, and no infinite spinner.
- Public category and profile URLs are indexable consistent with existing public talent surfaces (same robots/meta patterns).
- Responsive behavior matches talent profiles (mobile sticky CTA: Book primary; Hire secondary if present).
- Keyboard and screen-reader users can reach Book (and Hire if present) with visible focus and accessible names.

## Out of scope

- Logged-in booking/checkout, payments, calendar hold, or session fulfillment.
- Advisor application, vetting, onboarding, or availability management.
- New advisor-only profile sections, branding, or a forked renderer.
- Changing Hire behavior on pure talent (non-advisor) profiles.
- Messaging, proposals, or contracts.
- Personalized recommendations, logged-out saved lists, or account-based pricing.
- Admin/moderation tools and category taxonomy redesign beyond exposing `advisors`.
- Localization, new review types, or SEO content programs beyond matching current public talent patterns.

## Requirements

This section is the business-analyst contract for ticket **#2529** (logged-out marketplace browse for category `advisors`). Companion: `specs/builderforce/26-prd-advisor-platform.md`. Signed: Business Analyst · 2026-09-16.

### Composition constraints (non-negotiable)

1. **`advisors` is a talent-family filter**, not a fifth marketplace family, not a `MARKETPLACE_LISTING_KINDS` value, and not a `/advisors` route.
2. **One person, one profile.** An advisor who is also available-for-hire is still `/talent/{userId}` rendered by `TalentProfileView`. Do not fork a parallel advisor profile UI.
3. **A0 bind** (already on talent): `booking_hosts.host_ref` = talent `userId`. This slice **reads** that bind; it does not invent a second membership table.
4. **Primary CTA is Book** on every advisor card and profile. Hire is secondary and only when the same person is available-for-hire.
5. **Logged-out users never complete a paid or reserved action.** Book and Hire open the existing auth/signup gate (`signInHref`) and resume intent. No new checkout.
6. **Do not change Hire behaviour on pure talent (non-advisor) profiles.**

Kill condition (PRD 26): if the implementation needs `/advisors`, a new listing family, or a volunteer/chapter table, the slice is wrong.

### Current-state gaps (main)

- `LEGACY_CATEGORY` in `frontend/src/lib/marketplaceFamilies.ts` has no `advisors` row. Unknown `?category=` falls through `resolveFamily` to **Agents**, so `/marketplace?category=advisors` is currently the wrong family.
- Talent browse (`MarketplacePageClient` section `category === 'talent'`) lists all public talent via `listFreelancers`; it is not filtered to bookable advisors.
- Talent cards are a whole-card `<Link href="/talent/{userId}">` with a `book` / `viewProfile` span — not a labeled Book control.
- `TalentDetailClient`: Book shows for bookable profiles even when logged out; Hire/Message/Interview only when `canHire` (tenant + not owner). Logged-out Hire is omitted rather than secondary + auth-gated. `reserveTalentSession` is `auth: 'tenant'` — a guest Book click must not fire it.
- `TalentProfileView` already omits empty bio/skills/reviews. Keep that. No advisors-only sticky footer exists on talent; do not add one only here.

### Glossary

| Term | Meaning |
|---|---|
| **Advisor** | A publicly listable talent person who is **bookable** (active `booking_hosts.host_ref` = user id). Category membership **is** this predicate. |
| **Publicly listable** | Same visibility/published rules as the talent person grid. |
| **available-for-hire** | Existing talent hire opt-in (`users.available_for_hire` / the same predicate that shows Hire on a pure talent profile for a logged-in employer). Independent of bookable. |
| **Logged-out** | No session, or a session with no tenant. Both see public content; neither completes Book or Hire. |

### Functional requirements

**Category browse**

- **FR-1** `/marketplace?category=advisors` is a valid, bookmarkable, crawlable entry. `resolveFamily` / `LEGACY_CATEGORY` **must** map `advisors` onto `family=talent` (person listings + advisor filter). It must not 404, must not fall through to Agents, and must not add `FamilyId = 'advisors'`.
- **FR-2** `/marketplace?family=talent` with the advisors filter applied (talent kind chip labelled Advisors that is **not** a `MARKETPLACE_LISTING_KINDS` id, **or** the legacy category alias plus a nav entry that writes `category=advisors`) is acceptable. Both vocabularies must land on the **same** result set.
- **FR-3** Logged-out reachability: direct URL, marketplace family/kind bar (label **Advisors**), and existing `?category=` links. No login modal before first content.
- **FR-4** Grid lists **only** publicly listable **and** bookable people. Pure talent who are not bookable do not appear. Dual-supply people appear once.
- **FR-5** Cards show identity (avatar/initials, display name), headline or discipline, existing proof (rating, review count, trust badge), rate or session price when modeled (**$0 is valid and still shows Book**), and a Book affordance. Skills chips may match talent (first N).
- **FR-6** Book is the primary card action. Hire eligibility may be indicated but must not replace Book. The card may still navigate to the profile. **Book is a labeled control** (accessible name “Book”). **Do not nest a `<button>` inside the card `<Link>`.**
- **FR-7** Reuse talent person filters (search, discipline, sort, compact pagination, `TALENT_PAGE_SIZE`). No advisor-only filter IA. Filter changes reset to page 1.
- **FR-8** Empty and zero-result: HTTP **200**, existing empty-state pattern, no broken grid, no infinite spinner, no “sign in to see advisors”. Fetch failure uses the existing talent error state. Initial load may use `SkeletonGrid`.
- **FR-9** `GET /api/freelancers` (or the extended query) **succeeds unauthenticated** for public advisor rows.

**Profile**

- **FR-10** Profiles are `/talent/{userId}` via `TalentProfileView`. No `AdvisorProfileView`, no `/advisors/[id]`.
- **FR-11** Public talent fields remain viewable logged-out. No login wall before first paint.
- **FR-12** Advisor-specific attributes map into existing renderer slots (skills, bio, rate, availability, location). No second chrome in this slice.
- **FR-13** Missing fields omit the module; the page does not error. Unknown id: existing private/not-found copy.
- **FR-14** Back from an advisors-browse arrival returns to `/marketplace?category=advisors`, not `?category=talent`.
- **FR-15** Owner sees **Edit profile** only, not Book/Hire as a buyer.

**CTAs**

- **FR-16** Book is primary on cards and profile header actions (filled/primary). Any sticky/footer bar **only if talent already has one**.
- **FR-17** Hire is secondary (outline) **only** when available-for-hire; omitted when false — never disabled, never dual-primary.
- **FR-18** Logged-out Book does **not** call `reserveTalentSession`. It uses `signInHref` with a return URL that resumes booking on this profile (e.g. `/talent/{userId}?intent=book`). After auth, open `BookAdvisorPanel` without a second click when the intent is present.
- **FR-19** Logged-out Hire (when shown) uses the same gate and a hire intent resume (e.g. `?intent=hire`). After auth, existing hire behaviour. If still not hire-eligible, omit Hire — do not invent a consumer-hire path.
- **FR-20** Logged-in checkout/hold/payment are out of scope. Do not regress authenticated Book.
- **FR-21** Book and Hire are keyboard-reachable, visibly focused, and named. Hover-only is not enough.
- **FR-22** Mobile matches talent. **Do not add an advisors-only sticky bar.**

**Mixed / sparse**

- **FR-23** Advisor + hireable → Book then Hire. Advisor + not hireable → Book only. Hireable + not bookable → **not in this browse** (remain on talent person).
- **FR-24** Sparse cards omit missing rating/rate/skills; still show name + Book. No fake stars.
- **FR-25** Price `0` is listable; do not imply paid; do not force $0; Book stays primary.

### Data and API

- **DR-1** Filter **server-side** to public + bookable. Client-side filtering of the full talent list is not acceptable.
- **DR-2** Public list and profile GETs return 200 without auth for public rows.
- **DR-3** Do not add `advisors` to `MARKETPLACE_LISTING_KINDS` or `FamilyId`. Extend `LEGACY_CATEGORY` and the talent list query (e.g. `bookable=1` / `category=advisors` mapped to the A0 bind).
- **DR-4** If the card shows hire-eligibility, the list projection includes that bit (no N+1).
- **DR-5** Reservation and hire POSTs stay tenant-authed. Guest clicks never fire them.

### CTA matrix

| Visitor | Profile | Card | Profile actions |
|---|---|---|---|
| Logged-out | Advisor, not hireable | Book primary | Book → auth → resume book. Hire omitted. |
| Logged-out | Advisor + hireable | Book primary; optional hire hint | Book → auth → resume book. Hire (secondary) → auth → resume hire. |
| Logged-out | Talent, not advisor | Not in this grid | Unchanged. |
| Logged-in employer, not owner | Advisor, not hireable | Book | Book primary. Hire omitted. |
| Logged-in employer, not owner | Advisor + hireable | Book | Book primary, Hire secondary. |
| Owner | Own advisor profile | May still list | Edit profile only. |

### Routing and SEO

- **SR-1** Public: `/marketplace?category=advisors`, family-equivalent talent URL, `/talent/{id}`. No login wall before first paint.
- **SR-2** Indexability matches talent (`robots.ts` / sitemap / meta). Do not `noindex` the category.
- **SR-3** Reuse existing marketplace talent JSON-LD; no advisors-only Person/Service markup in this slice.
- **SR-4** Do **not** introduce `/advisors` or `/advisors/[id]`.

### Accessibility and NF

- **A11Y-1** Book and Hire (when present) named, focusable, keyboard-operable.
- **A11Y-2** “Advisors” chip has the same selected state as other kind chips.
- **A11Y-3** Empty state is text, not colour-only.
- **NF-1** Guest first content must not depend on a failing auth round-trip.
- **NF-2** Pagination and 250 ms search debounce match talent.
- **NF-3** Reuse `talent.*` / `marketplace.*`. New strings only for the Advisors label and empty-advisors copy if “no talent” would be misleading.

### Acceptance criteria (testable)

1. Logged-out `/marketplace?category=advisors` shows advisor listings or the empty state with **no** auth modal blocking first content. The page is not the Agents family.
2. HTTP **200** for a valid empty or populated category.
3. Every listed person is publicly listable and bookable. Non-bookable talent does not appear.
4. Cards and profiles use shared talent card + `TalentProfileView`. No separate advisor template.
5. Every advisor card and profile shows **Book** as the primary CTA.
6. Hire is visible **only** when available-for-hire, and is visually and sequentially secondary to Book.
7. Hire is **absent** when available-for-hire is false.
8. Logged-out Book or Hire opens standard auth/signup and preserves return intent. No reservation or hire POST while logged out.
9. After sign-in, the visitor lands on the same profile with the intended action resumed.
10. Missing profile modules are omitted; the page does not error.
11. Empty and zero-result views render an empty state and no infinite spinner.
12. Public URLs are indexable consistent with talent.
13. Responsive behaviour matches talent (no advisors-only sticky unless talent has one).
14. Keyboard and SR users can reach Book (and Hire if present) with visible focus and accessible names. Book is not a button nested in the card link.
15. Pure talent Hire behaviour is unchanged on non-advisor profiles.

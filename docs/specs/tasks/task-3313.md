# Task 3313 — Gap: auto SOC 2 evidence (PRD 08) not built

Parent: Epic 3062. Role: Business Analyst (lane `ready`).

## Finding (BA)

The gap as filed is **stale**. Repository inspection shows automatic SocEvidence capture for CC7/CC8 is implemented, idempotent and wired into the merge, scan and override paths. No new capture code is required to satisfy the acceptance criterion. This document records the requirements the shipped behavior satisfies, the evidence that it does, and an auditor-facing procedure so the control is demonstrable for Type I.

## Where it is implemented

- `api/src/application/governance/automatedSocEvidence.ts` — `recordAutomatedEvidence`, kind-to-control mapping (`merge`→CC8.1; `scan`→CC7.1+CC8.1; `review`→CC8.1; `override`→CC8.1), uploader `system:devsecops`.
- `api/migrations/1321_automated_evidence_and_incident_idempotency.sql` — idempotency index.
- Call sites: `repos/recordPullRequestRow.ts` (merge), `security/pullRequestSecurityStep.ts` (PR scan, includes run id / PR / commit provenance), `security/branchScanRun.ts` (branch scan), `security/prSecurityOverride.ts` (override).
- Tests: `governance/automatedSocEvidence.test.ts` (mapping, provenance, idempotency, per-control rows, segment-less skip).
- Baseline controls are created on demand by `ensureSoc2Baseline` for the segment.

## Acceptance mapping

Acceptance: "agent merges/PRs create SocEvidence for CC7/CC8, or a written manual procedure is attached."

- Merges/PRs create CC8.1 evidence (R1); scans create CC7.1 and CC8.1 evidence (R2). Primary acceptance path is **met by code**.
- Fallback manual procedure below is attached for cases where capture does not apply (see Limits).

## Auditor procedure (verification and manual fallback)

1. Export the package: `GET /api/governance/soc2/export?format=xlsx` (any tenant member, active segment).
2. Filter `control_ref` in {`CC7.1`, `CC8.1`} and `evidence_type` = `automated` (or `override`). Each row is a platform-written record of a governed change; the sample period is the `evidence_added_at` range.
3. For a sampled change, follow the evidence url/note to the PR and run id and confirm the PR was reviewed and scanned before merge.
4. Manual fallback (changes outside the governed pipeline, e.g. a direct push, or a segment where no row exists): the control owner attaches evidence through the manual evidence route with a type **other than** `automated`/`override` (for example `pr-review` or `change-ticket`), including the PR/commit URL, approver, review date and scan result in the note. The exception and its approver are noted on the control.
5. Cadence: reviewer confirms at least one automated CC8.1 row per merged PR in the sampled window; a merged PR with no row is raised as a ticket per the compliance README rule (missing evidence is a finding, not a pass).

## Limits and residual gaps (follow-ups, out of scope here)

- **G1 — export omits `source_ref`.** `soc2EvidenceExport.ts` columns do not include `source_ref`, so the stable provenance key is not visible in the grid. Recommend adding an `evidence_source_ref` column. Small API change.
- **G2 — no CC7/CC8 row for merges with no segment.** `recordAutomatedEvidence` returns 0 when `segmentId` is null; merges of PRs without a segment produce no evidence and fall to the manual procedure.
- **G3 — no coverage check.** Nothing alerts when a merged PR lacks an evidence row; coverage is verified manually per step 5.
- **G4 — ROADMAP drift.** The issue states Phase 7 is "Planned"; ROADMAP has no SOC 2 phase text matching it, so status wording should be reconciled by the product owner. No ROADMAP edit was made here.
- `docs/compliance/README.md` does not yet index this control. Recommend adding a row: *Change management (CC7/CC8) — `automatedSocEvidence.ts`, `/api/governance/soc2/export` — verify an automated CC8.1 row per merged PR quarterly.*

## Out of scope

Rewriting capture logic, new control mappings beyond CC7.1/CC8.1, and SOC 2 report generation.

# PRD: M1 leftover — CubeCL GPU backends + bench-kernel (70% go/no-go)

## Problem & Goal

Epic 2916 landed fused GEMV kernels on main and wrapped CubeCL 0.10.0 behind `bfi-core::Backend`, but PRD §8 M1 go/no-go is still open: token throughput versus the PrismML llama.cpp fork has not been measured. Shipping compile-and-match tests is not a throughput decision.

**Goal:** On one M-series Mac (Metal) and one NVIDIA box (Vulkan or CUDA), run `bfi bench-kernel` and record tok/s against llama-bench tg128. Pass only if both devices reach at least 70% of that baseline. If either misses, do not stub or fall back to CPU-only; file PRD §9 Fallback A as a follow-up gap (hand-written Metal via metal-rs and CUDA via cudarc for the hot GEMV only).

## Target users / ICP roles

- Inference engineers owning `builderforce-inference` kernel performance and the M1 go/no-go.
- Downstream agents implementing or reviewing this ticket on `seanhogg/builderforce.ai` (base `main`).
- Release owners who need a recorded pass/fail before treating CubeCL backends as the M1 path.

## Scope

In repo `builderforce-inference`, limited to `crates/bfi-core` and `crates/bfi` (`bench-kernel` CLI):

- Use the already-shipped stack: CubeCL `=0.10.0` pinned in `workspace.dependencies`; `bfi-core::Backend` with `cuda` / `rocm` / `metal` / `vulkan`; fused GEMV PQ2_0 / PTQ1_0 kernels; `bfi bench-kernel` (synthetic Bonsai-27B `hidden=5120` or `--gguf`); `BFI_BACKEND=cuda|rocm|metal|vulkan|cpu` with probe-order fallthrough when a GPU is missing.
- Measure, do not re-implement, the M1 comparison:
  - **Device A:** M-series Mac, Metal.
  - **Device B:** NVIDIA, Vulkan or CUDA.
  - **Metric:** tok/s from `bfi bench-kernel` versus PrismML llama.cpp fork `llama-bench` tg128.
  - **Bar:** each device ≥ 70% of its paired llama-bench tg128 number.
- Record both absolute tok/s figures and the ratio. Do not invent or stub results.
- If 70% is missed on either device, open a follow-up gap for Fallback A only. Do not silently ship CPU-only as the GPU result.

## Functional requirements

1. **Backend selection.** `BFI_BACKEND` selects a real backend (`cuda`, `rocm`, `metal`, `vulkan`, or `cpu`). A missing GPU falls through the remaining probe order; it must not be reported as a successful GPU run.
2. **Kernel correctness gate (already shipped, must remain green).** Fused GEMV PQ2_0 / PTQ1_0 GPU kernels compile and match CPU when a device is present (`gpu_pq2/ptq1_matches_cpu_when_device_present`). `cargo test -p bfi-core` and `--features vulkan` stay at 25/25.
3. **Bench entrypoint.** `bfi bench-kernel` runs the synthetic Bonsai-27B shape (`hidden=5120`) or a caller-supplied `--gguf`, on the selected backend, and emits a tok/s figure suitable for the go/no-go record.
4. **Paired baseline.** On the same host and comparable workload, run PrismML llama.cpp fork `llama-bench` tg128 and capture its tok/s. The CubeCL number is compared only to that paired run, not to a published or estimated figure.
5. **Two-device measurement.** Execute requirement 3 and 4 on Metal (M-series Mac) and on Vulkan or CUDA (NVIDIA). Both runs are required. A single-device result does not close the ticket.
6. **Go/no-go record.** Persist both tok/s numbers, backend used, device identity, workload (synthetic hidden=5120 or gguf path), llama-bench tg128 counterpart, and the percentage of baseline. Pass iff both percentages are ≥ 70. No stubs, no CPU numbers substituted for a missing GPU.
7. **Miss path.** If either device is under 70%, leave this ticket open and file Fallback A (hand-written metal-rs Metal and cudarc CUDA for the hot GEMV only) as a separate follow-up gap. Do not implement Fallback A inside this ticket, and do not mark M1 met.

## Acceptance criteria

- CubeCL remains pinned at `=0.10.0`. No version bump.
- `bf-local`, VSIX, and `ollama.rs` are untouched (`ollama.rs` is not deleted).
- Existing tests still pass: `cargo test -p bfi-core` and `cargo test -p bfi-core --features vulkan` are 25/25, including GPU-vs-CPU match when a device is present.
- A written measurement record exists for **both** required hosts, each with: backend, device, workload, `bfi bench-kernel` tok/s, llama-bench tg128 tok/s, and ratio.
- Go only if Metal ≥ 70% of its llama-bench tg128 **and** NVIDIA (Vulkan or CUDA) ≥ 70% of its llama-bench tg128. Otherwise no-go, with Fallback A filed as a follow-up and CPU-only explicitly not accepted as the GPU result.
- No fabricated, copied, or stubbed throughput numbers.

## Out of scope

- Bumping CubeCL or changing the `=0.10.0` pin.
- Editing `bf-local`, any VSIX, or deleting `ollama.rs`.
- Implementing Fallback A (hand-written metal-rs / cudarc GEMV) in this ticket.
- New kernels, quant formats, or backends beyond the shipped CubeCL wrap.
- Re-litigating epic 2916 merge contents already on main (06e624e, 1f97edf).
- ROCm as a required measurement host (selectable, not part of the two-device bar).
- Benchmarking unrelated products, publishing marketing numbers, or closing M1 from CPU-only or single-device data.

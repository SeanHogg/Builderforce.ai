## Problem & Goal

Archived tickets still render as incomplete on the VSIX chat rail. Ticket #6767 is archived on the server (`archived: true`, status still `backlog`), but the rail draws it as BACKLOG, 0/1, and counts it toward the incomplete header (67% · 2/3). Hide done does not hide it.

Archived tickets must read as closed: status `archived`, progress 100. They must not count as incomplete, and Hide done must hide them. An open, unarchived ticket must be unchanged.

## Target users / ICP roles

- Builders using the VSIX chat rail to scan ticket progress and hide done work.
- Brain chat consumers of `GET /api/brain/chats/:id/tickets` who rely on status and `progressPct` for task, epic, and gap health.

## Scope

Server health already has an unverified, uncommitted partial change. Remaining work is client rail progress, epic child rollup, and verification. Ship policy is commit locally, no push. Do not commit unrelated dirty files (api runtime, knowledge-graph-view).

Partial change already in the working tree (not verified, not committed):

- `Builderforce.ai/api/src/application/brain/taskTierTicketHealth.ts` — health select reads `tasks.archived` and rewrites an archived row’s status to `archived` (in `TASK_CLOSED_STATUSES`) before leaf progress and epic self-status are computed. `ticketHealthBatch` then applies `effectiveTicketProgress`, so a closed lane emits 100.

Still required:

1. Client rail. `clients/vscode/src/chatRail/railPayloads.ts` `railTicketProgress` uses `payload.status` and ignores `TicketValue.archived`. `RAIL_OWNED` does not include `archived` (it is a device field). A local record with status `backlog` and `archived: true` still draws incomplete until a refresh overwrites status. Treat `archived: true` as status `archived` inside `railTicketProgress` so the chip and Hide done agree without waiting on ingest. Add a case in `railPayloads.test.ts`.
2. Epic child rollup. `SQL_COUNT_DONE` only counts closed status, so an archived child whose lane is still `backlog` does not count done toward its parent. Count `tasks.archived` as done in that SQL (or the same status rewrite) so a parent’s done/total matches the chips.
3. Verify: api type-check / the brain ticket-health tests, and the vscode `railPayloads` test.

## Functional requirements

- An archived task, epic, or gap reports status `archived` and `progressPct` 100 on `GET /api/brain/chats/:id/tickets`.
- The VSIX chat rail treats `archived: true` as status `archived` inside `railTicketProgress`, even when the local payload status is still `backlog`, so the chip shows closed and Hide done hides it without waiting on ingest.
- Epic (and parent) done/total counts an archived child as done even when that child’s lane status is still `backlog`, so parent progress matches the chips.
- An open, unarchived ticket keeps its existing status and progress.
- A regression case covers the archived-but-backlog local record in `railPayloads.test.ts`.

## Acceptance criteria

- An archived task, epic, or gap reports status `archived` and progressPct 100 on `GET /api/brain/chats/:id/tickets` and on the VSIX rail.
- Hide done hides that archived ticket.
- Header incomplete counts and parent done/total no longer treat archived tickets as incomplete.
- An open unarchived ticket is unchanged.
- Api type-check and brain ticket-health tests pass; the vscode `railPayloads` test passes, including the new archived case.
- Only the intended files are committed locally. No push. Unrelated dirty files (api runtime, knowledge-graph-view) are not committed.

## Out of scope

- Changing archive semantics on the server beyond reading `tasks.archived` and treating it as closed for health, progress, and parent rollup.
- Adding `archived` to `RAIL_OWNED` (it remains a device field).
- Pushing the commit, or committing unrelated dirty files.
- Redesigning Hide done, rail chips, or ticket status lanes beyond the archived-as-closed behavior.

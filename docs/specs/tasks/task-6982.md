## Problem & Goal

Ground cameras in the knowledge-graph view (map/transit, system, graph, mind map, heat, style, features, sequence) already support a tilt of 0–60° and station extrusion via placement depth, but the resting depth is 0. The first paint is therefore a flat top-down map even though the redesign expects a tilted stage with raised stations.

**Goal:** When the caller omits depth, rest at **0.65** (about 39°) for both placement extrusion and the ground-camera stage rig, so the first frame is already in perspective. An explicit depth of **0** must remain flat. The separate 3D orbit camera is unchanged.

## Target users / ICP roles

- Engineers and reviewers opening Map (or any other ground camera) in the BuilderForce Visualization webview who expect the Code Visualizer redesign: tilted ground plane, extruded stations, no extra camera switch.
- Downstream agents implementing and testing placement and stage rig behavior in `packages/knowledge-graph-view`.

## Scope

In `Builderforce.ai/packages/knowledge-graph-view`:

- Default omitted depth to **0.65** in placement (`request.ts`, `rows.ts` `depthOf`, `map.ts` where depth is currently `req.depth ?? 0`) and in stage depth (`stageHooks.ts` `useDepth`, `Stage.tsx` setDepth / mount, `stage/rig` initial depth for non-orbit cameras).
- Ground cameras only: map/transit, system, graph, mind map, heat, style, features, sequence. Their rig field stays `depth: { tilt: [0, 60], orbit: false }` — range unchanged; only the **resting** depth changes.
- Initial rig depth for a ground camera is **0.65 before first paint** (no tween from 0; do not force depth toward 0 on mount for the resting value).
- Existing depth control and drag still span **0 (flat) through 1 (full raise)**.
- One regression test: omitted depth → extrude > 0 and a tilted camera; `depth: 0` → flat (extrude 0). Existing `placement.test.ts` and `mapParity.test.ts` cases that pass `depth: 0` and expect extrude 0 must keep passing.

## Functional requirements

1. **Omitted depth is 0.65.** If the caller does not pass depth, placement and the ground-camera rig use 0.65, not 0. Stations extrude; the camera is tilted on first paint.
2. **Explicit zero stays flat.** `depth: 0` means no extrusion and a flat layout. Do not coerce 0 to 0.65.
3. **First frame, not a tween.** For a non-orbit ground camera, stage rig depth is 0.65 before the first paint. If `Stage.tsx` currently drives depth toward 0 on mount, that must not override the resting value.
4. **User control unchanged in range.** Drag and the existing depth control can still flatten to 0 and raise to 1.
5. **Tilt range unchanged.** Ground rig remains `tilt: [0, 60]`, `orbit: false`. Do not edit that range.
6. **3D camera unchanged.** `scene3d` (`tilt: [5, 89]`, `orbit: true`) keeps its home. Do not switch the default view mode to the 3D camera or force the user into it.
7. **Captions unchanged.** DOM captions already cancel tilt (`stage/captions`). Do not restyle them.
8. **Regression coverage.** Add or adjust one test that a ground placement with no depth has extrude > 0 and a tilted camera, and that `depth: 0` stays flat.

## Acceptance criteria

- Opening Map, or whichever ground camera is selected, shows a tilted stage with raised stations on first paint, without opening the 3D camera.
- A ground camera with omitted depth rests near **0.65** tilt with extruded stations; it does not start at 0 and animate in.
- Passing `depth: 0` still yields a flat layout (extrude 0). `placement.test.ts` and `mapParity.test.ts` cases that assert that continue to pass.
- Depth drag / control can still reach 0 and 1.
- Ground tilt range remains `[0, 60]`; `scene3d` home and orbit behavior are unchanged.
- Captions are not restyled. CameraBar, Segmented, and the API drawer are not edited.

## Out of scope

- Switching the default view mode to the 3D orbit camera, or changing `scene3d` home, tilt `[5, 89]`, or `orbit: true`.
- Changing ground-camera tilt ranges (`[0, 60]`) or orbit flags.
- Editing CameraBar, Segmented, or the API drawer.
- Restyling DOM captions.
- Blocking on the design artifact URL; follow the screenshot and the knowledge-view redesign contract.
- Treating an explicit `depth: 0` as the new default.

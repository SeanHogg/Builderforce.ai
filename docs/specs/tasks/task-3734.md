# Native engine — remaining work

Status: WIP. Product cut-over shipped 2026-10-14 (chat #135). This epic and the ROADMAP Local LLM row stay open until M1, M3, and signed GitHub Release binaries all land. Repo: seanhogg/builderforce.ai, base main. Living doc: builderforce-inference/docs/PRD-native-engine.md.

## Problem & Goal

Synapse no longer depends on a local Ollama process. The sidecar supervises `bfi serve`, the Ollama feature flag and `bf-local` `ollama.rs` path are gone, and the extension finds Synapse through the desktop config. That product cut-over is shipped. The native engine is not done.

Three gaps still block calling the epic complete:

- GPU decode speed versus PrismML `llama-bench` tg128 has not been measured on Metal or NVIDIA, so the 70% tok/s bar is unverified.
- Live Bonsai 27B greedy output has not been compared to the fork. The harness exists; 27B weights are not in CI.
- GitHub Release binaries are not signed with the owner Apple Developer ID or Authenticode.

Goal: close those three items without reopening shipped cut-over work, without bumping CubeCL, and without marking ROADMAP Local LLM done early.

## Target users / ICP roles

- Synapse users running local models through the desktop sidecar (`bfi serve`), not a side Ollama install.
- VS Code extension users whose VSIX must discover the running Synapse from `~/.builderforce/desktop.json`.
- Installers of GitHub Release binaries who need Apple Developer ID and Authenticode signatures.
- Inference owners who must show GPU tok/s and Bonsai 27B greedy parity before the Local LLM row can leave Partial.

## Scope

In scope, still open:

- M1 (#3762 / #4465): measure GPU tok/s on Metal and NVIDIA against PrismML `llama-bench` tg128. Bar is at least 70%. CubeCL stays 0.10.0; cuda, rocm, metal, and vulkan backends already compile.
- M3 (#3764): run live Bonsai 27B greedy versus the fork on a machine that has the weights. Do not add 27B weights to CI. Reuse the existing harness.
- Signed releases (#3782 / #4481 / #3777): publish GitHub Release binaries signed with the owner Apple Developer ID and Authenticode secrets.
- ROADMAP (#3778): Local LLM stays Partial until M1, M3, and signed releases have landed. Then, and only then, mark this epic and that row done.

Already shipped; do not redo:

- M2 golden harness (#3763).
- M4 `mix_decode` plus tools (#3765).
- M5 Synapse cut-over (#3766): `bf-local` `ollama.rs` and `SYNAPSE_USE_OLLAMA` deleted; sidecar supervises `bfi serve`; `import-ollama` CLI remains in `crates/bfi/src/ollama.rs`.
- M6 VSIX discovery of Synapse via `~/.builderforce/desktop.json` (#3767).
- M7 product half (#3776 product slice): blog `synapse-runs-models-itself.md`, DONE.md cut-over entry, `cargo install` documented.
- CubeCL 0.10.0 GPU backends compile for cuda, rocm, metal, and vulkan.

## Functional requirements

- GPU measurement runs on real Metal hardware and real NVIDIA hardware. A compile-only or CPU result does not satisfy M1.
- The M1 report records tok/s for the native engine and for PrismML `llama-bench` tg128 on the same class of run, and states whether native decode is at least 70% of that PrismML figure on each required GPU.
- CubeCL remains pinned at 0.10.0. No backend bump is part of closing M1.
- M3 executes the existing greedy harness against live Bonsai 27B weights and the fork. Missing weights fail the run as not-yet-run, not as a pass.
- M3 does not check 27B weights into CI and does not require CI to download them.
- Release artifacts for the platforms covered by #3782, #4481, and #3777 are GitHub Release binaries signed with the owner Apple Developer ID and with Authenticode. Unsigned uploads do not close the release item.
- Signing uses existing owner secrets. This epic does not invent a new signing identity.
- `import-ollama` stays available in `crates/bfi/src/ollama.rs`. Cut-over must not delete that CLI.
- The sidecar continues to supervise `bfi serve`. `SYNAPSE_USE_OLLAMA` stays deleted.
- VSIX continues to discover Synapse only through `~/.builderforce/desktop.json`.
- ROADMAP Local LLM remains 🔄 Partial, and this epic stays open, until M1, M3, and signed releases are all done.
- Duplicate process wrappers of this epic that were cancelled on 2026-10-14 are not re-filed.

## Acceptance criteria

- M1 is closed only after Metal and NVIDIA runs exist and each meets at least 70% of PrismML `llama-bench` tg128 tok/s, with CubeCL still at 0.10.0.
- M3 is closed only after a live Bonsai 27B greedy comparison versus the fork has been run outside CI and the harness result is recorded. A skipped or weight-less CI job is not a pass.
- #3782, #4481, and #3777 are closed only when the corresponding GitHub Release binaries are signed with the owner Apple Developer ID and Authenticode.
- #3778 and this epic are marked done only after the three items above are done. Partial is the correct ROADMAP state until then.
- Shipped behavior still holds: no `SYNAPSE_USE_OLLAMA`, sidecar supervises `bfi serve`, `import-ollama` remains, VSIX reads `~/.builderforce/desktop.json`, and the M7 product notes stay in place.
- No new issues are opened to recreate the GPU, Synapse, VSIX, or release role-wrappers cancelled on 2026-10-14.

## Out of scope

- Re-implementing M2, M4, M5, M6, or the M7 product slice.
- Marking the epic or the ROADMAP Local LLM row done before M1, M3, and signed releases land.
- Bumping CubeCL off 0.10.0, or treating a successful GPU compile as the M1 performance result.
- Vendoring or fetching Bonsai 27B weights in CI.
- Removing the `import-ollama` CLI, restoring Ollama as the Synapse runtime, or changing VSIX discovery away from `~/.builderforce/desktop.json`.
- Re-filing the cancelled 2026-10-14 duplicate process wrappers.
- New signing identities, new package formats, or release channels beyond the signed GitHub Release binaries already tracked.

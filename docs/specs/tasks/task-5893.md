# PRD: Land `@builderforce/local-first` on `origin/main`

**Parent epic:** #5747 · **Blocks:** #5890, #5892, #5842

## Problem & Goal

### Problem
Committed callers already import `@builderforce/local-first`, but the package itself is not on `origin/main`. Specifically, `packages/local-first/package.json`, `src/index.ts`, `src/store.ts`, `src/sync.ts`, `src/policy.ts`, and `src/journalStore.ts` are absent. A clean clone therefore cannot resolve the specifier. As a result, `bootWebHost`, `bootVsixHost`, and `auditCloseCheckpoint` cannot be committed, and denied-network boots (which depend on local-first semantics) cannot resolve.

### Goal
Land a **closed, self-contained package set** at `packages/local-first/` so that:
1. A clean clone of `origin/main` resolves `@builderforce/local-first`.
2. The symbols already imported by committed callers exist and are exported.
3. A Node test inside the package passes, proving the package is functional in isolation.

This unblocks #5890, #5892, and #5842 without touching their owning files.

## Target Users / ICP Roles
- **Downstream implementation agents** working on #5890, #5892, #5842 who need the import to resolve before committing host-boot and audit-checkpoint code.
- **Frontend engineers** consuming `frontend/src/lib/localFirst/platformPolicy.ts` and related local-first call sites.
- **VS Code extension engineers** (`clients/vscode`) consuming the store/policy API for local record handling.
- **CI / release owners** who need a clean-clone build and test to be reproducible.

## Scope

### In scope
Add the following files, reconstructed from the contracts that existing committed callers already depend on:

| File | Responsibility |
|---|---|
| `packages/local-first/package.json` | Package manifest: name `@builderforce/local-first`, entry points, `exports`, `type`, `scripts.test`, and only the dependencies the source actually needs |
| `packages/local-first/src/index.ts` | Public barrel re-exporting store, sync, policy, and journalStore APIs |
| `packages/local-first/src/store.ts` | `LocalFirstStore` interface/types and `createMemoryLocalFirstStore` in-memory implementation |
| `packages/local-first/src/sync.ts` | Sync types/primitives required by `store.ts` and the barrel (no network side effects at import time) |
| `packages/local-first/src/policy.ts` | The policy exports imported by `frontend/src/lib/localFirst/platformPolicy.ts` |
| `packages/local-first/src/journalStore.ts` | Journal store types/implementation required by the barrel and store |
| `packages/local-first/test/*.test.ts` (or equivalent) | At least one `node:test` suite exercising the package |

The package set must be **closed**: every relative import inside `packages/local-first/src` resolves to a file within the package, and no source file imports from outside the package except declared dependencies.

### Discovery step (required before writing code)
Enumerate the exact import surface by searching the repo for `@builderforce/local-first` and reading `frontend/src/lib/localFirst/platformPolicy.ts` plus the other committed importers. Derive the required exported names and type signatures from **usage**, not guesswork. Where usage leaves a signature ambiguous, choose the narrowest type that satisfies all call sites.

## Functional Requirements

1. **Package resolution.** `@builderforce/local-first` resolves from a clean clone via the repo's existing workspace/module mechanism (npm/pnpm workspaces, tsconfig paths, or equivalent already in use). If workspace registration is required for resolution, add the minimal registration to the root manifest or workspace file; do not restructure tooling.
2. **Store API.** Export `LocalFirstStore` (type/interface) and `createMemoryLocalFirstStore()` returning a working in-memory implementation with the method set required by committed callers.
3. **Policy API.** Export every policy symbol imported by `platformPolicy.ts`, with types compatible with its current usage so `platformPolicy.ts` compiles **unmodified**.
4. **Journal store.** Provide `journalStore.ts` with whatever the barrel and store require, kept dependency-free and in-memory-capable.
5. **Sync module.** Provide `sync.ts` with the types/functions the store and barrel reference. It must be inert at import time: no network calls, timers, or global side effects, so denied-network boots resolve and run.
6. **Denied-network safety.** No module in the package may perform network access, `fetch`, or socket creation during import or during `createMemoryLocalFirstStore()` construction.
7. **Barrel completeness.** `src/index.ts` exports all public symbols; no caller should need a deep import path.
8. **Test.** A `node:test`-based suite in the package that runs via the package's `test` script, with no network and no external services.

## Acceptance Criteria

- [ ] `origin/main` contains `packages/local-first/package.json` and `src/{index,store,sync,policy,journalStore}.ts`.
- [ ] From a clean clone, `import ... from '@builderforce/local-first'` resolves (verified by a fresh install and a resolution check, e.g., a type-check or `node --input-type=module -e "import('@builderforce/local-first')"` equivalent for the repo's module setup).
- [ ] `createMemoryLocalFirstStore`, `LocalFirstStore`, and all policy exports used by `frontend/src/lib/localFirst/platformPolicy.ts` are exported from the package root.
- [ ] `frontend/src/lib/localFirst/platformPolicy.ts` type-checks against the new package with **zero edits** to that file.
- [ ] The package's Node test suite passes via its `test` script with the network disabled.
- [ ] Closure check passes: no relative import in `packages/local-first/src` escapes the package, and no undeclared third-party import exists.
- [ ] `git diff` against `main` shows **no changes** to any file listed under Out of scope.
- [ ] The PR description states that it unblocks #5890, #5892, #5842 and explicitly does **not** close #5747, #5861, #5890, or #5892.

## Risks & Notes
- **Contract drift:** Because the original sources are absent from `origin/main`, signatures are inferred from callers. If a caller relies on behavior not evident from types, flag it in the PR rather than editing the caller.
- **Resolution mechanism:** Confirm how sibling packages are resolved (workspaces vs. path aliases) before adding registration, to avoid introducing a second mechanism.
- **Side-effect discipline:** The denied-network requirement is the primary behavioral constraint; review `sync.ts` first for import-time effects.

## Design

### Architect design — M7 bfi standalone release (CPU sidecar)

**Boundary.** The `bfi` source lives in `SeanHogg/builderforce-inference`, not in this repo. This repo (`seanhogg/builderforce.ai`) only holds the release-notes/blog/`DONE.md`/`ROADMAP.md` copy and the umbrella `release.yml` (npm + Worker + VSIX publishing; it has no `bfi` job today). So the binaries are built and published by a release workflow in the **inference repo**; this repo must not grow a Rust build.

**Release pipeline (in builderforce-inference, tag `v*` or `workflow_dispatch`).**
- Matrix, CPU-only (no GPU runner): `aarch64-apple-darwin` on `macos-latest`, `x86_64-pc-windows-msvc` on `windows-latest`, `x86_64-unknown-linux-gnu` on `ubuntu-latest`. `cargo build --release --locked -p bfi`.
- Package: `bfi-<tag>-<target>.tar.gz` (`.zip` on Windows) plus a `SHA256SUMS` file; upload to one GitHub Release via `gh release create/upload`. A target that fails to build is simply absent; the release notes name it as not shipped and the child ticket stays open.
- Signing is **conditional on secrets and never faked**: a `sign` step runs only when the secret exists.
  - macOS: `APPLE_DEVELOPER_ID_CERT_P12` (base64), `APPLE_DEVELOPER_ID_CERT_PASSWORD`, `APPLE_TEAM_ID`, plus notarization creds; `codesign --options runtime` then `notarytool submit --wait`. This repo already has `agent-runtime/scripts/codesign-mac-app.sh` / `notarize-mac-artifact.sh` to copy the pattern from.
  - Windows: `WINDOWS_AUTHENTICODE_PFX` (base64) and `WINDOWS_AUTHENTICODE_PASSWORD`; `signtool sign /fd sha256 /tr <timestamp-url> /td sha256`.
  - Each leg writes a `signed: true|false` output; the release body is generated from those outputs (`Signed with Apple Developer ID` / `Authenticode` vs. `UNSIGNED — pending owner-supplied signing secrets`). No static copy claims a signature.
- Secrets are GitHub Actions repository secrets set by the owner (#3782). Nothing is committed; the workflow only references `${{ secrets.* }}` and tolerates empty values.

**Install paths (unchanged).** `cargo install --git https://github.com/SeanHogg/builderforce-inference bfi` stays the documented standalone install; the Release binaries are an additional channel. Every user-facing string keeps "Synapse runs models itself; Ollama is not required".

**This repo's changes for M7 (minimal).**
1. Do not edit `ROADMAP.md` Local LLM — it stays 🔄 Partial. Flip only in a PR that lands after #3762, #3764 and #3782 are all done (#3778).
2. Once a release exists, add a one-line link to the Release (with its signed/unsigned status copied from the release body) beside the existing install docs; do not touch the blog or the Synapse release-notes paragraph except to repair an Ollama-required regression.
3. Optional guard (follow-up, not required): a check that fails if `ROADMAP.md`/`DONE.md`/blog reintroduce "requires Ollama".

**Decisions / risks.**
- Unsigned-until-secrets is an accepted shippable state; macOS Gatekeeper and Windows SmartScreen will warn, which the release notes must state plainly.
- Release is owner-gated on secrets for signing only, not for building, so #3777/#4481 can ship unsigned first and re-release signed later.
- Children #3777, #3782, #4481, #3778 remain open; this ticket closes none of them.

# PRD: MK-09-D4 — No-repository runs end `pr_skipped: no_repository`

**ID:** MK-09-D4  
**Source:** PRD 09 §4 GAP-D4 (P1), decision D4  
**Priority:** P1  
**Repo:** seanhogg/builderforce.ai (github, base `main`)

## Problem & Goal

A run with no bound repository must finish as a skipped PR, not as a failed run and not as `needs_host`.

Today `cloudFinalize.ts` emits `pr_skipped` only when files were written and `repoCtx` is null, and the reason is free text (`repoMiss`). The typed reason `no_repository` has no uses under `api/src/application/runtime`, so unbound runs that wrote nothing never take that terminal path.

**Goal:** Every no-repository run ends with terminal event `pr_skipped` and typed reason `no_repository`, including when nothing was written. The run must not fail and must not end `needs_host`.

## Target users / ICP roles

- **Runtime consumers** (orchestrator and host) that branch on terminal event and reason. They need a stable typed reason instead of free text or a missing event.
- **Operators** reviewing run outcomes. An unbound repo is a skip, not a failure and not a host request.
- **Runtime engineers** owning cloud finalize. They need one terminal path and a test that locks it.

## Scope

In scope is the no-bound-repository terminal path in the application runtime, centered on cloud finalize under `api/src/application/runtime`.

- Treat “no bound repository” as `repoCtx` null (no repository bound to the run).
- Emit terminal `pr_skipped` with typed reason `no_repository` whether or not any files were written, including zero writes.
- Stop using free-text `repoMiss` as the reason on this path.
- Add a test that drives this terminal path.

Runs that already have a bound repository are unchanged.

## Functional requirements

1. When a run has no bound repository, cloud finalize must end the run with terminal event `pr_skipped` and reason `no_repository`.
2. The reason must be the typed value `no_repository` used from `api/src/application/runtime`, not free text and not `repoMiss`.
3. The same terminal event and reason must be emitted when zero files were written. File-write count must not gate the event.
4. The same terminal event and reason must still be emitted when files were written and `repoCtx` is null. That case must not keep `repoMiss`.
5. A no-repository run must not be marked failed and must not end `needs_host`. `pr_skipped: no_repository` is the terminal outcome, not an intermediate event later replaced by failure or `needs_host`.
6. A test must cover this terminal path, including the nothing-written case, and assert event `pr_skipped`, reason `no_repository`, and that the run is not failed and not `needs_host`.

## Acceptance criteria

- A no-repository run that wrote nothing ends `pr_skipped` with typed reason `no_repository`.
- A no-repository run that wrote files ends the same way, not with `repoMiss`.
- The run is not a failure and is not `needs_host`.
- `no_repository` is referenced under `api/src/application/runtime` and is the event reason on this path.
- A test covers that terminal path and passes.

## Out of scope

- Failing, retrying, or blocking the run because no repository is bound.
- Emitting or preserving `needs_host` for the no-repository case.
- Changing finalize behavior for runs that have a bound repository.
- Other `pr_skipped` reasons, unrelated `repoMiss` uses, or new terminal event types.
- Host, UI, or copy changes beyond this event contract.
- Broad refactors of cloud finalize that are not required to close GAP-D4.

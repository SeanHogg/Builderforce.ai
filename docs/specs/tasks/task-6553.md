# WIP PRD — B7–B9: Narration Fold, Diagnostics Honesty, and Ship-Time Ticket Titles

## Problem & Goal

Chat transcripts and run diagnostics currently misrepresent execution:

- **B7:** Repetitive assistant narration before tool calls remains in the model transcript, increasing prompt size and encouraging the model to repeat implementation status.
- **B8:** Chat diagnostics report an advertised-tool count of `1` for turns that advertise or call 15+ distinct tools, making tool-usage diagnostics dishonest.
- **B9:** Tickets created from a delta are titled using an estimated changed-file count, so their titles do not reflect the final diff at ship time.

Implement PRD 45 §4.7 items B7, B8, and B9 in the `Builderforce.ai` checkout while preserving concurrent B6 work and all excluded areas.

## Target Users / ICP Roles

- **Chat users:** Receive smaller, less repetitive model context and accurate tool diagnostics.
- **Agent-runtime maintainers:** Can trust advertised-tool counts when evaluating turns.
- **Reviewers and release operators:** See ticket titles that accurately describe the final changed-file set.
- **Downstream automation agents:** Consume deterministic transcript, diagnostic, and ticket-title behavior.

## Scope

### In scope

1. **B7 — Pre-tool narration fold**
   - Add a separate function or section in `Builderforce.ai/brain-embedded/src/run/brainFold.ts`.
   - Fold qualifying assistant narration to the literal text `(progress note)` in the model transcript.

2. **B8 — Honest advertised-tool diagnostics**
   - Correct the per-turn counter in `Builderforce.ai/brain-embedded/src/chatDiagnostics.ts`.
   - Report the number of distinct advertised tools for the turn, not advertisement events or merely the first tool.

3. **B9 — Final-diff ticket title**
   - Locate the `tickets_from_delta` implementation by searching for `Code change` under `brain-embedded` and `packages`.
   - Update ticket titles at ship time using the final changed-path count.
   - Primary implementation location: `Builderforce.ai/brain-embedded/src/selfReviewShip.ts`.

4. Unit or regression tests for B7, B8, and B9.
5. Relevant brain-embedded tests and typecheck.

### Constraints

- Work only in `Builderforce.ai`.
- Do not run any git write command, including commit or push.
- Do not modify `packages/run-guards/src/evidence/`.
- Do not modify `clients/vscode`.
- In `brainFold.ts`, add B7 behavior in a separate new section or function. Do not reorganize existing code or alter B6 superseded-read behavior.
- Keep modified source and test files under approximately 400 lines where practical.
- Existing tests must continue to pass unchanged unless an existing test directly encodes behavior corrected by this PRD.

## Functional Requirements

### B7 — Narration fold

For each assistant turn that contains tool calls:

1. Identify assistant text segments that immediately precede tool calls.
2. Compare the candidate segment’s word set with the previous turn’s corresponding pre-tool text using the word-set overlap measure defined by PRD 45 §4.7.
3. When overlap is at least `0.8`, replace the candidate text in the model transcript with exactly `(progress note)`.
4. Never replace:
   - A final assistant answer.
   - Assistant text in a turn without tool calls.
   - Text that does not meet the overlap threshold.
   - Tool calls, tool results, or unrelated transcript fields.
5. Preserve normal behavior when there is no previous turn or no comparable previous pre-tool text.
6. The regression case must model chat `#216`, including the recurring narration beginning:
   - `I'm mid-implementation across the four views… Continuing…`

### B8 — Diagnostics counter

1. Determine what the existing counter currently measures.
2. Change the reported `advertised per turn` value to the count of distinct tools advertised during that turn.
3. Repeated advertisements or repeated calls of the same tool must not inflate the distinct-tool count.
4. Counts must remain scoped to the individual turn.
5. A regression turn advertising at least 15 distinct tools must report at least 15.

### B9 — Ship-time ticket title

1. Locate every `tickets_from_delta` path that creates a title matching `Code change (N file)`.
2. Preserve the established title template while replacing `N` with the number of final changed paths.
3. Calculate the count at ship time, after the final changed-path set is known.
4. Deduplicate changed paths before counting so a path is not counted multiple times.
5. Update the ticket title even if the ticket was initially created with an estimate.
6. The final title must reflect the actual diff rather than the initial plan or pre-ship delta size.

## Acceptance Criteria

### B7

- A chat `#216`-style regression demonstrates that qualifying repeated pre-tool narration is folded to `(progress note)`.
- A final answer remains unchanged.
- A qualifying turn without tool calls remains unchanged.
- Text below the `0.8` overlap threshold remains unchanged.
- Existing B6 fold and superseded-read behavior remains intact.
- The B7 implementation is isolated in a new function or section of `brainFold.ts`.

### B8

- Before the fix, the implementation report identifies the original counter’s actual measurement behavior.
- A turn advertising 15+ distinct tools reports at least 15.
- Multiple events for one tool count as one distinct advertised tool.
- Diagnostic output identifies the count as a distinct-per-turn value.

### B9

- A ticket created from a delta receives a ship-time title containing the exact final changed-path count.
- Duplicate changed paths are counted once.
- A ticket’s title is updated when the final count differs from its creation-time estimate.
- Search results confirm that all relevant `Code change (N file)` title creation paths use the final count.

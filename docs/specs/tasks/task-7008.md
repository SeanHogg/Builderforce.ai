# PRD: Wire tenant-scoped BYO cooldown into dispatch, seed, route metadata, and tests

## Problem & Goal

`byoCooldown.ts` exists and is unwired. Owner-served `429` / `rate_limit` attempts are dropped by the `coolable` filter in `proxyDispatcher.applyCooldowns`, so a tenant whose BYO model is rate-limited is not cooled, the next request can put that model first again, and route metadata never reports the cooldown. `midCascadeCooldownCheck` always returns false for owner-served models. `proxyFunding.ts` incorrectly documents `vendorHealth` as tenant-scoped. `cooldownStore.ts` still uses raw `kv.get`/`kv.put` plus a module `Map` instead of the shared cache helpers.

Goal: finish W4 (continuation of task 7002 / chat #289) by recording owner-served cooldowns, resetting them on success, demoting cooled BYO seeds before the auto-ladder head is chosen (never demoting an explicit caller pin), exposing `cooled` on the completion envelope and the brain `llm.complete` step, migrating `cooldownStore` onto shared cache helpers, and locking the behavior with one new test file. Shared operator cooldown writes stay unchanged. Ship `leave_uncommitted`. Live gateway proof is blocked (no deploy).

## Target users / ICP roles

- Tenant operators on BYO vendor keys who should see their own rate-limited model demoted without affecting other tenants or the shared operator ladder.
- Callers who pin a model explicitly and must keep that pin even while the model is cooled.
- Downstream implementers on `Builderforce.ai/api` (`application/llm`) and `brain-embedded`, plus the owner of `presentation/routes/llm/chatCompletionResponse.ts` (outside `llm/*`).

## Scope

In-repo work on `seanhogg/builderforce.ai` (base `main`). Touch only the seams below. `byoCooldown.ts` is already written and is the single source for parse, TTL ladder, record, reset, read, and demote — do not fork that logic.

1. **Record owner-served cooldowns** in `proxyDispatcher.applyCooldowns`. Attempts currently dropped by `coolable` go to `recordByoCooldown(cfg.env, cfg.tenantId, a.vendor, a.model, retryAfter)`. Shared `recordFailures` write is unchanged.
2. **Capture Retry-After** through the existing `onUpstreamHeaders` seam (`createHeadroomObserver` in `dispatch()`; `DispatchParams.onUpstreamHeaders` fires on 429). Store in a per-dispatch `Map` keyed by vendor/model, parse with `parseRetryAfter()`, pass the value into `applyCooldowns`.
3. **Success reset.** `successJsonResult` and `dispatchStream` success call `resetByoCooldown` for the owner-served resolved model, alongside `clearVendorHealth`.
4. **Seed demotion.** In `proxySeed.composeCompletionSeed`, after `orderByoSeeds`, run `demoteTenantCooled` over `byoSeeds` before `seedHead` is built so the auto-ladder head demotes. `callerLeads` (explicit pin) is never demoted. Note that in cooled metadata.
5. **Metadata thread.** `cooled: [{ model, until, reason }]` flows `CompletionSeed` → `RoutePlan` (`proxyRoutePlan.ts`) → `ProxyResult.cooled` (`proxyTypes.ts`) → `completeChat` finalize. Serialize in `presentation/routes/llm/chatCompletionResponse.ts` `buildCompletionEnvelope` next to `failovers`. That file is outside `llm/*`; flag the owner rather than treating it as in-scope implementation.
6. **Mid-cascade read.** `proxyDispatcher.midCascadeCooldownCheck` owner-served branch returns `isTenantCooled(cfg.env, cfg.tenantId, vendor, model)` (the one exported reader).
7. **Comment fix.** `proxyFunding.ts` (~lines 99–101): `vendorHealth` is global (`vhealth:${vendorId}`), not tenant-scoped. Correct the comment and name `byoCooldown` as the tenant-scoped store (`byo-cooldown:${tenantId}:${vendor}/${model}`).
8. **Cache migration.** `infrastructure/auth/cooldownStore.ts`: move raw `kv.get`/`kv.put` and the module-`Map` backend (`kvBackend` / `memBackend`) onto shared `infrastructure/cache` helpers, matching `vendorHealth.ts` and `providerHeadroom.ts` (`getOrSetCached` / `setCached` / `invalidateCached` plus memory fallback). Storage change — needs review.
9. **Tests.** New `LlmProxyService.byoTenantCooldown.test.ts`. Harness copied from `LlmProxyService.byoCooldownScope.test.ts` (`llmProxyForPlan` + fetch stub + `_resetMemoryCooldowns`). `beforeEach` also calls `_resetMemoryByoCooldowns` and `__clearL1CacheForTests`.
10. **Brain parse.** `brain-embedded/src/streamChatCompletion.ts` (not `src/run/`): parse `_builderforce.cooled` into the `llm.complete` step beside failovers parsing. Verify the cited line range before editing.
11. **Verify.** API `type-check` script, the new test file, the three unchanged guard files (`byoCooldownScope`, `rateLimitBackoff`, `capacityLimit`), and `brain-embedded` type-check. Do not fill `excludeModels` client-side.

## Functional requirements

- Owner-served `429` / `rate_limit` attempts are recorded on the tenant-scoped BYO store. They are not dropped and they do not write the shared operator failure store.
- Retry-After is taken from upstream headers on the same dispatch, including 429. `parseRetryAfter()` is the only parser (seconds, HTTP-date, `x-ratelimit-reset-requests` / `-tokens` durations, `x-ratelimit-reset` epoch). Absent or unparseable header uses the 60s doubling ladder capped at 15 minutes (`byoCooldownTtlSeconds`). A parsed `Retry-After: 120` yields a 120s TTL.
- A successful owner-served completion (JSON and stream) resets that tenant’s cooldown for the resolved vendor/model and still clears vendor health.
- After seed ordering, cooled BYO models are stably partitioned behind uncooled ones before `seedHead` is chosen. Demotion never drops a model. An explicit caller pin (`callerLeads`) is never demoted; cooled metadata records that the pin was left in place.
- `isTenantCooled` is the only mid-cascade reader for owner-served models. A cooled owner-served model is treated as cooled for that tenant, vendor, and model.
- `ProxyResult.cooled` is `CooledModelInfo[]` (`model`, `until`, `reason`) and is serialized beside `failovers` in the completion envelope once the presentation owner lands the flagged change. Brain reads `_builderforce.cooled` the same way it reads failovers.
- Other tenants and the shared operator cooldown store are unaffected by a tenant’s BYO cooldown.
- `cooldownStore` persistence goes through shared cache helpers with the existing memory fallback. Key semantics and TTL behavior stay the same; only the backend access path changes.
- Test isolation resets both operator memory cooldowns and BYO memory cooldowns, and clears L1 cache, before each case.

## Acceptance criteria

- API `type-check` passes. `brain-embedded` type-check passes.
- New file `LlmProxyService.byoTenantCooldown.test.ts` passes all eight cases:
  1. BYO head 429s, then fails over.
  2. Same tenant, next request: cooled model is not first and appears in `cooled` metadata.
  3. Other tenant is unaffected.
  4. Shared operator store is untouched.
  5. After TTL, the model is tried first again.
  6. Success resets strikes.
  7. `Retry-After: 120` produces a 120s TTL.
  8. Explicit user pin is never demoted.
- `LlmProxyService.byoCooldownScope`, `rateLimitBackoff`, and `capacityLimit` tests pass unchanged.
- `applyCooldowns` routes owner-served coolable attempts to `recordByoCooldown` and does not change the shared `recordFailures` write.
- `midCascadeCooldownCheck` owner-served branch returns `isTenantCooled(...)`, not `false`.
- `proxyFunding.ts` comment states `vendorHealth` is global and `byoCooldown` is the tenant-scoped store.
- `cooldownStore.ts` no longer calls raw `kv.get`/`kv.put` or a private module-`Map` backend; it uses shared cache helpers. Storage-path change is called out for review.
- `streamChatCompletion.ts` parses `_builderforce.cooled` onto the `llm.complete` step next to failovers.
- Presentation envelope serialization is flagged to the file owner if not landed in this change; `llm/*` types already carry `cooled` through `CompletionSeed`, `RoutePlan`, and `ProxyResult`.
- Working tree left uncommitted. No client-side `excludeModels` fill. No live gateway proof.

## Problem & Goal

Dependabot pull request [#915](https://github.com/SeanHogg/Builderforce.ai/pull/915) bumps `next` from 15.5.28 to 15.5.29 in `/frontend` on branch `dependabot/npm_and_yarn/frontend/next-15.5.29`. The patch is a security maintenance release. The PR is blocked by `change_specific_checks_failed` and is out of date with `main`.

Goal: repair that existing PR in place, confirm the bump is compatible and closes the published moderate advisories without regressions, satisfy the repository’s normal checks and sign-offs, then merge it. Close it only if the bump cannot be made safe and green on the existing branch.

## Target users / ICP roles

- Maintainers of `seanhogg/builderforce.ai` who own frontend dependency and release risk.
- Downstream agents that must share this PRD and operate only on PR #915.
- Frontend engineers who ship against Next.js 15.5.x in `/frontend`.

## Scope

- Repository: `seanhogg/builderforce.ai` (GitHub). Base branch: `main`. Head branch: `dependabot/npm_and_yarn/frontend/next-15.5.29`.
- In-scope change: `next` 15.5.28 → 15.5.29 under `/frontend`, plus the lockfile update Dependabot already started (`frontend/package.json`, `frontend/pnpm-lock.yaml`) and any conflict resolution required to land that bump on current `main`.
- Security surface to validate against the 15.5.29 notes:
  - GHSA-pc58-hwjq-p385 — cross-client response injection and disclosure when self-hosted apps forward fetched responses.
  - GHSA-7qx7-33qx-rqx2 — SVG rejection bypass in Next.js image optimization.
  - GHSA-f3mh-rxg3-f5g2 — HttpOnly cookie exposure via an internal response header on Edge runtime routes.
- Repair path: sync latest `main`, fix the reported conflict or check failure, run the relevant checks, and push to the existing Dependabot branch. Do not open a replacement PR.
- Decision: merge when compatibility, security impact, required checks, and required sign-offs are satisfied; otherwise close #915 with the blocking reason.

## Functional requirements

1. Inspect PR #915, its diff, checks, reviews, and mergeability against current `main`. Confirm the only intended dependency change is `next` 15.5.28 → 15.5.29 in `/frontend` and the matching lockfile.
2. Sync the existing head with latest `main`. Resolve conflicts without widening the bump, changing unrelated packages, or rewriting Dependabot authorship beyond what conflict resolution requires.
3. Keep the version pin and lockfile consistent. Do not hand-edit the lockfile in a way that drifts from the package manifest.
4. Assess compatibility for a patch within 15.5.x: no expected public API break; call out any app usage that depends on the fixed behaviors (forwarded fetch responses, `next/image` SVG rejection, Edge response headers / cookies).
5. Record security impact: this release is a moderate security fix, not a feature upgrade. Merging is preferred when checks pass because it reduces exposure on those three advisories. Do not treat the GitHub advisory pages as a substitute for confirming the installed version is 15.5.29.
6. Run the repository’s relevant frontend and PR checks after the sync. Fix failures that are caused by the rebase or this bump. Do not disable, skip, or waive required checks.
7. Require the repository’s normal review sign-offs before merge. Do not automerge around failing checks, missing reviews, or branch protection.
8. Push fixes only to `dependabot/npm_and_yarn/frontend/next-15.5.29`. Do not open a new PR, do not retarget, and do not close-and-recreate.
9. Merge #915 into `main` only when the branch is up to date, the diff is limited to the intended bump plus conflict resolution, required checks are green, and required sign-offs are present. Use the repository’s normal merge method.
10. If the bump cannot be repaired without unrelated product changes, or checks fail for a reason this patch cannot fix, close #915 and state the blocker. Do not leave a conflicted or red PR open as if it were ready.

## Acceptance criteria

- PR #915 still exists as the same pull request; no replacement PR was opened.
- Head branch is `dependabot/npm_and_yarn/frontend/next-15.5.29` and includes latest `main` with conflicts resolved.
- `/frontend` resolves `next` to 15.5.29, and `frontend/package.json` and `frontend/pnpm-lock.yaml` agree.
- Diff versus `main` contains no unrelated dependency or product changes.
- Compatibility conclusion is documented on the PR: patch-level 15.5.x bump, security-only intent, no known app-breaking API change.
- Security conclusion is documented on the PR: 15.5.29 addresses the three moderate advisories listed above.
- Required CI checks for this change are green on the updated head.
- Required human or bot sign-offs required by branch protection are present.
- PR is either merged into `main` under those conditions, or closed with a specific blocker. It is not left mergeable-but-failing, conflicted, or superseded.

## Out of scope

- Opening a new pull request or abandoning #915 in favor of a manual bump PR.
- Upgrading `next` beyond 15.5.29, bumping other dependencies, or adopting Next.js 16.
- Refactors, feature work, or image/Edge/fetch behavior changes beyond what the patch itself ships.
- Ignoring this dependency, this minor line, or this major line via Dependabot comments.
- Force-pushing `main`, bypassing branch protection, or merging with failing required checks.
- Editing unrelated top-level apps, Dockerfiles, or agent config except where a conflict on those files must be resolved to sync `main`.

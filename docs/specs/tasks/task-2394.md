# PRD: Mobile Landing Hero Prompt Visibility

## Problem & Goal

**Problem:** On mobile viewports, the landing canvas hero board used a maximum height of `min(74vh, 620px)`. The resulting hero layout pushed the prompt input below the fold, requiring visitors to scroll before they could start a prompt.

**Goal:** Reduce the mobile board height so the prompt composer is visible and usable in the initial viewport, including on an iPhone 12 Pro at an 844px viewport height.

## Target Users / ICP Roles

- Mobile visitors evaluating the product who want to begin prompting immediately.
- Prospective builders arriving through marketing pages, shared links, or mobile search.
- Mobile visitors using narrow or short-height viewports where vertical space is constrained.

## Scope

- Update `.board` in `Builderforce.ai/frontend/src/components/home/LandingCanvasHero.module.css`.
- Apply the mobile board height constraint of `min(52vh, 420px)`.
- Preserve the existing board presentation, prompt composer, and prompt submission behavior.
- Limit changes to the specified CSS file and the board’s maximum height.

## Functional Requirements

| ID | Requirement |
|---|---|
| FR-1 | On mobile viewports, `.board` must use `max-height: min(52vh, 420px)` instead of `min(74vh, 620px)`. |
| FR-2 | The landing hero must expose the prompt composer without requiring the visitor to scroll the page to reveal it. |
| FR-3 | The prompt composer must remain readable, tappable, and usable at the reduced board height. |
| FR-4 | Board content must remain constrained by the configured maximum height and must not force the prompt composer below the fold. |
| FR-5 | Existing prompt entry, submission, and board interaction behavior must remain unchanged. |

## Acceptance Criteria

1. At an iPhone 12 Pro viewport of 390 × 844 CSS pixels, the prompt composer is visible in the initial viewport without scrolling the landing page.
2. The computed maximum height of `.board` at that viewport is 420px, consistent with `min(52vh, 420px)`.
3. The prompt composer is not clipped, overlapped, or obscured by the board at supported mobile viewport sizes.
4. A visitor can focus the prompt field, enter a prompt, and use the existing submission controls without first scrolling to reach them.
5. The change introduces no horizontal overflow or regressions to existing prompt and board interactions.
6. No files other than `Builderforce.ai/frontend/src/components/home/LandingCanvasHero.module.css` are modified.

## Out of Scope

- Redesigning the landing hero, board, or prompt composer.
- Changing prompt behavior, submission logic, validation, or backend flows.
- Changing board content, animations, or internal scrolling behavior.
- Introducing new responsive breakpoints or additional mobile layout components.
- Separate desktop or tablet height tuning beyond the effects of the shared `.board` rule.

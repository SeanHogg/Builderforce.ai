# PRD: Host relay — page gateway, runtime hook, and both launchers

Ticket #6996 (runtime half). Contract: `Builderforce.ai/docs/specs/app-manifest-ai-resource.md` revision 3 (accepted). Bound repo: `seanhogg/builderforce.ai` (base `main`).

## Problem & Goal

Application runtimes need a host-owned AI forward path so a process can call an OpenAI-compatible `/v1` endpoint without ever seeing host credentials, and without that endpoint appearing as a preview-origin ingress port.

The draft gateway and `HostRelay` types exist and are uncommitted, untypechecked, and untested. They are wrong in three ways: they read `request.path` instead of `HttpRequestData.url`, they type headers too loosely, and registering the gateway port announces a preview URL (`https://<app-origin>/__bfwc/.../__port/<port>/`) and can be treated as ingress.

**Goal:** Fix the draft, register a quiet in-process AI gateway before services start, inject `AI_BASE_URL` only when a `HostRelay` is present, and supply that relay from both launchers (web in-process; VSIX via one token-gated loopback hop). Connection-secret fill stays rejected (`connectionSecretsUnfilled`); #6999 owns the vault.

## Target users / ICP roles

- **Application process** inside a Builderforce runtime: calls `http://localhost:<ephemeral-port>/v1` with a process `Authorization` that must be stripped before the host forward.
- **Signed-in web user:** session attached only on the host side of `forwardAi`.
- **VSIX / extension-host user:** same forward, but the page never holds the session; it crosses one launch-token-gated `/__bf` hop to the extension host.
- **Downstream agents on this ticket:** implement and verify the slice below. Do not renegotiate the accepted contract or the #6999 signature.

## Scope

In scope:

- Fix `builderforce-webcontainers/packages/browser/src/app/aiGateway.ts` and keep `hostRelay.ts` / `types.ts` aligned with the signatures below (fix, do not rewrite).
- Quiet HTTP listen so the gateway port is not announced and is not ingress.
- `startApplicationRuntime` host-relay hook: gateway before services, `aiEndpoint` into existing `serviceEnv`, teardown in `stopAll` and `dispose`.
- Web adapter `HostRelay` and VSIX metadata thread (launcher options → `LaunchInfo` → page `BootDeps` → launcher-page adapter → extension host).
- Export `HostRelay` types from `packages/browser/src/app.ts` if frontend or launcher imports need them.
- Tests and typechecks listed under Acceptance criteria.

Signatures this slice must match (do not change `packages/core`):

```ts
interface HostRelay {
  forwardAi(req: {
    resourceId: string;
    models?: readonly string[];
    body: Uint8Array;
    stream: boolean;
  }): AsyncIterable<Uint8Array>;
  connectionSecrets(connectionId: string): Promise<Record<string, string>>;
}

// already committed in packages/core — do not change
serviceEnv aiEndpoint?(resourceId, client): { baseUrl: string } | undefined

// Gateway base URL: http://localhost:<ephemeral-port>/v1  (no trailing slash)
ApplicationRuntimeOptions.hostRelay?: HostRelay
ApplicationHost.listenHttp?(port, handler, owner): { port, close() }
```

`owner` is `{ applicationId, serviceId }`. `listen(0, handler, owner)` — one port per backend `ai` use.

## Functional requirements

### Gateway draft fixes

1. Read `HttpRequestData.url` (path + query). Do not read `request.path`.
2. `headerMap` accepts `Record<string, string>` only (`HttpRequestData.headers`).
3. `startAiGateway` registers one port per backend `ai` use via `listen(0, handler, owner={applicationId, serviceId})`.
4. `aiGatewayHandler`:
   - Strips process `Authorization`. Never copy it onto the relay request.
   - Rejects a model outside the host-read allowlist. Absent allowlist forwards.
   - Streams via `streamBytes`. Do not buffer the upstream body.
   - Writes only `content-type` and `cache-control` back to the process. Never `Set-Cookie`, `Authorization`, or `WWW-Authenticate`.
5. Frontend `ai` uses get no port.
6. Gateway module must not import `previewHeaders`.

### Quiet listen (not a preview port)

7. `PortRegistry.listen` emits `'open'`, and `ProcessHost`'s port watcher calls `serverUrl()`, which builds `https://<app-origin>/__bfwc/.../__port/<port>/`. Owning the port as the backend service does **not** hide it from preview `/__port`.
8. `ApplicationHost.listenHttp` registers an HTTP handler **without** announcing a preview URL and **without** treating the port as ingress: a quiet flag on `PortRegistry.listen`, or do not emit `'open'` / do not call `servers.portChanged` for gateway ports.
9. Do not add the gateway port to `previewIngress` routes.
10. Implement `listenHttp` on `host.ts` next to `listenTcp` and on `PreviewRuntime` (`runtimeOptions.ts`). `startApplicationRuntime` calls `options.runtime.listenHttp`. Fallback only if a test double has no `listenHttp`.

### Runtime hook

11. `startApplicationRuntime.ts` accepts `options.hostRelay`.
12. Register the gateway **before** services start: same moment as `portPolicy.register` (~line 139) and early enough that `serviceEnv` can see the base URL (before the `superviseService` loop at ~line 80, or compute env lazily).
13. Pass `aiEndpoint` into the existing `serviceEnv(spec, id, { databaseCredentials, aiEndpoint })` call (~line 85). `aiEndpoint` returns `{ baseUrl }` from the gateway: `http://localhost:<port>/v1`, no trailing slash.
14. Unregister/close the gateway in `stopAll` and `dispose`.
15. No relay ⇒ no `AI_BASE_URL` (current behaviour).

### Web adapter

16. `Builderforce.ai/frontend/src/lib/runTarget/browserRunTarget.ts` (~line 100) supplies an in-process `HostRelay`.
17. `forwardAi` attaches the signed-in session via `getStoredWebToken` / the existing API client. Do not invent a new auth path. `POST /v1/chat/completions` on the API host. Stream the body; do not buffer.
18. Do **not** add the API host to `PREVIEW_DEFAULT_EGRESS` or any `connect-src`.
19. `connectionSecrets`: `connectionSecretsUnfilled` (rejects). Do not invent vault field names. Document the stub. #6999 owns the vault fill.

### VSIX launcher thread

20. Thread **metadata, not a function**: `createLocalLauncher` options (`packages/browser/src/launcher/server/launcher.ts` `LocalLauncherOptions`) → `LaunchInfo` (`launcher/protocol.ts` — token + forward endpoint metadata only) → page `BootDeps` (`launcher/page/bootApplication.ts`, `runtimeDeps.ts`).
21. Page adapter lives in the **launcher page**. `forwardAi` crosses **one** token-gated loopback hop on the existing page-origin-only `/__bf` API (`LAUNCH_TOKEN_HEADER` / `LAUNCH_TOKEN_PARAM`; `pageRoutes.ts` `serveApi`) to the extension host (`Builderforce.ai/clients/vscode/src/composerCommands/host.ts`, which calls `createLocalLauncher` at line 162).
22. Extension host attaches the session and forwards to `POST /v1/chat/completions`.
23. Preview origins (`<key>.localhost`) must never be served `/__bf`. Missing or wrong launch token is 403.
24. Do not add a second `startApplicationRuntime` under `clients/vscode`.
25. Export `HostRelay` types from `packages/browser/src/app.ts` if the frontend or launcher need them.

### Port policy

26. A service whose `resourceUses` does not name the resource cannot dial the gateway port.
27. The gateway port is not ingress and is not published on a preview origin.

## Acceptance criteria

- Process `Authorization` is not forwarded; host session is attached on the host side of `forwardAi`.
- Response to the process never includes `Set-Cookie`, `Authorization`, or `WWW-Authenticate`. Only `content-type` and `cache-control` are written.
- Model outside the host-read allowlist is rejected; absent allowlist forwards.
- Body is streamed (`streamBytes` / `AsyncIterable<Uint8Array>`), not buffered, on both adapters.
- Gateway base URL is `http://localhost:<ephemeral-port>/v1` with no trailing slash. Frontend `ai` uses get no port. No relay ⇒ no `AI_BASE_URL`.
- Gateway is registered before services start; `aiEndpoint` is passed into the existing `serviceEnv` call; gateway is closed in `stopAll` and `dispose`.
- Gateway port is not announced (`serverUrl` / `'open'` / `servers.portChanged`), is not on `previewIngress`, and is not reachable as `https://<app-origin>/__bfwc/.../__port/<port>/`.
- A service whose `resourceUses` does not name the resource cannot dial the gateway port.
- `/__bf`: missing or wrong launch token → 403. `/__bf` is not served on a preview origin (`<key>.localhost`).
- A trace or test shows VSIX `/launch` supplies `HostRelay` into the launcher page's `startApplicationRuntime` options (gateway + `aiEndpoint` registered). No second runtime under `clients/vscode`.
- `connectionSecrets` remains `connectionSecretsUnfilled` (rejects). No new vault field names.
- API host is not added to `PREVIEW_DEFAULT_EGRESS` or any `connect-src`. Gateway module does not import `previewHeaders`.
- Verify from `builderforce-webcontainers` (lockfile root): `pnpm typecheck` and the scoped tests added for this slice. For frontend and `clients/vscode`, run their typecheck/test scripts scoped to what was touched.
- Do not commit or push. Do not touch production databases.

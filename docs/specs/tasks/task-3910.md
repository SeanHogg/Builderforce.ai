# PRD: M6 — VSIX Synapse Discovery + Model-Tab Install

> **Status:** WIP / shared working draft. **Repo:** `seanhogg/builderforce.ai` (base `main`).
> **Note:** Only the top-level repo layout was available when drafting. Module paths, API names, and existing component locations are **not yet verified**; items flagged *(verify)* must be confirmed by the implementing agent against the actual code before work starts.

---

## 1. Problem & Goal

### Problem
Builderforce users work with local/hosted models ("Synapses") but have no first-class way to find and install them from inside the VS Code extension (VSIX). Today, acquiring a Synapse requires leaving the editor, locating artifacts elsewhere, and wiring them up manually. This fragments the workflow, increases setup friction, and hides available Synapses from users who don't already know they exist.

### Goal
Deliver **in-extension discovery and one-click installation of Synapses**, surfaced through a dedicated **Model tab** in the VSIX UI, so that a user can browse available Synapses, understand what each does, install one, and see it become available for use, without leaving VS Code.

### Success looks like
- A user opens the Model tab, finds a Synapse, installs it, and can immediately select/use it.
- Install state (available / installing / installed / failed / update-available) is always accurate and visible.
- Failures are recoverable and clearly explained, never leaving a half-installed Synapse.

## 3. Scope

### In scope (M6)
1. **Discovery:** Query the Synapse catalog/registry and present browsable, searchable results in the VSIX.
2. **Model tab UI:** A dedicated tab within the extension showing available and installed Synapses, with detail view per Synapse.
3. **Install flow:** One-click install with progress, cancellation, success/failure states, and persistence of installed state.
4. **Installed-state management:** List installed Synapses; surface updates; support uninstall/remove.
5. **Selection handoff:** Installed Synapses are selectable/usable by existing extension features *(verify integration point)*.
6. **Telemetry hooks** for discovery/install funnel (respecting any existing privacy settings).

### Assumptions to validate *(verify)*
- A Synapse catalog source/API already exists or is defined elsewhere in the repo (likely under `Builderforce.ai/` or `agent-runtime/`); if not, a minimal catalog contract must be defined as a dependency.
- The VSIX extension source location and its existing webview/tab architecture.
- Where/how Synapse artifacts are stored locally and how the runtime loads them.

## 4. Functional Requirements

### FR-1 Discovery
- FR-1.1 The Model tab fetches the Synapse catalog on open and on manual refresh.
- FR-1.2 Results display name, short description, version, size, publisher/source, and compatibility info.
- FR-1.3 Users can search by text and filter (e.g., installed / not installed, category/capability *(verify available metadata)*).
- FR-1.4 Catalog responses are cached locally with a sensible TTL; the tab remains usable offline, showing cached + installed items with a clear "offline" indicator.
- FR-1.5 Empty, loading, and error states are all explicitly designed (no blank panels).

### FR-2 Synapse detail view
- FR-2.1 Selecting a Synapse shows full description, version, size, requirements, license, and changelog if available.
- FR-2.2 Incompatible Synapses (e.g., unsupported platform/runtime version) are clearly marked and install is disabled with a reason.

### FR-3 Install
- FR-3.1 An **Install** action downloads and installs the Synapse with visible progress (determinate where size is known).
- FR-3.2 Install is **cancellable**; cancellation cleans up partial artifacts.
- FR-3.3 Artifact integrity is verified (checksum/signature *(verify mechanism)*) before the Synapse is marked installed.
- FR-3.4 Install is **atomic**: a failure at any step leaves no partially installed Synapse and returns the UI to a retryable state.
- FR-3.5 Concurrent installs are either queued or explicitly limited; the same Synapse cannot be installed twice simultaneously.
- FR-3.6 Sufficient disk space is checked up front, with a clear message if insufficient.

### FR-4 Installed-state management
- FR-4.1 The Model tab lists installed Synapses with version and install date.
- FR-4.2 Users can **uninstall** an installed Synapse (with confirmation); this removes artifacts and updates state.
- FR-4.3 When a newer version exists, the UI shows **Update available** and offers an update action.
- FR-4.4 Installed state persists across VS Code restarts and is reconciled with on-disk reality on startup (self-healing if artifacts are missing/corrupt).

### FR-5 Selection & integration
- FR-5.1 After install, the Synapse appears in the existing model/Synapse selection surface *(verify)* without requiring a window reload.
- FR-5.2 A "Set as active" / "Use this Synapse" action is available from the detail view for installed items.

### FR-6 Observability
- FR-6.1 Emit events: catalog viewed, search used, install started/succeeded/failed/cancelled, uninstall, update. Include error category (not sensitive data).
- FR-6.2 Respect VS Code telemetry opt-out settings.

---

## 5. Non-Functional Requirements

- **Performance:** Model tab renders cached content in <500 ms; catalog refresh is non-blocking.
- **Reliability:** Network failures, interrupted downloads, and corrupt artifacts are handled gracefully with retry.
- **Security:** Downloads over HTTPS only; integrity verified; no execution of downloaded content outside the sanctioned runtime loading path. Aligns with `SOC2_TYPE1_COMPLIANCE.md` expectations *(verify applicable controls)*.
- **Accessibility:** Tab is keyboard-navigable and screen-reader friendly, following VS Code webview a11y guidelines.
- **Compatibility:** Works across supported OSes and the minimum supported VS Code version *(verify)*.

---

## 6. Acceptance Criteria

1. **Discovery:** Given network access, when a user opens the Model tab, then a list of Synapses loads with name, description, version, and size, and search/filter narrow results correctly.
2. **Offline:** Given no network, when the tab opens, then cached and installed Synapses display with an offline indicator, and Install is disabled with an explanatory message.
3. **Install success:** When a user clicks Install on a compatible Synapse, then progress is shown, integrity is verified, the Synapse appears as *Installed*, and it is selectable for use without reloading VS Code.
4. **Install failure/cancel:** When an install fails or is cancelled mid-way, then no partial artifacts remain, the UI shows a clear error (or returns to *Available* on cancel), and Retry works.
5. **Integrity:** Given a tampered or corrupt artifact, when installing, then install is rejected and the user is informed.
6. **Incompatible:** Given an incompatible Synapse, then Install is disabled and the reason is displayed.
7. **Uninstall:** When a user confirms uninstall, then artifacts are removed, state updates, and the Synapse no longer appears as selectable.
8. **Persistence & reconcile:** After restarting VS Code, installed state is accurate; if an installed artifact was deleted externally, the Synapse is flagged/repaired rather than shown as healthy.
9. **Update:** Given a newer catalog version, then *Update available* appears and updating replaces the old version atomically.
10. **Telemetry:** Install funnel events fire as specified and are suppressed when telemetry is disabled.
11. **Quality gate:** Unit tests cover install state machine and error paths; at least one integration/e2e test covers discover → install → select; no regressions in existing extension tests; docs updated.

## 7. Out of Scope (M6)

- Authoring, training, fine-tuning, or publishing new Synapses.
- Authentication/billing/paid-Synapse entitlement flows.
- A full Synapse marketplace (ratings, reviews, comments, social features).
- Server-side catalog/registry build-out beyond a minimal contract (unless confirmed missing, in which case spin out a separate task).
- Cross-device/cloud sync of installed Synapses.
- Auto-update without user consent.
- Non-VS Code clients (web, JetBrains, CLI).

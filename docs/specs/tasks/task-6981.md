# Icon buttons for view modes and panel controls

## Problem & Goal

In `Builderforce.ai/packages/knowledge-graph-view`, the view switcher and canvas panel controls are still text pills. The Code Visualizer redesign (ROADMAP knowledge view, opened 2026-11-21, plus the user’s screenshot) requires those controls to be icon buttons. Accessible names, tooltips, and existing role queries must stay the same so localization and tests keep working.

Goal: the View radiogroup and the Panels / Risk overlays triggers render an icon only (no visible label text), with the existing localized accessible name and tooltip, without changing unrelated chrome.

## Target users / ICP roles

- Engineers using the BuilderForce Visualization webview who switch cameras and open panels from the knowledge-graph canvas.
- Downstream implementers working only in `packages/knowledge-graph-view` surface UI and its package tests.

## Scope

Files:

- `Builderforce.ai/packages/knowledge-graph-view/src/surface/ui/Segmented.tsx`
- `Builderforce.ai/packages/knowledge-graph-view/src/surface/CameraBar.tsx`
- `Builderforce.ai/packages/knowledge-graph-view/src/surface/PanelDock.tsx`
- `Builderforce.ai/packages/knowledge-graph-view/src/surface/OverlayMenu.tsx`
- `Builderforce.ai/packages/knowledge-graph-view/src/KnowledgeGraphView.surface.test.tsx`
- `Builderforce.ai/packages/knowledge-graph-view/src/surface/SceneOverlay.test.tsx`

`SceneTools.tsx` should need no logic change if `PanelToggle` and `OverlayMenu` own the icons. Read `HEADER_PANELS` / `panels.ts` for real panel ids and icon only ids that exist. Read `CameraBar` for the cameras that already exist; do not invent a Simulate camera.

## Functional requirements

1. **Segmented icon items.** A `SegmentedItem` may carry an optional `icon` ReactNode. When `icon` is set, the control shows only that icon. The svg is `aria-hidden`. Do not render `item.label` as visible text. Always set `aria-label={item.label}` and `title={item.title ?? item.label}` so `getByRole('radio' | 'button', { name: label })` still matches. Select-mode radio semantics, arrow keys, and the selected accent style stay. An icon item is a square control: reuse CONTROL height, padding 0, inline-flex centered. Text items with no icon stay as they are.

2. **Camera switcher icons.** In `CameraBar.tsx`, pass an icon for every switcher camera. Add a small local Glyph helper by copying the existing 16×16 `currentColor` stroke svg in that file. Glyphs by camera id:

   - `transit`: isometric map (two offset rects)
   - `system`: three stacked layers
   - `graph`: three connected nodes
   - `map`: radial mind-map (center dot, three spokes)
   - `3d`: a cube
   - `heat`: three rising bars
   - `style`: a swatch circle
   - `features`: a flag
   - `list`: three horizontal lines
   - `sequence`: a timeline, only if that id appears
   - `simulate`: a play triangle, only if that id already exists

   Do not rename labels. Do not add Simulate if it is not already a camera. Do not rename Map to Simulate.

3. **Panel toggle icons.** In `PanelDock.tsx` `PanelToggle`, pass icons into the Segmented items. The collapsed Menu trigger gets an icon plus the existing `panelsLabel`, not a new English string. Icons only for ids that exist:

   - `coverage`: shield
   - `patterns`: grid
   - `api`: braces
   - `agentRuns` / `agent-runs`: a person-or-bot mark
   - `sync`: circular arrows
   - `run`: play

4. **Risk overlays trigger.** In `OverlayMenu.tsx`, the Risk overlays trigger becomes an icon button (warning triangle). `aria-label` and `title` stay the existing localized label. Menu items and their behavior are unchanged.

5. **Tests.** Update assertions that expect switcher or panel/overlay control `textContent` to equal the label strings (`KnowledgeGraphView.surface.test.tsx` around the `cameras()` textContent expectation, and any SceneOverlay / header test that reads visible text of those controls). Assert `aria-label` or the accessible name instead. `getByRole(..., { name })` must still pass.

## Acceptance criteria

- The View radiogroup renders an svg per camera and no visible label text. Each control’s accessible name is the existing label. `title` shows that label (or the existing title when set).
- Panel Segmented controls and the collapsed panels Menu trigger render an svg and do not show a new English label. Accessible name remains the existing localized label / `panelsLabel`.
- The Risk overlays trigger is a warning-triangle icon button. Accessible name and tooltip remain the existing localized label. Menu behavior is unchanged.
- Select-mode radios, arrow-key movement, and selected accent styling still work. Icon buttons are square (CONTROL height, padding 0, centered). Text-only Segmented items are unchanged.
- Package tests for the listed surface files pass. Name queries still find these controls. `textContent` expectations that required the visible label string are updated to the accessible name.

## Out of scope

- Question chips, the ask bar, and zoom/Fit. Do not add zoom/Fit to the top bar. Do not change question-chip copy.
- Stage tilt, the API drawer, `ApiEndpointRow`, and `labels/surface.api.ts`.
- Renaming any camera or panel label, including Map to Simulate.
- Adding a Simulate camera or any panel id that is not already present.
- Blocking on the design URL; it is unverified. Follow the screenshot and the ROADMAP knowledge-view contract.
- Logic changes in `SceneTools.tsx` unless icons cannot be owned by `PanelToggle` and `OverlayMenu`.

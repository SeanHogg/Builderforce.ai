## Requirements

The autonomy wiring audit must count a spec-shaped in-review ticket as a non-code deliverable, not as missing code. Production behaviour is already implemented; this ticket only pins it. Do not change production code unless a test proves a bug. Do not edit `ROADMAP.md` or `DONE.md`.

### Classification (already implemented)

`classifyReviewDeliverable` in `api/src/application/activity/autonomyWiringAudit.ts` is the seam `review_has_deliverable` filters on. It delegates “does this ticket expect a branch?” to `expectsCodeDeliverable(taskType, actionType, title)`:

- Return `non_code` when that helper is false. A spec-shaped title (`isSpecShapedTitle`) is non-code even when the action type is a coding shape (`backend_api`, `frontend_ui`) and there is no branch or PR. The document is the deliverable.
- Return `has_code` only when the ticket expects code and has `gitBranch` or `githubPrUrl`.
- Return `missing_code` only when the ticket expects code and has neither.

Pins that must hold:

- `actionType: backend_api`, title `Write the PRD for the billing API`, no branch → `non_code` (not `missing_code`).
- `actionType: frontend_ui`, title `Spec: onboarding wizard`, no branch → `non_code`.
- Title `Implement the billing API per the spec`, no branch or PR → `missing_code` (a title that says implement is code work that merely references a spec).
- The same implementation title with a branch → `has_code`.

`review_has_deliverable` fails only on `missing_code` rows. Spec-shaped tickets must not fail that check.

### Test

No database fixture: the audit’s review check is a filter over that pure function. Verify with the api package test script scoped to that file. No unrelated refactors.

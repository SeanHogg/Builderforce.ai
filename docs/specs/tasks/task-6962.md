# PRD: Wire KnowledgeGraphView depth trail and walkthrough step

## Problem & Goal

Depth navigation and walkthrough narration already exist as isolated surface pieces, but `KnowledgeGraphView` does not pass the drill stack, system title, climb handler, or current step into the components that render them. Users who drill into a graph therefore do not see a depth trail they can climb, and the act panel does not show the walkthrough sentence for the current step.

Goal: finish the remaining slice of tickets 6952 and 6953 by wiring those existing props only, then prove the surface tests and typecheck pass. Do not redo or revert work already landed.

## Target users / ICP roles

- Product engineers working in `packages/knowledge-graph-view` who need the graph surface to reflect drill depth and the current walkthrough step.
- Downstream agents and reviewers who share this PRD and must not reopen completed `ActCards`, `ActPanel`, `PathStrip`, or `useDrill` behaviour.

## Scope

In-scope files and behaviour:

- Re-read `src/KnowledgeGraphView.tsx` immediately before editing, then pass into the existing `<PathStrip>`:
  - `trail={surface.drill.stack}`
  - `systemName={titleOf(graph.scope.rootId)}`
  - `onClimb={surface.drill.climb}`
- Pass `step={surface.step}` into the existing `<ActPanel>`.
- If `tsc` fails only because inline `DrillModel` fixtures omit `climb`, add `climb: vi.fn()` next to existing `out: vi.fn()` fixtures under `packages/knowledge-graph-view`. Do not change drill behaviour.
- From `Builderforce.ai/packages/knowledge-graph-view`, run:
  - `pnpm exec vitest run src/surface --pool=threads`
  - `pnpm --package=typescript dlx tsc --noEmit -p .`
- Fix failures only in files this slice owns.

Already landed and must not be reverted:

- `surface/ActCards.tsx` exports `WalkthroughNote` (sentence + metaphor).
- `surface/ActPanel.tsx` renders it beside the action cards when a path is drawn, using optional `step` (default 0).
- `surface/PathStrip.tsx` accepts `trail`, `systemName`, and `onClimb`, renders `DepthTrail` above the journey, and renders `data-testid="kg-step-narration"` via `walkthroughSentence`.
- `surface/transit/useDrill.ts` `climb(depth)`: `0` is the system; a non-finite or negative depth is `0`; a depth at or past the current stack is a no-op. Existing `out()` is unchanged.

## Functional requirements

1. `KnowledgeGraphView` must pass the current drill stack as `PathStrip` `trail`, the root scope title as `systemName`, and `surface.drill.climb` as `onClimb`.
2. `KnowledgeGraphView` must pass the current surface step into `ActPanel` so the walkthrough sentence matches that step once a path is drawn.
3. The wire must be minimal: no new drill logic, no redesign of `DepthTrail`, `PathStrip`, `ActPanel`, or `WalkthroughNote`, and no change to `climb` or `out` semantics.
4. Type fixtures that construct a `DrillModel` and already stub `out` must also stub `climb` when that is required for `tsc` to succeed.
5. Surface tests under `src/surface` and the package typecheck must pass after the wire. Failures outside files this slice owns are not in scope to rewrite.

## Acceptance criteria

- `DepthTrail.test.tsx` passes, including the `PathStrip` case that clicks "Back to App" and expects the narration `Walk the hallway from Login to Accounts (2 calls). Leave through the door Accounts.`
- With `step` passed from the view, the act panel shows the walkthrough sentence for the current step.
- `pnpm exec vitest run src/surface --pool=threads` passes from `Builderforce.ai/packages/knowledge-graph-view`.
- `pnpm --package=typescript dlx tsc --noEmit -p .` passes from that package, with fixture-only `climb: vi.fn()` additions if and only if missing `climb` is the failure.
- No commit is created.
- Landed `WalkthroughNote`, `ActPanel` rendering, `PathStrip` trail rendering, and `useDrill.climb` behaviour are unchanged.

## Out of scope

- Reimplementing `WalkthroughNote`, `ActPanel`, `PathStrip`, `DepthTrail`, or `useDrill`.
- Changing `climb` rules or existing `out()` behaviour.
- New product features, visual redesign, or unrelated knowledge-graph tickets.
- Fixing failures in files this slice does not own.
- Committing, pushing, or opening a pull request.

# PRD: Commit the local read path so an offline run reads its work back out of the local store

## Problem & Goal

Gap G06 (#5840, epic #5747) shipped the library half in commit `1dd5a46bd` on `origin/main`: `installLocalDomainTools` installs on the host dispatch path, a denied `project-create` / `ticket-create` writes the local repository and queues a sync event instead of reaching `bfApi`, and the acceptance test reads the real host file.

The write path is wired, but the local read path is not on HEAD. `clients/vscode/src/runChangeSetRecorder.ts`, `installRunChangeSets.ts`, `localRead.ts`, and `localWorkManagement.ts` exist only as untracked working-tree files. Nothing committed proves that a run started with the platform denied reads its project and ticket back out of the local store, or that a run-change-set sync event is queued durably.

Goal: review those four modules for correctness, commit them without sweeping unrelated dirty work, and land a committed test that an offline (platform-denied) run serves its own project and ticket from the local store and durably queues a run-change-set sync event.

## Target users / ICP roles

- Extension host runtime: the agent run that must keep working when platform domain tools are denied.
- Downstream reviewers and agents on epic #5747 who need committed evidence, not untracked files, that local-first read and durable queueing actually serve the run.

## Scope

In-scope, and only these paths unless a selective hunk in `clients/vscode/src/extension.ts` is strictly required to install the recorder:

- Review, then commit: `clients/vscode/src/runChangeSetRecorder.ts`, `clients/vscode/src/installRunChangeSets.ts`, `clients/vscode/src/localRead.ts`, `clients/vscode/src/localWorkManagement.ts`.
- A committed test that starts a run with the platform denied and asserts the run reads its project and ticket from the local store (not the platform) and that a run-change-set sync event is queued durably.
- If the recorder must be wired from `extension.ts`, inspect `git diff` first and stage only the hunk that performs that wiring. The commit must not include the other agent’s ~66 uncommitted lines or the import of the untracked `sendPermissionActivation` module.

Repo: `seanhogg/builderforce.ai`, base `main`. Do not treat untracked files as already reviewed; they have never been through review.

## Functional requirements

1. Review each of the four untracked modules before commit. Correctness bar: a denied domain-tool run writes locally, then a later read in the same offline run returns that project and ticket from the local store, and the run-change-set is stamped onto a durable sync queue rather than an in-memory-only side effect.
2. Commit those four files (and any test file required by requirement 3) so HEAD knows about them. Do not leave the local-read or recorder implementation untracked.
3. Land a committed test that fails if the local read path or the durable run-change-set queue stamp is absent. The test must show:
   - a run started with the platform denied;
   - that run reading its project and its ticket back out of the local store;
   - a run-change-set sync event queued durably.
4. Preserve the already-shipped host dispatch contract: `installLocalDomainTools` on the host path, `runInstalledDomainTool` returning the host domain-tool line, and `routeDeniedDomainTools` wrapping the catalog the run executes. Do not re-open the library half or point the acceptance test back at the library instead of the host file.
5. Shared-tree isolation: do not stage or commit `clients/vscode/src/extension.ts` by path, `clients/vscode/package.json`, or any `package.nls*.json`. Do not touch the other ~90 dirty or untracked files. If `extension.ts` must change, the commit contains only the recorder-wiring hunk.

## Acceptance criteria

- `runChangeSetRecorder.ts`, `installRunChangeSets.ts`, `localRead.ts`, and `localWorkManagement.ts` are committed on a branch based on `main`, after review, and are no longer untracked-only.
- A committed test demonstrates an offline, platform-denied run reading its project and ticket from the local store, and a run-change-set sync event queued durably. Removing the local-read wiring or the durable queue stamp fails that test.
- The commit does not include other agents’ edits to `extension.ts`, `package.json`, or the five `package.nls*.json` catalogs, and does not reference an uncommitted module such as `sendPermissionActivation`.
- No other dirty or untracked files in the shared tree are included.
- The previously shipped denied-write behavior (local repository write plus sync event, no `bfApi` call) remains intact.

## Out of scope

- Re-implementing or re-verifying the already-shipped library/host write path from `1dd5a46bd`, except as a regression check that this change does not break it.
- #5936 (registering the dead-letter command), including any edit blocked on the dirty `extension.ts`.
- #5938 (corrupt-snapshot recovery).
- Committing or cleaning anyone else’s in-flight work, including the ~66 uncommitted lines in `extension.ts`, package manifests, NLS catalogs, and the rest of the dirty shared tree.
- Product UX, billing, or platform API changes beyond what the local read path and durable run-change-set queue require.

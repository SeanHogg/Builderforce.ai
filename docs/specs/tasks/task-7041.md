# PRD: Intent clarification before hire or manifest write

## Problem & Goal

When a user utterance contains the word “agent” and the project already has an app manifest, the run can take two different product paths: hire a teammate onto the board, or write an AI feature into the app manifest. Those paths are not interchangeable. Starting either one without a fixed human choice risks hiring the wrong thing or writing the wrong resource.

Goal: before any hire tool and before any manifest write, the run preamble asks the human channel a fixed two-option question and routes on that answer only. The clarification is a pure function with no LLM. This slice lands on its own and does not wait on the `ai` resource release.

## Target users / ICP roles

- Product owner or builder driving a run in a project that already has an app manifest, who said “agent” and must pick teammate vs in-app feature.
- Downstream agents that share this PRD: the run-preamble implementer and the brain-embedded test author. They implement the contract; they do not invent copy or a third path.

## Scope

In scope for epic #6994 / task #6997, contract `docs/specs/app-manifest-ai-resource.md` §12:

- A pure function `clarifyAgentIntent(utterance: string, hasAppManifest: boolean)` in the brain-embedded package.
- Return type: `null` or exactly `{ question: 'Add an AI agent — which one?'; options: ['a teammate on the board', 'an AI feature inside the app'] }`.
- Call site: the run preamble (`brain-embedded/src/runStore/runPreamble.ts` is the candidate) asks the human channel that exact list before any hire tool and before any manifest write.
- Routing: hiring stays the teammate path; the manifest path is the feature path.
- Verification with the brain-embedded package’s own test runner. Changes stay uncommitted (`leave_uncommitted`; owner run ships once).
- Base: `seanhogg/builderforce.ai`, branch `main`. No code exists yet for this slice.

## Functional requirements

1. `clarifyAgentIntent` is a pure function. It does not call an LLM, network, or store. Same inputs always yield the same output.
2. It returns the fixed choice object only when both are true: the utterance contains the word `agent` (case-insensitive whole word), and `hasAppManifest` is true.
3. Otherwise it returns `null`. No question is asked. Hire and manifest write proceed under existing rules without this gate.
4. The question string is exactly `Add an AI agent — which one?`. The options array is exactly `['a teammate on the board', 'an AI feature inside the app']` in that order. No paraphrase, no extra option, no reordering.
5. The run preamble presents that exact list on the human channel and waits for the choice before invoking any hire tool and before any manifest write.
6. Choice `a teammate on the board` follows the existing hire / teammate path only. It must not write the app manifest as an AI feature.
7. Choice `an AI feature inside the app` follows the manifest / feature path only. It must not hire a teammate.
8. If the function returns `null`, the preamble does not inject this question and does not block hire or manifest write on this slice’s account.
9. This slice has no runtime or compile dependency on the `ai` resource release. It can merge independently of other slices of the epic.

## Acceptance criteria

- Unit tests in the brain-embedded package’s own test runner cover: word `agent` present and `hasAppManifest === true` returns the exact question and the two options in order; missing word, non-word substring (for example “agency”), or `hasAppManifest === false` returns `null`; repeated calls with the same inputs are identical.
- The returned question and options match the strings above character-for-character. Tests fail on paraphrase, a third option, or a reordered list.
- Preamble integration: when the function returns the choice object, the human channel is asked that list, and neither a hire tool nor a manifest write runs until the human answers.
- Answer `a teammate on the board` takes the hire path and does not perform a manifest feature write. Answer `an AI feature inside the app` takes the manifest feature path and does not hire.
- When the function returns `null`, preamble does not ask this question and does not add a new block on hire or manifest write.
- The slice builds and tests without the `ai` resource release present.
- Working tree changes for this slice are left uncommitted.

## Out of scope

- Implementing or releasing the `ai` manifest resource, its schema, or other slices of epic #6994.
- Any LLM classification, paraphrased prompts, free-text clarification, or a third option.
- Changing hire-tool behavior or manifest-write behavior beyond gating them on this fixed choice when the function returns the choice object.
- Shipping, committing, or opening a pull request. Owner run ships once under `leave_uncommitted`.
- UI beyond asking the human channel the exact list specified above.

# PRD: Execute $0 platform migration

## Problem & Goal

### Problem
The platform is being run at the lowest sustainable cost. Neon (Postgres) is on the **Free** tier; the Cloudflare account is on **Workers Paid**. Several earlier passes acted on a wrong premise ("Cloudflare is also Free") and began disabling paid-only runtime features. The ticket needs a single authoritative record of what is done, what must NOT be touched, and what remains.

### Goal
Finish the $0 database migration (Neon Free) without removing any capability that the Workers Paid deployment legitimately backs, and close the one remaining unknown: **Neon autosuspend state on the Free branch**.

## Design decisions (binding on future runs)

1. **Cloudflare is Workers PAID.** Cloudflare Containers require Workers Paid. The four `[[containers]]` blocks in `api/wrangler.toml` (`AgentContainerDO` max 25, `QaRunnerContainerDO` max 3, `StageSandboxContainerDO` max 3, `MediaRenderContainerDO` max 3) and their four matching `[[durable_objects.bindings]]` (`AGENT_CONTAINER`, `QA_RUNNER_CONTAINER`, `STAGE_SANDBOX_CONTAINER`, `MEDIA_RENDER_CONTAINER`) are **correct and must stay**.
   - The two halves move together: a Container-derived class bound as a plain DO has no image to start. If either is ever gated, gate **both**.
   - Disabling them silently removes live preview, the Agentic Tester QA sweep, the Stage sandbox, and server-side canvas video render.
2. **`PlanLimits.ts` needs no cut.** `livePreview` / `containerRuntime` / `serverVideoRender` being `true` on paid tiers is backed by the deployment — not a commercial leak.
3. **`CACHE_L2_KV="false"` (`api/wrangler.toml`, commit `9a6d607b1`) is deliberate.** It caps billable Workers KV writes, at the cost of falling through to Neon on cache misses. It is not a Free-tier hard limit. Revisit only if that fall-through latency becomes a *measured* problem.
4. **Do not unbind `AUTH_CACHE_KV`** (id `ce66c3418ad64952b6847227962429d0`) to save KV writes. The cron work-gate (`cron:work-pending`, `cron:last-floor-sweep`) lives on that namespace; removing it makes every frequent cron tick fail open and keeps Neon awake — directly defeating the Free-tier compute budget.
5. **Neon is Free.** Storage work (#5221/#5222) reduces data size but does **not** fix compute-hour limits.

## Remaining work

**Confirm Neon autosuspend state on the Free branch.** A Free compute that never suspends will exhaust its monthly compute allowance regardless of storage size.

Operator checklist (Neon console / API — no repo change expected):
- [ ] For the project's Free branch/endpoint, confirm `suspend_timeout_seconds` is the Free default (5 min) and not disabled (`-1`) — Free tier does not allow disabling autosuspend, so a never-suspending compute indicates constant traffic, not config.
- [ ] Check the endpoint's recent state history: it should show `idle` periods. If it is `active` 24/7, identify what is keeping it awake.
- [ ] If kept awake, inspect the usual suspects in order: (a) cron ticks that fail open because `AUTH_CACHE_KV` work-gate is unreadable (see decision 4); (b) health/uptime probes hitting a DB-backed route; (c) connection poolers/keepalives holding sessions; (d) `CACHE_L2_KV="false"` fall-through under steady traffic (decision 3).
- [ ] Record the measured compute-hours used this billing period vs. the Free allowance on this ticket.

## Out of Scope

- Disabling or gating any Cloudflare Container / Durable Object binding.
- Cutting plan entitlements in `PlanLimits.ts`.
- Re-enabling `CACHE_L2_KV` or unbinding `AUTH_CACHE_KV`.
- Any Neon storage work (already done under #5221/#5222).

- Autosuspend confirmation is an operator action against the Neon console; this repo change records the decision and checklist only.

# PRD: Optional AI-agent piece on the react-vite-node-express starter

**Status:** WIP. Not started; no code written.  
**Epic / task:** #6994 / #6997.  
**Repo:** `seanhogg/builderforce.ai`, base `main`.  
**Contract:** `docs/specs/app-manifest-ai-resource.md` §11 is the source of truth for the `ai` resource shape. This PRD does not redefine that contract.  
**Ship policy:** leave changes uncommitted (`leave_uncommitted`). The owner run ships once. Do not commit.

## Problem & Goal

The `react-vite-node-express` starter has no optional in-app assistant. Composers who want a shop assistant must invent a second starter or a new service role, which this slice forbids.

**Goal:** add one optional piece on kit id `react-vite-node-express` only (lives in `Builderforce.ai/packages/ide-templates`, covered by `kits/compose.test.ts`). When the piece is chosen, the composed app declares an `ai` assistant resource, exposes `POST /api/agent`, and shows a chat widget in the kit web app. The assistant answers by calling `AI_BASE_URL` `/chat/completions` with tool calls over that shop’s catalog and orders. When the piece is not chosen, the starter is unchanged.

## Target users / ICP roles

- **IDE composer user:** picks the existing react-vite-node-express starter and may opt into an assistant. They are not asked to choose a second starter or a new service role.
- **Shop demo user:** uses the kit web app’s catalog and orders and, only if the piece was selected, chats with the assistant about those resources.
- **Downstream implementer:** agents sharing this PRD. They implement only this kit piece, follow the kit’s own string and theme convention, and stop at an uncommitted tree.

## Scope

In scope is a single optional piece on kit id `react-vite-node-express` and nothing else in the template catalog.

When the piece is chosen, the composed manifest and app must include all of the following:

- `resources.assistant` with type `ai`, matching §11.
- The existing api service remains `role: "backend"` and declares `uses` for the assistant. No new role.
- Api route `POST /api/agent` that calls `AI_BASE_URL` at `/chat/completions` and performs tool calls over the shop catalog and orders only.
- A chat widget in the kit web app, styled and stringed with that kit’s own convention. The `frontend/src` i18n rule does not apply.

Validation targets for the starter-with-agent:

- `app_manifest.validate` is clean.
- `validateManifest` (runtime parser) is clean, the same bar `clients/vscode/src/composerCommands/manifestContract.test.ts` asserts for every kit.

**Blocker (shared, ticket eebdbdce):** published `@seanhogg/builderforce-webcontainers-core@2026.11.12` does not know resource type `ai`. A manifest with an `ai` resource fails `unknown-resource-type` on that validator today. The starter-with-agent cannot be proven clean until the #6996 core release lands. Do not fork the contract, rename the type, or drop the resource to force a green run against 2026.11.12.

## Functional requirements

1. The piece is optional and attached only to kit id `react-vite-node-express`. Kit selection without the piece yields the current starter behavior and manifest.
2. Selecting the piece does not create a second starter and does not add a service role. The api service stays `role: "backend"` and gains `uses` that bind it to the assistant resource.
3. The selected manifest includes `resources.assistant` with type `ai` exactly as §11 requires. No other new resource types.
4. The api exposes `POST /api/agent`. The handler calls `AI_BASE_URL` `/chat/completions` and uses tool calls limited to the shop’s catalog and orders. It does not invent tools outside that shop surface, and it does not add a new backend role to host the route.
5. The kit web app renders a chat widget only when the piece is part of the composed app. Copy and theme follow the kit’s existing string and theme convention, not the `frontend/src` i18n rule.
6. Manifests produced for starter-with-agent must be valid under `app_manifest.validate` and under runtime `validateManifest`, once the validator knows `ai`. Until #6996, record the eebdbdce / 2026.11.12 failure as the known blocker rather than changing the manifest to satisfy the old validator.
7. Verification uses the ide-templates package test runner and `clients/vscode/src/composerCommands/manifestContract.test.ts`. Implementation stops with a dirty, uncommitted worktree.

## Acceptance criteria

- Optional piece exists only on `react-vite-node-express`. No second starter is added. Other kits are untouched.
- With the piece off, starter manifest and app behavior match the pre-change kit.
- With the piece on, manifest has `resources.assistant` type `ai`, api service `role: "backend"` with `uses`, and no new role.
- With the piece on, `POST /api/agent` calls `AI_BASE_URL` `/chat/completions` and tool-calls only the shop catalog and orders.
- With the piece on, the kit web app shows a chat widget using the kit’s own strings and theme.
- `app_manifest.validate` and `validateManifest` are clean for starter-with-agent after the #6996 core release. Before that release, a failure solely as `unknown-resource-type` on `@seanhogg/builderforce-webcontainers-core@2026.11.12` is the known blocker (eebdbdce), not a license to alter the `ai` contract.
- ide-templates tests and `manifestContract.test.ts` have been run (or the blocked validator result recorded). The tree is left uncommitted.

## Out of scope

- A second starter, a new service role, or the same piece on any other kit.
- Applying the `frontend/src` i18n rule, or redesigning the kit theme beyond the chat widget.
- Changing §11, teaching `ai` to `@seanhogg/builderforce-webcontainers-core@2026.11.12`, or shipping the #6996 core release in this task.
- Tool calls beyond the shop catalog and orders, extra agent routes, or a non-optional assistant.
- Committing or pushing. Owner run ships once under `leave_uncommitted`.

# Product Requirements Document (PRD): Connect GitHub Repo to Project 11

## Problem & Goal
### Problem
The `projects.get(11).githubRepoUrl` field is currently `null`, causing developer containers for tasks #2545, #2554, and #2600 to fail with the error "no repository bound." This issue is part of a broader class of binding problems affecting tasks #700, #2532, #2538, and #2588.

### Goal
Connect the GitHub repository `SeanHogg/Builderforce.ai` to project 11 via the platform's GitHub integration. This will resolve the binding issue and unblock the affected tasks.

## Target Users / ICP Roles
- **Developers**: Users who rely on the developer containers for tasks #2545, #2554, and #2600.
- **Project Managers**: Individuals responsible for managing project settings and ensuring all integrations are correctly configured.

## Scope
- Connect the GitHub repository `SeanHogg/Builderforce.ai` to project 11.
- Verify the connection by ensuring the following fields are correctly populated:
  - `githubRepoUrl` is non-null.
  - `githubRepoOwner` is set to `"SeanHogg"`.
  - `githubRepoName` is set to `"Builderforce.ai"`.
- The connection must be performed through the platform's GitHub integration settings (Project Settings → Source Control → Connect GitHub).

## Functional Requirements
1. **Access Project Settings**
   - Navigate to the project settings page for project 11.
   
2. **Navigate to Source Control**
   - Within the project settings, locate and select the "Source Control" section.
   
3. **Connect GitHub Repository**
   - Initiate the GitHub connection process.
   - Enter the repository URL: `https://github.com/SeanHogg/Builderforce.ai`.
   - Authenticate and authorize the connection if prompted.
   
4. **Verify Connection**
   - After the connection is established, verify that:
     - The `githubRepoUrl` field is populated with the correct URL.
     - The `githubRepoOwner` field is set to `"SeanHogg"`.
     - The `githubRepoName` field is set to `"Builderforce.ai"`.
   
5. **Save Changes**
   - Save the updated project settings to apply the changes.

## Acceptance Criteria
- **AC1**: The `githubRepoUrl` field for project 11 is non-null and correctly set to `https://github.com/SeanHogg/Builderforce.ai`.
- **AC2**: The `githubRepoOwner` field is set to `"SeanHogg"`.
- **AC3**: The `githubRepoName` field is set to `"Builderforce.ai"`.
- **AC4**: Developer containers for tasks #2545, #2554, and #2600 no longer fail with the "no repository bound" error.
- **AC5**: The connection process does not introduce any new errors or issues in the project settings or developer environments.

## Out of Scope
- **Additions to Advisor Listing**: Do not add the `advisor` listing kind as part of this task.
- **Volunteer Table**: Do not modify or add to the volunteer table.
- **/advisors Route**: Do not create or modify the `/advisors` route.
- **Code Branches**: The A0 code should remain on the `builderforce/task-2545` branch and should not be moved to any gap branches.
- **Automated Tools**: This task must be performed manually through the platform's UI as the `builtin_projects_update` function cannot set the required fields.

## Requirements

## R-1: Human Operator Must Connect GitHub Repo via Platform UI
**Verified:** `builtin_projects_update` cannot set `githubRepoUrl`, `githubRepoOwner`, or `githubRepoName` — these fields silently no-op. The only path is the platform's Project Settings → Source Control → Connect GitHub UI. Agent tools (including `builtin_projects_update`, `builtin_tasks_update`, and all repo-level tools) cannot perform this bind.

## R-2: Required Post-Connection Verification
After the operator completes the connection, verify via `builtin_projects_get(11)` that:
- `githubRepoUrl === "https://github.com/SeanHogg/Builderforce.ai"`
- `githubRepoOwner === "SeanHogg"`
- `githubRepoName === "Builderforce.ai"`

## R-3: Unblocked Tasks
Once the bind is live, the following tasks must be re-tested:
- #2590 (R1) — developer container
- #2545 (A0) — developer container
- #2600 — developer container
- #2554 — developer container
- Plus the broader bind-gap class: #2532, #2538, #2588

## R-4: Kill Conditions (Constraints)
- Do NOT add `advisor` listing kind, volunteer table, or `/advisors` route.
- A0 code stays on `builderforce/task-2545`, not on gap branches.

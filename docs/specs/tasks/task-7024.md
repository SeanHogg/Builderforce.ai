## Problem & Goal

The API non-streaming `_builderforce` envelope now emits `cooled: [{ model, until, reason }]` beside `failovers` (`chatCompletionResponse.ts`, via `ProxyResult.cooled`). The brain-embedded client never reads that field, so cooling never lands on `GatewayRouting` or on the `llm.complete` step. Downstream W1 therefore cannot render lines such as `moonshot/kimi-k3 cooled until 23:10 (429)`.

`readGatewayRouting` also returns `undefined` unless `raw.failovers` is an array, which drops a cooled-only frame.

Goal: parse `_builderforce.cooled` into `GatewayRouting` and attach a formatted `cooled` string on `llm.complete` step args (via `gatewayRoutingArgs`) so W1 can render model cooldown without the client choosing model order.

## Target users / ICP roles

- Brain-embedded runtime: consumers of `GatewayRouting` and `llm.complete` traces.
- W1 trace renderer: reads the `cooled` step arg and displays cooldown (`model cooled until <time> (reason)`).
- Operators debugging gateway routing: need failovers and cooldown visible on the same step.

## Scope

Repo `seanhogg/builderforce.ai`, base `main`. Client half of W4 only.

- `brain-embedded/src/streamChatCompletion.ts`: extend `GatewayRouting` and `readGatewayRouting`.
- `brain-embedded/src/runStore/gatewayRoutingTrace.ts`: add a `cooled` string arg in `gatewayRoutingArgs` beside `failovers`.
- Confirm `turnRecorder.ts` already spreads `gatewayRoutingArgs` and leave it unchanged.
- Inspect the streaming terminal diagnostics frame (`api` `streamDiagnostics.ts`). Surface `cooled` on the streaming path only if that frame already carries it. Non-streaming envelope is already wired; streaming metadata was not part of this slice.

## Functional requirements

1. `GatewayRouting` (around line 355 in `streamChatCompletion.ts`) gains an optional field:
   `cooled?: Array<{ model: string; until: number; reason: string }>`.
2. `readGatewayRouting` (around line 370) parses `raw.cooled` into that field. Keep entries that have a string `model`, a numeric `until`, and a string `reason`. Ignore malformed entries. Omit `cooled` when the parsed list is empty.
3. Relax the early return `if (!raw || !Array.isArray(raw.failovers)) return undefined;` so a frame is accepted when it carries either a `failovers` array or a `cooled` array. A frame with neither still returns `undefined`. Existing failover parsing is unchanged when `failovers` is present.
4. `gatewayRoutingArgs` adds a `cooled` string arg beside `failovers`. Format each entry as `model until <ISO> (reason)`, with `until` rendered as an ISO-8601 timestamp, and join entries with `, `. Example shape: `moonshot/kimi-k3 until 2026-04-11T23:10:00.000Z (429)`. Omit the arg when there is no cooled list.
5. Because `turnRecorder.ts` already spreads `gatewayRoutingArgs`, the `llm.complete` step picks up `cooled` with no change in that file.
6. Do not set or fill `excludeModels` on the client. Server owns model order.
7. Streaming check: if the terminal diagnostics frame already includes `cooled`, parse it with the same shape and formatting as the non-streaming path. If it does not, leave the streaming client path unchanged and do not add server streaming metadata in this task.

## Acceptance criteria

- A non-streaming `_builderforce` frame with only `cooled` yields a `GatewayRouting` value whose `cooled` array matches `{ model, until, reason }` and is not dropped.
- A frame with both `failovers` and `cooled` still parses failovers as today and also populates `cooled`.
- A frame with neither `failovers` nor `cooled` still yields `undefined`.
- Malformed cooled entries are skipped; an all-invalid `cooled` array does not invent a `cooled` field or arg.
- `gatewayRoutingArgs` includes `cooled` formatted as `model until <ISO> (reason)`, comma-joined, and omits the key when absent.
- `llm.complete` step args include that string solely via the existing `gatewayRoutingArgs` spread. `turnRecorder.ts` has no diff.
- Client code does not write `excludeModels`.
- Streaming path either parses `cooled` from an already-present diagnostics field or is explicitly left unchanged after confirming the frame does not carry it. No new server streaming fields are added.
- `brain-embedded` type-check passes: `npx tsc --noEmit -p .` (package `type-check` script).
- `streamChatCompletion.test.ts` and `routingByRole.test.ts` are unchanged.

## Out of scope

- Server emission of `cooled` on the non-streaming envelope (already done).
- Any client-side `excludeModels` fill or reorder.
- Edits to `turnRecorder.ts`.
- W1 rendering of the cooldown string (this task only carries the arg).
- New streaming metadata on the API if `streamDiagnostics.ts` does not already carry `cooled`.
- Changes to `streamChatCompletion.test.ts` and `routingByRole.test.ts`.

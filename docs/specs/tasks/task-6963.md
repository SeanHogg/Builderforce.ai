# PRD: Wire KnowledgeGraphView depth trail and walkthrough step

## Problem & Goal

Tickets 6952 and 6953 landed the depth-trail and walkthrough pieces in isolation. `PathStrip` can render `DepthTrail` and step narration, `ActPanel` can show `WalkthroughNote` beside action cards, and `useDrill` exposes `climb`. `KnowledgeGraphView` does not yet pass the live drill stack, system name, climb handler, or current step into those components, so the surface never shows the trail or the step sentence for the drawn path.

Goal: minimal wiring in `KnowledgeGraphView` so the existing `PathStrip` and `ActPanel` receive live drill and step state, then prove it with the surface vitest suite and a typecheck. Do not reimplement trail, narration, or drill behavior, and do not revert work already landed.

## Target users / ICP roles

- Engineers finishing the knowledge-graph surface slice (this agent and any agent that shares this PRD).
- Reviewers of tickets 6952 and 6953 who need a bounded diff: props only, plus fixture stubs if the typecheck demands them.
- Downstream product users of the graph view (indirect): people walking a drawn path who need the depth trail (“Back to App”) and the walkthrough sentence for the current step.

## Scope

Bound repo: `seanhogg/builderforce.ai`, base `main`. Work only under `Builderforce.ai/packages/knowledge-graph-view`.

In scope:

1. Re-read `src/KnowledgeGraphView.tsx` immediately before editing. Other agents edit that file; do not overwrite their unrelated changes.
2. On the existing `<PathStrip>`, pass:
   - `trail={surface.drill.stack}`
   - `systemName={titleOf(graph.scope.rootId)}`
   - `onClimb={surface.drill.climb}`
3. On the existing `<ActPanel>`, pass `step={surface.step}`.
4. If `tsc` fails because inline `DrillModel` fixtures omit `climb`, add `climb: vi.fn()` next to existing `out: vi.fn()` fixtures under `packages/knowledge-graph-view`. Do not change drill behavior.
5. From `Builderforce.ai/packages/knowledge-graph-view`, run:
   - `pnpm exec vitest run src/surface --pool=threads`
   - `pnpm --package=typescript dlx tsc --noEmit -p .`
6. Fix failures only in files this slice owns. Do not commit.

Already landed (do not revert or re-do):

- `surface/ActCards.tsx` exports `WalkthroughNote` (sentence + metaphor). `surface/ActPanel.tsx` renders it beside the action cards when a path is drawn, using optional `step` (default 0).
- `surface/PathStrip.tsx` accepts `trail`, `systemName`, and `onClimb`, renders `DepthTrail` above the journey, and renders `data-testid="kg-step-narration"` via `walkthroughSentence`.
- `surface/transit/useDrill.ts` `climb(depth)`: depth `0` is the system; a non-finite or negative depth is `0`; a depth at or past the current stack is a no-op. Existing `out()` is unchanged.

## Functional requirements

1. `KnowledgeGraphView` must pass the current drill stack into `PathStrip` as `trail`, so `DepthTrail` reflects the live stack rather than an empty or omitted trail.
2. `KnowledgeGraphView` must pass `systemName` from `titleOf(graph.scope.rootId)` so the trail root label matches the scoped system (the PathStrip case expects the “Back to App” control).
3. `KnowledgeGraphView` must pass `surface.drill.climb` as `onClimb`. Climb semantics stay in `useDrill`: `0` returns to the system; non-finite or negative depth is treated as `0`; a depth at or past the current stack is a no-op. `out()` stays unchanged.
4. `KnowledgeGraphView` must pass `surface.step` into `ActPanel` so `WalkthroughNote` uses the current step instead of the default `0`.
5. Wiring is props-only. Do not duplicate `DepthTrail`, `walkthroughSentence`, `WalkthroughNote`, or `climb` inside the view.
6. Typecheck fixtures that construct a `DrillModel` and already stub `out: vi.fn()` must also stub `climb: vi.fn()` if `tsc` reports the omission. Stubs must not alter runtime drill behavior.
7. Verification commands above must be run from `Builderforce.ai/packages/knowledge-graph-view`. Failures outside this slice are not this slice’s to fix. No commit.

## Acceptance criteria

- `DepthTrail.test.tsx` passes as part of `pnpm exec vitest run src/surface --pool=threads`.
- The PathStrip case that clicks “Back to App” expects the narration: `Walk the hallway from Login to Accounts (2 calls). Leave through the door Accounts.` That assertion passes.
- Once the view passes `step`, the act panel shows the walkthrough sentence for the current step (not only the default step `0`).
- `pnpm --package=typescript dlx tsc --noEmit -p .` exits cleanly. Any `DrillModel` fixture gap is closed only by adding `climb: vi.fn()` beside existing `out: vi.fn()` stubs.
- Diff does not revert `WalkthroughNote`, `ActPanel` step rendering, `PathStrip` trail/narration, or `useDrill.climb` / `out`.
- No commit is created.

## Out of scope

- Rebuilding depth trail, walkthrough copy, metaphors, or drill stack logic.
- Changing `climb` or `out` behavior, including edge cases already specified in `useDrill`.
- New UI, new test files, or refactors unrelated to the prop wire and fixture stubs.
- Fixing vitest or `tsc` failures in files this slice does not own.
- Commits, pushes, ticket status changes, or edits outside `packages/knowledge-graph-view`.

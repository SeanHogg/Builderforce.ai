## Problem & Goal

The committed `Builderforce.ai/brain-embedded/dist` is stale. Source commit `0e5cb78f8` removed ONNX Bonsai model rows from the runnable catalog, but those rows remain in the committed bundle. The VS Code extension ships `brain-embedded` through `dist`, so the stale rows are what users get.

Rebuild `brain-embedded/dist` from current source so the ONNX Bonsai rows are gone, commit only that dist, and audit the other committed dists (`brain-ui`, `studio`, `studio-embedded`) the same way: commit a dist only when a fresh build shows real content drift; otherwise restore noise-only diffs and leave the package untouched.

Success means every committed dist matches a fresh build of its source, with grep evidence that ONNX Bonsai rows are absent from `brain-embedded/dist`, and no source, version, or changelog files changed.

## Target users / ICP roles

- Extension and studio consumers who load committed bundles rather than rebuilding from source.
- Downstream agents on this task who share this PRD and must not touch other sessions' uncommitted work.
- Maintainers reviewing the dist-only commits on `seanhogg/builderforce.ai` (`main`).

## Scope

Workspace-relative repo: `Builderforce.ai` (git repo `seanhogg/builderforce.ai`, base `main`). Workspace root is not a repo; all git and shell work runs with repo/cwd `Builderforce.ai`.

In scope paths:

- `Builderforce.ai/brain-embedded/dist` (must rebuild and commit)
- `Builderforce.ai/packages/brain-ui/dist` (audit)
- `Builderforce.ai/studio/dist` (audit)
- `Builderforce.ai/studio-embedded/dist` (audit)

Shared checkout: `main` is live with other sessions. Do not reset, stash, or rewrite files this task did not author. Other sessions own uncommitted work in `api/src/application/llm/*`, `docs/specs/app-manifest-ai-resource.md`, `packages/knowledge-graph-view/**`, and `ROADMAP.md`. Leave those alone.

## Functional requirements

1. **Learn stale markers before rebuilding.** Case-insensitive search of `brain-embedded/src` and `clients/vscode/src/catalogEngine.ts` for `bonsai` and `onnx` to capture the model ids and row strings source now holds out. Grep `brain-embedded/dist` for those markers and record the hits as pre-rebuild staleness evidence.

2. **Rebuild brain-embedded.** From `Builderforce.ai/brain-embedded`, run `pnpm install` only if `node_modules` is missing (lockfile root is this package). Run `pnpm run build` (tsup writes `dist/`). Confirm ONNX Bonsai markers are absent from `dist/index.cjs` and `dist/index.mjs` by grepping the actual identifiers, not comments (comments are stripped).

3. **Commit brain-embedded dist only.** Inspect `git status` and list the actual changed dist files. Check `git diff --cached` before committing. Commit only `Builderforce.ai/brain-embedded/dist` (`allowBaseBranch: true`). If the index is foreign, use a temp index on `origin/main` and commit only those exact dist paths. No Co-Authored-By trailer. No source edits, version bump, or VSIX packaging.

4. **Audit the other three dists independently.** For each of `packages/brain-ui`, `studio`, and `studio-embedded`: read the build script in that package's `package.json`, install at its own lockfile root if `node_modules` is missing, rebuild, then inspect `git diff` of that dist path.
   - Real content changes (stale code): commit that dist separately, one commit per package, only that dist path. Same index and trailer rules as requirement 3.
   - Diff is only build-stamp or banner noise (timestamp or hash churn with identical code): restore those files with `git checkout -- <those dist files>` (files this task just rewrote) and report the package as not stale.
   - Build fails for reasons outside this scope: leave that package's dist untouched and report the exact error as a blocker.

5. **Push.** Wait for any in-progress CI on `main` before pushing. Push with `allowBaseBranch: true` after each commit or once at the end. Report commit hashes and push results.

6. **Verify.** Grep evidence that ONNX rows are absent from `brain-embedded/dist`. Each committed dist matches a fresh build of its source. No source, `package.json` version, changelog, `DONE.md`, or `ROADMAP.md` changes.

## Acceptance criteria

- Pre-rebuild grep shows the ONNX Bonsai markers still present in `brain-embedded/dist`; post-rebuild grep of `dist/index.cjs` and `dist/index.mjs` shows those identifiers absent.
- `brain-embedded/dist` is committed alone; the commit contains only files under that dist path.
- Each of `brain-ui`, `studio`, and `studio-embedded` is either committed separately (real stale code) or reported not-stale after a noise-only diff was restored, or reported blocked with the exact build error and an untouched dist.
- `git status` shows no new changes to source, versions, changelogs, `DONE.md`, `ROADMAP.md`, or other sessions' files.
- Commit hashes and push results are in the report. No Co-Authored-By trailers.

## Out of scope

- Editing source, `package.json` versions, changelogs, `DONE.md`, or `ROADMAP.md`.
- VSIX packaging, catalog redesign, or re-adding ONNX Bonsai rows.
- `git reset`, `git stash`, or checkout/rewrite of files this task did not author.
- Touching `api/src/application/llm/*`, `docs/specs/app-manifest-ai-resource.md`, `packages/knowledge-graph-view/**`, or `ROADMAP.md`.
- Committing mixed paths, amending foreign commits, or pushing while CI on `main` is in progress.
- The separate `builderforce-webcontainers` repo.

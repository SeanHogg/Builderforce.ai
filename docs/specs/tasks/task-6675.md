## Problem & Goal

Ten vitest tests in `packages/agent-tools` fail together under gap 6644 at HEAD `0df16cbf9`, while a single test passes in isolation. Failures are cross-test / cross-file pollution, not the WS3 scheduler gate. The mocked `pumpReplica` is never invoked (`expected [] to have a length of 1/2 but got +0`), and one assertion expects `'unreachable'` but receives `undefined`. The lock test stalls about one second on a real timer under fake timers.

Goal: land the minimal correct fix so the three replicaHost files pass together, the full knowledge suite is 661/661, and typecheck is clean. Prefer production code. Do not rewrite a fix another session already landed if that change already makes the suite pass.

## Target users / ICP roles

- Agent-tools maintainers who own replica host pump, lock, and retry behavior.
- Downstream agents on this task who must share one diagnosis, one fix, and one verification bar.
- CI consumers of `packages/agent-tools` knowledge vitest and `npm run typecheck`.

## Scope

- Repo: `seanhogg/builderforce.ai`, base `main`. Work only under `Builderforce.ai/packages/agent-tools`.
- First inspect the working tree: `git -C Builderforce.ai status` and `git diff -- packages/agent-tools`. If a sub-agent (a1) already landed a fix that makes the suite pass, keep it, verify fully, and report that instead of rewriting.
- Investigate `src/knowledge/replicaLock.ts` (`fileReplicaLock().acquire`) for cross-instance state or timers frozen by vitest fake timers, and how `replicaHost.ts` `startReplicaPump`'s `lock.acquire` await interacts with `vi.useFakeTimers()`.
- Check whether running the three test files in one vitest worker causes module-mock pollution (the quiet test `vi.mock`s `./replicaPump.js`).
- Files in scope:
  - `src/knowledge/replicaHost.ts`
  - `src/knowledge/replicaLock.ts`
  - `src/knowledge/replicaHost.quiet.test.ts`
  - `src/knowledge/replicaHost.lock.test.ts`
  - `src/knowledge/replicaHost.retry.test.ts`

## Functional requirements

1. Confirm whether uncommitted changes under `packages/agent-tools` already fix the suite before editing. If they do, keep them and do not rewrite.
2. Eliminate cross-test and cross-file pollution so the three replicaHost files pass when run together in one vitest worker.
3. Ensure `fileReplicaLock().acquire` does not leak cross-instance state or leave timers that stall under `vi.useFakeTimers()`. The lock-lost regression must stop the pump at once and report the loss without a ~1s real-timer stall.
4. Ensure `startReplicaPump`'s await on `lock.acquire` advances correctly under fake timers so the pump is invoked as the tests expect.
5. Isolate module mocks so `vi.mock('./replicaPump.js')` in the quiet file does not suppress `pumpReplica` for the lock and retry files (or vice versa).
6. Restore the expected outcomes: mocked `pumpReplica` is invoked (length 1 or 2 as each test asserts), and the unreachable case reports `'unreachable'` rather than `undefined`.
7. Do not change the WS3 scheduler gate. Do not broaden the fix beyond replica host lock/pump isolation.
8. Do not commit or push. Do not edit files outside the replicaHost/replicaLock area. Preserve other sessions' uncommitted work (`clients/vscode`, `_probe_sqlite.cjs`, `factStoreNode.ts`, `portablePack*`, `packGraph*`, `index/packMeasure.test.ts`, `knowledgePackCommands.ts`).

## Acceptance criteria

- `npx vitest run src/knowledge/replicaHost.quiet.test.ts src/knowledge/replicaHost.lock.test.ts src/knowledge/replicaHost.retry.test.ts` passes all tests in those three files together.
- `npx vitest run src/knowledge` is 661/661, with no new failures (previously 651/661 with exactly these 10 failing: quiet 7, lock 1, retry 2).
- `npm run typecheck` in `packages/agent-tools` is clean.
- The lock regression ("a lock lost to another host (after a stall) stops the pump at once and is reported") passes without a real-timer stall under fake timers.
- If an existing working-tree fix already satisfies the above, it is kept and reported rather than replaced.
- No commit and no push. No edits outside the replicaHost/replicaLock area. Other sessions' uncommitted files remain untouched.

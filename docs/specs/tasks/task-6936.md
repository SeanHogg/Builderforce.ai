# PRD: MK-09-W10 — Ticket branch collision handling

**Status:** WIP  
**Priority:** P1  
**Source:** PRD 09 §4 GAP-W10  
**Repo:** seanhogg/builderforce.ai (base `main`)  
**Code anchor:** `ticketBranchName` in `api/src/application/repos/commitFileAsPendingChange.ts`

## Problem & Goal

Pending-change commits are written to a ticket branch named `builderforce/task-<taskId>`. That name is not checked for collisions. If a human (or any other actor) already created that branch, the system can select it and mix automated pending changes into work it does not own.

**Goal:** Before a pending-change commit uses a ticket branch, detect a pre-existing branch of that exact name and do not use it. Allocate a suffixed name and continue. If a free suffixed name cannot be allocated within the bound below, refuse with a clear message and do not commit. A test must cover the collision.

## Target users / ICP roles

- **Builderforce agent runtime:** commits file changes as pending changes on a per-ticket branch and must not land those commits on a branch it did not originate.
- **Human engineers:** may create `builderforce/task-<taskId>` themselves. Their branch must be left untouched, and any refusal must tell them why the commit did not proceed.
- **Repo maintainers:** need a deterministic, testable rule so ticket branch selection does not depend on who created the branch first.

## Scope

In scope is branch selection for the pending-change commit path that derives its branch from `ticketBranchName` in `api/src/application/repos/commitFileAsPendingChange.ts`.

- Treat an existing local or remote branch whose name equals the unsuffixed ticket branch name as a collision.
- Do not create, check out, commit to, reset, delete, or force-update that pre-existing branch.
- Resolve the collision by suffixing, or refuse with a clear message when suffix allocation fails.
- Cover the collision with a test in the API test suite.

## Functional requirements

1. **Unsuffixed name unchanged.** When no branch named `builderforce/task-<taskId>` exists, `ticketBranchName` (or the selector that uses it) still resolves to `builderforce/task-<taskId>`. Non-collision behavior must not change.
2. **Collision detection.** Before the pending-change commit uses the ticket branch, determine whether a branch of that exact name already exists. A name match is a collision regardless of who created the branch and regardless of whether the match is local, remote, or both.
3. **Do not touch the collided branch.** On collision, the implementation must not check out, commit onto, push to, reset, rename, delete, or otherwise modify the pre-existing branch.
4. **Suffix allocation.** On collision, allocate the first free name in this order: `builderforce/task-<taskId>-2`, then `builderforce/task-<taskId>-3`, and so on, up to and including `-10`. Use that name for the pending-change commit. Suffix search must be deterministic and must re-check each candidate for existence before use.
5. **Refusal when allocation fails.** If every candidate from `-2` through `-10` already exists, do not commit. Fail the operation with a clear message that states the original branch name, that it already exists, and that no free suffixed name was available through `-10`. The message must be suitable for an API error or thrown error that a caller and a human can read. It must not be an empty string, a generic git error alone, or a silent no-op.
6. **Resolved name is the name that is used.** Callers that persist, return, or log the branch for that commit must use the allocated suffixed name, not the collided unsuffixed name.
7. **Collision is observable.** When a suffix is used, the collision and the resolved branch name must be visible in the operation result or in an error/log message that includes both the original name and the suffixed name. Silent substitution is not acceptable.
8. **Test.** Add or extend a test that starts from a pre-existing branch named `builderforce/task-<taskId>`, invokes the pending-change branch selection or commit path, and asserts that the pre-existing branch is not the branch used. The test must assert either that the resolved name is `builderforce/task-<taskId>-2` (when that suffix is free) or that the operation fails with a message identifying the name collision. The test must fail on the current code, which has no collision handling.

## Acceptance criteria

- Given no existing `builderforce/task-<taskId>` branch, a pending-change commit still targets `builderforce/task-<taskId>`.
- Given an existing branch of that exact name, the commit does not target it, and that branch’s existence and tip are unchanged by the operation.
- Given that collision and a free `builderforce/task-<taskId>-2`, the operation uses `builderforce/task-<taskId>-2` and records or reports both the original name and the suffixed name.
- Given the unsuffixed name and every suffix from `-2` through `-10` already exist, the operation does not commit and returns or throws a clear message naming the collision and the exhaustion of the suffix bound.
- A test in the API suite covers the collision and passes. The same scenario without the new handling would not pass.
- `ticketBranchName` remains the source of the unsuffixed ticket branch name. Collision handling may live beside it in `api/src/application/repos/commitFileAsPendingChange.ts` or in the direct caller that selects the branch for the pending-change commit, but it must run on this path.

## Out of scope

- Deleting, renaming, rebasing, or merging the human-created branch.
- Copying commits from the collided branch onto the suffixed branch.
- Changing the unsuffixed pattern `builderforce/task-<taskId>` for the no-collision case.
- Collision handling for branches that do not use this ticket branch name.
- Branch-protection rules, force-push policy, and remote permission errors that are not this name collision.
- A UI to pick or rename the branch.
- Repair of repositories that already received automated commits on a human-created `builderforce/task-<taskId>` branch.
- Raising the suffix bound above `-10` or supporting arbitrary caller-supplied branch names.

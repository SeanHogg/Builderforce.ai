# PRD: Code Visualizer top bar — icon controls and dead `panelToggles` cleanup

**Status:** WIP  
**Repo:** seanhogg/builderforce.ai (`main`)  
**Context:** Code Visualizer redesign (chat 280)

## Problem & Goal

CameraBar Out/Back are already icon buttons, and zoom/Fit already live only on the stage nav. The top bar is still inconsistent: text controls remain in `Toolbar.tsx` and in `SceneTools.tsx` (`PanelToggle`, `OverlayMenu`), and a dead `panelToggles` slot is still threaded through CameraBar and SceneOverlay. An unreferenced `surface/PanelVisibilityToggles.tsx` is leftover from that slot.

Finish the chrome pass so those remaining controls are icon buttons, the dead slot and file are gone, and dock collapse/expand is locked by a DockEdge test (28px rail, then full restore).

## Target users / ICP roles

- **Primary:** engineers using the Code Visualizer to inspect a codebase. They need a quiet top bar whose controls are recognizable without text labels, with the same actions as today.
- **Secondary:** QA and downstream agents. Existing role/name queries must keep passing; do not rename accessible names to make tests match.

## Scope

In scope:

- Convert remaining text controls in `Toolbar.tsx` to icon buttons.
- Convert `PanelToggle` and `OverlayMenu` in `SceneTools.tsx` to icon buttons.
- Source each control’s `aria-label` and `title` from `labels/`.
- Preserve current button behavior and current accessible names.
- Remove the unused `panelToggles` prop from CameraBar and SceneOverlay, including types and call sites, so no empty slot renders.
- Delete unreferenced `surface/PanelVisibilityToggles.tsx` and any imports or references.
- Add a DockEdge test for collapse → 28px rail and re-expand → panel restored.

Out of scope is listed below. Do not restyle controls that this redesign already finished.

## Functional requirements

1. **Toolbar icon buttons.** Every text control still rendered by `Toolbar.tsx` is an icon button. Use the same icon-button pattern as CameraBar Out/Back. Visible text labels are removed. Action, disabled, and toggle behavior stay as they are.
2. **Scene tools icon buttons.** `PanelToggle` and `OverlayMenu` in `SceneTools.tsx` are icon buttons under that same pattern. Menu/toggle behavior is unchanged; only the control presentation changes.
3. **Names and tooltips from `labels/`.** Each converted control sets both `aria-label` and `title` from the existing `labels/` strings for that control. Do not hardcode new copy. The accessible name must remain the string current role/name queries already use, so those queries are not rewritten to new names.
4. **Semantics.** Converted controls stay native buttons (or keep an explicit `button` role) and remain keyboard-activatable. Icon-only presentation must not drop the accessible name.
5. **Remove the dead slot.** Delete the unused `panelToggles` prop from CameraBar and SceneOverlay (props, types, and every caller). CameraBar must not reserve or render an empty panel-toggles region.
6. **Delete the dead module.** Delete `surface/PanelVisibilityToggles.tsx`. The tree must have no remaining import, re-export, or reference to `PanelVisibilityToggles` or the removed `panelToggles` prop.
7. **DockEdge regression test.** Add a DockEdge test that collapses a dock edge and asserts a 28px rail remains, then re-expands and asserts the panel is restored (visible again, not left as a rail).

## Acceptance criteria

- Top-bar controls from `Toolbar.tsx` and from `SceneTools.tsx` (`PanelToggle`, `OverlayMenu`) render as icon buttons, not text buttons.
- Each of those controls has an `aria-label` and a `title`, both taken from `labels/`, and the accessible name matches the existing role/name query for that control.
- Existing role/name queries for these controls pass without renaming the expected names.
- CameraBar Out/Back remain icon buttons. Zoom and Fit still appear only on the stage nav.
- CameraBar and SceneOverlay no longer accept or render `panelToggles`. Call sites compile without that prop.
- `surface/PanelVisibilityToggles.tsx` is deleted. A repo search finds no references to `PanelVisibilityToggles` or `panelToggles`.
- The new DockEdge test fails if collapse does not leave a 28px rail, and fails if re-expand does not restore the panel. The test passes on the finished change.
- No new user-facing copy is introduced outside `labels/`.

## Out of scope

- Redesigning CameraBar Out/Back, or moving zoom/Fit off the stage nav.
- Changing what panels, overlays, or toolbar actions do, beyond presenting them as icon buttons.
- Changing dock layout rules, rail width, or collapse behavior except as needed for the 28px rail assertion to hold.
- Adding panels, toggles, or a replacement for `PanelVisibilityToggles`.
- Renaming accessible names, rewriting unrelated tests, or drive-by refactors outside these controls, the `panelToggles` call sites, and the deleted file.

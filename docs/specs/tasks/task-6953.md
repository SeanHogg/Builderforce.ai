## Problem & Goal

The Code Visualizer depth trail (system › module › class › method) is only half-built. `DepthTrail` can render crumbs and emit `onClimb(depth)` (0 = system), but `PathStrip` does not accept or render that trail, and drill state can only pop one frame via `out()`. Users cannot click an earlier crumb to jump back to that depth.

Goal: wire the existing trail into `PathStrip` and `KnowledgeGraphView`, and add a stack-slicing `climb(depth)` so each earlier crumb climbs back in one click. Leave the work uncommitted.

## Target users / ICP roles

- Developers navigating a knowledge graph in the Code Visualizer who drill system → module → class → method and need a one-click way back to an ancestor depth.
- Downstream implementers on this slice: they share this PRD and must not redesign the trail component.

## Scope

In `packages/knowledge-graph-view` of `seanhogg/builderforce.ai` (base `main`):

- Extend `src/surface/PathStrip.tsx` with optional `trail`, `systemName`, and `onClimb`, and render `DepthTrail` above the stops.
- Add `climb(depth)` next to `out()` in `src/surface/transit/useDrill.ts`: slice the drill stack to that depth; `0` clears it. `out()` stays a single-frame pop.
- If the new method is required for typecheck, update the three inline drill stubs in `src/stage/overlay/callSite.test.tsx` and `src/stage/overlay/routeLine.test.tsx`.
- Minimal edit of `src/KnowledgeGraphView.tsx`: pass `surface.drill.stack`, the root title, and a climb handler into `PathStrip`.
- Re-read `PathStrip.tsx` and `KnowledgeGraphView.tsx` immediately before editing; other agents edit them.
- Do not change the already-written `DepthTrail` behavior except as required to satisfy its existing tests.

## Functional requirements

1. `PathStrip` accepts optional `trail`, `systemName`, and `onClimb`. When those props are omitted, existing stop rendering and behavior are unchanged.
2. When trail props are present, `PathStrip` renders `DepthTrail` above the stops, forwarding `trail`, `systemName`, and `onClimb`.
3. Trail visibility and interaction stay as implemented in `DepthTrail`: hidden when the stack is empty; the current crumb is not a button; earlier crumbs call `onClimb(depth)` with `0` meaning system.
4. `useDrill` exposes `climb(depth)` beside `out()`. `climb` slices the stack to `depth`. `climb(0)` clears the stack. `out()` still pops exactly one frame.
5. `KnowledgeGraphView` passes `surface.drill.stack` as the trail, the root title as `systemName`, and a handler that calls `climb` into `PathStrip`. No other view behavior changes.
6. Drill stubs in `callSite.test.tsx` and `routeLine.test.tsx` gain `climb` only if the new method is required for those stubs to typecheck.
7. Verification from `packages/knowledge-graph-view`:
   - `pnpm exec vitest run src/surface/DepthTrail.test.tsx src/surface/PathStrip.test.tsx --pool=threads`
   - `pnpm --package=typescript dlx tsc --noEmit -p .`
8. Do not commit.

## Acceptance criteria

- `DepthTrail.test.tsx` passes, including the `PathStrip` case that expects `trail`, `systemName`, and `onClimb`.
- `PathStrip.test.tsx` passes.
- `tsc --noEmit -p .` from `packages/knowledge-graph-view` exits clean, including the overlay drill stubs.
- Clicking an earlier crumb climbs to that depth in one action; depth `0` returns to system (empty stack). The current crumb is not clickable. An empty stack shows no trail.
- `out()` still pops one frame only.
- `PathStrip` without trail props still renders stops as before.
- `KnowledgeGraphView` change is limited to passing stack, root title, and climb handler into `PathStrip`.
- No commit is created.

## Out of scope

- Redesign of `DepthTrail`, crumb copy, or visual styling beyond wiring it above PathStrip stops.
- Changing drill-in behavior, route lines, call-site overlay logic, or any navigation other than climb-back.
- New depth levels beyond system › module › class › method.
- Commits, PRs, or edits outside the files required to wire and typecheck this slice.
- Refactors of `KnowledgeGraphView` or `PathStrip` unrelated to the trail props and climb handler.

# PRD: Register the dead-letter export command (G13a)

## Problem & Goal

The dead-letter export/repair command exists in the working tree but is not reachable from a clean product build. `builderforce.exportDeadLetters` is absent from `origin/main` (`extension.ts`, `package.json`, and `package.nls.json`). A person cannot discover or invoke it from the VS Code command palette.

Registration, manifest entry, and translated titles are implemented and verified, but they cannot land yet. `clients/vscode/src/extension.ts` also contains another agent's uncommitted work that imports the untracked module `./sendPermissionActivation`. Committing `extension.ts` alone would ship a build that cannot resolve that import.

**Goal:** Once `sendPermissionActivation.ts` and the other in-flight `extension.ts` work are committed, land the dead-letter command registration, manifest entry, five NLS titles, and host tests as **one commit** so a person can reach `builderforce.exportDeadLetters` from the command palette. Do not commit the patch file.

## Target users / ICP roles

- **Extension user:** needs a discoverable command to export or repair dead letters, with a localized title in their VS Code locale.
- **Landing agent:** commits the already-verified wiring only after the blocking module is on the branch, without sweeping unrelated uncommitted work or leaving a broken import.

## Scope

Land the command so it is registered on activate, declared in the extension manifest, titled in all five NLS catalogs, and proven wired by tests that read those files from disk.

In-scope paths:

- `clients/vscode/src/extension.ts` — register `EXPORT_DEAD_LETTERS_COMMAND` into `context.subscriptions` inside `activate`
- `clients/vscode/package.json` — command id `builderforce.exportDeadLetters`, title `%command.exportDeadLetters%`
- Five NLS catalogs — de, es, fr, zh-cn, and base English titles
- `clients/vscode/src/deadLetterCommand.host.test.ts` — disk-backed host tests
- Existing `deadLetterCommand.test.ts` remains part of the verification set

The registration body, module, and manifest entry currently live in the same in-flight working tree. The patch at `Builderforce.ai/.g13a-deadletter-command.patch` is a holding artifact only. It does not apply to a clean `origin/main` checkout and must not be the landed artifact.

## Functional requirements

1. On activate, register `vscode.commands.registerCommand(EXPORT_DEAD_LETTERS_COMMAND, ...)` and push the disposable into `context.subscriptions`, following the `installAuditClose()` pattern.
2. Route registration failures through `surfaceError(error, "command:exportDeadLetters", ...)`. The activate path must not fetch, flush, or retry.
3. Declare the command in `package.json` as `builderforce.exportDeadLetters` with title `%command.exportDeadLetters%`, matching the neighbouring `%command.fixErrors%` style.
4. Provide a real translated title in each catalog, not an English copy:
   - base: Export Dead Letters
   - de: Tote Briefe exportieren
   - es: Exportar letras muertas
   - fr: Exporter les lettres mortes
   - zh-cn: 导出死信
5. Keep host tests non-self-referential: they must `readFileSync` `extension.ts`, `package.json`, and all five catalogs from disk and fail if registration, command id, or titles are removed.
6. Land only after `sendPermissionActivation.ts` and the other in-flight `extension.ts` work are committed. Then commit `extension.ts`, `package.json`, the five NLS catalogs, and `deadLetterCommand.host.test.ts` together. Do not commit `Builderforce.ai/.g13a-deadletter-command.patch`.
7. The landed tree must resolve every import in `extension.ts`. Do not commit a partial `extension.ts` that references an untracked module.

## Acceptance criteria

- From a checkout that includes the blocking module, `builderforce.exportDeadLetters` is registered during `activate` and disposed with the extension context.
- The command appears in the contributed commands list with title key `%command.exportDeadLetters%`.
- All five catalogs contain the titles listed above; none is a copied English string where a translation is required.
- `deadLetterCommand.test.ts` (3) and `deadLetterCommand.host.test.ts` (8) pass (11/11).
- Removing the registration or the command id causes the host tests to fail (previously observed: 5 of 8). Restoring the wiring restores a green run.
- `origin/main` before this land has zero occurrences of the command in `extension.ts`, `package.json`, and `package.nls.json`. After the single commit, those files and the host test are present and consistent.
- The commit does not include the `.g13a-deadletter-command.patch` file and does not leave `extension.ts` importing an untracked `sendPermissionActivation` module.
- Activate registration does not perform fetch, flush, or retry.

## Out of scope

- Implementing or changing dead-letter fetch, flush, retry, export payload format, or repair logic.
- Committing or applying `Builderforce.ai/.g13a-deadletter-command.patch` as the delivery mechanism.
- Landing `extension.ts` before `sendPermissionActivation.ts` and the other in-flight extension work are committed.
- Sweeping another agent's uncommitted lines into this change, or editing `installRunRecovery`, `deadLetterCommand`, or `platformPolicy` beyond what this registration requires.
- New locales beyond the five catalogs already carrying titles.
- Command-palette UX beyond standard VS Code command contribution (no new views, keybindings, or menus unless already required by the existing contribution).

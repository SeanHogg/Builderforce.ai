# PRD 50: One pipeline above runAgent

## Problem & Goal

Turns above the kernel are forked. Web, VS Code participant, VS Code panel, and cloud each reach the agent differently: omitted or defaulted entry labels, a second participant journal, a direct `runBrainLoop` call, surface-replaced hook bodies, and a child host that skips `gateStarts`. Behavior diverges by surface even though every turn should be the same pipeline into `runAgent` → `runAgentLoop`.

The kernel is not the problem. `packages/agent-run/src/runAgent.ts` calling `packages/agent-loop/src/loop.ts` stays as it is. Consolidate every fork above that call so each surface starts the same pipeline, passes ports and an explicit `entryPoint`, and does not replace shared policy.

This session left an unshipped, unverified edit. `BrainRunRequest.entryPoint` is required in `brain-embedded/src/runStore/runTypes.ts`, and `brain-embedded/src/run/runPrepared.ts` calls `requiredEntryPoint(req.entryPoint)`. That function does not exist. The tree does not compile. Repair that before any other slice.

Contract: `docs/specs/50-prd-one-pipeline.md` (also referenced as `Builderforce.ai/docs/specs/50-prd-one-pipeline.md`). Fork inventory: `docs/specs/_scratch-agent-pipeline-map.md`. Read both before editing. Do not write a second spec.

## Target users / ICP roles

- Engineers and downstream agents changing `brain-embedded`, `packages/agent-run`, and the web, VS Code, and cloud surfaces in `seanhogg/builderforce.ai` (base `main`).
- Surface owners for web conversation, the VS Code panel host, the VS Code participant (`clients/vscode/src/nativeBrainRun.ts`, `clients/vscode/src/chatParticipant.ts`), and cloud policy wiring.
- Reviewers who must accept slices 1–4 before any later slice starts.
- End users on web, VS Code, and cloud, who should get one gated run path rather than a surface-specific loop or journal.

## Scope

In scope, in order. Do not start a later slice until the previous one compiles and matches this contract.

1. Restore compile and make a missing `entryPoint` fail closed. Update every production caller, test, and harness that omitted the label. Web conversation does not set `entryPoint` today; that caller must set it explicitly.
2. Route the VS Code participant through the panel host start (`brainRunHost.ts`) with `entryPoint: 'vscode'`. Delete the participant's second journal. Stop calling `runBrainLoop`.
3. Surfaces pass ports into `policy/*` factories `createFinishHook`, `createGuardsHook`, and `createCompactionHook`. Stop replacing hook bodies from VSIX `runPrepared`, cloud `cloudPolicyModules`, and web `agentReplyRun`.
4. One `spawnChild` in `packages/agent-run/src/policy/subagents/child.ts` that re-enters that surface's user start. Remove the VSIX `childRunHost` path that skips `gateStarts`.

Use the source map to find forks. Close only the forks these four slices name. Ship policy is `commit_push` to `seanhogg/builderforce.ai`, base `main`, only after verification below passes. Do not leave the tree uncompiled on the branch you push.

## Functional requirements

1. Fix the broken `requiredEntryPoint` call first. Define `requiredEntryPoint` where `brain-embedded/src/run/runPrepared.ts` already calls it. It must throw when `entryPoint` is missing, undefined, or empty, and otherwise return the given label unchanged. Do not assign a fallback. A direct `req.entryPoint` read without that fail-closed throw does not meet this requirement.
2. Keep `BrainRunRequest.entryPoint` required. Do not make it optional to silence callers. A missing label must fail. It must never become `'web'` or any other default in `runPrepared`, `runTypes`, factories, or callers.
3. Update every production caller the required field breaks, including web conversation, which must pass its real surface label explicitly at start. Update tests and harnesses that still omit the label so they pass an explicit label. Do not delete or weaken assertions to keep an omission compiling.
4. The typecheck error list is the caller inventory. Every remaining omission is in scope for this slice. Do not treat the unverified session edit as shipped until this slice compiles and fail-closed behavior is present.
5. Participant entry in `clients/vscode/src/nativeBrainRun.ts` and `clients/vscode/src/chatParticipant.ts` must call the panel host start in `brainRunHost.ts` and pass `entryPoint: 'vscode'`. It must not call `runBrainLoop`. It must not keep a second journal, including a journal that is only unwired but still written.
6. After that routing, participant and panel share one user start, one journal, and the same gates. No participant-only loop remains.
7. `createFinishHook`, `createGuardsHook`, and `createCompactionHook` own the hook bodies. Web, VSIX, and cloud pass ports into those factories. Delete or stop using the body replacements in VSIX `runPrepared`, cloud `cloudPolicyModules`, and web `agentReplyRun`. Do not copy those bodies into new surface-local hooks.
8. Child runs use only `spawnChild` in `packages/agent-run/src/policy/subagents/child.ts`. That function re-enters the surface's user start so `gateStarts` and the rest of start policy run. VSIX `childRunHost` must not start a child by skipping `gateStarts`. Remove that side door rather than wrapping it.
9. Do not change how `packages/agent-run/src/runAgent.ts` calls `packages/agent-loop/src/loop.ts`. No new loop, no kernel rewrite, no parallel runner beside `runAgent`.
10. Do not loosen conformance or unit assertions. If a test fails because a fork was removed, update the test to the single pipeline. Do not relax the expected failure, label, gate, or hook behavior.

## Acceptance criteria

- `brain-embedded` typechecks with `requiredEntryPoint` defined and `BrainRunRequest.entryPoint` required. A missing, undefined, or empty label throws. No code path sets a missing label to `'web'` or any other default.
- Web conversation, every other production caller, and every test and harness that previously omitted `entryPoint` pass an explicit label. The repo typechecks without reverting the required field.
- Participant start goes through `brainRunHost.ts` with `entryPoint: 'vscode'`. There is no participant call to `runBrainLoop` and no second participant journal.
- Finish, guards, and compaction hook bodies come only from the `policy/*` factories. VSIX `runPrepared`, cloud `cloudPolicyModules`, and web `agentReplyRun` do not replace those bodies. Surfaces supply ports only.
- Child spawn has one implementation, `packages/agent-run/src/policy/subagents/child.ts`, and re-enters the surface user start. No VSIX child path skips `gateStarts`.
- `packages/agent-run/src/runAgent.ts` still only enters the loop through `packages/agent-loop/src/loop.ts`, with no kernel redesign in the diff.
- brain-embedded typecheck, agent-run typecheck, and the conformance suites named in `docs/specs/50-prd-one-pipeline.md` pass. Assertions are unchanged in strength.
- Slices 1–4 are committed and pushed under ship policy `commit_push` to `seanhogg/builderforce.ai` with base `main`. The pushed tree compiles.

## Out of scope

- Redesign of the kernel, `runAgent`, or `packages/agent-loop/src/loop.ts`.
- Starting later slices before slices 1–4 have landed and been reviewed: `routeRun`, `planWork` / `evaluateRun`, one stall module, one `buildOpening`, and deleting `channelAdapter`.
- New entry labels, new journals, new loop entry points, or a `'web'` (or any other) default for a missing label.
- Loosening assertions, skipping named conformance suites, or shipping the current non-compiling tree.
- Product or UX changes unrelated to collapsing forks above `runAgent`.

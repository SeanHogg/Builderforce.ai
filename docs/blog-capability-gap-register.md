# Blog capability gap register

Last code audit: 2026-08-04. Scope: all 59 files in `frontend/src/content/blog`.

The articles remain published. This register treats their product statements as acceptance criteria. A claim is **evidenced** only when a production path and a regression test exist; UI copy or a mock is not evidence.

## Implemented in this slice

- `webgpu-lora-explained`, `local-first-ai-webgpu-in-the-browser`: LoRA rank/alpha now drive a real frozen-base adapter; local-only mode performs no training API calls; output is PEFT-shaped safetensors; the API validates LoRA A/B tensors and bounds before R2 persistence. The remaining WebGPU-kernel and named-pretrained-model claims are still open below.
- `build-and-train-evermind-on-the-creation-canvas`, `brain-operates-the-creation-canvas`: an Evermind object's `train` action now opens the real adapter studio, links a completed workspace job/artifact to the object, and `evaluate` invokes the canonical evaluation endpoint instead of creating an unevaluated placeholder.
- `real-time-collaboration-humans-and-agents`, `video-meetings-standups-and-shared-calendars`: meetings now expose a direct-media-only control. That mode requests STUN-only ICE configuration and tests prove every TURN URL is removed; relay-fallback explicitly discloses that encrypted media may traverse TURN.

## CI policy to add

Each material blog claim should receive a stable capability ID in frontmatter. CI should fail when an ID has no passing evidence test, when its test is skipped, or when evidence is older than the product/version named in a comparison. The gap table above is the migration backlog; new articles should not merge without IDs from day one.

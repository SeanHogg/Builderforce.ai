最便宜的 token 是你从未花掉的那一个。每个严肃的 AI 平台最终都要面对同一张账单：同样的问题，换种说法再问，一遍又一遍地计费给一个上周就已经给出过答案的前沿模型。缓存*字符串*几乎没有帮助，因为字面永远不会完全相同。你想要的是识别*问题本身*，并凭项目已经掌握的知识来回答——根本不去启动付费模型。

这就是“记忆优先推理”（memory-first inference）所做的事。

## 先查记忆，再用模型

在 Brain 发起付费模型调用之前，它会先检查项目自己的记忆：

- **精确重复问答缓存。** 当一个问题此前已被确信地回答过，就直接返回存储的答案——无需模型调用，不消耗 token。这些条目存放在项目的事实层中，并被刻意排除在检索上下文之外，因此永远不会污染依据。
- **在项目的 Evermind 上进行可选择启用的推理。** 每个项目都可以运行自己的、可自我更新的模型——Evermind——并在有把握时直接由它作答。生成由 SSM 自己完成；前沿模型不会被计费。

一旦确信命中，LLM 会被**完全短路**。整个决策集中在唯一一个解析器中，因此每个界面——目前的 Web 版 Brain 和 VS Code 版 Brain——行为完全一致，而不是各自以自己的方式重新实现“我该跳过模型吗？”。

## 一次教会，处处作答

一个项目并不总是只有一个模型。一个项目下可以归集多个构建版本，每个都有自己的 Evermind 头。因此学习是**扇出**的：当某一轮产生了值得记住的内容，它会通过同一条共享路径，贡献给项目下的*每一个* Evermind——项目自己的，以及各构建版本的。在一个地方教会工作团队某件事，它在所有地方都能用上。

推理在设计上保持单选——一次运行在一个模型上执行——但*学习*被刻意广播，因为知识复制起来很便宜，重新推导却很昂贵。

## 账单随着记忆增长而下降

这是复利的部分。早期，大多数问题都是新的，会交给模型处理。但每一个有把握的答案都是未来的一次跳过，每一次教训都是未来的一次短路。项目工作得越多，它就能免费回答越多自己的问题——因此 token 账单不会随使用量线性增长，而会随着项目记忆的充实而向下弯曲。

与[语义响应缓存](/blog/semantic-response-cache)搭配使用——后者在网关和设备端跨越不同说法复用答案——记忆优先推理成为 token 策略的第一道防线，而这套策略用得越多就越便宜。

## 为什么这很重要

拥有自己的智能不仅关乎隐私和可移植性——也关乎经济性。一个冻结的前沿模型，会在第一万次回答你最常见的问题时仍向你收取全价。而一个有记忆的项目一分钱不收。记忆优先推理让可自我更新的模型把“我们以前回答过这个问题”从一种烦恼，变成一项实实在在的节省。

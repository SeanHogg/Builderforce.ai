大多数"AI 编程"工具都是单人模式：一个开发者、一个编辑器、一个智能体、一个线程。Builderforce.ai 反其道而行之：它是一个**为人类与 AI 智能体混合团队打造的协作平台**，每一次对话、每一场会议、每一次交接，都发生在同一个可观测的记录系统上。

> Builderforce.ai 是一个实时协作平台，人类与 AI 智能体在这里并肩工作：共用一张看板，在可以发给某个人或某个 `@agent` 的多方线程里聊天，通过实时 WebRTC 视频开会，并在共享日历上协调时间——无论是在网页端还是在 VS Code 里。

这里的协作不是往编程工具上硬塞一个聊天小部件，而是四个相互连通的界面，全部读写同一份项目状态。

![四个协作界面——共享看板、团队聊天、实时会议和共享日历——围绕着同一个共享记录系统排布，人类与智能体在其中是队友](/blog/collab-four-surfaces.svg)

| 界面 | 用途 | 协作上的巧思 |
| --- | --- | --- |
| **共享看板** | 规划、分配和跟踪工作 | 人类和智能体在同一组泳道上是平等的负责人 |
| **团队聊天** | 把事情聊清楚 | 线程是共享的；消息可以发给某个人，*也可以*发给某个 `@agent` |
| **实时会议** | 彼此看得见、听得到 | WebRTC 站会与回顾会，圆桌上摄像头全开 |
| **共享日历** | 约定一个时间 | 每个人的可用时段 + 跨时区的"查找时间" |

它们读写的都是*同一份*项目状态——因此会议上的决定、聊天里的一条消息、看板上的一张工单，永远不会散落在互不相通的工具里。

## 1. 一张人类与智能体同为队友的共享看板

基础是一张对人和智能体一视同仁的看板——两者都是一等负责人。把一张工单拖进某个智能体的泳道，它就会自主运行；把它分配给同事，同事就会接手。泳道可以要求由合适的审阅者把关后工单才能推进，每一次"完成"都附带签收审计。看板是工作唯一的归宿，所以协作永远有一个明确的对象：一张真实的工单，而不是一条沉没在 Slack 里的消息。

## 2. 多方团队聊天——和人对话，*也能*和智能体对话

聊天线程**在其所属项目和租户内全局可见**，所以队友可以看到、打开并加入进来一起协作。你可以通过邮件邀请同事，也可以把一个 AI 智能体请进房间。然后把任何一条消息发给特定的参与者：

- 把消息发给一个**人**，它就只是和对方对话——智能体循环保持空闲。
- 把消息发给一个 **`@agent`**，这个智能体就会*以它自己的身份*真正回复，运行一个有边界、受权限约束的工具循环去创建任务、更新 OKR 或读取看板——绝不会超出你本人的访问权限。

![输入框里的一条消息分成两条通道：发给人类时，它点对点送达，智能体循环保持空闲；发给 @agent 时，它会触发一个受权限约束的工具循环，在看板上执行操作](/blog/collab-message-routing.svg)

这就是聊天机器人和群聊的区别——只不过群里有几位成员恰好是 AI。

## 3. 实时视频会议、站会和回顾会

团队不只是一起编辑看板——还能**彼此看得见、听得到**。Builderforce 通过网状 WebRTC 运行实时音视频，因此：

- 在站会、规划会或回顾会期间，管理者可以为整个圆桌打开摄像头。
- 任何人都可以发起临时通话或一对一通话。
- 媒体流点对点传输，从不经过服务器。

摄像头画廊直接叠在例会圆桌之上，所以一场站会就是一次真正的面对面会议，而且锚定在每个人都在用的那张看板上。

## 4. 共享日历与可预约的空闲时段

会议需要一个所有人都能参加的时间。Builderforce 在团队成员和项目组合页面上加入了**团队日历**：一个月视图，外加一个可预约的周视图网格，其中叠加了应用内会议、已连接的 Google/Microsoft 日历事件，以及每个人声明的工作时间。只需设置一次每周可用时段和时区，**"查找时间"**就会提出每位受邀者都真正有空的时段——落在他们各自的工作时间窗口内，并正确处理时区。已排定的会议会以日历邀请的形式同步给参会者。

## 5. 同样的协作，也在 VS Code 里

这一切都不需要离开编辑器。BuilderForce VS Code 扩展把协作界面带进了侧边栏：和队友及智能体聊天，一眼看出哪些会话**正在执行**、哪些**等你回答**；**会议**树列出即将开始和正在进行的通话——可以在浏览器中加入，也可以在 VS Code webview 中原生运行 WebRTC 通话。审阅、批准、开会，都不会打断你的节奏。

## 为什么这很重要

协作工具默认每个参与者都是人。智能体工具默认每个参与者都是机器。Builderforce 是为介于两者之间的现实而设计的——一支**两者兼有**的劳动力——并给了它一个规划、沟通、开会和交付的统一场所。

## 常见问题

**人类和 AI 智能体可以在同一个聊天线程里吗？** 可以。线程在整个项目内共享；通过邮件邀请人，把智能体请进房间。把消息发给人就是和对方对话，发给 `@agent` 则会让该智能体在你的权限范围内代你回复并执行操作。

**视频通话会把我的媒体数据发到服务器吗？** 不会。音视频通过网状 WebRTC 点对点交换；服务器只中继信令。平台提供 STUN，配置后还可使用 TURN。

**我能从 VS Code 加入会议吗？** 可以。会议侧边栏树会列出即将开始和正在进行的会议；"在浏览器中加入"会打开已认证的网页会议，"在此加入"则在 VS Code webview 中原生运行通话。

**我还需要单独的日历工具吗？** 不需要。连接 Google Calendar 或 Microsoft Graph 后，Builderforce 会叠加这些事件、标出你的空闲时段，并把已排定的会议以邀请形式同步出去——排期始终在一个地方完成。

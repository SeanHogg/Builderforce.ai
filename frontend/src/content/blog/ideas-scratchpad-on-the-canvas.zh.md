大多数想法并不是因为不够好才死掉的。它们死在了笔记应用里。

你在淋浴时冒出一个，在散步时冒出一个，在讨论别的事情的通话中途又冒出一个。你把它记在某个地方——笔记应用、收据背面、发给自己的一条 Slack 消息——然后它就和另外四十个想法躺在一起，没有哪一个比你想到它的那天更进一步。六个月后，你说不清哪些想法真正和客户验证过，哪些只是你*感觉*不错。

画布则有相反的问题。它能容纳经过调研的客户细分、竞品对比卡、客户访谈和打过分的实验，却没有地方安放引发这一切的那个尚不成形的念头。

## 客户访谈在哪里发挥作用

一个想法的价值取决于它背后的对话，因此草稿板中的每个想法都有一个 **Plan an interview** 按钮。按下它，三件事同时发生：一张以该想法命名的客户访谈卡片落在看板上；该想法记录下这场访谈是用来检验它的；而一个仅处于已捕捉或探索中的想法会进入验证中。

当访谈整理成文——包括问题、对方未经提示就提到的痛点、原话引述——想法就会把它计入。每个想法都用平实的语言展示自己的证据：*经 2 场访谈和 1 个实验检验*，或*尚未检验——在构建之前先和人聊聊*。如果某个想法指向的访谈并不在看板上，它会如实说明，而不是把它计入。

草稿板顶部还有一个值得据以行动的数字：你的未完结想法中，有多少还没有任何人与客户验证过。

## 它在方法论中的位置

Idea to Real 按 **Idea → Make → Run → Measure** 运行，而第一步被刻意设计得最便宜：[Read 与 Prove](/blog/read-prove-build-the-inner-loop) 先于 Build，这样决定构建就是一个决策，而不是惯性。

草稿板就是这第一步的前门。**Capture** 是 Read 之前的那一刻——想法必须先存在于某个地方，才有人能去调研它。**Exploring** 就是 Read：Brain 可以接手看板上的任何想法，调研它周围的问题、细分人群和竞争格局。**Validating** 就是 Prove：用客户访谈或实验把假设变成事实，也是[让想法成真的八种方式](/blog/eight-ways-to-make-an-idea-real)中成本最低的一种。只有经历了这两步的想法，才应该被 **Promoted** 成你要构建的东西。

这一阶段需要它，是因为方法论在此处没有对应的对象。其后的一切都有——验证、项目、发布、指标。而想法本身，则存在于你想到它时碰巧打开的任何应用里。

## 现在你能用它做什么

- **几秒内捕捉一个想法**，在任何画布上，用一句话，无需先决定它是什么。
- **一眼看到所有想法**，按时间倒序，一键按阶段筛选。
- **一键规划检验某个想法的客户访谈**，双向关联。
- **看清哪些想法真正经过检验**——以及有多少未完结的想法没有人与客户聊过。
- **让 Brain 调研看板上的任何想法**，因为每个想法都已经是它能读取并填写的一张卡片。

# AI Coding and Agent Platforms — A Criteria-First Guide

AI coding products change too quickly for a permanent winner table. Pricing, models, deployment options, and agent behavior can change between releases. Use this guide to identify the category that fits your work, then verify critical requirements with the vendor.

## Start with the job

- **Editor assistance:** prioritize latency, edit quality, repository context, and review ergonomics.
- **Terminal engineering:** prioritize tool permissions, isolation, recovery, and reproducibility.
- **Hosted autonomous work:** prioritize task success, supervision, billing controls, and artifact ownership.
- **Open runtime:** prioritize deployment, model adapters, maintenance, and operational responsibility.
- **Connected delivery:** prioritize collaboration, workflow coordination, approvals, provenance, and handoff into real systems.

Builderforce.ai belongs primarily in the last category. Its creative canvas connects supported artifacts, people, and agents, then moves reviewed work into supported projects and execution paths. BuilderForce Agents is a separate MIT-licensed engineering runtime that can run on private infrastructure; hosted collaboration and connected services retain their own boundaries.

## Questions worth testing

1. Can your representative task be completed and reopened without losing context?
2. Which actions can require approval, and what happens when policy resolution fails?
3. Where does each step execute: browser, hosted workspace, private runtime, or connected service?
4. Which records are retained, and where are there observability gaps?
5. Are price, quotas, and availability generated from enforced entitlements?

Run the same representative workflow in every shortlisted product. Record the date, plan, model, configuration, completion quality, human interventions, elapsed time, and cost. That evidence is more useful than a universal score.

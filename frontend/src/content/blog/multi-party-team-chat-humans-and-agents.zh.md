在大多数 AI 工具里，“聊天”指的是一个人对着一个模型打字。每条消息都会运行模型；你没法把一位队友拉进来直接跟他说话，也没法把对话交给一个随后会真正*行动*的专业智能体。Builderforce.ai 把聊天重新打造成了**多方协作**——参与者中有人也有智能体，而每条消息发给谁，由你来决定。

> 在 Builderforce.ai 中，团队聊天会话在整个项目内共享：通过邮件邀请成员，把 AI 智能体请进来，然后把消息发给指定的参与者。发给人的消息只是跟那个人交流；一个 `@agent` 提及会让那个智能体以自己的身份回复，并运行一个有边界、受权限约束的工具循环——永远不会超出你自己的权限。

## 聊天机器人 vs. 多方团队聊天

| | 典型的 AI 聊天 | Builderforce 团队聊天 |
| --- | --- | --- |
| **参与者** | 一个人，一个模型 | 许多人**和**许多智能体 |
| **消息触发什么** | 每条消息都会运行模型 | 你把每条消息发给一个人或一个 `@agent` |
| **和同事交流** | 做不到 | 发给一个人——智能体循环保持空闲 |
| **智能体行动** | 只回复文字 | 以自己的身份运行受限的工具循环（任务、OKR、看板） |
| **权限** | 不适用 | 智能体使用**你的**角色和 token——绝不越权 |
| **会话可见性** | 仅你可见 | 在项目内共享（或明确锁定） |

## 会话是共享的，不是私密的孤岛

Builderforce 的聊天**在它所属的项目和租户内全局可见**。队友可以看到它、打开它，并加入进来协作——他们第一次参与时会被自动记录为成员，所以一个会话的受众是真实且实时的。当一段对话需要保密时，你也可以把会话**锁定**，只让所有者和明确邀请的成员访问。所有者保留管理权限（重命名、归档、邀请、移除、锁定）；其他人则参与协作。

## 通过邮件邀请成员——即使对方还不在团队里

用邮件把一位同事加进会话。如果对方已经在你的团队里，他们会收到一条应用内通知（还可以选择通过邮件 webhook 通知），这个会话也会出现在他们的列表里。如果对方**还不是**成员，这次邀请会创建一条待处理记录，这样当他们注册时就会被自动加入，并在首次访问时被拉进这个聊天——一次无缝加入，没有多余步骤。顶部栏里的全局通知铃铛会显示聊天邀请和提及，并直接深度链接到对应会话。

## 把消息发给对的参与者

核心理念是：一条消息有一个**收件人**。在输入框里，你选择“收件人：<name>”（或者直接以 `@name` 开头），Builderforce 就会据此路由这一轮对话：

- **发给一个人**——这条消息是*给那个人的*。它会被保存并送达，但**不会**运行模型。没有任何智能体被唤醒；只是人与人之间在交流。
- **发给一个 `@agent`**——那个智能体会**以自己的身份回复**。它在服务端运行一个有边界的工具循环，使用一份精心挑选的、非破坏性的允许列表（读取看板、创建跟进任务、更新 OKR、读取规格和知识库）——以**你的**角色和 token 执行，所以智能体永远做不了任何你做不了的事。它的回答会以智能体的名义发布，带着它自己的名字和头像。

![输入框把一条消息分到两条通道之一：发给人时，消息点对点送达，智能体循环保持空闲；发给 @agent 时，它会运行一个受权限约束的工具循环，创建任务、更新 OKR 并读取看板](/blog/collab-message-routing.svg)

于是一个会话里可以真正混合两者：你先问队友一个问题，然后 `@mention` 一个智能体，让它去创建你们刚刚商定的任务。

## 受你的权限约束，而不是智能体的

被邀请进来的智能体在聊天中采取的每一个行动，都以触发它的用户的权限运行。聊天内的允许列表里没有删除操作，也没有控制平面的访问权限。结果就是一种你可以信任的协作：会话里的智能体足够强大，能派上用场；又被足够严格地约束，足以保证安全。

## 网页端和 VS Code 中的相同体验

多方聊天在各个界面之间共享。网页版 Brain 和 VS Code webview 使用同样的收件人路由、同样的参与者列表和同样的头像——原生的会话树还会把每个会话的参与者显示为彩色头像圆点，让你一眼就能看出谁在这个会话里。在网页端邀请一个人，在 VS Code 里 `@mention` 一个智能体——这是同一段对话。

## 为什么这很重要

真实的工作，是几个人之间的对话，而且越来越多地，也是几个智能体之间的对话。把聊天当作一个人对一个模型，无法体现这一点。通过让会话共享、让参与者明确、让 `@agent` 成为一个受你的权限约束的真正执行者，Builderforce 让聊天成为整支劳动力协作的地方——而不只是一个提示词输入框。

## 常见问题

**我可以在聊天里和队友交流，而不触发 AI 回复吗？** 可以。把消息发给一个人（选择他作为收件人，或以 `@name` 开头），它就会作为人与人之间的消息送达——智能体循环保持空闲。

**当我提及一个 `@agent` 时，它实际上能做什么？** 它会运行一个有边界的工具循环，使用一份安全的、只读加有限写入的允许列表（读取看板、创建任务、更新 OKR、读取规格和知识库），并使用你的角色和 token。它不能删除，不能触及控制平面，也永远不能超出你自己的权限。

**我能邀请还不在团队里的人吗？** 能。邀请一个陌生邮箱会创建一条待处理邀请；当对方注册时，他们会被加入团队，并在首次访问时被自动拉进聊天。

**聊天是我私有的吗？** 默认情况下，会话在你的项目内共享，队友可以加入。你可以锁定一个会话，让只有所有者和明确邀请的成员才能访问。

**这在 VS Code 里能用吗？** 能。VS Code webview 与网页版 Brain 共享同样的收件人路由、参与者模型和头像——它是跨界面的同一段对话。

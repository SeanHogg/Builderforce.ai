## 从精准的能力提示词开始

能力提示词是整个数据集的种子。模糊的提示词产出泛泛的数据集；具体的提示词产出有针对性、真正有用的数据集。

**较弱的提示词：**
> “一个乐于助人的编程助手。”

**较强的提示词：**
> “一个擅长把遗留 JavaScript 重构为现代 TypeScript 的 TypeScript 助手。它能识别隐式的 `any` 类型，添加显式标注，把 CommonJS 的 `require` 转换为 ESM 的 `import`，并为每处改动附上一句话的理由说明。”

由此产生的数据集——以及最终的智能体——差别非常显著。

## 追求多样性

好的数据集覆盖智能体在生产中会遇到的输入的*完整分布*。使用 Builderforce 的**多样性设置**来增加以下方面的变化：

- **输入复杂度**——混合简单、中等和复杂的示例
- **边界情况**——包含格式错误的输入、含糊的请求和棘手的边界情况
- **语气与格式**——变化问题和回答的写作风格

一个包含 500 条多样化示例的数据集，通常优于包含 2 000 条近似重复示例的数据集。

## 选用合适的生成模型

Builderforce 允许你为数据集生成选择任意 OpenRouter 模型。一般建议如下：

| 使用场景 | 推荐模型 |
|----------|-------------------|
| 面向代码的数据集 | Claude 3.5 Sonnet、GPT-4o、Gemini 1.5 Pro |
| 推理类数据集 | o1、Claude 3 Opus |
| 通用指令微调 | Llama 3.1 70B、Mistral Large |
| 注重预算的生成 | Gemini Flash、Llama 3.1 8B |

对于专业领域（医疗、法律、金融），请在能力提示词中把强大的基础模型与领域特定的示例搭配使用。

## 训练前先审查样本

不要未经审查就用自动生成的数据训练。在你确认开始训练之前，Builderforce 会向你展示 20 条随机样本。请留意：

- ✅ 清晰、无歧义的指令
- ✅ 准确、详细的回答
- ✅ 一致的格式
- ❌ 捏造的事实或无法编译的代码
- ❌ 过短或离题的回答
- ❌ 重复或近似重复的内容

如果样本中超过 10–15% 看起来不对劲，就用改进后的提示词重新生成。

## 为复杂智能体分层组合数据集

对于需要多种能力的智能体，请**按能力分别生成数据集**，并在训练前合并。这样你可以控制混合比例：

```
dataset_a: 300 examples for TypeScript refactoring
dataset_b: 200 examples for code explanation
dataset_c: 100 examples for error diagnosis
─────────────────────────────────────────────────
merged:    600 examples, 50% / 33% / 17% split
```

50/33/17 的比例会让智能体偏向其主要任务，同时保持次要能力的敏锐。

## 用 AI 评估闭环

训练之后，针对留出的测试切分运行 **AI 评估**（Builderforce 会自动保留数据集的 20%）。评估报告会显示：

- **正确性得分**——输出是否回答了指令？
- **推理得分**——逻辑是否严密？
- **幻觉率**——输出是否包含捏造的事实？

如果得分低于目标，请查看哪些*类别*的示例得分最低——那些就是需要更多训练数据的能力。

## 快速迭代

最好的数据集是迭代构建出来的。一个好的工作流程：

1. 生成 200 条示例 → 训练 → 评估
2. 根据评估报告找出薄弱环节
3. 针对薄弱环节生成 100 条有针对性的示例
4. 合并数据集 → 重新训练 → 再次评估
5. 重复，直到得分达到你的标准

借助 Builderforce 的浏览器内流水线，每次迭代端到端大约需要 15–20 分钟。

## 导出并为数据集做版本管理

训练之前，务必把最终数据集导出为 JSONL 文件。这会带给你：

- 可复现的训练产物
- 以后在不同基础模型上重新训练的能力
- 未来迭代的起点

用语义化的方式命名导出文件：`typescript-refactor-v1.jsonl`、`typescript-refactor-v2-more-edge-cases.jsonl`，依此类推。

# D’un canevas vierge à un playbook reproductible : modèles, cadres, branches et points de contrôle

Un canevas vierge est libérateur une fois. Un processus d’équipe reproductible a besoin d’une structure réutilisable sans figer chaque projet dans le même document.

Le Creation Canvas distingue quatre types de réutilisation : les packs de démarrage, les cadres réutilisables, les points de contrôle nommés et les branches.

![Vue produit du menu de modèles du canevas avec six packs livrés, un espace de travail encadré, un historique de points de contrôle nommés, un indicateur de branche et des commandes de relecture de fusion objet par objet](/blog/canvas-reuse-versioning-workspace.svg)

## Les packs créent des systèmes d’objets opérationnels

Builderforce livre six packs de démarrage via le catalogue de modèles du canevas :

- **Studio de campagne** — flux de travail, site web, tableau de bord et agent de campagne.
- **Découverte produit** — jeu de données, synthèse de fonctionnalités, ensemble de maquettes et évaluation.
- **Récit de données** — jeu de données, graphique, tableau de bord et diapositives.
- **Point quotidien improvisé** — point quotidien, membre du personnel, agent et tâche de suivi.
- **Laboratoire de modèles Evermind** — jeu de données, Evermind, évaluation et agent de modèle publié.
- **Revue exécutive** — projet, tableau de bord, feuille de route et diapositives.

Le pack place de véritables types d’objets enregistrés et des relations de départ. La politique du tenant continue de régir chaque ressource vivante rattachée ensuite ; installer un pack n’accorde pas l’accès à un projet, un modèle, un agent ou une intégration.

## Les cadres préservent un agencement utile

Un cadre est un objet de collaboration à part entière, avec un objectif, une couleur et une bordure. Les équipes peuvent regrouper une zone de revue, un atelier, un pipeline de modèle ou une séquence de présentation sans laisser entendre que chaque objet voisin s’exécute avec les autres.

Des préréglages de cadres personnalisés peuvent être enregistrés en privé sur l’appareil et réinsérés depuis le menu de modèles. C’est utile pour des rituels récurrents et des conventions de mise en page qui ne justifient pas un modèle d’espace de travail complet.

## Les points de contrôle nomment les états significatifs

L’historique automatique répond à « qu’est-ce qui a changé ? ». Un point de contrôle nommé répond à « quel état l’équipe a-t-elle jugé important ? ». Dans une session adossée au serveur, les éditeurs peuvent nommer un point de contrôle avant une revue exécutive, une expérience, une décision de livraison ou un changement d’entraînement de modèle.

Les points de contrôle apparaissent dans l’historique de la session aux côtés des instantanés de révision. Ils ne remplacent pas l’expérimentation par branche ; ce sont des repères durables sur la ligne de travail en cours.

## Les branches isolent les expériences

Une branche crée une session indépendante dérivée du parent. Utilisez-la pour une autre architecture de l’information, une autre orientation de campagne, un autre plan de modèle ou une autre grille de priorisation. Les collaborateurs peuvent travailler sans faire passer le canevas parent par tous les états intermédiaires.

Lorsqu’une branche revient, Builderforce prépare une relecture de fusion explicite. Pour chaque objet existant dans les deux versions, le relecteur choisit la version de la branche ou conserve celle du parent. Les nouveaux objets peuvent être acceptés sans remplacer le travail du parent qui n’est pas concerné.

Ce modèle objet par objet correspond mieux à l’unité réelle de création que « remplacer tout le tableau ».

## L’export garde la session portable

L’export du canevas offre un autre chemin de récupération et de portabilité. Ensemble, ces couches forment une progression pratique :

**pack pour un système de départ → cadre pour un agencement réutilisable → point de contrôle pour un état convenu → branche pour une expérience → fusion pour une décision explicite → export pour la portabilité**

La réutilisation devient plus précise, car chaque mécanisme répond à une question différente.

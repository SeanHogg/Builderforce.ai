看一个智能体在大型代码仓库里开始一项任务，数一数它在第一次修改之前调用了多少次工具。

它用你请求里的一个词去 grep。这个词不在代码里——你描述的是行为，代码给它起的是另一个名字。它列出一个目录。它读一个 2,000 行的文件去找一个函数，接着读到了错误的相邻函数，然后又重新读第一个文件，因为它需要的那段内容已经滑出了上下文。十次、二十次、三十次调用只是为了找方向，每一次都要付费，而什么都还没改。

接着你换了另一个工具，它又把这一切重来一遍——因为之前学到的东西没有存放在任何其他工具能读取的地方。

这就是缺口：**你用的每个 AI 工具都从零开始，而且各自从零开始。**

## Synapse

Synapse 是一个驻留在系统托盘里的小应用，为每个代码仓库维护一个索引——就在你的电脑上，并且始终与你最近一次保存同步。

应用一运行，三件事就变了。

**智能体一开始就有方向。** 每一轮的上下文都带着仓库地图，智能体在打开任何模块之前就知道哪些模块重要。它还获得了 `semantic_search`：问一句“退款是怎么进入总账的？”，答案就是负责这件事的那个函数——路径、行范围、函数体——一次调用就拿到。

**所有工具共享它。** 同一个索引既为 VS Code 里的 Builderforce 智能体服务，也通过一条 MCP 配置为 Claude Code 和 Cursor 服务。配置一次，全部受益。

**过时的记忆会被发现。** 这一点比我们预想的重要得多。

## 知道自己何时出错的记忆

Evermind 会记住之前的运行对你的项目学到了什么：约定、根本原因、东西放在哪里。正是这份记忆，让第十次运行不必重新推导第一次已经弄清楚的事。

但它也可能以最糟糕的方式出错。一条写着“权限校验走 `resolveMembership()`”的记忆，在写下的那天是对的。三周后这个函数不见了——被重命名、合并或删除——而这条记忆依然自信、依然具体，却已经错了。信任它的智能体会去找不存在的代码，更糟的是，会把它重新写一遍。

## 一切留在你的电脑上

索引、切分和向量计算全部在本地运行。向量模型只下载一次，索引存放在你的用户目录里——绝不放进代码仓库——应用也从不向任何地方上传代码。它运行的本地服务由每次启动生成、只有你的用户账户能读取的密钥保护，并且直接拒绝来自网页的请求。

## 在方法中的位置

Builderforce 上的每项工作都走同一个内循环：[阅读、验证、构建](/blog/read-prove-build-the-inner-loop)。阅读和验证是刻意免费的——它们用来判断昂贵的那一步，也就是构建，是否值得去做。

Synapse 是一项**阅读**功能，而阅读恰恰是智能体最薄弱的地方。读不好代码的智能体并不会跳过阅读；它只会读得很糟，而且按构建的价格付费——每次找方向的调用都按构建步骤计费，每次重读都在消耗真正修改所需要的上下文。让阅读既便宜又准确，才能让整个循环名副其实：验证基于真实的代码，构建从正确的文件开始。

过时记忆检查在同一步里补上了一个更隐蔽的缺口。阅读也包括重读你已经知道的东西——而一条记忆只有在仍然正确时才算知识。

## 今天就能做的事

- **让智能体进入一个陌生的区域**，通过描述函数的作用让它找到函数，而不是去猜名字。
- **让 Claude Code 和 Cursor 使用与 Builderforce 智能体相同的索引**——在应用的“连接”面板里添加一次即可。
- **更放心地使用召回的记忆**，因为过时的记忆会自己说出来。
- **处理不能离开公司的代码**，同时仍让智能体完整了解这些代码。

[下载 Synapse](https://github.com/SeanHogg/Builderforce.ai/releases?q=desktop-v&expanded=true)（支持 Windows、macOS 和 Linux），然后在装有 Builderforce 扩展的 VS Code 中打开一个文件夹。

开始做一件事，过去总带着三个没人写明的前提。

你需要一个**账号**，因为页面做的第一件事就是调用服务器，而服务器想知道是谁在问。你需要一块 **GPU**，因为在自己的电脑上运行模型意味着 WebGPU，没有合适显卡的笔记本会被礼貌地告知：请改用云端。你还需要**网络**，因为无论从哪里进来，你输入的文字都会被发往某处。

这些都不该成为让人停止思考的理由。深夜十一点冒出的想法，在一台只有集成显卡的工作电脑上，在火车上，依然是一个想法。这次发布去掉了这三个前提，并补上了本该从一开始就有的东西：一个关于你的文字可以去往哪里的简单选择。

**仅本地**是一项承诺，而不是一种偏好。在这个模式下，内容请求在离开之前就会被拦截，实时连接也一样——也就是那些本来会把画布同步到服务器、或把运行过程流式传到服务器的通道。如果本机上没有模型能回答，你会被明确告知，并得到两条出路：下载一个模型，或切换到混合模式。不会有任何东西悄悄替你发往云端。

**混合**是登录后的默认模式。本机上的模型先接手这一轮；它处理不了时，免费云端额度接着处理；发生切换时你会看到提示，所以你始终知道某个回答来自界线的哪一侧。

**指定模型**是严格的。你选一个模型，就运行那个模型——不替换，也不会把后备方案伪装成你要的东西。它适合做对比、跑基准测试，或者你就是清楚自己想用哪个模型的任务。

## 无需账号，无需 API 调用

Studio 和 Rovr 现在以**匿名**方式启动。无需注册，也无需调用我们的服务器才能开始：页面加载，本地模型在你的浏览器里加载，你就可以开始工作了。在这种状态下你做的一切都留在你的设备上，因为它们根本没有别处可去。

登录会带来那些确实需要账号的功能——默认混合模式、跨设备同步、已连接的服务商账号，以及对你过往工作的记忆回溯。如果你不想注册但想用云端，以访客身份选择**混合**就会启用一小份访客额度；这是访客的文字离开设备的唯一时刻，而且是你自己选择的。

这建立在画布上[先创作，后注册](/blog/create-before-you-sign-up)的基础之上。不同之处在于：回答你的模型不必再住在别处。

## 无需 GPU

[上一次发布](/blog/models-that-run-on-your-machine)带来了下载一次、即可在浏览器 GPU 中运行的模型——当时我们也坦白说过，它需要 WebGPU。这个限制现在没有了。1 比特的 **Bonsai** 模型现在也能在 **CPU** 上运行，在浏览器允许时分摊到多个线程，并在后台 worker 中执行，让页面在模型思考时依然保持流畅。

CPU 比好的 GPU 慢，这一点不必回避。但一个在你手头这台机器上几秒钟就能回答的模型，胜过一个在你没有的那台机器上才能加载的模型。改写、摘要、针对某个页面提问、给计划打个初稿，这些它都绰绰有余——而且从设计上就是私密的。

## 会学习哪些轮次该留在本地的混合模式

简单的"本地优先"有一个明显的代价：每一轮本地模型处理不了的对话，你都要先等它失败，云端才有机会接手。这种情况一多，混合模式就会比直接用云端还慢。

所以混合模式会学习。一个在你设备上运行的小型预测器会观察你自己每一轮的结果——哪些由本地模型处理了，哪些被转交了出去——随着时间推移，它会把那些预计本地模型处理不了的轮次**直接发往云端**，不再绕路。

背后还有两项较小的改变。当一轮对话确实发往云端时，**只要免费模型与付费模型等效，就优先使用免费模型**——这是一项账户偏好，会根据你是否连接了自己的服务商密钥自动推断，你也可以修改。另外，**洞察（Insights）** 现在会标记**运行异常**：那些成本远高于、耗时远长于、或工具失败次数远多于此前运行的记录，让异常值成为你能看到的东西，而不是在账单上才发现的东西。

## 它在方法中的位置

在 Builderforce 上的工作遵循一条主线：**想法 → 制作 → 运行 → 衡量 → 触达**，而从想法跨入制作的循环是[阅读、验证、构建](/blog/read-prove-build-the-inner-loop)。阅读和验证本应是不花钱的两步，这样决定去构建才是一个真正的决定。

这次发布让这件事名副其实，而它位于主线的最开端：**想法**。

任何项目中最昂贵的时刻都不是构建，而是那个从未被问出第一个问题的想法——因为第一个问题需要注册、需要 GPU、需要某人恰好没有的网络连接。把这些成本从想法阶段移走，才能让更多想法走到验证——也才能让那些不该被构建的想法在任何人动手之前就被识别出来。洞察中的运行异常则守住了另一端：真正发生的运行都会被衡量，异常值会回到你面前。

## 你今天就能做的事

- **无需账号即可开始。** 打开 Studio 或 Rovr，提出你的第一个问题；你设备上的模型会回答。
- **按规则留在你的机器上。** 选择**仅本地**，什么都不会被发送——不发提示词，也不建立实时连接。
- **在任何笔记本上运行模型。** 没有 GPU 也没关系：Bonsai 可以在网页、Rovr 和 VS Code 中用 CPU 运行。
- **让混合模式负责路由。** 先本地，再免费云端，切换时有提示——用得越久，浪费的本地尝试越少。
- **关键时刻锁定一个模型。** **指定模型**会严格运行你选的那个，绝不悄悄替换。
- **找出昂贵的运行。** 洞察会标记在成本、耗时和工具失败上远超正常范围的运行。

打开 `/` 菜单，选择 **Model（模型）**，挑选你想要的运行方式。

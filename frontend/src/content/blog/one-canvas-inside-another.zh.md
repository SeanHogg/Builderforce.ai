把离职流程画一次。收回账号、结清最后一笔工资、追回笔记本电脑、通知团队。六个步骤，连好线，构建完成，按计划运行。很好。

现在来画晋升流程。它批准加薪、更新合同、通知薪酬部门——而在中间某处，它还要为这次晋升所替补的那名外包人员办理离职。

又是那六个步骤。

自从画布成为工作流以来，诚实的回答一直是：重画一遍。而你修好的那一份，永远不是正在运行的那一份。有人在离职画布里修正了薪酬那一步，另外四张画布却继续按老办法执行，悄无声息，按部就班，一连好几个月。

## 画布现在就是一个步骤

`Run a canvas`（**运行画布**）和其他步骤一样，是一种步骤类型。放下它，选择一张画布，你在别处画好的流程就成了这张看板上的一张卡片。

这个步骤是一个值，而不是一种新的对象——就像让一个新行业成为一个 `discipline` 值、而不是一套新词汇的那条规则一样。这意味着它的绘制、连接、分组、构建和运行，都和旁边的分支开关一模一样。

## 它接受什么，是从看板上读出来的，而不是声明出来的

诱人的设计，是在子画布上放一张契约卡片：一份参数列表、一份返回值列表，由父画布去绑定。它明确、稳定，却会在有人添加一个步骤的第一个下午就出问题——因为这时关于这张画布需要什么，就有了两种说法，而真正运行的那一种，并不是任何人在看的那一种。

所以没有契约卡片。接口是从实际画出来的流程中推导出来的：

在步骤里选择一张画布，它会当场告诉你这张画布接受什么、返回什么——你不必打开它。

## 冻结，还是实时

复用会引出一个没有唯一正确答案的问题，所以这个步骤会直接问你。

```bf-figure
{
  "kind": "compare",
  "title": "依赖别人画布的两种方式",
  "columns": [
    { "title": "快照——默认", "hue": "make", "items": ["构建时，子画布的步骤会被复制到这个流程中", "一个定义，一次运行，一条时间线", "那边的修改不会影响这里，直到你再次构建", "你交付的是什么，运行的就是什么"] },
    { "title": "实时——需手动开启", "hue": "run", "items": ["这个流程存储的是对子画布自身构建的引用", "这个流程每次运行时，都会重新读取子画布", "把离职画布修好一次，所有调用方都会跟着更新", "子画布必须至少在它那边构建过一次"] }
  ],
  "caption": "共享的子程序需要“实时”。一个必须保持获批时行为的流程需要“快照”。两者都只是这个步骤上的一个下拉选项。"
}
```

两种绑定都不允许悄悄失败。无法读取的画布、没有任何步骤的画布、含有仍需填写提示词的步骤的画布、引用了自身的画布，以及嵌套超过五层的组合，全都会被**拒绝**——构建停止，报错信息会点出那张画布的名字。这是刻意的，也与编译器一直以来对“没有任何调用的步骤”所采用的规则相同：一个能运行、报告成功、却没有做成那件事的流程，比一个根本构建不出来的流程更糟。

## 它在方法论中的位置

组合属于**构建**——第三幕，也是昂贵的那一幕——但它真正改变的是之后发生的事，也就是运营和衡量。

[读取和验证](/blog/read-prove-build-the-inner-loop)排在前面，是为了让“构建”成为一个决定。组合关注的，是让你已经决定下来的那次构建值得长久保留。一个画一次、反复复用的流程，也是一个只需*改进*一次的流程：薪酬的修正只落在一个地方，它下游的一切在下一次运行时都是正确的，因为调用方持有的是引用，而不是副本。

## 你今天就能用它做什么

- **把任何画布变成可复用的步骤**——不需要导出，不需要模板，不需要复制。它就是那张画布，正在运行。
- **在连线之前就看到它接受什么**——参数和返回值从子看板推导而来，并显示在步骤里。
- **选择冻结还是实时**——一次你可以推理清楚的构建，或是一个所有调用方都会继承的共享子程序。
- **最多组合五层**，自我引用或过深的调用链会被点名拒绝，而不是等到运行卡死时才被发现。

入职、离职、采购审批、事故通报、合同续签：每个组织都有八个这样的流程，每一个都出现在十几个更大的流程里。它们一直都是同一个流程。现在，它们也是同一个对象。

你可以把一个构想带到画布上，把它推敲成一个个对象，把东西构建出来，把它当作一家公司来运营，再看它是否奏效。然后，总得有人来买它。

直到本周之前，左侧导航栏对这个问题的诚实回答只面向一种账号。**销售中心**——销售管道、营销活动、每周目标、报表、收款、销售资料——是一行只有注册为 Builderforce 销售伙伴才能看到的入口。其他所有人，包括每一位刚在平台上交付了产品的创始人，看到的导航栏是 *构想 · 构建 · 运营 · 衡量*，然后塞给他们一个市场商品页，祝他们好运。

这不是缺了一个功能，而是一个已经建好的功能被挡在了错误的门后面。

## 真正把它拦住的是什么

一行代码。负责回答*这是谁的销售工作区*的服务，在把某人自己的工作区交给他之前，会先检查账号类型：

```
if (requested === current.id) return current.accountType === 'sales' ? { … } : null;
```

销售中心涉及的每一行数据——联系人、营销活动、目标、推荐、佣金规则——本来就以 `ownerUserId` 为键。账号之间从来没有共享过任何东西。这项检查并没有保护任何人的数据；它只是在决定谁有资格拥有一条属于自己的销售管道。所以开放它，是拆掉一道闸门，而不是扩大一个范围；跨账号读取也依然和以前一样严格：超级管理员仍然只能打开平台销售伙伴的工作区，绝不能打开客户的私人销售管道。

## 它在方法论中的位置

触达。而触达现在说起来少了一个阶段。

导航栏过去有第六个产出阶段，叫**扩展**，而它的全部内容就是销售计划。它所做的区分在纸面上确实成立——*触达*是把东西摆到人们面前，*扩展*是借此把生意做大——但代价是人们在找到任何东西之前，要多读一个词。

而一旦站在它面前的是创始人而不是销售伙伴，这个区分就不再成立了。销售你做出来的东西，和因为它而被人发现，是同一件事的不同音量。于是触达吸收了它，这条弧线的问题稍微长了一点——*卖出去、被发现、做大它*——而整套方法又回到了五个词，这正是一个人读过一遍导航栏之后能复述出来的数量。

这就是这套导航一直以来要经受的检验。菜单就是方法论；如果你说不出方法论，菜单就已经失灵了。

## 直说"吃自己的狗粮"这件事

Builderforce 向自家的销售伙伴提供销售计划。一个产品卖销售计划，却不给在它上面创办公司的人一份，这很奇怪——更奇怪的是，交付了一个 CRM，用它跑了几个月自己的收入，然后却让客户去买另一个。

这个平台上的每一项能力，都是使用它的创始人迟早会需要的。而这一项，他们在自己构建的东西跑通的那一天就需要。

最新的 Builderforce 版本改变了关于 AI 工作的一个基本假设：画布不再是一个你每当需要产品的其他部分时就要离开的页面。它是产品底层持续存在的工作空间。

这一架构层面的改变带来了你可以立即使用的实用改进——无需账户的本地优先创作、在看板旁边打开的参考页面、原生的文档和数据体验、更广泛的集成，以及一块可以在 Web 和 VS Code 之间往返的 Creation Canvas。

## 你的看板始终与你同在

现在，打开工具、集成指南、诊断或其他参考页面，会在当前画布之上打开一个面板。看板仍然挂载在它的后面，保留对象位置、选中状态、正在进行的 Brain 回复以及实时会话状态。关闭面板，你就回到了同一个工作上下文。

这把导航变成了查阅。你可以阅读某个集成的工作方式、运行一次评估，或查看一份参考资料，而不必放弃把你带到这里的工作。在较大的屏幕上，面板可以调整大小；在窄屏幕上，它会成为聚焦的界面，而画布仍是会话的锚点。

## 先在本地开始，再决定何时注册

未登录的访客可以创建一块真正的本地看板、添加对象、与 Brain 协作，并回到已保存的本地草稿。当没有工作区时，“新建画布”会在本地创建，因此主要操作名副其实，而不是把你重定向到账户表单。

共享遵循同样的原则。本地看板可以打开一个访客房间并生成邀请链接，而无需先要求账户。加入房间的人看到的是预置好的看板，而不是一个空的工作区，后加入者会收到当前的快照。创建账户是持久保存和管理工作的方式——而不是试用或向别人展示的代价。

## 文件就像文件

文档、幻灯片、图表、表格和电子表格现在都按它们本来的样子渲染：

- 文档在一个易读的页面上显示标题、列表、表格、代码和引文。
- 演示文稿以有序的 16:9 幻灯片呈现，而不是一段源文本。
- Draw.io 和 Mermaid 图表在看板上渲染为图表。
- 表格和电子表格支持直接编辑单元格和表头。
- Files 面板把创作的对象和已交付的导出内容汇集在一个可搜索的地方。

同一个对象可以被打开、编辑、检查和导出，而无需维护第二份副本。文档可以作为文档导出，幻灯片作为演示文稿导出，图表以其图表格式导出，表格以便于电子表格使用的格式导出。

文件导入也更直接了。把受支持的文件拖到画布上，它就会以合适的对象出现。HTML 文档会变成可读的文档，同时保留其源码以便无损导出，已连接的 Drive 文件也可以被带入同一个工作区。

## 数据可以成为答案，而不只是附件

Brain 可以查询完整导入的数据集，而不是基于寥寥几行预览数据来推理。它可以筛选、推导分类、分组、聚合、排序，并把结果物化为 Table、Chart、Dashboard 或 KPI 对象。

这对于诸如“按成功与失败对货运分组”“绘制这些地点”或“显示收入前五的类别”之类的日常问题很重要。结果由实际的行计算得出，并作为可复用的产物放回画布上。数据集画像会展示列类型、覆盖率、不同取值和范围，让你可以检查视觉背后的证据。

## 已连接的能力更容易找到

公开的集成目录现在通过一个合并的目录，反映产品的连接器、看板同步、数据、Drive 和邮箱能力。如果某个服务参与了不止一个界面，它只会出现一次，并附带这些能力。

在画布上，工具是能力，而不是孤立的迷你应用。Brain 可以发现一个诊断，并通过明确的画布工具把它作为对象添加。连接器可以参与工作流，而邮箱、Drive、代码仓库、构建和看板连接则始终显示在工作发生的上下文中。

## 浏览器和 VS Code 中是同一块画布

VS Code 画布和 Web 画布现在使用同一套实现。当你在不同界面之间切换时，对象行为、Brain 控件、布局和核心交互模型不会分叉。Builder 对象可以充当浏览器内的项目工作区，而扩展则把同样的空间视图带到离代码仓库更近的地方。

结果是更少的上下文重建。在浏览器中从一个提示开始，在代码旁边继续，与协作者共享看板，再回到参考面板，而无需在每个地方重建项目的状态。

## 一个围绕连续性组织的版本

这些功能表面上看起来各不相同——面板、访客共享、文件渲染、数据集查询、集成——但它们解决的是同一个问题。每当某个去处打断上下文链条，AI 工作就会失去价值。

Builderforce 现在把画布、它的对象、它的 Brain 对话以及它的实时房间视为一个连续的会话。其他一切都可以支撑这个会话，而不是取代它。

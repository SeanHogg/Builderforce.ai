你描述了一个小应用：一个保存报名信息、有人加入时会给你发邮件的候补名单页面。三十秒后，就有了十几个文件、一个服务器和一个表单。

接下来发生的事才是关键，而在此之前，它总会以三种方式之一变糟。项目需要一个服务器，而预览跑不了服务器。或者智能体的下一轮操作弄坏了一分钟前还好用的东西，却没有一条干净的回头路。又或者一切都正常，但你完全不知道报名信息去了哪里。

**Builderforce Studio** 就是围绕这三个时刻构建的。

## 一个窗口，从提示词到运行中的应用

## 无论是哪种应用，它都能运行

过去的预览只覆盖页面，不覆盖服务器。如果智能体写的是 Express API、Vue 应用或 Svelte 应用，预览就没有东西可展示。

现在，整个应用都在你的浏览器里、基于 Builderforce 自己的运行时运行。项目的依赖会被安装，它的服务器会启动，预览展示的是它真实的路由。Vue 和 Svelte 项目的预览与发布方式与 React 项目相同。终端是真正的 shell：`npm install`、`node server.js`、`ls`、`cat`。

发布同样在浏览器中构建站点，生成带哈希的资源和相对基础路径，随时可以部署到你的子域名。检查会对项目做类型检查并构建。任何失败都会连同错误一起交给智能体，因此损坏的构建会被修好，而不是看起来像完成了似的摆在那里。

## 每一轮都是一个版本

当智能体完成一轮操作时，它改动过的文件会成为一个版本：*修改了 App.tsx、Header.tsx 等 2 个文件*。在尝试有风险的操作之前，你可以自己给版本命名。恢复只需两次点击，而且会先保存你当前所处的状态，所以一次恢复本身也是可以撤销的。

## 应用的数据有了安身之处

已发布的应用会保留人们发给它的内容。**数据库**视图就在预览和代码的旁边：

- **表。** 应用写入的每个集合，连同它的行、它的端点和它的开关：为每次提交开一个工单，让已登录的用户读回自己的行。可以添加表、删除行或删除表。
- **用户。** 所有登录过你应用的人。他们通过邮件中的一次性验证码登录，因此无需管理密码。你可以停用某人（会让他们在所有地方登出），或者将其移除。
- **服务端函数。** 应用的后端处理函数及它们使用的密钥。这些在发布之前就能使用。

在首次发布之前，该视图会告诉你这一点，并打开发布面板。发布之后，一切都会自动填充。

## 它在方法中的位置

Builderforce 上的工作遵循一条弧线——**Idea → Make → Run → Measure**——而每一幕都经过同一个内循环：[Read、Prove、Build](/blog/read-prove-build-the-inner-loop)。

Studio 是把 **Make** 这一幕变短。一个想法在你描述它的那个窗口里就变成了运行中的应用，**Build** 不再是注意力流失的那一步：不用去别处开终端，不用等部署，也不用再开一个标签页。

版本让 **Build** 保持诚实。当智能体尝试某件事时，你在预览中看到结果，如果不对，你就回退一轮。尝试没有成本，循环本该是这种感觉。

数据库视图是 **Run** 的起点。应用一上线，使用它的人以及他们发来的内容，就和为他们提供服务的代码出现在同一个屏幕上。这也是 **Measure** 可以着手分析的第一批证据：谁注册了，他们提了什么需求。

## 今天你能用它做什么

- **从一个提示词直达运行中的应用**，包括服务器，无需安装任何东西。
- **两次点击撤销智能体的任何一轮操作**，并为重要的版本命名。
- **在代码旁边查看和管理应用的数据与用户。**
- **从页眉处发布**到你自己的子域名，或推送到 GitHub。

Next.js、Nuxt 和 SvelteKit 的开发服务器目前还不能在浏览器中运行；对于它们，运行会告诉你原因，而不是悄无声息地失败。

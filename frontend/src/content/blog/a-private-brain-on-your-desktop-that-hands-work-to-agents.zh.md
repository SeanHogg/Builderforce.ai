你用的每个 AI 工具，都是从零开始对话。

你再解释一遍项目。你重申上周做的决定、定下的约定、否掉那个显而易见方案的理由。工具回答得不错，然后就忘了。明天你又要再解释一遍——换一个工具、换一个窗口，说同样的话。

而当答案是“这件事得有人去做”时，聊天就不再有用了。工作在别处：一块看板、一张工单、另一个标签页里你雇的代理。

这就是缺口：**你对话的那个东西不了解你，也没法把工作交给能做的人。**

Synapse 现在像 VS Code 扩展一样登录 Builderforce——你在浏览器里批准一个代码，密钥保存在系统的凭据存储中。你的工作区聊天也随之而来：就是你在网页和编辑器里看到的那些对话。

## 它在方法中的位置

Builderforce 上的工作沿着一条弧线前进——**想法 → 制作 → 运行 → 衡量**——每一幕都走同一个内循环：[阅读、验证、构建](/blog/read-prove-build-the-inner-loop)。

聊天是**想法**开始的地方，而它过去总是冷启动。现在，第一次**阅读**的是你自己的记忆：Brain 回答之前，会先读取你和你的工具已经确立的内容，于是想法从你上次停下的地方开始，而不是从零开始。

**运行**是代理所在的地方，在聊天中指定一个代理，就是从“说”到“做”的交接，而且不用离开对话。

**衡量**就是这个大脑。你教了什么、运行了什么、模型学到了什么、损失如何变化，都是从存储中画出来的，而不是被描述出来的——这是你看得见的证据，证明这份私有能力真的在成长。

## 你今天就能做到

- **在 Synapse 中登录 Builderforce**，与网页版和 VS Code 在同样的聊天里工作。
- **向 Brain 提问**，得到建立在你的私有 Evermind 在你电脑上学到的内容之上的回答。
- **给聊天指派代理，并用 @ 指定它们**——它们以你的身份、用自己的工具完成工作。
- **在侧边栏里看着你的 Evermind 学习**，并在 Evermind 页面上看到全貌——各个区域、训练损失、三十天的活动。

# 你不再逐行阅读智能体写的代码了。现在你可以看到它的运行做了什么

一次智能体运行结束了。改动了四十个文件，测试全绿，总结写着“完成，所有测试通过”。你会打开这份 diff 吗？

如今大多数人不会再打开了，而这正是使用智能体的意义所在。但不读代码，从来不等于不在乎代码发生了什么。在那四十个文件里，某条路由可能丢掉了它的身份验证检查；某个循环可能现在要为每一项都等一次数据库；某个原本失败的测试可能被标成了 `.skip`，于是“所有测试通过”确实成立。

diff 能告诉你这一切，前提是你去读，并且知道该看哪里。而运行自己的总结，恰恰出自你正想评判的那个智能体之手。在这两者之间，过去什么都没有。

## 运行变化卡片

现在，VS Code 聊天中的每次智能体运行都会以一张**运行变化**卡片收尾。它不去读 diff 再做总结，而是把运行之前的代码和运行之后的代码各自归约为事实，比较这两组事实，然后就四个问题给出结论。

**安全。**攻击面变了吗？一条丢失了身份验证守卫的路由、一个新的入口点、一项新的系统能力（例如导入了 `child_process`）、弱加密算法、被写进代码的密钥。密钥会以打码形式显示，而不是原样回显给你。

**性能。**这次运行是否在循环里加入了 await 的 I/O 调用，或加入了阻塞式 I/O 调用？这些是静态规则，这一行会标明“仅静态分析”，免得被当成基准测试结果。

**质量。**代码是否变差了？智能体是否**削弱了用来评判它的测试**？跳过或删除测试、添加 `.only`、减少断言、换成更宽松的匹配器、屏蔽 lint 或类型检查、调高超时，都算在内。一旦发生，标题结论会直接写出“测试被削弱”。

**各项质量特性**，依据 ISO/IEC 25010。兼容性：某个导出的 API 被破坏，或新增了一个 API。可维护性：新的依赖环、越过的分层边界、变大的重复代码组、未使用的代码、继续膨胀的超大文件。安全性：破坏性的数据库结构变更、脚本里的强制推送或递归删除。卡片目前还没有测量的特性会显示为**未测量**，而不是显示为零，因为“零”本身就是一个论断。

```

有几条规则让这张卡片保持诚实：

- **五种结论，而不是两种。**更好、更差、无变化、无法比较、未测量。如果两侧无法公平比较，比如运行期间分支被切换了，卡片会写“无法比较”并说明原因，而不是去猜。
- **≈ 表示启发式。**来自启发式而非精确规则的发现会带上 ≈，你就知道哪些数字是估计值。
- **影响范围是相对的。**低、中、高是与你自己仓库过去的运行相比得出的，所以“高”指的是对这个代码库而言偏高，而不是和别人的代码库相比。
- **它不碍事。**卡片在你自己的机器上计算，离线、未登录都能用，而且不会让它所描述的那次运行失败或变慢。

## 查看详情

**查看详情**会在聊天上方打开一个侧边面板。发现先按维度分组，再按来历分组：本次运行新增、本次运行已解决、本次运行已变更、原本就存在。每条发现都附有证据，以及一个跳到相关代码行的**打开代码**链接。

```

对于无人盯着聊天的自主运行，移除身份验证守卫和削弱测试会被标记为**阻止完成**。这正是智能体能让自己的工作“看起来已完成”的两种做法。

卡片、面板和每一条发现都提供英文、中文、西班牙文、法文和德文版本。

## 它在方法中的位置

Idea to Real 依次经过 **Idea、Make、Run 和 Measure**。内循环 [Read, Prove, Build](/blog/read-prove-build-the-inner-loop) 带你从 Idea 走进 Make：先理解现状，再低成本地验证论断，然后才把钱花在构建上。这个循环在 Measure 阶段闭合，而 Measure 只问一个问题：它奏效了吗？

一次智能体运行就是一次构建，而在此之前，它的 Measure 只是智能体自己的一句话。测试通过，只证明了剩下的那些测试通过了。运行变化就是这次运行的 Measure：证明它让事情变得**更好**，而不只是变得不同。它读起来就像一份验证结果：说明它检查了什么、说明它检查不了什么，并为每个结论给出证据。

## 你今天就能用它做什么

- **不读 diff 也知道一次运行做了什么：**四个结论加一句标题结论，就出现在产生它们的那次运行末尾。
- **抓住给自己判作业的智能体：**被跳过、被删除、被放宽的测试会在标题结论里点名。
- **运行一结束就看到丢失的身份验证守卫或新的 `child_process` 导入**，而不是等到之后的评审。
- **从一个结论直达那一行代码**，通过“查看详情”和“打开代码”。
- **在飞机上也能用：**离线、未登录都能工作。

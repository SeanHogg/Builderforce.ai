## 精确表述的核心论点

Evermind 把**时效性**而非规模作为首要的设计维度。我们押注的不是“小模型能在参数量上胜过大模型”——它做不到，我们也从未这样声称。我们押注的是：一种*在构造上就保证知识始终最新*、*自主掌控生成过程*、并且*能装进工作发生之处的运行时*的架构，能在冻结的前沿模型在结构上注定放弃的那些维度上胜出。

Evermind 就是模型本身——而不是外挂在别人的 LLM 上的记忆。它由三个协同工作的层组成，大致对应一种粗粒度的神经功能分解。

![Evermind 的三层架构：选择性状态空间皮层、写穿式海马体和可训练的边缘层，前端是一个推理路由器，并可选配前沿模型桥接](/blog/evermind-architecture-full.svg)

- **皮层（Cortex）**——一个共享专家的混合状态空间模型，能以线性时间生成语言，*并且*能在为其提供服务的同一台设备上执行梯度更新。
- **海马体（Hippocampus）**——一个写穿式知识记忆，写入时*替换*旧信念，而不是追加。
- **边缘系统（Limbic）**——一个小型可训练循环单元，用于调节情感。

三者都是可微的，三者都运行在 WebGPU 上，零运行时依赖。下面逐一来看。

## 皮层：选择性状态空间生成器

生成器不是注意力堆叠，而是 Mamba 家族的选择性状态空间模型（SSM）。每个通道维护一个隐藏状态 `h_t`，它按照一个依赖输入的线性递推演化。经过零阶保持离散化、并采用内容选择性步长 `Δ_t` 之后，每个 token 的更新简单来说就是：

```
Ā_t = exp(Δ_t · A)              # state decay (A stored as log(−A) for stability)
B̄_t = (Ā_t − 1) / A · B_t       # input gain
h_t = Ā_t ⊙ h_{t−1} + B̄_t · x_t  # recurrence
y_t = C_t · h_t + D · x_t        # readout
```

关键词是**选择性**：`Δ_t`、`B_t` 和 `C_t` 都是从 token 本身投影出来的，因此动态过程取决于内容。正是这一点，让 SSM 以线性代价获得了类似注意力的表达能力。

在一个块内，输入先经过 RMS 归一化和投影，再经过因果一维卷积和 SiLU 门控，接着进入选择性扫描，然后再由 `SiLU(z)` 门控一次，经下投影后加回残差流。三种变体共享这一骨架：**Mamba-1**（即上面的 S6 扫描）、**Mamba-2**（结构化状态空间对偶——每个头一个标量 `A`，从而暴露出矩阵乘法形式），以及 **Mamba-3**（复数值状态，采用指数-梯形离散化，能表示实对角 `A` 无法表示的振荡模式）。还可以按混合调度穿插可选的注意力层。

![选择性 SSM 块：RMSNorm、输入投影、因果卷积、由依赖输入的 (Δ, B, C) 驱动的选择性扫描、SiLU 门控以及残差相加](/blog/evermind-ssm-block.svg)

### 为什么它能并行

线性递推看起来是顺序执行的，但其实不然。把每一步写成一个二元组 `(a, b) = (Ā_t, B̄_t·x_t)`，并定义运算

```
(a₁, b₁) ∘ (a₂, b₂) = (a₁·a₂,  a₁·b₂ + b₁)
```

这个运算满足**结合律**（技术报告给出了证明，单位元为 `(1, 0)`），而前缀积的第二个分量的累积值恰好就是 `h_t`。结合律就是全部关键：任何满足结合律的扫描，都能在 `⌈log₂ L⌉` 轮并行扫描中算出所有前缀。因此，长度为 `L` 的序列的所有状态可以在 `O(log L)` 的跨度和 `O(L)` 的工作量内得出——而稠密注意力需要 `O(L²)` 的工作量。

![将选择性递推作为并行的结合律前缀扫描来计算——对二元组 (a, b) 进行 log L 轮扫描](/blog/evermind-parallel-scan.svg)

### 在提供服务的设备上训练

引擎内置基于磁带的反向模式自动微分和 GPU AdamW 优化器，因此皮层可以直接在浏览器中执行梯度更新。我们还采用了 **WSLA**（权重选择性层适配）：在线更新只触及那些决定内容如何路由进状态的选择性投影行，冻结大部分表示。正是这一点，让在线学习足够廉价，只需几个 epoch 就能完成，无需单独的训练集群。

## 海马体：写穿式认知

这是真正与众不同的部分。缓存让*答案*保持新鲜；海马体让*知识*保持新鲜。

每一条候选事实都流经同一条管线：**规范化**为稳定的主题键 → **召回**现有信念 → **评估**证据 → **调和** → **写穿**。调和会返回四种裁定之一：

- **augment（补充）**——全新的主题；写入。
- **confirm（确认）**——与现有信念相同；只刷新置信度。
- **supersede（取代）**——存在冲突，且证据支持新主张；*替换*现有信念。
- **reject（拒绝）**——存在冲突，但证据不支持；保留现有信念。

存储是一个从键到*唯一*内容的偏映射，不存在追加。由此得到一个可以表述为定理并加以证明的性质：**在任意时刻，每个键在存储中至多对应一条内容，被取代的事实会彻底消失——而不仅仅是排名靠后。**只追加的 RAG 存储可能在检索时让过时事实重新浮现；Evermind 在结构上就不可能如此，因为过时的内容已不复存在。从构造上说，矛盾率为零。

召回通过**版本令牌缓存**提供服务：缓存键中嵌入一个全局版本计数器，任何 `supersede`/`augment` 都会使其递增。一次递增就能在 `O(1)` 内让*所有*缓存的召回结果失效——无需逐条清理。因此，读取永远是最新的。

## 召回：混合检索

当模型从记忆中检索时，它会融合两个排序器——基于归一化嵌入的稠密余弦相似度和 BM25 词法得分——采用倒数排名融合（`k = 60`），再用最大边际相关性（`λ = 0.7`）对列表顶部进行多样化处理。结果是一个有硬上限的 top-K（默认 5 条），内容经过截断，因此记忆*缩小*了提示词规模，而不是让它膨胀。

![混合召回：稠密余弦与稀疏 BM25 排序经倒数排名融合合并，并由 MMR 进行多样化](/blog/evermind-hybrid-recall.svg)

## 边缘层

三者中最小的一个：一个门控循环单元，把经验嵌入和情感状态映射为有界的情感增量和奖励估计。更新方式是一个泄漏积分器——一个学习得到的门决定保留多少先前的情感、接纳多少新的经验。**性格被编码为固定的设定点；边缘单元提供围绕这些设定点的动态变化。**它以观测到的 `(Δaffect, reward)` 为目标，用简单的 MSE 目标函数训练。

## 路由与在线蒸馏

请求首先到达一个成本优先的路由器。没有配置前沿模型桥接？那就由设备端 SSM 提供服务。否则，只有当一个廉价的句法测试（复杂度关键词、输入长度）——或者最后一道困惑度探测——表明设备端模型力不从心时，路由器才会升级。一旦升级，前沿模型的响应不只是被返回——它还会成为一个**教师信号**：皮层用 WSLA 在其上进行蒸馏，并设有门控，跳过已经学会的模式。整个循环在设备端闭合，适配后的权重会持久化到检查点。

## 哪些已证明，哪些已构建，哪些仍是假设

这是大多数架构文章都会略过的部分，却是任何评估这些主张的人最应该关注的部分。

**已证明并已实现。**三个 SSM 内核家族、自动微分和优化器、带有单一现任不变量与 `O(1)` 失效机制的调和运算、混合召回、边缘单元、路由器、蒸馏循环、导出管线（safetensors / ONNX / GGUF / Hugging Face——ONNX 已验证与参考前向传播的 logit 误差低于 `1e-5`），以及**基准测试框架**，全部已经构建并经过测试。

**已测量，而不只是断言。**“这个模型到底有多好？”这个问题不再留给未来的某个协议。引擎内置了一个基准测试框架，并在 Studio 中于设备端运行：它预留出一部分模型从未训练过的语料，然后报告预留困惑度、每 token 比特数、top-1 与 top-k 下一个 token 准确率以及生成吞吐量——还能对两个检查点做 A/B 对比，让每一次适配都必须*证明*自己比上一次更好。在 Studio 中训练的每一个模型，在发布之前都会拿到这份评分卡。

**仍是假设。**这个框架目前还没有做的，是大规模地运行*对比*。那些比较性的主张——Evermind 在*时效性*上胜过冻结的前沿模型、它能以一小部分内存占用维持交互式生成、WSLA 蒸馏能带来提升而不会导致灾难性遗忘——在报告中都被表述为**附带测量协议的可证伪假设**，而不是基准测试上的胜利。测量工具如今已经存在并且开放；下一个里程碑，就是拿它与冻结的基线正面对比。在这些数据出来之前，我们会一直称它们为假设。今天真正拿得出手的贡献，是形式化表述、开放的实现，以及衡量它的手段。

我们认为这才是发布一项研究主张的正确方式：让它精确，让它开放，让它易于被证伪。

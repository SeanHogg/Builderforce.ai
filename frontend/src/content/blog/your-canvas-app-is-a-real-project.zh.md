你在画布上勾勒出一个想法，让 Brain 做一个营销网站，然后按下 **App**。

直到今天，你在那里看到的还只是一个预览。画布把白板上的代码卡片拼接起来，把页面及其样式表合成一个文档，放在一个框架里展示。它适合用来看效果，但没法运行任何东西的服务端部分，不能安装依赖包，也没有数据库。一旦想法需要这些能力，你就得离开画布去 Studio，在第二个窗口里、开启第二段对话，从头再来。

现在，App 标签页**就是** Studio。同一个工作区，就在你原本所在的画布之内。

- **背后是一个真实的项目。** 其中有智能体写下的文件、一个能安装依赖包并运行开发服务器的浏览器内运行时（如果你的应用有 Node 服务端，也能运行），此外还有终端、检查和问题列表。
- **只有一个 Brain。** 右侧的 Brain 面板就是画布的 Brain，也就是你一直在对话的那个。它现在可以列出、读取、搜索和编辑应用的文件，所以“把页头固定住”会直接修改代码，预览随之更新。
- **你的代码卡片变成文件。** 如果你之前一直在白板上用代码卡片搭建，App 会在第一次打开时把它们带入项目，之后每当卡片有变化，也会再次同步。无需确认，也不会丢失任何内容。
- **需要时就有数据库和发布。** Studio 里同样的数据库视图和发布面板，在会话栏一点即达。
- **想要整个屏幕时，选择“在 Studio 中打开”。** 它是同一个项目，所以不需要复制任何东西。

你不需要先注册，就能验证这个想法行不行。没有账号的画布，会在保存于浏览器中的文件之上运行它的应用，使用的正是 Studio 所用的同一个运行时。当它值得保留时，按下**保留你的作品**。白板会迁移到你的账号，应用也随之进入一个持久化项目，拥有版本历史、数据库和发布功能。

## 一块白板上可以有多个应用

一块白板可以容纳多个构建：一个营销网站加一个管理工具，或者一个 Web 应用加它的手机版“孪生兄弟”。App 一次只运行一个，一旦出现第二个，会话栏中就会出现切换器。打开白板上的任意一张构建卡片，就会直接跳转到对应的应用。

## 它在方法论中的位置

Make 是想法变成可用之物的那一步。它也曾经是被拆分到两个产品中的那一步。Read 和 [Prove](/blog/read-prove-build-the-inner-loop) 发生在画布上，而正式的构建发生在另一个独立的 IDE 里。两者之间的距离，意味着一次上下文切换、一次想法的复制粘贴，以及一个从零开始的 Brain。

## 你今天就能做什么

- **在任意画布上打开 App**，用真实的文件、依赖包和服务器来构建，无需离开白板。
- **继续与 Brain 一起构建**，它现在可以直接编辑你应用的代码。
- **只需打开 App，就能把现有的代码卡片变成运行中的项目。**
- **无需账号即可尝试**，值得保留时再保留。
- **在同一块白板上切换应用**，或在 Studio 中以全屏方式打开其中任何一个。

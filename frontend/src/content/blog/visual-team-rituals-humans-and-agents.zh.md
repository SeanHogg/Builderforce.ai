大多数站会都消失在记忆或一份转录稿里。讨论过的阻碍与它们所阻碍的工作相互割裂，后续事项又变成了第二轮行政事务。

在 Creation Canvas 上，一场仪式可以成为一个活的对象，与它所协调的人、智能体、项目和任务处于同一个空间系统中。

![可视化站会框架的产品视图，其中包含人类 Staff Member 与 AI Agent 参与者、当前焦点、阻碍、一个 Timer、对象评论，以及三个受治理的后续 Task](/blog/visual-team-rituals-workspace.svg)

## 把团队放到画布上

Staff Member 对象承载一个人的角色、当前焦点和视觉强调色。Agent 对象承载其配置的模型、指令、工具和自主程度。Team 和 Role 对象补充组织背景。它们都可以与正在讨论的实际 Project、Task、Roadmap 或 Evaluation 并排放置。

Stand-up 对象会把已经在会话中的 Staff Member 和 Agent 聚集起来。每位参与者提供一个名字和当前焦点。Builderforce 通过成员关系把这些参与者对象连接到仪式上，而不是把一份名册复制到互不相连的笔记里。

## 本地起草，带着持久上下文开始实时进行

匿名的本地画布可以安排团队、准备 Stand-up，并勾勒后续事项体系。要发起协作式站会则需要账户，因为实时参与者、共享活动、租户权限和后续工作都需要持久的身份。

在带有规范 Project 的服务器会话中，Builderforce 可以发起一场项目仪式，并把其产生的身份附加到 Stand-up 对象上。没有 Project 时，同一个对象可以一直保持为一个已准备好的仪式框架，直到团队补充交付上下文。

![Staff Member 和 Agent 通过成员关系边加入 Stand-up；Brain 主持进展、阻碍和下一步行动；评论、提及、绘图和计时器支撑对话；获批的后续事项成为与 Project 治理相连的 Task](/blog/visual-standup-followup-loop.svg)

## Brain 围绕可见的工作来主持

Stand-up 摘要会告诉 Brain 去询问进展、阻碍和下一步行动。由于这场仪式与 Task、诊断、原型、报告和 Project 共处同一块画布，对话可以直接指向这些对象本身。

一个阻碍可以引用一份 Diagnostic。一项后续事项可以变成一个 Task。一个决定可以作为 Note 或 Comment 保留在受影响的对象上。因此，会议记录是一张由参与和后果构成的图，而不只是一段文字。

## 使用仪式周围的协作对象

Frame 为会话划出一块有意设计的会议区域。绘图便于快速说明。评论始终附着在对象上，带有提及和解决状态。Timer 提供可见的专注计时。Presence 让你看到协作者，却不强迫所有人挤在同一个视口里，而演示或跟随模式则支持有引导的评审。

已发布的 **Impromptu stand-up**（即兴站会）包提供了 Stand-up、Staff Member、Delivery Agent 和 Follow-up Task，作为一个起点。

## 以可问责的工作来结束仪式

站会真正有用的产出，并不是每个人都发了言，而是阻碍变得可见，下一步行动有了负责人、上下文和交付路径。

Creation Canvas 保留了这条链条：

**参与者 → 当前工作 → 阻碍证据 → 达成一致的行动 → 受治理的 Task**

人和智能体可以参加同一场仪式，因为两者都被表示为这项工作中可问责的成员，而不是各自独立的聊天模式。

搭建开发环境这件事，少则 20 分钟，多则好几天，而且几乎学不到什么东西。克隆仓库，装对 Node 版本，配好环境变量，跟原生依赖较劲，然后发现 README 已经三年没更新了。

Builderforce 的浏览器内 IDE 把这一切都省掉了。打开浏览器，打开项目，你就已经在运行一个真正的 Node.js 环境——文件系统、包管理器、开发服务器、终端，外加一位 AI 结对编程伙伴——什么都不用安装。

## 工作原理：WebContainers

IDE 由 **WebContainers** 驱动——这是一个基于 WebAssembly 的 Node.js 运行时，完全运行在浏览器标签页内。WebContainers 提供：

- 一个真正的、兼容 POSIX 的文件系统（在内存中运行，并持久化到 R2）
- 一个完整的 Node.js 运行时，支持原生模块
- 能够运行 `npm install`、`npm run dev`、`npm test`——和在本地完全一样
- 一个浏览器可以访问的 localhost 网络层——你的开发服务器的 3000 端口可以直接在预览窗格中访问

这不是模拟，也不是远程虚拟机。代码在你的浏览器里运行，开发服务器也在你的浏览器里运行。执行本身不涉及任何服务器端计算。

## 打开 IDE

前往 [/ide](/ide) 并选择一个项目，或者直接从项目详情页打开 IDE。

IDE 采用三栏布局：

```
┌─────────────┬──────────────────────────────┬──────────────┐
│ File        │                              │              │
│ Explorer    │  Code Editor (Monaco)        │  Preview /   │
│             │                              │  Terminal /  │
│  src/       │  // Your code here           │  AI Chat     │
│  ├ app/     │                              │              │
│  ├ api/     │                              │              │
│  └ tests/   │                              │              │
└─────────────┴──────────────────────────────┴──────────────┘
```

### 左侧面板——文件浏览器

浏览、创建、重命名和删除文件。文件树实时反映 WebContainers 的文件系统——你在编辑器中做的修改会立即出现，智能体（通过 BuilderForce Agents）做的修改也会在写入时同步出现。

### 中间面板——Monaco 编辑器

完整的 Monaco 编辑器——与驱动 VS Code 的是同一个引擎。你可以获得：

- 所有主流语言的语法高亮
- TypeScript 语言服务（类型检查、自动补全、跳转到定义）
- 行内错误和警告标记
- 带未保存修改提示的多文件标签页
- 全项目范围的查找/替换

### 右侧面板——随上下文切换

右侧面板通过顶部的切换按钮，在三种视图之间切换：

| 视图 | 内容 |
|---|---|
| **预览** | 连接到 WebContainer localhost 的实时 iframe；开发服务器热重载时自动刷新 |
| **终端** | 连接到 WebContainer shell 的完整终端——可以运行任何命令 |
| **AI 聊天** | AI 结对编程伙伴（见下文） |

## AI 结对编程伙伴

AI 聊天面板是一个对话式界面，完全了解你当前项目的上下文：

- **打开的文件**——AI 知道你正在看什么
- **文件树**——它理解项目结构
- **终端输出**——它能看到开发服务器或测试运行器报出的错误
- **Git 历史**——它可以访问最近的提交

在工作上下文中，你可以问它任何问题：

> “这个组件重新渲染得太频繁了。你能找出原因并给出修复建议吗？”

> “为 `parseDate` 工具函数写一个覆盖边界情况的测试。”

> “API 返回了 500，终端里的报错就在上面——哪里出了问题？”

AI 可以直接编辑你的文件（需要你的批准），在终端中运行命令，并且边做边解释它在做什么。

## 实时协作

邀请一位队友加入你的 IDE 会话，你们就能同时处在同一个环境中。

协作由 **Yjs** 驱动——一个基于 CRDT 的实时同步库——通过 Builderforce 的 Durable Object WebSocket 中继实现：

- **光标感知**——看到每位协作者的光标位置
- **实时编辑**——修改实时出现，且不会冲突
- **聊天**——IDE 会话内的侧边栏聊天频道
- **共享终端**——一位用户运行的命令，所有人都能看到

这里没有“所有者”——每位协作者对文件系统、终端和编辑器都拥有同等的访问权限。底层的 WebContainer 状态对所有参与者都保持一致。

协作会话中既可以有人，也可以有智能体。如果一个 BuilderForce Agents 智能体正在同一个项目上工作，它的文件修改会作为实时变更出现在编辑器里——你可以在自己审阅代码的同一个窗口中，看着智能体写代码。

## 连接 BuilderForce Agents

IDE 和 BuilderForce Agents 是与同一个项目交互的两种方式。IDE 是浏览器原生的界面；BuilderForce Agents 是自托管的智能体运行时。它们共享：

- **同一个文件系统**——BuilderForce Agents 把工作区同步到 Builderforce；IDE 从同步后的状态读取
- **同一个任务看板**——在 IDE 任务面板中创建的任务，就是 BuilderForce Agents 执行的那些任务
- **同一份聊天记录**——你在 IDE 聊天中发送的消息会被中继到当前的 BuilderForce Agents 会话；BuilderForce Agents 的回复也会实时出现在 IDE 聊天中

这意味着 IDE 不只是一个代码编辑器——它是一扇**观察智能体工作的窗口**。当 BuilderForce Agents 在你的服务器上执行工作流时，你可以在 IDE 中看着文件发生变化，在聊天面板中跟随智能体的推理，并在发现不对劲时及时介入——全程无需离开浏览器。

## 在 IDE 中创建项目

从零开始创建一个新项目：

1. 在 [/projects](/projects) → **New Project** 中创建项目
2. 选择一个模板（Next.js、Vite + React、Node + Express、空白）
3. 在 IDE 中打开项目——WebContainers 完成初始化，依赖安装完毕，开发服务器随即启动
4. 预览窗格中会显示你正在运行的应用

模板会在容器首次初始化时自动运行 `npm install`。之后再次打开时，会从 R2 恢复上一次的文件系统状态，让你的会话从上次离开的地方无缝继续。

## 源代码管理集成

对于配置了源代码管理集成的项目，IDE 内置 git 支持：

- **状态栏**——显示当前分支和未提交的更改
- **提交面板**——无需离开 IDE 即可暂存、提交和推送
- **创建 PR**——工作完成后，直接在 IDE 中发起拉取请求
- **切换分支**——检出分支、创建功能分支、合并

在 IDE 中提交的更改会触发 BuilderForce Agents 的目录同步——AgentHost 的本地工作区会随之更新，让 IDE 与本地智能体的状态保持一致。

## 什么时候用 IDE，什么时候用 BuilderForce Agents

| 使用 IDE | 使用 BuilderForce Agents |
|---|---|
| 直接浏览和编辑文件 | 运行长时间的自主工作流 |
| 针对具体问题与 AI 结对编程 | 在整个项目中批量执行任务 |
| 审阅和批准智能体生成的差异 | 处理从门户派发的任务 |
| 与队友实时协作 | 无人值守的通宵工作 |
| 运行快速的终端命令 | 持久运行的后台服务 |

两者本就是为配合使用而设计的——在 IDE 中借助 AI 开始一个功能，把实现工作交给 BuilderForce Agents 工作流，等智能体完成后再回到 IDE 审阅结果。

## 最佳实践

**做前端开发时保持预览窗格打开。**热重载预览带来的即时反馈，是浏览器 IDE 最大的工作流改进之一——不要只盯着终端而忽略了它。

**一次性的命令用终端，重复的模式交给智能体。**如果你为了调试同一个问题已经跑了三次以上的 `npm test`，那就把失败情况描述给 AI 聊天，让它来跑这个迭代循环。

**在 IDE 中频繁提交。**小而频繁的提交，能给你和 BuilderForce Agents 都留下一份清晰、便于推理的历史记录。大量未提交的改动，会让依赖 git 历史获取上下文的智能体无所适从。

**把 IDE 项目分配给一个 BuilderForce Agents 实例。**连接了 AgentHost 之后，IDE 会更加强大——右侧面板的 AI 聊天可以派发给完整的智能体运行时，而不只是浏览器内的模型。

# Create Before You Sign Up: A Private Canvas That Grows With the Work

Most creative tools ask for commitment before they have earned it. Create an account, name a workspace, invite a team, choose a plan—and only then can you find out whether the idea is worth pursuing.

Builderforce reverses that order. Type an idea on the home page and enter a complete **local Creation Session** immediately. No tenant, Project, or team assignment is required. The canvas and its objects remain private on that device while you explore.

![Product view of a private local Creation Session containing a Workflow, Website, Dataset, and Note beside the account gate opened by Publish, with the canvas explicitly preserved and the claimed workspace gaining permissions, history, and delivery](/blog/create-before-signup-workspace.svg)

## Local does not mean throwaway

The local canvas is the real object workspace. You can add and edit workflows, websites, prototypes, datasets, charts, dashboards, notes, reports, roadmaps, model blueprints, agents, drawings, frames, and the rest of the Creation Object palette. You can connect them with typed relationships and ask Brain to reason across the whole canvas, a selection, or a frame.

The session is stored locally instead of being disguised as a server draft. Refreshing the page does not turn the work back into a blank prompt. That makes the anonymous state useful for genuine exploration, not merely a marketing demo.

## The account boundary follows the action

Some actions need durable infrastructure. Publishing a website, delivering a mockup, assigning work, authenticating an integration, executing an MCP operation, recording media, generating video, training a model, comparing canonical Projects, or starting a live stand-up all require workspace identity, permissions, history, or compute.

When one of those actions is requested from a local session, Builderforce opens an account prompt for that specific action. The existing canvas stays unchanged on the device. Nothing is silently discarded and no operational action pretends to have completed.

![Local exploration supports authoring, arranging, connecting, and Brain evaluation; durable operations such as publish, deliver, assign, authenticate, execute, record, generate, train, compare, and start cross an explicit account gate before entering a permissioned workspace](/blog/local-to-durable-action-gate.svg)

This is a more honest boundary than blocking the canvas itself. The work becomes durable at the moment durability has a purpose.

## Claim the session without rebuilding it

After sign-in, the local session can be claimed into the workspace. Its initial request, objects, and relationships move forward as one Creation Session rather than being copied manually into a new project. From there the session can gain server history, invitations, roles, comments, canonical resources, and governed execution.

A Project is still optional. Claiming a session gives it a durable home; adding a Project gives selected work a planning and delivery context. Those are separate decisions.

## Privacy remains legible

The share surface states whether a session is **Private on this device** or backed by server access. Capability-gated resources do not appear merely because an anonymous canvas can represent their blueprint. Attaching a live Project, Agent, integration, or model still uses the permissions of that resource.

The result is a simple progression:

**imagine locally → structure the work → ask Brain → decide it is worth keeping → sign in for durable action**

You do not create an account to discover whether Builderforce can help. You create because the work has reached the point where it deserves a team, a history, or a delivery path.

Das neueste Builderforce-Release ändert eine grundlegende Annahme über KI-Arbeit: Der Canvas ist keine Seite mehr, die Sie verlassen, wenn Sie einen anderen Teil des Produkts brauchen. Er ist der dauerhafte Arbeitsbereich unter dem Produkt.

Diese architektonische Änderung bringt praktische Verbesserungen mit, die Sie sofort nutzen können – lokales Erstellen ohne Konto, Referenzseiten, die neben dem Board öffnen, native Dokument- und Datenerlebnisse, breitere Integrationen und einen Creation Canvas, der zwischen Web und VS Code wandert.

## Ihr Board bleibt bei Ihnen

Wenn Sie ein Tool, einen Integrationsleitfaden, eine Diagnose oder ein anderes Referenzziel öffnen, öffnet sich jetzt ein Panel über dem aktiven Canvas. Das Board bleibt dahinter eingehängt und bewahrt Objektpositionen, Auswahlen, eine laufende Brain-Antwort und den Live-Session-Zustand. Schließen Sie das Panel, und Sie kehren in denselben Arbeitskontext zurück.

So wird Navigation zur Konsultation. Sie können nachlesen, wie eine Integration funktioniert, ein Assessment durchführen oder eine Referenz prüfen, ohne die Arbeit aufzugeben, die Sie dorthin geführt hat. Auf größeren Bildschirmen ist das Panel in der Größe veränderbar; auf schmalen Bildschirmen wird es zur fokussierten Fläche, während der Canvas der Session-Anker bleibt.

## Lokal starten, dann entscheiden, wann Sie sich registrieren

Ein nicht angemeldeter Besucher kann ein echtes lokales Board erstellen, Objekte hinzufügen, mit Brain arbeiten und zu gespeicherten lokalen Entwürfen zurückkehren. „Neuer Canvas“ erstellt lokal, wenn es keinen Workspace gibt, sodass die primäre Aktion tut, was sie sagt, statt auf ein Kontoformular umzuleiten.

Das Teilen folgt demselben Prinzip. Ein lokales Board kann einen Gastraum öffnen und einen Einladungslink erzeugen, ohne zuvor ein Konto zu verlangen. Wer dem Raum beitritt, sieht das vorbefüllte Board statt eines leeren Workspace, und spät Beitretende erhalten den aktuellen Snapshot. Ein Konto zu erstellen ist der Weg, die Arbeit dauerhaft zu behalten und zu verwalten – nicht der Preis dafür, sie auszuprobieren oder jemandem zu zeigen.

## Dateien verhalten sich wie Dateien

Dokumente, Foliensätze, Diagramme, Tabellen und Spreadsheets werden jetzt so dargestellt, wie es ihrer Art entspricht:

- Dokumente zeigen Überschriften, Listen, Tabellen, Code und Zitate auf einer gut lesbaren Seite.
- Präsentationen erscheinen als geordnete 16:9-Folien statt als Absatz aus Quelltext.
- Draw.io- und Mermaid-Diagramme werden auf dem Board als Diagramme gerendert.
- Tabellen und Spreadsheets unterstützen die direkte Bearbeitung von Zellen und Kopfzeilen.
- Ein Dateien-Panel bündelt selbst erstellte Objekte und gelieferte Exporte an einem durchsuchbaren Ort.

Dasselbe Objekt kann geöffnet, bearbeitet, inspiziert und exportiert werden, ohne eine zweite Kopie zu pflegen. Dokumente können als Dokumente hinausgehen, Foliensätze als Präsentationen, Diagramme in ihren Diagrammformaten und Tabellen in Spreadsheet-tauglichen Formaten.

Auch der Dateiimport ist direkter. Ziehen Sie eine unterstützte Datei auf den Canvas, und sie erscheint als passendes Objekt. HTML-Dokumente werden zu lesbaren Dokumenten und behalten ihren Quelltext für verlustfreien Export, und verbundene Drive-Dateien lassen sich in denselben Workspace holen.

## Daten können zu einer Antwort werden, nicht nur zu einem Anhang

Brain kann den vollständigen importierten Datensatz abfragen, statt aus einer Handvoll Vorschauzeilen zu schließen. Es kann filtern, Klassifizierungen ableiten, gruppieren, aggregieren, sortieren und das Ergebnis als Tabelle, Diagramm, Dashboard oder KPI-Objekt materialisieren.

Das ist wichtig für gewöhnliche Fragen wie „Sendungen nach Erfolg und Fehlschlag gruppieren“, „diese Standorte darstellen“ oder „die fünf umsatzstärksten Kategorien zeigen“. Das Ergebnis wird aus den tatsächlichen Zeilen berechnet und als wiederverwendbares Artefakt zurück auf den Canvas gelegt. Das Dataset-Profiling zeigt Spaltentypen, Abdeckung, eindeutige Werte und Wertebereiche, sodass Sie die Belege hinter der Visualisierung prüfen können.

## Verbundene Fähigkeiten sind leichter zu finden

Der öffentliche Integrationskatalog bildet jetzt die Connector-, Board-Sync-, Daten-, Drive- und Mailbox-Fähigkeiten des Produkts in einem gemeinsamen Katalog ab. Wenn ein Dienst an mehr als einer Fläche teilnimmt, erscheint er einmal mit den zugehörigen Fähigkeiten.

Auf dem Canvas sind Tools Fähigkeiten statt losgelöster Mini-Apps. Brain kann eine Diagnose entdecken und sie über explizite Canvas-Tools als Objekt hinzufügen. Connectors können an Workflows teilnehmen, während Mailbox-, Drive-, Repository-, Build- und Board-Verbindungen in dem Kontext sichtbar bleiben, in dem die Arbeit stattfindet.

## Ein Canvas im Browser und in VS Code

Der VS-Code-Canvas und der Web-Canvas nutzen jetzt dieselbe Implementierung. Objektverhalten, Brain-Steuerung, Layout und das zentrale Interaktionsmodell gabeln sich nicht, wenn Sie zwischen den Flächen wechseln. Ein Builder-Objekt kann als Projekt-Workspace im Browser dienen, während die Erweiterung dieselbe räumliche Ansicht näher an das Repository bringt.

Das Ergebnis ist weniger Kontext-Rekonstruktion. Starten Sie mit einem Prompt im Browser, machen Sie neben dem Code weiter, teilen Sie das Board mit einem Mitwirkenden und kehren Sie zu einem Referenz-Panel zurück, ohne den Projektzustand an jedem Ort neu aufzubauen.

## Ein Release, das auf Kontinuität ausgerichtet ist

Diese Funktionen sehen an der Oberfläche unterschiedlich aus – Panels, Gast-Sharing, Datei-Rendering, Dataset-Abfragen, Integrationen –, doch sie lösen dasselbe Problem. KI-Arbeit verliert an Wert, wenn jedes Ziel die Kontextkette unterbricht.

Builderforce behandelt den Canvas, seine Objekte, seine Brain-Konversation und seinen Live-Raum jetzt als eine durchgehende Session. Alles andere kann diese Session unterstützen, ohne sie zu ersetzen.

项目报告通常是一份一份单独阅读的。这就使人很难看出重复的功能、共同的风险，或者为什么某个项目推进得比另一个更快。借助 Builderforce Creation Canvas，投资组合负责人可以在一个会话中放入两个或更多实时的 Project 对象，并让 Brain 比较它们的权威数据。

## Project 是上下文，而不是入场门槛

一个 Creation Session 并不需要 Project。从你关心的问题、证据或概念开始即可。只有当 Project 的规划和交付数据能让工作更有用时，再添加 Project 对象。

每个 Project 都保持与其 Builderforce 规范记录相连。把它加到画布上，不会复制它的任务，也不会绕过它的权限。你可以展开所选的视角——交付、指标、客户反馈或全部——来添加你需要的相关条目，而不会让看板泛滥成灾。

## 提出一个比较问题

选中这些 Project 对象，然后提问：

> 按所请求的功能、成熟度、评分、绩效、生产力、交付风险和战略重叠度比较这些项目。

Brain 评估的是结构化的项目事实，并返回一份持久的比较结果，附带可检查的来源和新鲜度。这个区别很重要：结果不是基于卡片碰巧摆放的位置，也不是基于一份陈旧的粘贴摘要。

把仪表盘、KPI、报告、客户反馈数据集或任务分组放在比较结果旁边，让分歧一目了然。评审者可以顺着引用回到它的源对象、评论，或者请求另一个视角。

## 把分析变成演示

团队就事实达成一致后，请 Brain 创建一个面向特定受众的 Roadmap 和 Slides 对象。高管版本可以强调成果、依赖关系、投资决策和风险。销售版本可以强调客户价值、差异化优势、证明点和发布叙事。

生成的材料始终与促成它的 Project 和证据保持相连。如果 Brain 提议改动多个资源，Builderforce 会在应用任何改动之前，先展示一个可选择的变更集。

## 从演示走向可问责的交付

路线图不必停留在仅用于演示。已批准的 Mockup 或 Feature 对象可以交付到所选的 Project，附加到某个 Task，分配给人类或 AI Agent，并在同一个会话中跟进。Project 提供治理和指标；Session 则保留导向该决策的推理与协作。

这让画布在高管评审之前、之中和之后都有用。它是一幅共享的运营全景，而不是一个临时的幻灯片生成工具。

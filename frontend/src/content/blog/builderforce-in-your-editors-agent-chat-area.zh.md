# BuilderForce 进驻 VS Code 的智能体聊天区，就在你的代码旁边

VS Code 现在为编程智能体专门留出了位置。右侧的辅助侧边栏里放着 Chat、Claude Code 和 Codex，每个都有自己的标签页。你在那里输入，智能体修改的代码就在旁边的编辑器里开着。

以前，BuilderForce 不在这一排里。它的聊天以**编辑器标签页**的形式打开，占用了代码本该用的空间。想看智能体修改文件，你得手动拆分编辑器，或者在对话和代码之间来回切换。

现在，BuilderForce 在这一排里有了自己的标签页。

## 一个聊天，一个位置

这不是第二个聊天。这个标签页显示的就是你在网页上看到的同一段对话：同样的记录、同样的工具审批、同样的模型选择、同样的项目范围。标签页隐藏时运行仍会继续，因为智能体运行在扩展里，而不是标签页里。

现在，所有打开聊天的方式都会进入这个标签页：**打开聊天**命令、在会话列表中点开的会话、看板上的*处理此任务*，以及从 Project 360 发出的提示。“打开我的聊天”总是去往同一个地方。

在 1.106 之前、还没有智能体聊天区的 VS Code 版本中，同一个标签页会出现在 BuilderForce 侧边栏里。

## 它在方法中的位置

构建是第三幕，排在[阅读与证明](/blog/read-prove-build-the-inner-loop)之后。从*提出修改*到*看到修改*的这个短循环，在这一幕最重要。每次跳出这个循环都会分散注意力：切换标签页、手动拆分编辑器、对话挡住了它正在修改的文件。

## 试一试

更新 BuilderForce 扩展，重新加载 VS Code，然后打开智能体聊天区。BuilderForce 在 Chat、Claude Code 和 Codex 旁边有了自己的标签页。也可以运行 **BuilderForce: 打开聊天**，它会在那里打开。

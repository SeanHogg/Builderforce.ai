你在为 Kimi 付费。Kimi K3 是一款强大的编程模型，拥有百万 token 的上下文窗口。你希望把它用在手头的工作上：规划一次改动、编写它，或者两者兼顾。

在此之前，这需要比应有的更多配置。Kimi 的边缘网络会在读取凭据之前就拒绝来自托管云平台的流量。因此，连接到工作区的 Kimi 订阅只有在另一个 Builderforce 运行时在线并负责转发时才能使用。在编辑器里，只有你另外安装了 Kimi Code CLI 并在其中登录，Kimi 才会出现。在 Rovr 里则根本不会出现。

## 选择 Kimi，登录自然就来

现在的顺序就是你期望的那样：先选模型，只有在还没有账户时，Builderforce 才会请你连接。

有两个细节让它在日常使用中站得住。

**令牌刻意设计为短期有效。** 你的电脑只保存一个十五分钟的访问令牌，从不保存长期有效的续期凭据。Kimi 每次使用都会更换该凭据，如果两处同时续期，其中一处手里的凭据总是失效的。由 Builderforce 负责续期，每台设备在需要时向它索取新令牌。只要令牌仍然有效，编辑器和 Rovr 在重启后会继续使用已保存的令牌，因此大多数轮次不会产生额外请求。

**是否使用 K3 由你决定，而不是靠猜。** Kimi K3 包含在部分 Kimi 套餐中，并非全部。Builderforce 不会悄悄把每一轮 Kimi 请求都发给你的套餐可能拒绝的模型。如果你的套餐包含 K3，打开“设置 → 自带模型 → Kimi”，把 K3 移到最前面。编辑器、Rovr 和云端运行都会优先使用它，必要时再沿着你的列表依次回退。

## 它在方法中的位置

大多数时候，这关乎**构建**这一幕。构建是[阅读、验证、构建](/blog/read-prove-build-the-inner-loop)中代价最高的一步，模型的编程能力决定了一次改动需要多少轮。Builderforce 已经为每一轮分配角色：一次运行先做规划，再把第一处代码改动交给你连接的最强编程模型。现在 Kimi K3 可以担任其中任一角色，或者两者兼任：用便宜的模型规划、用 K3 编码；用 K3 规划、交给 Claude 编码；或者全程使用 K3。

它对**阅读和验证**同样重要。这两步不花钱，正是为了让“开始构建”成为真正的决定；而百万 token 的窗口意味着在决定改动之前，可以一次读完整个代码库。

## 你今天就能做什么

- **在 VS Code 中选择 Kimi K3**，无需额外安装任何东西。模型选择器提供“连接 Kimi”，连接后可选择新轮次使用哪个 Kimi 模型。
- **在浏览器助手 Rovr 中使用 Kimi。** “设置 → 模型”会列出你的 Kimi 模型。如果某一轮 Kimi 请求找不到账户，聊天中会显示连接卡片，而不是报错。
- **为整个工作区只连接一次。** 在编辑器中连接的账户会出现在网页端和 Rovr 中，反之亦然。
- **如果你的套餐包含 K3，就把它放在首位**，所有界面都会优先使用它。

# Build, Tune, and Evaluate an Evermind Model on the Creation Canvas

Model development is rarely one action. It combines evidence, dataset preparation, tokenizer choices, tuning, evaluation, packaging, deployment, and ongoing observation. Creation Canvas makes that lifecycle visible as a connected system instead of hiding it behind a sequence of separate pages.

## Start with the model you need

Open a blank session and describe the outcome:

> Create a customer-support Evermind that learns from our approved resolutions, answers with citations, and must pass safety and accuracy gates before publishing.

Add an Evermind object or use the Model Lab pack. Anonymous creators can sketch and refine the full pipeline locally before an account, tenant, Project, or compute resource is required. Saving, collaboration, canonical training, and publishing begin after the session is claimed into an account.

## Make the learning pipeline explicit

Expand the Evermind creation and training pipeline to place connected Dataset, tokenizer, tuning run, Evaluation, and telemetry objects on the canvas. Typed connections make the intent machine-readable: data feeds preparation and training; evaluations gate delivery; telemetry observes the deployed model.

Dataset objects can import CSV or TSV evidence and create charts for quality review. Notes, reports, dashboards, and Project context can sit beside the pipeline. Brain can assess whether the available examples cover the intended audience, identify weak segments, and propose improvements.

## Keep model changes governed

Canvas access never expands access to an underlying dataset, Project, or Agent. Brain scopes its reasoning to objects the member can read. Credentials and imported row contents are excluded from safe search previews.

Multi-resource changes appear as a reviewable proposal. The operator selects which updates to accept, while canonical training and publishing continue to use their existing permission, version, and approval rules. Named checkpoints and Session branches support experiments without overwriting the agreed design.

## Collaborate across specialties

Invite a domain expert as a Commenter, a model engineer as an Editor, and an operator as a Runner. They can inspect the same model plan, leave object-level comments, follow a presentation, and see accepted activity in real time. A developer can open the Session in VS Code and add repository files, selections, diagnostics, terminal output, or a local service to the same graph.

## Keep learning after delivery

Evermind is designed to evolve as approved work creates new evidence. The Canvas gives that learning loop an operating picture: source data, current version, evaluations, teaching or tuning activity, quality gates, and telemetry stay connected. Teams can return to the Session to understand not only which model is running, but why it was approved and what should improve next.

智能体的内置能力只是起点。技能则是你扩展这些能力的方式——注入领域知识、API 集成、结构化工作流和专家行为，而无需重新训练底层模型。

在 Builderforce 上，有两种方式可以把技能装到智能体身上：**技能市场**（社区发布，浏览即可分配）和**自定义技能**（你来构建，归你所有）。两者遵循同一套分配模型，并且都会在启动时自动加载到你的 BuilderForce Agents 实例上。

## 什么是技能？

技能是一种结构化的能力扩展。最简单的技能就是一段**系统提示片段**，为智能体提供特定的知识或指令。更复杂的技能还包括：

- **工具定义**——智能体可以调用的结构化函数签名（例如一个 GitHub API 技能，定义了 `create_pr`、`add_comment`、`merge_branch`）
- **工作流模板**——智能体遵循的分步运行手册（例如一个事件响应技能，定义了“分诊 → 诊断 → 修复 → 沟通”的闭环）
- **领域知识**——智能体在推理时使用的内嵌参考资料（例如一个 `typescript-strict` 技能，内嵌了你团队的 TypeScript 规范）

技能一旦加载，智能体就会表现得仿佛早已掌握了其中的全部内容，无需任何额外提示。

## 技能市场

前往 [/skills](/skills) 浏览社区发布的技能。

每个技能条目都会显示：

| 字段 | 说明 |
|---|---|
| **名称和 slug** | 用于分配的唯一标识符（`org/skill-name`） |
| **描述** | 这个技能教给智能体什么 |
| **类别** | 宽泛的领域标签（开发、运维、营销等） |
| **标签** | 用于筛选的细分能力标签 |
| **版本** | 当前发布的版本 |
| **下载量** | 被分配的次数 |
| **点赞** | 社区的质量信号 |
| **作者** | 发布者 |

### 浏览与筛选

市场搜索支持：

- **全文搜索**——搜索名称、描述和标签
- **类别筛选**——按领域缩小范围
- **标签筛选**——查找带有特定能力标签的技能
- **排序**——按下载量、点赞数或最新发布

### 发布技能

如果你为自己的智能体构建了一个其他团队也可能用得上的技能：

1. 前往 [/skills](/skills) → **发布技能**
2. 填写名称、slug、描述、类别和标签
3. 粘贴你的技能定义（系统提示片段、工具 schema 或工作流模板）
4. 点击**发布**

已发布的技能会立即出现在市场搜索结果中。你可以随时更新元数据和内容，已发布的版本都会被记录下来，方便使用者锁定到某个特定版本。

## 分配技能

技能在被**分配**之前不会产生任何作用——也就是说，要把它关联到应该使用它的智能体或智能体主机上。Builderforce 采用两级分配模型。

### 租户级分配

**租户级分配**让一项技能对你组织内的**所有智能体主机**可用。适用于每个智能体都应该具备的技能——你的编码规范、你的 API 约定、你公司特有的工具链。

在 [/skills](/skills) → **租户分配**标签页中管理租户级分配：

1. 搜索或粘贴技能 slug
2. 点击**分配给所有智能体主机**
3. 该技能会在每个智能体主机下次启动时出现在其技能注册表中

### 智能体主机级分配

**智能体主机级分配**为某个特定的 BuilderForce Agents 实例覆盖或新增一项技能。适用于装备专项智能体主机——比如你的 `frontend-workstation` 可能需要 React 和 Tailwind 技能，而其他智能体主机都用不上。

在智能体主机详情面板 → **技能**标签页中管理智能体主机级分配：

1. 点击**分配技能**
2. 搜索并选择技能
3. 分配会在该智能体主机下次启动时生效

当同一个技能 slug 同时出现在两个级别时，智能体主机级分配会**覆盖**租户级分配——以智能体主机的专属配置为准。

## 技能如何在启动时加载

当 BuilderForce Agents 启动且已配置 Builderforce 连接时，它会拉取合并后的技能列表：

```
GET /api/agent-hosts/:id/skills
```

返回的是以下两者的并集：
1. 所有租户级技能分配
2. 针对该智能体主机的所有智能体主机级覆盖

合并后的技能集会加载到智能体主机本地的**技能注册表**中，并在该进程的整个生命周期内供智能体使用。如果你在门户中新增了一项技能分配，智能体主机会在下次重启时获取它。

要查看某个正在运行的智能体主机加载了哪些技能，可以查看它的启动日志：

```
[skill-registry] loaded 4 skill(s): typescript-strict, github-api, test-runner, our-coding-standards
```

也可以在门户中该智能体主机的**技能**标签页查询，那里会显示实时的分配状态。

## 制品分配：完整的范围模型

技能只是**制品**的一种。Builderforce 使用一套统一的**制品分配**系统，适用于技能、角色设定和内容，可在任意范围级别生效：

| 范围 | 适用对象 |
|---|---|
| `tenant` | 组织内的所有智能体主机和智能体 |
| `agentHost` | 某个特定的 BuilderForce Agents 实例 |
| `project` | 在某个特定项目上工作的任何智能体主机 |
| `task` | 执行某个特定任务的智能体 |

范围解析遵循优先级：`task > project > agentHost > tenant`。如果某个任务分配了特定技能，即使租户级分配另有规定，也以该任务的分配为准。

在 [/skills](/skills) → **制品分配**中管理制品分配，你可以在同一个界面里，按任意范围分配任意类型的制品。

## 构建自定义技能

技能不只属于市场。对于内部工具、专有工作流或公司特有的规范，你可以构建永远不会离开你租户的私有技能。

一个技能定义由三部分组成：

**1. 系统提示片段**
```markdown
## Code Style
Always use TypeScript strict mode. Prefer `const` over `let`.
Never use `any` — use `unknown` and narrow with type guards.
All async functions must handle errors explicitly.
```

**2. 工具定义（可选）**
```json
{
  "name": "create_github_pr",
  "description": "Create a pull request on GitHub",
  "input_schema": {
    "type": "object",
    "properties": {
      "title": { "type": "string" },
      "branch": { "type": "string" },
      "base": { "type": "string", "default": "main" },
      "body": { "type": "string" }
    },
    "required": ["title", "branch"]
  }
}
```

**3. 元数据**
```json
{
  "name": "Our TypeScript Standards",
  "slug": "acme/typescript-standards",
  "category": "development",
  "tags": ["typescript", "code-style", "internal"],
  "version": "1.0.0"
}
```

私有技能（发布时未带 `public` 标志）仅对你的租户可见。

## 定时触发的技能

技能还可以作为**定时任务**的支撑。如果你有一个用于生成每日站会摘要、每周依赖审计或夜间测试运行的技能，可以在 [仪表板](/dashboard) → **Cron** 标签页中为它配上一个 cron 任务：

```
Schedule: 0 9 * * 1-5   (9am Monday–Friday)
Task: "Run the daily standup summary skill for project X"
```

被分配的智能体主机上的 cron 轮询器会在启动时拉取任务计划，并在正确的时间执行任务。无需任何外部 cron 基础设施。

## 最佳实践

**一个技能，只管一件事。** 一个同时涵盖 TypeScript、测试、GitHub 和部署的技能，既难维护也难调试。把它拆成聚焦的技能（`typescript-style`、`jest-patterns`、`github-actions`），再通过分配把它们组合起来。

**更新之前先升版本。** 如果某次技能更新会改变智能体的行为，发布前请先提升版本号。锁定在 `v1.2` 的使用者不受影响；想要新行为的使用者则主动更新自己的分配。

**先单独测试，再做租户级分配。** 先把新技能分配给一个智能体主机，跑几个任务，检查输出。确认无误后，再推广到租户级。

**把角色设定与技能搭配使用。** 技能传授知识；角色设定塑造语气与决策风格。两者结合——一个同时装有你的 TypeScript 技能和“资深工程师”角色设定的智能体主机——产出的结果比单独使用任何一项都更一致、更贴合品牌。

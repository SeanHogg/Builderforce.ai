图表工具特别擅长“扣押人质”。作品很有价值，文件却是专有格式，而导出选项的设计方式，恰好让唯一无损的那个格式在别处都打不开。结果，团队年复一年地为一个没人用的席位付费，唯一的目的就是偶尔重新打开一张四年前画的图。

这是一份把作品带出来的实用指南——每条路径实际能保留什么、该走哪一条，以及当你手里只剩一张 PNG 时该怎么办。

## 导出格式的等级

导出格式并不生而平等，区别在于保留下来的是**结构**，还是仅仅是**外观**。

## Visio → 画布

**导出：**`.vsdx` 文件本身。直接拖到看板上。

Visio 是最常见的外来格式，也是人们最常以为是死胡同的格式。其实不然——`.vsdx` 是一个 OPC ZIP 包，和 `.docx` 是同一种容器结构，形状就放在 `visio/pages/page1.xml` 里。

能带过来的内容包括：每个形状的位置和尺寸、它的文本、它所基于的母版（*Decision* 母版正是因此变成菱形，*Terminator* 变成椭圆），以及它的连接线——包括每条连接线连接了哪些形状，这一信息取自 `<Connects>` 块，这是文件中唯一声明它的地方。

导入时会发生两次换算，而这恰恰是每个天真的 Visio 读取器都会弄错的两件事：坐标以**英寸为单位、从页面左下角算起**；形状以其**中心点**而非角点定位。漏掉任何一个，图就会上下颠倒，而且每个形状都偏移半个身位。

**回到 Visio：**转换为 Draw.io。Visio 可以导入 `.drawio` 文件，这样就完成了往返。我们不提供直接写出 `.vsdx`，这是有意为之——一个有效的 Visio 包需要正确的内容类型、三个关系部件、一个文档部件和一个母版部件，而 Visio 面对一个有细微错误的文件不会优雅降级，而是直接拒绝打开。

**多页图纸：**只读取第一页。一个画布对象就是一张图表，把五页叠在一起，还不如只读文件打开时的那一页。

## Lucidchart → 画布

**导出：**如果你的套餐支持，用 `File → Export → Visio (.vsdx)`。否则用 `SVG`。

Lucidchart 的 `.vsdx` 导出质量不错，走的就是上面的 Visio 路径。如果你的套餐不支持——或者账号已经过期，这通常正是你读到这里的原因——那就导出 SVG 再拖进来。

拖到看板上的 SVG 默认仍是一张**图片**，这是有意为之：一个 logo 的 SVG 就是一张图片，把它变成“一张带有一个神秘矩形的图表”，是另一种方向的错误。选中它并选择 **Convert to a diagram**，形状就回来了：

- `<rect>` 变成方框，如果带有 `rx` 则变成圆角方框
- `<circle>` 和 `<ellipse>` 变成椭圆
- `<polygon>` 按顶点识别——三个点是三角形，四个点落在方框各边中点是判断菱形，六个点是六边形
- `<line>`、`<polyline>` 和直线的 `<path>` 变成连接线
- 锚点落在某个形状内部的 `<text>` 成为该形状的标签；不属于任何形状的文本会成为独立标签，而不是被扔掉

SVG 唯一无法告诉你的，是一支箭头连接的是哪两个形状——它只有坐标。这一点通过几何方式恢复：两端分别落在两个方框内的箭头，*就是*它们之间的一条关系。如果没有这一步，一旦把结果转换为 Mermaid，所有连接线都会消失。

## Miro → 画布

**导出：**看板的 PDF 或图片导出作为参考，然后重建真正重要的部分。

这是诚实的回答。Miro 导出的是一张图片，而图片里没有任何可以恢复的结构。画布提供的不是魔法般的导入，而是一个更好的重建流程：

1. 把导出文件拖到看板上——它会作为图片落地。
2. 在旁边放一个图表对象，让 Brain 以这张图片为参考，用 Mermaid 重画一遍。
3. 在文本中修正结果，这只需几分钟，而不是花几个小时重新拖拽方框。

图片会一直留在看板上、紧挨着图表，方便你在核对副本时随时看到原图。

## Excalidraw → 画布

**导出：**`.excalidraw` 文件。

这是所有导入中最完整的一种，因为 Excalidraw 的格式是诚实的 JSON，带有真实的几何信息和真实的绑定关系——`startBinding` 和 `endBinding` 明确说明一支箭头连接了哪些元素。矩形、菱形和椭圆直接映射为形状，绑定的文本变成标签，已删除的元素会被略过。

有一个陷阱值得点明：Excalidraw 也会导出为 `.excalidraw.json`，有时甚至是一个光秃秃的 `.json`。过去这个扩展名会把场景送进数据导入器，结果一张工作坊草图变成了只有一行的电子表格，每个单元格里都是 JSON 碎片。现在它通过 `type: "excalidraw"` 声明而不是文件名来识别，所以无论文件叫什么名字，它都会以本来的样子——一张图——落地。

**回到 Excalidraw：**Excalidraw 是一个完整的转换目标。导出结果是确定性的——同一张图每次导出都会得到逐字节相同的输出，而不是每导一次就生成一个新文件，因此可以比较差异。

## draw.io / diagrams.net → 画布

**导出：**`.drawio` 文件，或 `.xml`。

双向原生支持。压缩文件也能处理——draw.io 要么写出纯 mxGraph XML，要么写出经 deflate 压缩并 URI 编码的载荷，两种都能正确导入。*写出*的文件始终不压缩，这是有意为之：纯文本文件能在拉取请求中比较差异，智能体能把它当作文本编辑，而且无需解压步骤就能重新读取。

## Confluence / Sphinx / 内部 wiki → 画布

**导出：**`.puml` 源码，它通常已经放在页面宏或代码仓库里了。

PlantUML 的组件词汇——`rectangle`、`card`、`usecase`、`database`、`node`、`hexagon`、`file`——可以直接读取，`[Component]` 和 `(Use case)` 这类简写也一样。时序图和活动图语法刻意不做转换；它们不是方框构成的图，把它们压平只会得到一张能渲染、却会误导人的东西。

## 生成的图 → 画布

**导出：**你的工具链本来就在输出的 `.dot` 或 `.gv`。

依赖图、调用图和构建 DAG，大多以 DOT 的形式从各自的工具中产出。标签、形状、填充和边属性都能完整读取，包括默认属性语句（`node [shape=box]`）——这一点很重要，因为 Graphviz 自己的默认形状是椭圆，一个覆盖了默认值的文件，就是明确要这个形状。

## 流程工具 → 画布

**导出：**`.bpmn` 文件。

来自 Camunda、Flowable、Zeebe 或 bpmn.io 的 BPMN，只要文件带有图形交换信息，就会按其真实坐标读取。如果没有——这对代码生成的 BPMN 来说是常态——流程会根据其顺序流自动排布，而不是被拒收。没有图形的流程依然是流程，而这恰恰是最需要看到它的情况。

## 当目标格式无法承载全部内容时

几何类与文本类格式之间的转换并不总是完整的，而画布会明确告诉你，而不是让你事后才发现。

```bf-figure

  "title": "可能丢失的两类东西，以及会发生什么",

      "title": "在转换那一刻就告诉你",

        "填充、描边和虚线之外的精确样式"
      ]
    },
    {
      "title": "绝不会悄悄丢掉",
      "hue": "prove",
      "items": [
        "端点只有几何信息的箭头——会在写出前恢复连接关系",
```

三种只读格式——Visio、ArchiMate 和 SVG——从不作为转换*目标*出现，所以转换菜单不可能在你点击之后才失败。它只显示对你所选对象确实可行的格式；对一张照片来说，就只有 Draw.io，照片会被嵌入其中，而不是假装自己是一堆形状。

第三步和第四步的分流才是关键。描述一个不断变化的系统的图表应该是文本，因为一张架构图在画出来的第二天就会过时，而且没人会注意到。要交给别人的图表应该是 draw.io，因为布局本身就是信息，而人人都能打开才是重点。

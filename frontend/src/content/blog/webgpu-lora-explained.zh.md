## 背景：什么是 LoRA？

**LoRA**（Low-Rank Adaptation，低秩适应）是 Hu 等人于 2021 年提出的一种参数高效微调技术。LoRA 不更新大语言模型中的全部权重，而是冻结原始权重，并在每个注意力层中注入小型的**适配器矩阵**。

形式上，对于权重矩阵 `W₀ ∈ ℝᵐˣⁿ`，LoRA 加入：

```
W = W₀ + BA
```

其中 `B ∈ ℝᵐˣʳ`，`A ∈ ℝʳˣⁿ`，秩 `r ≪ min(m, n)`。

只训练 `B` 和 `A`，在 7B 模型、秩为 8 的情况下可将可训练参数减少 10 000 倍——这使得浏览器内训练成为可能。

## 为什么选择 WebGPU？

WebGPU 是 WebGL 的现代继任者，专为 GPU 计算而设计。WebGL 围绕光栅化管线而构建，而 WebGPU 则通过 WGSL 暴露原始的计算着色器——非常适合在神经网络训练中占主导地位的矩阵乘法。

相比 CPU 回退方案的主要优势：
- **并行矩阵运算**——数千个着色器线程同时执行
- **共享内存**——基于分块的 GEMM，配合片上缓存
- **无数据外流**——权重绝不离开你的机器

## Builderforce 训练流水线

```
Dataset (JSONL) → Tokeniser → Batching → Forward Pass → Loss → Backward Pass → Weight Update → Repeat
```

每一步都作为 WebGPU 计算管线运行：

1. **分词**——通过 Transformers.js 的 WASM 分词器在 CPU 上运行
2. **前向传播**——注意力层和前馈层被分派到 GPU 着色器
3. **损失计算**——在词表分布上计算交叉熵
4. **反向传播**——在 WGSL 中通过反向模式自动微分计算梯度
5. **AdamW 更新**——LoRA 适配器权重 `A` 和 `B` 带动量更新

## SharedArrayBuffer 与 COOP/COEP

WebGPU 需要 `SharedArrayBuffer`，以便在 CPU 与 GPU 之间无需拷贝地传输张量数据。这个 API 受跨源隔离响应头的限制：

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: credentialless
```

Builderforce 在每个页面上都设置这些响应头，在启用 `SharedArrayBuffer` 的同时仍允许跨源的字体和图片。

## 隐私保证

由于训练完全在你的浏览器中进行：

- 你的训练数据**绝不离开你的机器**
- 你的模型权重**绝不经过我们的服务器**（除非你明确选择发布）
- 我们无法查看、记录或变现你的微调数据

LoRA 适配器权重会从 GPU 缓冲区序列化，可下载为 `.safetensors` 文件，或在你的账户下推送到 Cloudflare R2。

## 局限性

浏览器内训练确实存在约束：

| 因素 | 浏览器上限 | 云端对照 |
|--------|--------------|-----------------|
| 模型规模 | 约 2B 参数 | 无限制 |
| 显存 | 与操作系统共享（约 8 GB） | 40–80 GB |
| 训练速度 | 约 50 tok/s | 约 5 000 tok/s |
| 批大小 | 1–4 | 32–256 |

对于更大的模型或更快的迭代，你可以导出数据集，在任何标准平台上继续训练——Builderforce 不会挡你的路。

## 结语

浏览器中的 WebGPU LoRA 微调并不是噱头——它是为特定任务个性化小模型的一种实用方式，既不需要任何云基础设施，也没有数据隐私方面的顾虑。在[你的下一个项目](/dashboard)中试试吧！

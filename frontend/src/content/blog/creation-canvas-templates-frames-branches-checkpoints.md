# From Blank Canvas to Repeatable Playbook: Templates, Frames, Branches, and Checkpoints

A blank canvas is liberating once. A repeatable team process needs structure that can be reused without freezing every project into the same document.

Creation Canvas separates four kinds of reuse: starter packs, reusable frames, named checkpoints, and branches.

![Product view of the Canvas template menu with six shipped packs, a framed workspace, named checkpoint history, branch indicator, and object-by-object merge review controls](/blog/canvas-reuse-versioning-workspace.svg)

## Packs create working object systems

Builderforce ships six starter packs through the Canvas template catalog:

- **Campaign studio** — Workflow, Website, Dashboard, and campaign Agent.
- **Product discovery** — Dataset, Feature Summary, Mockup Set, and Evaluation.
- **Data story** — Dataset, Chart, Dashboard, and Slides.
- **Impromptu stand-up** — Stand-up, Staff Member, Agent, and follow-up Task.
- **Evermind model lab** — Dataset, Evermind, Evaluation, and published-model Agent.
- **Executive review** — Project, Dashboard, Roadmap, and Slides.

The pack places real registered object kinds and starter relationships. Tenant policy still governs every live resource attached afterward; installing a pack does not grant access to a Project, model, Agent, or integration.

## Frames preserve a useful arrangement

A Frame is a first-class collaboration object with a purpose, color, and border. Teams can group a review area, workshop, model pipeline, or presentation sequence without implying that every nearby object executes together.

Custom frame presets can be saved privately on the device and inserted again from the template menu. This is useful for recurring rituals and layout conventions that do not justify a full workspace template.

![Starter packs place registered objects and typed edges; reusable Frames preserve local arrangements; named Checkpoints save meaningful server states; Branches support independent experiments; merge review chooses the branch or parent version for each matching object](/blog/canvas-reuse-layers.svg)

## Checkpoints name meaningful states

Automatic history answers “what changed?” A named checkpoint answers “which state did the team agree mattered?” In a server-backed Session, editors can name a checkpoint before an executive review, experiment, delivery decision, or model training change.

Checkpoints appear in session history alongside revision snapshots. They are not a substitute for branch experimentation; they are a durable landmark on the current line of work.

## Branches isolate experiments

A branch creates an independent Session derived from the parent. Use it for a different information architecture, campaign direction, model plan, or prioritization lens. Collaborators can work without moving the parent canvas through every intermediate state.

When a branch returns, Builderforce prepares an explicit merge review. For every object that exists in both versions, the reviewer chooses the branch version or keeps the parent version. New objects can be accepted without replacing unrelated parent work.

This object-by-object model matches the actual unit of creation better than “replace the whole board.”

## Export keeps the session portable

Canvas export provides another recovery and portability path. Together, the layers form a practical progression:

**pack for a starting system → frame for a reusable arrangement → checkpoint for an agreed state → branch for an experiment → merge for an explicit decision → export for portability**

Reuse becomes more precise because each mechanism answers a different question.

# 在你构建它的浏览器标签页里，用 Python 训练 LoRA 适配器

你有一种直觉：一个小模型在你的数据上会表现得更好。过去要验证这一点，得先绕一段远路：租一台 GPU 机器，安装 PyTorch，把数据复制过去，运行脚本，把权重复制回来，再想办法把它们加载到一个真正能试用的地方。

等答案到来时，问题早已凉了。

这段远路现在可以不走了。**你项目中的 Python 训练脚本会在你构建它的浏览器标签页里运行，它保存的适配器会变成一个你可以发布和调用的模型。**

## 按下 Run 时会发生什么

在项目的 `builderforce.json` 中把脚本声明为一个 `training` 服务——`python train.py`，不需要端口。按下 Run，脚本就会在标签页里与应用的其余部分一起启动。

在脚本中，`import torch` 和 `import peft` 都能正常工作。它们通过 WebGPU 在你的 GPU 上运行，使用的是与浏览器内训练器相同的引擎。脚本用 `bfwc.training.log(step, loss)` 记录损失。训练结束时，它用 peft 的 `save_pretrained` 把适配器保存到 `bfwc.training.artifact_dir()`。如果你提前停止它，运行时会请求它保存检查点：检查 `bfwc.training.checkpoint_requested()` 的脚本会保存并干净地退出。

打开训练面板，在 **来自 Python 训练服务的适配器** 下选择该服务，并加载它保存的适配器。从这里开始，它就是与面板内训练运行所产出的同一种产物。发布它，用一个提示词测试它，并在留出文本上对它进行基准测试，与在面板中训练的适配器完全一样。

## 它适合做什么，不适合做什么

这是一个用于小型、快速实验的工具，其限制是真实存在的：

- **GPU 速度需要 WebGPU。** 没有 WebGPU，同一个脚本会在 CPU 上运行，速度要慢得多。
- **仅限小模型。** 浏览器把基础模型和适配器都保存在你标签页的内存中。
- **仅限 LoRA 适配器。** 适配器针对的是浏览器 Evermind 模型的词元嵌入，也就是浏览器模型加载适配器的模块。在你的脚本中，这意味着一个名为 `embed_tokens` 的 `nn.Linear`，其权重就是 Evermind 基础模型的词元嵌入；目前尚未提供现成的 Python Evermind 模型。完整微调和其他目标模块不在支持范围内。
- **基础模型随适配器一起提供。** 保存的结果可以带上自己的基础模型（`base_model.safetensors` 和 `tokenizer.json`）；否则，你需要在面板中选择训练时所用的基础检查点和分词器。

大模型仍然属于云端训练。这是为之前的那一步准备的：弄清楚这些数据究竟有没有带来改变。

## 它在方法中的位置

Idea to Real 是一道弧线——**Idea → Make → Run → Measure**——其中还有一个循环：[Read、Prove、Build](/blog/read-prove-build-the-inner-loop)。一个微调想法和其他任何想法一样，都是一次验证。验证它最便宜的方式，是在小模型上训练一个小适配器，就在你所在的地方运行，并用模型从未见过的文本来评估。

在标签页里训练，把这次验证放进了 Run 阶段。面板中的基准测试就是 Measure 阶段：在留出文本上衡量困惑度和准确率，让你凭数字而不是感觉做决定。

## 今天你可以做什么

- **在标签页里运行 Python 训练脚本**，使用 `import torch` 和 `import peft`，通过 WebGPU 在你的 GPU 上运行。
- **停止它而不丢失成果。** 检查检查点请求的脚本会在退出前保存。
- **把保存的结果变成一个模型**，在训练面板中发布、调用并进行基准测试。
- **让数据留在本地。** 在你选择发布之前，训练数据和保存的适配器都留在你的浏览器中。
- **升级到云端训练**，当这个想法值得一个更大的模型时。

一天的工作，大部分并不发生在编辑器或画布上，而是发生在浏览器的标签页里：报销单、供应商门户、预订页面、为了做一个决定要浏览的十几个网页、这个月第四次填写的同一张表单。

Builderforce 的智能体可以在 VS Code 里写代码，也可以在看板上搭建应用。但在浏览器里，它什么也做不了。你从网页上复制文字，粘贴到聊天里，读完回答，再回去自己一下下地点。助手知道得很多，却在真正干活的地方帮不上一根手指。

Rovr 补上的正是这块空白。

## Rovr 是什么

Rovr 是 Builderforce 自己的浏览器助手——一个 Chrome 扩展，以侧边栏的形式在你当前页面旁边打开。你告诉它需要什么，它会阅读页面，找到对应的输入框和按钮，填写内容，在标签页之间切换，一步一步完成任务，并随时告诉你它做了什么。

它和一个恰好放在浏览器旁边的聊天窗口有三点不同。

**它记录每一个操作。** 它读过的每个页面、每一次点击、填写的每个字段、你拒绝的每一步，都会写进操作记录：做了什么、在哪个页面、结果如何。你随时可以回看；这份记录会随对话一起同步——你在浏览器里看到的记录，就是你的团队在 Builderforce 里看到的那一份。

**你可以告诉它该怎么做。** 操作手册是用你自己的话写下的指示——*当我说“提交我的报销”时，打开报销网站，把收件箱里的每张收据都加进去，并在提交前停下。* 当请求匹配时，Rovr 会按你的步骤执行，而不是临场发挥。操作手册通过你的 Chrome 个人资料同步，你登录的每个浏览器里都能用。

**重要的事情先问你。** Rovr 只在你允许的网站上工作，第一次需要新网站时会先征求你的同意。凡是会提交表单、购买东西、发送或发布消息、删除内容，或涉及密码、银行卡号的操作，都会在侧边栏里等你点头。网页内容一律被当作信息，而不是指令：一个让 Rovr 无视你的网页，只不过是一个说了奇怪话的网页。

## 默认私密，需要时才联网

Rovr 优先在你自己的电脑上运行模型。只要 Synapse、Ollama 或 FreeToken 正在运行，你的请求就会交给它：不需要账户，不计费，任何内容都不会离开你的电脑。当某一步超出了本地模型的能力——比如一个要用到很多工具的长任务——Rovr 会在你看到回答的第一个字之前，悄无声息地把这一步交给 Builderforce 的云端模型。

## 任务落在团队看得到的地方

当你让 Rovr 记住某件事——*周五跟房东跟进一下*、*在域名过期前续费*——或者某个任务带出了后续工作时，它会在对话里添加一个任务。在设置中选择一个项目后，每个任务都会创建在该项目中，并关联到产生它的那段对话，接手的人能清楚地看到它从何而来。

## 它在方法论中的位置

在 Builderforce 上，工作遵循一条主线：**构想 → 制作 → 运行 → 衡量**，而每个环节内部都有同一个循环：[阅读、验证、构建](/blog/read-prove-build-the-inner-loop)。Rovr 把这个循环带进了你已经打开的标签页。

- **构想**始于你注意到某件事的那一刻。就眼前的页面问 Rovr 一个问题，这个问题就成了一段对话，页面就是它的依据。
- **阅读**是 Rovr 在每个任务中做的第一件事：动手之前先看页面，从不猜测一个它没见过的按钮。
- **验证**就是那张确认卡片。在任何有后果的操作之前，你都能看到 Rovr 准备做什么，以及它为什么要问你。
- **运行**是任务本身，一步一步执行，优先在你的电脑上。
- **衡量**是操作记录和任务。发生过的事被记录并同步，因此下一次运行——无论是你的还是同事的——都能从这一次的结果出发。

## 你今天就能用它做什么

- **不用自己动手点击就在网站上完成任务**——填写表单、从三个页面汇总数据、找到藏在四层菜单里的设置。
- **把你希望的做事方式写一次**，作为操作手册，Rovr 每次都会照做。
- **没有网络也能继续工作**，使用在你自己电脑上运行的模型，联网后再让对话同步。
- **把一段对话变成可追踪的工作**——Rovr 创建的任务会进入你的项目，并关联到产生它们的对话。
- **清楚地看到发生了什么**——每一个操作、每一个页面，按顺序呈现，在浏览器里和 Builderforce 里都能看到。

把 Rovr 添加到 Chrome，用你的 Builderforce 账户登录（也可以不登录，完全在自己的电脑上运行），允许一个网站，然后开口问吧。

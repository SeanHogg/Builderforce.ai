模型开发很少是单一动作。它结合了证据、数据集准备、分词器选择、调优、评估、打包、部署和持续观察。Creation Canvas 把这个生命周期呈现为一个相互连接的系统，而不是把它藏在一连串彼此分离的页面背后。

## 从你需要的模型开始

打开一个空白会话，描述你想要的结果：

> 创建一个客服 Evermind，从我们已批准的解决方案中学习，回答时附带引用，并且在发布之前必须通过安全性和准确性关卡。

添加一个 Evermind 对象，或使用 Model Lab 套件。匿名创作者可以先在本地勾勒并完善整条流水线，无需账户、租户、Project 或计算资源。保存、协作、正式训练和发布，要在会话被认领到账户之后才开始。

## 让学习流水线显式化

展开 Evermind 的创建与训练流水线，即可在画布上放置相互连接的 Dataset、分词器、调优运行、Evaluation 和遥测对象。带类型的连接让意图可被机器读取：数据流向准备与训练；评估把关交付；遥测观察已部署的模型。

Dataset 对象可以导入 CSV 或 TSV 证据，并创建图表用于质量审阅。笔记、报告、仪表盘和 Project 上下文可以放在流水线旁边。Brain 可以评估现有样例是否覆盖了目标受众，找出薄弱的细分，并提出改进建议。

![受治理的 Evermind 学习闭环：已批准的数据集经过准备和分词器处理，进入有版本的调优运行；准确性、安全性和引用评估为打包与发布把关；遥测与已批准的解决方案把新的证据反馈给模型](/blog/evermind-governed-learning-loop.svg)

## 让模型变更受到治理

Canvas 的访问权限从不扩大对底层数据集、Project 或 Agent 的访问。Brain 把推理范围限定在该成员可读取的对象内。凭据和导入的行内容会被排除在安全搜索预览之外。

涉及多项资源的变更以可审阅提案的形式出现。操作者选择接受哪些更新，而正式的训练与发布仍沿用其现有的权限、版本和审批规则。具名检查点和 Session 分支支持实验，而不会覆盖已商定的设计。

## 跨专业协作

邀请领域专家担任 Commenter，模型工程师担任 Editor，运维人员担任 Runner。他们可以查看同一份模型方案，留下对象级评论，跟随演示，并实时看到已被接受的活动。开发者可以在 VS Code 中打开该 Session，并把仓库文件、选区、诊断信息、终端输出或本地服务添加到同一张图中。

## 交付之后继续学习

Evermind 的设计目标，是随着已批准的工作产生新的证据而不断进化。Canvas 为这个学习闭环提供了运行全景：源数据、当前版本、评估、教学或调优活动、质量关卡和遥测都保持相连。团队可以回到该 Session，理解的不只是哪个模型正在运行，还有它为何获得批准，以及接下来应该改进什么。

# From Customer Feedback to Ten Interactive Mockups in One Session

Product teams rarely lack feedback. They lack a trustworthy path from thousands of comments to a small set of decisions—and from those decisions to something customers can actually evaluate.

Creation Canvas turns that path into one visible session.

## 1. Bring in the evidence

Start a session with a prompt such as:

> Visualize our customer feedback, identify the ten most-requested features, and create an interactive concept for each.

Add a Dataset object and import CSV or TSV feedback. You can also place project-backed feedback, reports, dashboards, documents, or connected MCP sources on the canvas. Sensitive source access continues to follow the underlying resource permissions; adding an object does not copy around those controls.

Ask Brain to profile themes, segments, frequency, and recency. A Chart or Dashboard object can show which requests dominate overall and which matter disproportionately to a high-value customer segment.

## 2. Synthesize—not merely count

Raw mention count is useful, but it is not a roadmap. Two customers can describe the same need in different language, and one strategically important request may matter more than fifty cosmetic preferences.

Brain creates a Feature Summary object that groups semantically related feedback and retains citations to the original evidence. A good summary records:

- the customer problem;
- representative source evidence;
- frequency and affected segments;
- expected outcome;
- known constraints and dependencies;
- confidence and evidence freshness.

Because the summary is an object, collaborators can comment on it, connect project metrics, or ask for a different prioritization lens without losing the first interpretation.

## 3. Expand the ten features into mockups

Connect the Feature Summary to a Mockup Set and ask Brain to expand every item. Each feature becomes an individually reviewable Mockup object rather than a static collage.

Use a WYSIWYG Prototype object when a concept needs higher fidelity. Edit headlines, calls to action, color, responsive viewport, navigation, or data bindings directly in the inspector. Add drawings and notes around a concept during critique. Group related variants in a reusable Frame.

At this point the canvas becomes a visual decision room: evidence to the left, synthesized opportunities in the middle, and interactive concepts to the right.

## 4. Evaluate concepts against reality

Add the relevant Project object and expand its customer-feedback, metrics, or delivery lens. Brain can now compare a mockup to current features, open work, product health, and delivery constraints.

Ask questions such as:

- “Which concept resolves the largest verified customer problem?”
- “Which features overlap with work already planned?”
- “What dependencies make these three concepts risky this quarter?”
- “Create a sales narrative and an executive roadmap from the approved set.”

Brain adds persistent Evaluation, Roadmap, and Slides objects with inspectable sources. Recommended multi-object changes remain proposals until a reviewer selects and applies them.

## 5. Deliver approved work

Projects are optional during exploration, but valuable at delivery time. From an approved Mockup, choose **Add to project and assign**. Builderforce creates or links a Task, attaches the artifact, assigns a human or AI Agent, and applies the project’s approval policy.

The task run remains visible from the session. Reviewers can see whether the work is ready, running, awaiting approval, blocked, or delivered without abandoning the evidence and decisions that produced it.

This is the crucial difference between generating ten pictures and developing ten product concepts. Every concept has provenance. Every approval has an audit trail. Every delivered artifact has a route into accountable work.

## Use a reusable Product Discovery pack

**evidence → synthesis → visual concepts → evaluation → approval → delivery**
